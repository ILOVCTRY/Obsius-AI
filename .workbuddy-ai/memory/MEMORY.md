## 前端（webui/）

- **改完必须重建**：`cd webui && npm run build`（= `tsc -b && vite build`）。平台**dist 静态优先**，不重建看不到改动。构建会清空 `dist/assets` 旧 hash 包。
- 样式集中在 `webui/src/index.css` 的 `.wb-*` 段（智能体工作台）；会话流部分已迁 Tailwind 工具类。
- **主题体系（2026-10-15 起 5 套配色 + 毛玻璃质感模式）**：`src/lib/theme.ts` 的 THEMES + index.css 每主题一个 `[data-theme="..."]` 块（shadcn 语义 token + `--brand*`/`--surface*`/`--viz*`/`--status*` + `--theme-raw-*` 兼容层，~250 token/块）。配色 = cyber-dark（默认）/ warm-dark / light / **rose-dark 绯樱** / **rose-light 蔷薇**。**毛玻璃不是主题而是 `html[data-glass="1"]` 质感模式**（`applyGlassMode`/`getGlassMode`，localStorage `ui.glass`，与配色正交可叠加；`applyTheme` 会重放该属性，切配色不丢质感）。新增配主题三件套同步：theme.ts + index.css 块 + `index.html` 首帧防 FOUC 白名单。粉色两张由 `scripts/gen_rose_themes.py`、玻璃模式由 `scripts/gen_glass_theme.py`（幂等标记 `glass-mode:start/end`，只出一个通用块：各主题都有 `--surface-*-lch`/`--text-lch` 基色，玻璃块统一加 alpha/color-mix）派生——**改口径先改脚本再重放，跑完必须 grep 校验无 `None` 残留**。**玻璃模式隐形杀手**：① `.app-shell{background:var(--background)}` 整屏罩子——明亮两套 `--background` 只给 0.55（0.8 会把壁纸洗白）；② **`backdrop-filter` 绝不加在整屏 `.app-shell`**（会把整幅壁纸糊掉，dim=0 也模糊），只加 portal 浮层 + `.app-nav`/`.wb-aside`/`.wb-composer`/`.wb-panel`；③ **`-webkit-backdrop-filter` 前缀必须写在标准属性之前**（写反了 lightningcss 去重只留前缀版，而本机 Edge 不认 → 糊化整体静默失效）；④ **两个不同档位的玻璃表面之间夹透明缝 = 额外亮带**（`.app-nav` 的 raw 实色 `border-r` + 2px `bg-transparent` 的 `<Separator className="nav-sep">` 透出 `.app-shell` wash；修法见 `gen_glass_theme.py`：边框退透明、发丝线改由 `.nav-sep` 右缘出 `--border`、`.nav-sep` 延续导航表面并进 backdrop-filter 名单）；⑤ **嵌套 `backdrop-filter` 会丢下层 = 面板发黑**（`.app-nav` 有 blur → 成为 backdrop root；里面停靠的 `.wb-aside` 再 blur 时只拿到导航那层半透明底色、丢掉壁纸，63% 深色叠黑上渲染成近黑。实测：停靠面板 (32,23,26) vs 导航 (70,64,66)。**父层已糊过的子面板必须关掉自己的 `backdrop-filter`**，且只在停靠态关——非停靠态它仍需自己 blur）。玻璃块不带 layer 会盖掉 Tailwind 的 `hover:bg-accent`/`data-[separator=active]:bg-accent`，高亮需在块内显式重声明。viz 画布 token 保持实色（var 自引用成环，模式里无法加 alpha）。**未被玻璃档覆盖的表面**（2026-10-16 已修）：`.wb-drawer-panel`/`.wb-rail`/`.wb-context-rail`/`.wb-rail-handle` 原先吃 `--theme-raw-8b524e3722` 原色（自带 55% alpha、无 blur）、不在糊化名单里 → 是偏实的深色板；现已并入 `.wb-aside` 同档（同 token、同 `--glass-aside-a`、同 blur）。
- **背景壁纸（毛玻璃模式配套）**：`src/lib/wallpaper.ts`——blob 进 IndexedDB、dim/fit 进 localStorage、`--wallpaper-*` CSS 变量挂 documentElement（JS 内联值优先于块内默认）；`.wallpaper-layer`（fixed z-index -1）所有模式共用、**仅玻璃模式显影**；`main.tsx` 启动 `initWallpaper()`；设置页 AppearancePane「毛玻璃与壁纸」分区（开关 + 上传/滑块/chips/恢复默认，上传即自动开玻璃）。旧版 `ui.theme="glass"` 已迁移为 cyber-dark + 玻璃开（theme.ts 与 index.html 首帧两处）。
- 动效统一尊重 `prefers-reduced-motion`（index.css 末尾有一段集中 `transition: none !important`，新增带 transition 的类要登记进去）。
- **左导航分组折叠**（`App.tsx` `NAV_GROUPS` + `NavRail`）：`collapsible:true` 的组标题行可点折叠、`defaultOpen` 控首次默认；状态按组名存 `ui.nav-groups-open`（JSON，旧键 `ui.nav-more-open` 自动迁移）。**展开与否在渲染期派生**：`open = !collapsible || !expanded || (groupOpen[label] ?? groupHasActive(group.items, active))`——只有用户没做过显式选择时才回退到「当前视图在组内就展开」，折叠按钮才点得动；**别写成 effect 里 `setGroupOpen`**（多一次渲染 + oxlint `react(set-state-in-effect)` 会报，本项目该规则 0 error）。窄栏态恒展开；无项目（`locked`）时分组拍平无标题。
- **工作台左栏停靠进左导航列（2026-10-16）**：agents 视图 + 有项目时，工作台左栏（会话线程列表）经 `createPortal` 投进左导航列下半的 `.nav-rail-slot`，主区多出整列宽。机制 = `App.tsx` 的 `railActive` 决定 NavRail 是否渲染槽位 + `railSlotRef` 交节点 + `NavRailSlotContext`（`src/lib/navRail.ts`）下发 + `AgentWorkbenchView` 读 `useNavRailSlot()` 决定 `docked`；**槽位不存在时 context 为 null → 原样两列布局**（导航收起/窄栏/非 agents/无项目）。停靠态卸载工作台自己的 `.wb-splitter`。**两个坑**：① 停靠态 `.wb-aside` 必须显式 `min-height:0`（基础规则 `flex:0 0 236px` + `min-height:auto` 取内容高 ≈265px，槽位压低时直接溢到页脚）；② 槽位与 `.nav-scroll` 都 `flex:1` 时槽位写 `min-height:0` 会先缩到 0 —— 要给较大 flex-basis（实测 **560px**）配 `min-height:240px` 保底。槽位**不加 `overflow:hidden`**。
- **智能体切换只在 composer（2026-10-16）**：左栏的 `.wb-aside-head`/`.wb-agent-trigger`/`.wb-agent-name`/`.wb-agent-role` 四类已整体删除，切换入口只剩 composer 的 `.wb-composer-agent` 药丸（→ `.wb-agent-menu` 浮层）与 composer-bar 的 `Agents` 面板。**浮层挂 `.wb-composer-wrap`**（`.wb-composer` 有 `overflow:hidden`，内嵌被裁），定位 `bottom:calc(100%+8px); left:12px; width:300px`——**必须定宽**，原口径 `left/right` 撑满父容器在 236px 左栏里合适，搬到 1067px 主区会变成巨型菜单。新增浮层一律照 `.wb-model-pop` 这套（wrap 内 + `.wb-model-backdrop` 关外点）。
- **悬浮待办卡（2026-10-16）**：`.wb-todo` 改 `position:sticky` 钉在 `.wb-stream` 顶部，`z-index:6`。两条**通用 CSS 教训**（不止本项目适用）：① **Chromium 的 sticky 约束矩形顶边取滚动容器的内容盒顶（已内缩 `padding-top`）**，故 `top:0` 只会钉在「内容起点」= 流顶下方 padding-top，上方留缝露出被截断的正文；要真正贴顶得写 `top: calc(-1 * var(--stream-pad-top, 20px))`（本项目把 `.wb-stream` 的 `padding-top` 提成 `--stream-pad-top` 变量联动）。grid 父容器里的 sticky 子项**能**正常钉住（实测证伪「grid item sticky 失效」）。② **`background` 简写里 `<color>` 只允许出现在最后一层**，写成 `..., <0.8色>, oklch(不透明垫底)` 会让颜色落在中间 → 整条声明计算值阶段判无效、background 整体回退成 none/transparent（卡片变透明）。垫底要拆 `background-color` 单列，或把中间那层颜色写成同色 `linear-gradient(c,c)`。玻璃模式由 `gen_glass_theme.py` 的 `[data-glass="1"] .wb-todo` 去掉不透明垫底、换回磨砂（(0,2,0) > 基础规则 (0,1,0)，不靠源码顺序）。对比图 `scratch/todo-sticky-before-after.png`。
- 文档同步约定：改 `views/*` 或 `components/*` 时同步 `webui/CLAUDE.md` 对应条目（该项目 CLAUDE.md 是逐文件清单式，很细）。

## 本机写文件坑（2026-10-15 实测）

- 文件名含 U+FF1A`：`/U+FF5C`｜` 时 `pathlib.write_bytes` 抛 `[Errno 22]` → 用 `os.open(rel, O_WRONLY|O_BINARY|O_TRUNC)+os.write`。
- 本机 `core.autocrlf=true`：`write_text` 写 CRLF 而 git HEAD 是 LF → 批量改写 md 后必须按 HEAD 的 EOF/CRLF 形态归一工作副本，否则 status/diff 计数虚高几百。
- 行切分改写 md 一律 `split("\n")`+`"\n".join`，勿用 `splitlines()`（丢 EOF 换行，曾误伤 535 文件）。
- 大批量 `find|xargs rm` 会被 SIGTERM，删除/查询改小批量（每批 3-6 个）显式跑。

- 黑板 schema 版本：`core/blackboard/schema.py` 的 `SCHEMA_VERSION` + 顶部版本注释 + `_migrate()` 幂等 ALTER。**改版本号必须同步 `tests/test_blackboard.py` 里硬编码的 `== <N>` 断言**（有两处：`test_schema_v7_migration`、`test_schema_v11_migration_idempotent`）。
- 迁移写法惯例：`if cols and "x" not in cols: ALTER TABLE ... ADD COLUMN x TEXT NOT NULL DEFAULT ''`（幂等、老库开即补、历史行不回填）。
- 本地 Python：项目自带 `.venv`（`./.venv/Scripts/python.exe`），测试 `./.venv/Scripts/python.exe -m pytest tests/... -q`。
- **删资产可级联删发现（2026-10-16）**：`store.delete_asset(..., cascade_findings=False)` 默认保留旧 409 守卫（`bb_delete_asset`/`bb_delete_assets` agent 工具与 `scripts/normalize_dirty_domains.py` 都吃默认值，行为不变）；`cascade_findings=True` 同事务把 `target_asset_id` 指向该资产的发现一并物理删除，**与 `delete_finding` 共用 `_purge_finding_in_tx`**（摘反向 `relates_to` 边、不触发撤回传播、chain_links/inbox/poc 产物保留），返回 `findings_deleted`、逐条补发 `finding.deleted`（带 `via: "asset.deleted"`）。API `DELETE /api/projects/{pid}/assets/{id}?cascade=true`（Web UI 删除按钮带上）。有子资产时级联也不放行。
- **资产计数口径 level-two-counts（2026-10-16）**：资产数 = 资产树「根节点 → 二级子节点 → 三级 URL」里**只数二级子节点**（深度恰为 1、父为根；根是分组容器、三级 URL 只是二级明细，都不进分母）。`core/coverage.py::level_two_stats` 是唯一出处（纯函数，`COVERAGE_TYPES` 四类限定保证分子分母同一总体，binary 不算），`GET /api/projects/{pid}` 的 `assets`/`assets_clean`/`assets_clean_pct` 消费之，前端顶栏显「已测干净 N/M · P%」。clean = effective_status==tested_clean（含父派生 clean）；pct=round(clean*100/total)，total=0 返 0。
- **知识库索引红线**（`core/skills/kbsearch.py`）：`kb_documents_fts.path` 是 **UNINDEXED** 列，FTS5 按 path 删行 = 全表扫 content 影子表，逐行删是 **O(N²)**。**新增按 path 删 FTS 的代码一律走 `_delete_fts_rows`（分块 `IN` 批量删），勿写逐行 `DELETE ... WHERE path=?`**。背景：`KbSearchIndex.search()` 每次调用都 `sync()`，一次 `kb_search` 要遍历 N 个能力 → N 次 sync，曾导致单次工具调用卡 4 分钟。
- **仓库卫生（2026-10-16）**：`Knowledge/src-strike` 是**无 `.gitmodules` 注册的 gitlink**（索引 `160000`）——父仓库 `git add -A` 不会带上其内部改动（子模块 13 个脏文件需进子模块单独提交），`git submodule status` 无输出属正常。根目录曾有误落截图 `lqcx_cap1.png` 被 add 带走（已 unstage），**`git add -A` 前留意根目录新增的 png**。
