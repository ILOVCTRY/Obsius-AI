## 诊断：毛玻璃模式下「停靠线程面板 / 工具抽屉」偏暗（2026-10-16 01:20，待用户定方案）

**现象（Nan 截图）**：左导航列下半的停靠会话线程面板、右侧工具抽屉两处是「深色透明」，用户希望
改成「浅色透明」。像素实测（1920×1078 截图，x=140 纵剖）：导航区 (70,64,66) → 停靠面板 **(32,23,26)**
→ 导航页脚 (70,64,66)；右侧抽屉 (26–62)。主题为 **rose-dark**（暗配色）。

**成因 ①（真 bug）停靠面板比导航更暗 = 嵌套 backdrop-filter**
`.wb-aside` 停靠态是 `background: transparent`（`.nav-rail-slot .wb-aside`），但**它自己也在玻璃糊化名单里**。
`.app-nav` 已有 `backdrop-filter` → 它成为 **backdrop root**；里面 `.wb-aside` 再 blur 时，拿到的「背景」
只有导航那层半透明底色本身（丢掉了下层壁纸），63% 深色叠在黑上 → 渲染成近黑 (32,23,26)。
**变体对照实测**（`%TEMP%\bisect_dark.py`，rose-dark + 亮壁纸，采样点 停靠面板）：
`baseline 37` / `.wb-aside{backdrop-filter:none} **75**` / `.app-nav{backdrop-filter:none} 76` /
`.wb-aside{background:nav token} 15`（更黑，印证底色叠在暗背景上）/ 槽位关 blur 无变化 37。
→ 结论：**停靠进 `.app-nav` 的 `.wb-aside` 必须关掉自己的 backdrop-filter**（父层已经糊过了）。
注意此规则只在停靠态生效；非停靠态（导航收起/窄栏）它仍需自己 blur。

**成因 ②（口径缺失）工具抽屉等右侧栏根本没进玻璃档**
`.wb-drawer-panel` / `.wb-rail` / `.wb-context-rail` / `.wb-rail-handle` 都吃
`var(--theme-raw-8b524e3722)` **原色**（自带 55% alpha、**无 backdrop-filter**），不在 `gen_glass_theme.py`
的糊化名单里 → 是块偏实的深色板，与导航/侧栏那套玻璃不同族。

## 请求 M：待办卡改悬浮（不随滚动移动）

**需求**（Nan，verbatim）：「让红色方框内的待办作为一个悬浮卡片，不随上下翻页而移动。」
→ `.wb-todo` 由静态卡改 `position: sticky`，钉在 `.wb-stream`（最近滚动容器，`overflow-y:auto`）视口顶部。

**先证伪关键假设**：`%TEMP%\sticky_test.html` 对照 grid 父容器 vs 块容器里的 sticky ——
`A: scrollTop 0→300 | todo offset 21→21 => PINNED`；`B: 同上 => PINNED`。
→ **Chromium 下 grid 父里的 sticky 子项同样能钉住**，不必把卡片挪出 `.wb-timeline`（`display:grid`），纯 CSS 可解。

**踩坑一：钉位 ≠ `top:0`**。实测 Chromium 的 sticky 约束矩形顶边取滚动容器的**内容盒**顶（已内缩 `padding-top`），
故 `top:0` 让卡片钉在「内容起点」= 流顶下方 20px → 卡片上方留一条 20px 缝、**露出一行被截断的正文**（像 bug）。
运行时注入变体对照（不重建，`%TEMP%\e2e_todo_variants.py`，`scrollTop=300` 读 `todoTopRel`）：
- `v_base`（`top:0`）→ **20**（露字缝）
- `v_negmargin`（`.wb-timeline{margin-top:-20px}` + `:first-child{margin-top:20px}`）→ **20**（负 margin 无效，包含块钳制照旧）
- `v_streampad0`（`.wb-stream{padding-top:0}`）→ **0** ✓
- `v_topneg`（`.wb-todo{top:-20px}`）→ **0** ✓ ← 采用（零风险，不动 padding / Hero / 消息间距）

**落地**：`.wb-stream` 的 `padding-top` 提成变量 `--stream-pad-top: 20px`（`padding: var(--stream-pad-top) 24px 8px`），
`.wb-todo` 写 `top: calc(-1 * var(--stream-pad-top, 20px))`（自解释、随 padding 联动）。
副作用：`scrollTop 0→20` 卡片从 20 平滑升到 0 再钉住（20px「先升后钉」，标准 sticky 行为；流默认滚到底部，通常看不到）。

**踩坑二：`background` 简写里 `<color>` 只能在最后一层**。补不透明垫底时写成
`background: <高光渐变>, var(--theme-raw-ff24ae504f), oklch(var(--surface-1-lch))` ——
那个 0.8 色落在**中间** → 整条声明在计算值阶段判无效 → `background` 整体回退成 `none`/`transparent`
（端到端实测非玻璃模式 `backgroundImage=none backgroundColor=rgba(0,0,0,0)`，卡片变成透明）。
正解：拆成 `background-color: oklch(var(--surface-1-lch))`（不透明垫底）
+ `background-image: <高光渐变>, linear-gradient(<0.8 色>, <0.8 色>)`（后者用同色渐变表达，绕开限制）。

**脚本改动**（`scripts/gen_glass_theme.py`，重放输出 `[data-glass="1"] x36, None x0`）：
糊化名单加 `.wb-todo`；新增 `[data-glass="1"] .wb-todo { background: linear-gradient(180deg, var(--theme-raw-deaf08acbf), transparent 70%), var(--theme-raw-ff24ae504f); }`
（去掉不透明垫底、换回磨砂 + 自身 backdrop-filter；选择器 (0,2,0) > 基础规则 (0,1,0)，不靠源码顺序）。

**端到端校验**（非玻璃 / 玻璃 × `scrollTop` 0 / 300）：
- 几何：`scrollTop=0` → `todoTopRel=20`（自然位）；`scrollTop=300` → `todoTopRel=0`（钉到流顶）；两模式一致。
- 非玻璃卡片内部**逐像素完全相同**（`diffbbox=None`，0 像素差异）→ 不移动、不穿透。
- 玻璃卡片 `background-color=oklch(0.17 0.014 250 / 0.8)` + `backdrop-filter=blur(22px) saturate(1.35)`，
  差异仅 <12 灰阶（磨砂透出滚动内容的正常表现）。
