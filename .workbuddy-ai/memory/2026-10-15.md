## 访问测试：修复「点击没反应」+ 表格空白间隙（2026-10-15 深夜，用户反馈 C）

**用户反馈**：点「切换到此 IP」没有用；操作列周围空白间隙太大。

**根因（三层，都在链路上但都不报错）**：
1. 前端 `onUse={(p) => guard(() => api.proxyUse(p))}`——`guard()` 把异常吞进**页面级** banner，访问测试是**模态**弹窗，整个盖住它 → 用户侧就是「点击没反应」。弹窗自己的 try/catch 永远等不到抛错（guard 不 rethrow）。
2. 后端 `ProxyPool._control` 用 `urllib`，`HTTPError` 是 `URLError` 子类 → serve 的 404（旧版 serve 不认 `/select`）被吞成「代理控制通道不可达：HTTP Error 404」——服务明明在跑，文案误导。
3. 结果表 auto 布局把剩余宽度按内容比例摊给各列，「说明」短文本后一大块空白才顶到操作按钮。

**修复**：
- `core/proxy/pool.py::_control`：`HTTPError` 单分一支。`/select` 404 → ProxyError「代理服务是旧版启动的，不支持精确切换——请先停止服务再启动服务重新拉起」；其他路径 → `代理控制通道 HTTP <code>: <body>`。已用内联 404 stub server 验证两支。
- `ProxyPoolView.tsx`：父级 `onUse` 传**裸 promise**（成败弹窗自理）；弹窗 `use()` 自己 try/catch——失败红色横幅 `switchErr`（命中 `404|unknown path|旧版|控制通道` 时追加「先重启后端，再停止/启动服务重拉代理服务」），成功灰条 `switchNote` + `onDone()` 立即刷新（不等 3s 轮询）。
- 结果表改 `table-fixed` + `colgroup`（代理 27%/协议 8%/状态码 9%/延迟 9%/结论 9%/说明吃剩余/操作 68px），代理与说明列 `truncate`+`title`；按钮文案「切换到此 IP」→「切换」（完整语义在 title）。
