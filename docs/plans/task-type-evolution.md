## 3. 设计详述（打磨稿）

### 3.1 限速网关（方向 1）——噪声档做实

**三层现实性递减**：

| 层 | 机制 | 现实性 |
|----|------|--------|
| 命令层（主线） | run 网关按任务计数（每分钟 N 次主动类命令），超限拒绝并反馈 LLM「限速已触发，请调整节奏」 | ✅ 网关本就拦每个命令，计数天然 |
| 脚本启动层 | 启动脚本时网关注入约定参数/环境变量（如 `RATE_LIMIT=N`）；脚本超速被 kill 时反馈「请给脚本加限速重试」 | ✅「告诉 LLM 改脚本」落此层，交互闭环成立 |
| 脚本内部流量层 | host 直跑脚本内部对目标的请求网关不可见，强制限速做不到；Docker 执行的可在容器出口控制 | ⚠️ 只能靠注入参数引导，不能强制——方案边界要写明 |

**核心打磨点——passive 档语义重订**：passive 真做实成「禁主动」则现有用法大面积违约（passive 标注在跑端口扫描）。候选：a) passive 只告警不拦软启动；b) 四档重定义（passive=告警 / low=N 次/分 / medium=M 次/分 / high=不限）；c) 存量任务标记豁免。**实施前置盘点 `rateguard` 现有职责，决定扩展还是新建 task-rate 规则**。计数器存储（网关内存 per-task / 黑板资源租约扩展）待定。

### 3.2 注册表管理+中文化（方向 2+3）——对齐专家池 M3 模式

- **yaml 结构化升级**：行式 `type: noise` → 结构化条目 `type: {noise, label_zh, desc}`（desc=几句话概述），旧行式读兼容（taxonomy 读法升级）；
- **管理 API**：对齐 `/api/experts` CRUD 先例——`GET/PUT /api/tracks/{track}/task-types`，设置页可编辑（噪声档/中文名/说明），API 直写 yaml；**doctor 联动校验**：被剧本条目/技能 frontmatter/专家 yaml 引用的类型删除/改名要校验拦截（防引用断裂）；
- **前端落点**：设置页新增任务类型管理面板（与专家/技能管理并列）；发布栏 datalist 显示「中文名+概述」；看板 chip 中文显示；
- malware 轨补注册表文件（或明确该轨仅 generic 并在 UI 说明）。

### 3.3 专家类型偏好 + 人工发布审核（方向 4）

- **偏好接线（软偏好非硬门）**：`task.role` 未显式指派时，绑窗专家选择/认领排序加「任务 task_type 命中专家声明 `task_types` 者优先」（SkillRouter +10 同精神）；`_generalist` 兜底不变；
- **人工发布过编排器审核（硬门+开关）**：看板发布 → 编排器下一 tick 审核（**放行 / 优化参数〔改类型/加 conflict_keys/调噪声〕 / 指派专家 / 否决附因**）→ 放行后才走 L0-L2 挡位逻辑（L2 自动起跑延迟一个 tick）；项目级开关 `meta.orchestrator_review`（默认值待打磨）；审核是质量层不是权限层，L0-L2 审批语义不变；对话发布/剧本发布已过编排器或闸门，不受影响。

### 3.4 编排器第二执行人（方向 5）——伞型渐进路线

**定位**：对话化编排器+异常唤醒（已实施）的延伸——编排器从「派单+对话」扩展为「平台副驾驶/代理管理员」，工具面按需渐进添加，不做大跃进。

**操作分类学先行（敏感度矩阵草案，全表待打磨）**：

| 敏感度 | 操作类 | 处置 |
|--------|--------|------|
| 低 | 读类（态势/查询/检索） | 全自动 |
| 中 | 写类（发任务/改配置/清理/放回任务） | 自动+事后审计事件 |
| 高 | 删项目/改专家/**apply 提案**/动 providers/config | 恒人工 |

**人工指令溯源双通道（网关审核层）**：管理操作带指令背书（chat 指令 id / 审批单 id）→ 网关验证「确系人工指挥」放行；无背书且命中高敏感类 → 拦截转人审。与 §3.1 限速网关是同一层基建（网关=策略执行点）。

**两条红线（不因升级动摇）**：
1. `proposals.apply` 恒 `decided_by=human`——记忆投毒防线（编排器读的事件流含不可信内容，权限越大注入伤害越大，参见 HackingBuddyGPT CVE-2026-90621 前车之鉴）；
2. `config/providers.json` 禁触。

**渐进路线**：一期=审批代理（中低敏感审批单自动批，白名单制）+ 管理查询工具面；二期=配置修改工具 + 人工发布审核落地（§3.3）；三期起=按需添加工具，每次添加过操作分类学评审。
