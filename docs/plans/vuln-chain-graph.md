# 跨站漏洞链图谱（vuln-chain-graph）

> 把 campaign 战役记忆从「非结构化收尾摘要库」升级为「全局漏洞原语图谱」：节点=各站 verified 漏洞提供/需要的能力原语，边=A 的提供命中 B 的需要。目标是让几个不同站的 low/info 能被论证、验证并串联成高危链。定位=**链参谋 + 人决策**，不是自主打链。

- **状态**：**讨论收敛初稿（2026-09-24），待细化打磨与用户排期；未写 DESIGN.md、未挂账**
- **拍板记录**：见 §2（方向、边界、分阶段均为 2026-09-24 讨论产物；存储落点与原语抽取口径尚待打磨确认）
- **关联代码**：`core/blackboard/campaign.py`（CampaignMemory 全局库，拟加结构化层）、`core/agent/loop.py`（`_campaign_memory` 写入钩子 / `_sediment_verdict` 门槛）、`core/blackboard/store.py`（finding/asset 数据）、`core/blackboard/traces.py`（任务轨迹与 effect_stats）、`core/verify.py`（链验证规格）、前端链路画布（DAG 布局现成）

## 1 背景与现状盲区

真实渗透里高危常来自组合：单个系统只评 low 的问题，拼起来可能是 critical。当前 zut 目标群具备典型的可串联条件——多系统共挂同一个 `authserver.zut.edu.cn` CAS、同 IP 多 vhost、`*.zut.edu.cn` 共享 cookie 域——但现状把它们拆成了 4 个孤立的 result_note 摘要：

1. **campaign 存的是非结构化文本**：无法表达「A 站漏洞的产出 = B 站漏洞的前提」，召回只能按关键词相似度，不能按原语组合。
2. **资产/站点清单是 per-project 的**：跨项目「有哪些站、归属什么组织、挂哪个 SSO」没有全局索引，链边无从画起。
3. **无链级验证与归因**：单漏洞有 verify 验收口径，但跨站链没有候选生成、验证步骤和采纳归因。

## 2 设计定稿（初稿）

### 2.1 决策表

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 核心形态 | 从「文档库」转「**能力图谱**」：每漏洞建结构化原语节点（provides / requires），候选边 = provides∩requires；LLM 只提议、人审确认，不自动落边 |
| D2 | 连接组织 | 五类：**身份**（SSO/CAS/会话域/凭证复用）、**网络**（同主机/内网/SSRF）、**数据**（A 泄露的 ID 是 B 的输入）、**浏览器**（cookie 域/CORS/postMessage/开放重定向）、**供应链**（同厂商应用/DNS 层级） |
| D3 | 节点准入 | 只收 **verified** 产出（复用 campaign 现有门槛）；FP/未验证发现不得当原语节点（FP 可作死路参照，不进链） |
| D4 | 边的纪律 | 每条候选边必须带**证据锚点**（两端 finding id + 命中的 provides/requires 对），防幻觉连边；边状态=候选→人审确认/驳回 |
| D5 | 存储落点（待打磨） | 倾向在 `campaign.db` **新增结构化层**（原语表 + 全局边表），现有摘要条目保留为溯源材料；弱引用 (project_id, finding_id)，源项目进 .trash → 节点标失效、不级联删除 |
| D6 | 明确不做 | 自动攻击图规划 / 自动打链；对中枢认证（CAS）的高风险动作自动执行；自研向量检索（沿用 2-gram 口径） |

### 2.2 原语模型

每漏洞节点从 finding + result_note + traces 中抽取：

- **provides（提供什么）**：匿名读某类数据 / SSRF 可达网段 / 可控跳转（挂某域）/ 可写存储 / 一组凭证 / 同域执行环境……
- **requires（需要什么前提）**：某类 ID 输入 / 内网端口可达 / 受害者携带某 cookie 访问……
- 附：track、站点指纹、SSO 归属、证据锚点、时效（失效条件）。

候选链示例（贴合现网，均为分析对象、非自动执行）：

1. 实验中心 API 越权读 → 工号/学号/姓名 → CAS 攻击面分析（撞库类是红线，不自动跑）；
2. 老系统 JSONP/开放重定向 → `.zut.edu.cn` 域下窃取 CAS 票据 → SSO 账号 → 接 CAS 系统全通；
3. A 站 SSRF → 同段 B 站内网-only 管理接口；
4. A 站可信域附件 URL → 对 B 站用户的凭据收割。

## 3 实施切分（拟）

### M1 被动图谱 /「链参谋」（优先，安全零授权风险）

- 全局站点/组织索引（跨项目站点指纹 + SSO 归属；cyberspace-mapping 的自然延伸）。
- 原语抽取助手：LLM 从 finding/result_note/traces 提 provides/requires 草稿 → **人审确认**（同 kb 提案纪律）。
- 候选边生成（provides∩requires + 五类连接组织）+ 链路画布可视化（DAG 现成）。
- 产出=「这几个 low 可如此串成高危、建议如此验证」的**论证**，不执行；直接服务报告。

### M2 主动验证（后置，高风险默认挂起）

- 对人审确认的候选链生成验证步骤，复用 `core/verify.py` 验收规格 + replay 网关。
- 经 L0/L1 审批门执行；跨站链涉 CAS 中枢认证，默认 awaiting_human 等人。
- 采纳归因：记录「某链/某边被验证或被报告采用」，为图谱价值提供可证伪指标。

## 4 风险与对策

| 风险 | 对策 |
|------|------|
| LLM 幻觉连边，拼出不成立的链 | 边必须带双端证据锚点 + 人审确认；未确认边只作候选标注；M1 不执行 |
| 跨站链误判升级，报告夸大 | 链结论需 M2 实证背书方可进高危；未验证链以「假设链」呈现 |
| 自动动作触及中枢认证造成真实危害 | 默认挂起 + L0/L1 审批；撞库/票据窃取类只分析不自动执行 |
| 源项目删除/归档致引用悬空 | 弱引用 + 失效标记，不级联删除；画布保留孤儿节点可溯源 |
| 语料过少（现 4 条且同源） | M1 先在小样上验证抽取与连边质量；不为少量样本调打分、不上向量 |
