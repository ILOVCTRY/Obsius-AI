# Web 能力包红线（永久强制，优先级最高）

> 状态：**草案（AI 起草 2026-09-16，待人审定稿）**。
> 适用于启用 web 能力包的所有项目（全轨注入）；与任何 skill / 知识库冲突时以本文件为准。
> 轨级红线（如 assessment 的 scope/锁面纪律）在此基础上叠加，两者冲突以更严者为准。

## 验证纪律（最小伤害）

1. **越权验证 · 最小伤害**：默认用读/列表差分证明跨用户/跨租户（优先 GET/查询）。
   写越权要测但有顺序：先添加 → 删除自己刚加的那条；不改/删别人已存在的对象；
   没有创建口时只改自己能改回的字段，打一次；扣钱、清库存、批量不做。
2. **禁止登出/注销**：用户提供登录态后，全程严禁调用登出/注销/吊销令牌；
   改绑/改密验证过了立刻改回，不留死局。
3. **出界即停**：任何时候发现要测的资产不在项目授权范围内 → 立即停手，
   写黑板 + 上报，不得继续（范围以项目绑定与任务描述为准，不自行外推）。

## 证据纪律

4. **无证据不下结论**：无 HTTP 包/截图/日志时只能写「待验证/假设」，
   对应黑板 findings 的 status=unverified——禁止直接标 verified。
5. **payload/案例反幻觉**：优先查库（kb 弹药库）；库中无 → 允许现场构造，
   报告里标注「现场构造」；禁止编造案例编号与 CVE 编号。
6. **弱口令默认力度**：单账号默认 ≤10 个候选、慢速单发不数组；有成果性发现才可酌情加量；
   登录爆破/撞库仅在任务明确授权时进行。

## 状态机纪律（E7）

7. **访问 ≠ 测试**：只浏览未验证标 `visited`，开始扫描标 `scanning`，
   测完无问题才标 `tested_clean`（必附 note：测了什么/怎么测）；测出问题直接 bb_add_finding。
