# 任务文件夹（永久强制 · 任务根格式）

> 用户强制（沿革：2026-08-04 独立 `js/` + 资产只放公网 URL；2026-09-06 任务根从桌面移到工作区 `./target/`，并去掉 `_SRC挖洞` 强制后缀）：  
叫我做任务时，**在工作区** `./target/` 下建任务根目录；分夹清楚、条例清晰。  
**禁止**把报告/脚本/资产/js 直接堆 `./target` 根 / 工作区根；**禁止**只丢一个扁平 `xxx_dig` 就把报告塞 dig 里凑合。

***

## 1. 标准目录格式（永久模板）

任务根一律建在**工作区** `./target/`下。

### 1.0 任务根命名（推荐，不强制）

**推荐组合（按已知信息量从多到少自由组合，不强制全有）：**

1. **域名 + 单位名称 + 业务 title**（最完整） — 例：`af.gues.edu.cn_贵州工程应用技术学院_智慧安防后台管理系统`
2. **域名 + 业务 title**（单位未知时） — 例：`cggl.aiit.edu.cn_采购管理`
3. **域名**（只知主域） — 例：`nypay.bitzh.edu.cn`

**域名完整性（硬 · 不分推荐/强制一律遵守）：** 只要域名信息参与命名，**必须写完整 host（含全部子域）**，禁止省略二级/三级域名或截断到根域：

| 正确 | 错误 |
|------|------|
| `70.zut.edu.cn_中原工学院` | `zut.edu.cn_中原工学院` |
| `softlab.zut.edu.cn_实验室平台` | `zut.edu.cn_实验室平台` |
| `nypay.bitzh.edu.cn` | `bitzh.edu.cn` |

（多个 host 同任务才允许按业务簇命名，但每个 host 首次入库 `资产/` 时仍须写完整 host。）
4. **同等清晰的中文名**（非域场景） — 例：`某品牌线上商城`

**已确认信息越多命名越完整；未确认的字段直接跳过，不要瞎猜占位。**

**开新任务时必须一起建齐：**

````
./target\{任务根名}\
  README.md          ← 任务说明、目录结构、进度、续跑命令
  资产\              ← 挖掘途中发现的「公网可挖 URL 资产」（域名/URL 清单）
  js\                ← 从站点提取/下载的 JS 源文件（分析用）
  报告\              ← 正式报告
  temp\              ← 本次测试用脚本、批量日志、payload 文件（脚本一律写入此目录并在其中执行）
    evidence\        ← HTTP 证据包 / 响应头快照，报告中按相对路径引用
  {名}_dig\         ← 脚本、queue、state、findings、日志、临时探测
````

**对照范例（必须对齐目录结构，目录名按 §1.0 自由组合）：** `./target\{任务根名}\`

| 子目录      | 放什么                                                                                                                                                                                                                                                            | 不放什么                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `资产/`     | 公网可挖 URL/域名清单（挖掘途中发现并沉淀的目标资产：url 列表、子域、接口入口 URL、FOFA 导出里的可打面等）；**自由跳还必须有 `种子队列.md`**（业务名/品牌/SRC 域/全资域 + pending/doing/done，见 dig-scope §1.4；数量无上限） | **禁止**塞提取的 `.js`；禁止报告、跑扫脚本 |
| `js/`       | 从目标站点**提取/下载**的 JS 文件（LinkFinder/手动抓包/批量下的前端包），供逆向接口用                                                                                                                                                                             | 禁止正式报告；禁止把「URL 资产清单」塞这里                                                  |
| `报告/`     | 正式报告 `.md`，文件名=标题=`资产分析报告：<目标>.md`（体例唯一认 `vuln-report-format`；**≥低危就写（2026-09-11 用户改），信息级/无洞不落**）                                                                                                                              | 脚本、state、半截日志、JS 原文                                                              |
| `{名}_dig/` | dig 脚本、queue/state/findings、验证小脚本、日志、临时探测；**拉子线程任务必须有 `线程必读.md`**（迭代闸，见 §1.3+`hunt-iter`）                                                                | 最终交付报告；**定稿的提取 JS 应落到 `js/`**，不要只堆 dig 里当资产 |
| `temp/`     | 本次测试用脚本、批量日志、payload 文件（脚本一律写入此目录并在其中执行）；HTTP 证据包 / 响应头快照落 `temp/evidence/`，报告中按相对路径引用                                                     | 最终交付报告；与 `{名}_dig/` 重复堆积（选一处放） |
| `README.md` | 结构说明、进度表、续跑命令、收录纪律；**必须有迭代闸一行**（见 `hunt-iter.md`）                                                                                                                                                                                   | —                                                                                           |
| （任务根根目录） | **除上述四夹 + `README.md`（+ 可选 `{名}_dig/` 内文件）外，不允许再散落任何文件**（app.js/vendor.js/*.py/ht.txt/缓存等一律进对应子夹）                                                                                                                             | 见改：散抛文件违背结构          |

### 1.1 资产 vs js（强制分清）

| 内容                                                         | 正确路径                                                                        |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| 公网可挖的 URL / 域名 / 入口清单（挖途中发现的可继续打的面） | `资产/`                                                                         |
| 从页面/CDN 抽下来的 `.js` 源文件                             | `js/`                                                                           |
| 临时下载、半截、仅用于一次探测的 JS/HTML 缓存                | 可先在 `{名}_dig/`；**有分析价值的正式提取件 → 移入 `js/`** |

**禁止（用户点名）：** 再把提取的 JS 丢进 `资产/`。

## 1.3 归档（生命周期 · 仅手动）

**严禁自动移入**。`归档/` 只由**用户手动点名**某个任务根才发生：把 `./target/<任务根名>/` **整棵移动**到 `./target/归档/<任务根名>/`（不另存副本、不删报告/资产）。任何流程（清理、完成出口、续挖）都**不自动触发**。

- **导航**：`./target/归档/` 下会放由用户手动移入、已中止/搁浅的任务根。
- **清理豁免**：§3 全量清理**跳过 `归档/`**；归档内任务如需清理，**点名该任务**才处理（读其 `报告/` 有无文件，沿用 §3.1/§3.2 判定）。
- **续挖豁免**：归档 = 明确搁浅，不在活队列，续挖不自动纳入。
- **命名**：整棵搬，保留原任务根名，**不另加时间戳**（便于定位）；用户如需可在 `归档/` 内存备注。

## 1.4 模板（复制即用）

> 手建容易漏。**推荐直接用脚手架 `tools/init_task.ps1`**（见 `tools/README.md`）一键生成 —— 含目录骨架 + 带迭代闸的 README / 线程必读 + 末尾自检。
> **调用硬规则（2026-09-12 教训）：** 必须 `-NoProfile`：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/init_task.ps1 …`——带 profile 时 conda activate 在 GBK 控制台 UnicodeEncodeError 崩掉、脚手架不落地（后台壳卡 running）。崩了先看任务根是否真的建成，别默认成功。
> **单位名先核对再命名：** `-Unit` 不凭域名缩写/记忆猜（zut.edu.cn ≠ 郑州科技学院，是**中原工学院**）；以进站 `school.json`/首页页脚/备案主体为准，错了重建任务根。

## 2. 硬规则

1. **一任务一根目录**，起手就建，再开始产出。
2. **四类分夹 + dig + temp**：`资产/` + `js/` + `报告/` + `{名}_dig/` + `temp/`（证据 `temp/evidence/`）— **条例清晰，不混放**。
2.a **根目录不散落**：任务根根目录**只允许** 五夹 + `README.md`（+ `{名}_dig/`、`temp/` 内文件）——不再是上述子夹的散抛文件（app.js/vendor.js/*.py/ht.txt/cache 等）一律必须进对应子夹，禁止堆在任务根根目录。
3. 报告路径固定：`{任务根}/报告/`；脚本里 `REPORT_DIR` 必须指向这里。
4. 提取 JS 路径固定：`{任务根}/js/`；下载/提取脚本默认输出到这里。
5. URL 资产路径固定：`{任务根}/资产/`；只写公网可挖 URL/域名类清单，不写 JS 文件。
6. 续跑、增量、Pass2/3/4 → **仍进同一任务根**，不另开任务根外的散文件。
7. `./target` 根（任务根外）**禁止** 再落报告 `.md`、queue、state、零散 py/js。
8. 用户已指定路径时以用户为准；未指定 → 本格式。
9. **迭代闸分级（拉子线程才需要完整文件）：**
   - **单窗任务（不拉子线程）**：最低要求 = `README.md`（及自由跳的 `资产/种子队列.md`）顶部钉「迭代见 `hunt-iter.md`」一行；**不强制**建独立 `线程必读.md`。
   - **拉子线程任务**：必须起手建 `{名}_dig/线程必读.md`，写「迭代见 `hunt-iter.md`」。**位置一律在 `{名}_dig/`**，不放任务根根目录。
   - **子线程交付必须含迭代**（本站 `DONE.md` 写拟进/拟补/不进，主控过门槛+三问再并短表，认 `hunt-iter.md`）。条文只在 `hunt-iter.md`。

## 3. 用户说「清理」时（操作）

口径只认 `vuln-report-format.md`「清理」那一行。本文件只写怎么删、删哪、浏览器别动。

判定「有报告」：`{任务根}/报告/` 存在且至少 1 个正式报告 `.md`。夹不存在或空 = 无报告。

### 3.1 无报告 → 整根全清

| 动作                   | 说明                                                                           |
| ---------------------- | ------------------------------------------------------------------------------ |
| **删除整个任务根目录** | `./target\{任务根名}\` 整棵移除                                                |
| 含其内一切             | `资产/`、`js/`、`{名}_dig/`、`temp/`、`README.md`、过程垃圾等**一并删**，不单独保留资产 |

适用：无洞任务、只跑了 dig/资产/js 没交报告、空 `报告/` 夹。

### 3.2 有报告 → 只留「资产 + 报告」

| 保留（禁止删）                  | 删除（可清）                            |
| ------------------------------- | --------------------------------------- |
| `{任务根}/报告/` 及夹内全部文件 | `{名}_dig/` 整夹                        |
| `{任务根}/资产/` 及夹内全部文件 | `js/` 整夹；`temp/` 整夹（**报告归档前不清空** temp；清理即归档动作，可删） |
| 任务根目录本身（外壳留下）      | `README.md`、其它散落脚本/日志/临时文件 |
|                                 | `./target` 根误落的本任务相关垃圾       |

有报告时：**禁止**删 `报告/`、`资产/`；**禁止**把报告/资产挪没再整根删掉任务根。  
清理后形态：

````
./target\{任务根名}\
  资产\     ← 保留
  报告\     ← 保留
````

（无 `js/`、无 `*_dig/`、无 README 亦可。）

### 3.3 范围

1. 用户说「清理」且**点名任务** → 只处理该任务根。
2. 用户说「清理」且指**所有任务文件夹 / 理一遍规则落地** → `./target` 下全部任务根（不限后缀，按 §1.0 目录树结构识别）按 §3.1 / §3.2 逐个处理；**`归档/` 整体跳过**（§1.3 清理豁免，其内任务点名才处理）。
3. **不是**任务文件夹的目录（工具、SRC文档资料夹、普通软件安装包等）**不要**当任务根误删。
4. 会话 **工作区** `mcp-servers\.playwright-mcp` 下本轮 snapshot/console **文件**可清（仅该目录内临时截图/日志）。

### 3.3.1 浏览器账号密码与配置 — 永久禁止清

> 用户明确：**以后清理不要把浏览器保存的账号密码清理了。**

清理时 **一律禁止** 触碰、删除、重置、清空下列对象（即使用户只说「清理」）：

| 禁止对象                                                  | 说明                                                                                |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 浏览器已保存的账号 / 密码 / 自动填充                      | Chrome/Edge 密码库、Login Data、Autofill                                            |
| 浏览器用户配置目录                                        | `User Data`、`Default`、Profile、`Login Data`、`Web Data`、Cookies 库整夹           |
| MCP 所连真实浏览器（`playwright-claude`，9244）的 profile | 不得 `ClearBrowserCookies` 整库、不得关「保存密码」、不得 wipe 凭据                 |
| Playwright 持久化上下文里的凭据存储                       | 不得清 storage state 中用户依赖的登录保存（任务 dig 内临时 cookie 文件可随 dig 删） |

**允许清的浏览器相关垃圾（仅限）：**

- 工作区 `mcp-servers\.playwright-mcp\` 下 **snapshot / console 临时文件**（页面快照、控制台导出）
- 任务 `{名}_dig/` 内过程 cookie 文本、探测缓存（**不是**浏览器密码库）

**禁止** 为「清理」执行：关闭浏览器用户配置、删除 Profile、`Clear-Site-Data` 全站、重置浏览器、清「密码和表单」、对 MCP 所连浏览器做全局 storage clear。

### 3.4 执行顺序

1. 列出待处理任务根（点名 or `./target` 下按 §1.0 目录树结构识别的所有任务根）；**跳过 `归档/`**（§1.3 清理豁免）
2. 每个任务根检查 `报告/` 是否**有文件**
3. **无报告** → `Remove-Item` 整棵任务根
4. **有报告** → 只删 dig / js / README / 其它；**锁定保留** `报告/` + `资产/`
5. 若有报告但无 `资产/` 夹 → 可保留空 `资产/` 或不建；**绝不动 `报告/`**
6. 浏览器：只可清工作区 `mcp-servers\.playwright-mcp` 临时 snapshot/console；**绝不碰密码库/Profile**

### 3.5 自检（清理前）

- [ ] 是否先数过 `报告/` 里有没有文件？
- [ ] 无报告时是否整根删（含资产/js/dig）？
- [ ] 有报告时是否只留了 `资产/` + `报告/`，没有误删报告？
- [ ] 是否误把非任务目录（如 `SRC文档` 资料夹）当任务根删了？
- [ ] 是否**跳过 `归档/`**（其内任务点名才处理，不随全量清理）？
- [ ] **是否会误清浏览器保存的账号密码 / Profile / Login Data？禁止则继续。**

- [ ] 提取的 JS 是否只在 `js/`（**不在** `资产/`）？
- [ ] `资产/` 是否只是公网可挖 URL/域名类清单？
- [ ] 报告是否只写在 `报告/`？
- [ ] dig 状态与脚本是否只在 `{名}_dig/`？
- [ ] 有没有东西误落在 `./target` 根 / 工作区根？有则 **移入对应子夹**（不是删掉糊弄）

***

**一句话：** 开新任务 = 在 `./target/` 建 `README + 资产(公网URL) + js(提取JS) + 报告 + *_dig`——**建议直接跑 `tools/init_task.ps1` 生成**；任务根根目录只允许四夹+README、**根目录不散抛文件**；迭代闸分级（单窗一行 / 拉子线程起手建 `{名}_dig/线程必读.md`）；`归档/` 生命周期独立、清理豁免。**JS 绝不进资产**；**任务根命名按 §1.0 推荐组合（域名+单位+业务），不强制；域名参与命名时必须完整 host（含全部子域，不得省略二级/三级域名），硬规则。**清理口径只认 `vuln-report-format`。
