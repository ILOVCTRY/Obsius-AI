## 5. Web 判级速查（影响「报上去定什么级」）

- **严重**：RCE / 任意代码执行 / 上传 webshell / SQLi 拿系统权限 / 缓冲区溢出；核心 DB（资金、身份、交易）SQLi 可拖大量身份/订单/银行卡；逻辑缺陷（任意账号资金消费、任意账号登录、任意密码修改）
- **高危**：一般服务器权限获取；非核心 DB SQLi、源码压缩包泄露、加密算法可逆/明文存储、移动 API 摘要、硬编码、**Github 泄露可登录重要服务器的账号密码**；绕过认证进后台、后台弱口令（见 §5 ①）、SSRF 捞大量内网敏感信息；越权敏感操作（改重要信息/订单越权/业务配置修改）；可自动传播且能拿认证 Cookie 的存储型 XSS
- **中危**：需交互方影响他人的存储型 XSS、重要 CSRF；普通越权（改用户资料）；Web/系统路径遍历、密码经 HTTP 明文传输（HeyTap 登录）；验证码逻辑缺陷被绕过撞库；重要账号体系无限制爆破
- **低危**：反射型 XSS / DOM-XSS、普通业务存储型 XSS；路径参数、SVN、phpinfo、日志、异常信息泄露、非 HeyTap 登录 HTTP 明文；OPPO URL 跳转（需证明跳非 OPPO 域且无提示才算）；Self-XSS、json hijacking、clickjacking+有效 exp、非重要敏感 CSRF、需 MITM 的 RCE+有效 poc；运维配置不当、组件权限漏洞；短信轰炸（单 IP/用户半小时定向 >50 条且无限制）
- **无危 / 不收**：功能 bug、乱码、样式混编、无意义目录遍历、兼容性问题；无法利用的扫描器报告；`http smuggling`（HTTP 请求夹带）；需用户交互的 CORS 拿 Cookie；无敏感信息的 json hijacking；内网 IP/域名泄露；无敏感操作 CSRF（购物车/点赞/评论）；中间件版本号；6 位验证码分布式爆破；其它危害过低

**Web 判级红线（特殊说明）：**
- ① 管理后台弱口令：进去**无**敏感信息/操作 → 最高只到**中危**；进的洞一般**降级**处理
- ② DoS 只收漏洞导致的那种；大流量高并发 DoS **不收**
- ③ 用 XSS / URL 重定向去打 App → **中危**起步
- ④ 最近披露的 0day 要等 **30 天冷静期**，且只收 OPPO 产品/服务自身

## 6. 不收的漏洞类型（白交也要判无危，别堆）

最近披露 0day（冷静期）、公开已知的公共文件/目录、已知易受攻击库无针对本实现打点描述、OPTIONS/TRACE 启用、登录/注销/未认证 CSRF、软件版本公开、注销后 Cookie 继续工作、表单自动完成、非敏感 Cookie 缺 HttpOnly/Secure、Self-XSS、自动化工具/扫描报告、协议标准问题、**用户名枚举（登录/忘记密码/注册）**、强制策略/账号锁、SSL/TLS/SSH 配置、不切实际复杂 clickjacking、SPF/DKIM/DMARC、密码恢复策略（重置链接过期/复杂度）、**公众可访问登录面板**、注册缺邮箱验证、内容欺骗/文本注入、缺安全头、混合内容、密码改后活跃会话、超链接注入、已知凭据库泄露的凭据、缺 crossdomain.xml 等策略文件/通配符、MITM（除密码等敏感外）、不影响业务的功能缺陷/乱页/路径遍历。

> 白话：**用户名枚举、后台弱口令本体、公众登录面板、账号锁、已知库无利用、缺安全头、0day 冷静期** —— 这些别当必打项、别指望钱；要打就打到「进去后有敏感面」那步才算有效。

## 7. 敏感信息泄露定级（数量门槛，报数据规模有用）

| 级别 | 用户个人敏感信息（身份/金融/健康/位置/通讯录…） | 欧加集团员工信息（不含代理/供应商） |
|------|------|------|
| **严重** | 三元组 ≥100万 或 二元组 ≥300万条 | 三元组 ≥6万 或 二元组 ≥8万条 |
| **高危** | 三元组 ≥10万 或 二元组 ≥30万条 | 三元组 ≥3万 或 二元组 ≥5万条 |

- 其他按实际危害评；数量仅参考，随系统重要度/总量浮动
- 提醒：未授权读少量（收敛≤5组）走**越权中危**，别硬凑成敏感泄露去够严重线

## 8. 移动应用判级速查（ColorOS / realme UI / 软件商店自有 App）

- **严重**：远程 RCE / 远程或弱交互**静默装任意应用** / 远程账户接管·锁屏绕过·转账
- **高危**：本地 RCE；弱交互或本地敏感泄露（登录凭据/短信/通话/通讯录/浏览记录/App 私有目录）；本地提权；弱交互或本地账户接管等；浏览器 **UXSS**
- **中危**：MITM 的 RCE 或静默装（有效 poc）；IMEI/IMSI/手机号泄露；远程 DoS
- **低危**：MITM 敏感窃取（有效 poc）；有实际危害的 UI 欺骗
- **无危/不收**：功能缺陷、扫描器报告（又「无加固/反编译」）、业务需要配置的组件暴露（Activity export 无法利用）、**本地 DoS（仅本地发起致临时崩溃）**、无法重现
- 交互定义：**远程**=不碰手机网络触发；**本地**=要装恶意应用/adb/NFC/蓝牙；**弱交互**=诱导点链接即可；**强交互**=诱导装 app/钓鱼邮件/≥2次确认

## 9. 验证证明（收敛，别打狠）

借萤石通用纪律（OSRC 未细分，按实际危害 + CVSS 综合）：
- **越权**：禁批量；读/操作真实数据 ≤ **5 组**，数据**另作他用**
- **SQLi**：禁读表内数据，**证明存在即可**；UPDATE/DELETE/INSERT 类**禁自动化**
- **XSS**：证明危害即可；**禁**窃取他人 cookie / 隐私
- **RCE / shell**：只传**纯文本证明**、写明地址口令；**禁**读源码/敏感文件、**禁**删写命令
- **SSRF**：证明可回连/出网即可，**禁**横移打内网
- **隐私维度**：最小一条证明，不批量、不存留
- **App 维度**：抓包测接口越权/明文/敏感泄露为主；反编译产物仅本地分析、不上传不传播
- **IoT / 终端**：**禁**破坏性测试、**禁**刷固件变砖、**禁**远程操控他人设备

## 10. 操作红线

自己手机号/邮箱、禁轰炸；禁物理/社工/非技术手段；禁内网渗透、主机提权；禁 DoS/DDOS/IIS 拒绝服务类；禁保存/分享经漏洞获取的数据，验完即删。

## 11. 计奖 / 提交战术（决定钱到手方式）

- **同系统同类漏洞打包提交**：级不变、奖金提高；**分开提交 → 后面同类按重复处理**。别吐水管
- 同一链接多参数类似漏洞**合并**；同一漏洞源（同接口/同发布系统/泛域解析/多点未鉴权越权等）**只记第一个**；通用组件/SDK 多终端同问题只记第一个
- **组件漏洞（服务端 Tomcat/Apache/OpenSSL/第三方 SDK）**：公开 1 个月内若 OPPO 已知则不过；>1 月且 OPPO 不知情 → 给第一个提交者，**一级不高于中危**
- **组件漏洞（客户端 Android 原生/App 通用）**：公开 3 个月窗口同理，>3 月仍未修给第一个，**一般不高于中危**
- **Chromium 组件**：未发版已知=忽略；公告后 60 工作日内=忽略；60-90 工作日=**低危**；>90 且能在 OPPO 浏览器复现=正常评级 → 挖浏览器别指望 Chromium 本体，只剩自有逻辑 / UXSS / 超期仍有效才值
- **0day**：只收 OPPO 产品/服务自身的
- 报告**一次写完整**（URL/包名+版本+PoC+复现链路+修复建议），无 PoC 无详细分析直接影响评定

## 13. 提交到平台（OSRC 表单字段）

> 两层分开：**内部落盘报告仍只认 `vuln-report-format`**（资产分析报告版式 + PoC 用原始 HTTP 报文），写入 `report/` 不变；本节省的是**把洞交到 OPPO 平台表单**时的填法。同一洞 = 内部报告（自己留底）＋ 平台表单（对外提交），各行其道，别互相顶掉。

- **漏洞名称**：`漏洞类型 + 受影响资产 + 风险能力`，例：`未授权访问 list 接口，可批量获取用户手机号`（与本地命名口径一致：越权/匿名未授权/可批量要写清）
- **漏洞等级 / 漏洞类型**：平台下拉选；等级对照 §5/§8 判级速查，不虚报、不降报
- **漏洞详情六段**（各段必填与否按平台标注）：
  1. **漏洞摘要【必填】**：一句话讲清漏洞是什么 + 触发条件
  2. **受影响资产【必填】**：完整 URL/API 端点、应用版本、所属业务模块
  3. **复现手册**：① 测试环境【必填】= 操作系统/浏览器版本/测试工具（含版本号）/测试账号及对应权限；② 操作步骤【必填】= 审核人员仅凭此即可独立复现；③ 预期结果 & 实际结果【必填】= 正常逻辑 vs 异常表现
  4. **附件 POC【必填】**：请求数据包 / Payload / 截图 / 录屏 / 测试 EXP；若打包 ZIP，须放 `README.txt` 说明各文件对应步骤编号
  5. **风险影响评估【必填】**：可能的攻击行为、影响范围、安全后果（建议从机密性 / 完整性 / 可用性三角度）
  6. **修复建议【选填】**：原理性修复思路，**非**临时规避
- 平台审核大概率只凭「第 3 步操作步骤 + POC」复现 → PoC 沿用本地规范：**可整体复制的原始 HTTP 报文**，会话实值 + 替换说明都要写，截图/录屏与步骤编号对应
- §11 报告质量（20-30% 优质报告补贴）：详情/原理/利用/修复写得清 + 无 PoC 别交
