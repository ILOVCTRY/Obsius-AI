# 认证与会话判据库

> 来源：86 篇涉及认证/会话的赛题 WP 提炼（377 条观测 / 233 条失败尝试）。原始 WP 已消化完毕并从库中移除，仅保留本节判据。
> 主库 `漏洞分类/认证与会话/` 与 `OAuth-JWT-SAML 安全.md` 已覆盖 JWT/OAuth/SAML 的细节，
> 本文只补**会话载体识别**与**密钥可还原**两类主库薄弱的部分。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| Cookie 是三段 `xxx.yyy.zzz` base64 | JWT，先解 payload 看字段 | §1.1 |
| Cookie 是 base64 但带 `.` 分隔且能解出 JSON | Flask session，先找密钥 | §1.2 |
| Cookie 是 `PHPSESSID` 但服务端不存 session | 可能是签名 cookie（`cookieSession`） | §1.3 |
| Cookie 是 `rO0AB` 开头 | Java 序列化 session | §1.4 |
| 登录后有 `role`/`isAdmin` 字段可改 | 客户端信任，直接改 | §2.1 |
| 删除 token 仍能访问 | 路由缺 middleware | §2.2 |
| 改 URL 里的 id 能看别人数据 | IDOR | §3.1 |
| 有 `/api/` 但前端没调用 | 隐藏端点，先枚举 | §3.2 |
| 密码重置链接的 token 可预测 | 弱随机，看时间戳/UUID 版本 | §3.3 |
| 能爆破但字典太大 | 先判密钥空间（2 字符 3844 次可接受） | §2.3 |

## 1. 会话载体识别

**判据**：先看 cookie 的**形态**，形态决定攻击面。

### 1.1 JWT

```text
header.payload.signature   三段 base64url
eyJhbGciOi...              header 以 {"alg" 开头
```

先解码：

```bash
echo '<payload>' | cut -d. -f2 | base64 -d 2>/dev/null | jq .
```

判据是 **payload 里有没有 `role`/`admin`/`uid`**。有就是权限载体，值得伪造。

### 1.2 Flask session

```text
eyJ...==.eyJ...==.xxxxx   三段，前两段是 base64 的 JSON，第三段是 HMAC
```

```bash
flask-unsign --decode --cookie '<cookie>'
flask-unsign --unsign --cookie '<cookie>' --wordlist rockyou.txt
```

**关键判据**：密钥若来自 `random.seed(time)`，可以按启动时间窗口还原，不用爆破。源码里出现 `random.seed` + `SECRET_KEY` 就是这条。

### 1.3 PHP 签名 cookie

`cookieSession` 类库用 `keys[]` 数组做 HMAC。判据是**源码里出现 `keys` 数组且被硬编码**。拿到 keys 就能伪造任意 `PHPSESSID`。

### 1.4 Java 序列化 session

`rO0AB` 开头。判据是**能控制 cookie 字节**，此时走反序列化链（见 `反序列化-判据.md`）。

## 2. 伪造与绕过

### 2.1 客户端信任的三种表现

```text
1. cookie/localStorage 里有 isAdmin: false → 直接改 true
2. JWT payload 有 role 字段但签名可绕 → alg:none / 弱密钥
3. 隐藏字段 <input type="hidden" name="role" value="user"> → 改 POST
```

判据是**权限判断发生在客户端还是服务端**。改完能用就是客户端。

### 2.2 路由缺 middleware

```text
现象：删除 token / 换成空 token 仍能访问管理接口
判据：框架的鉴权是「按路由挂中间件」，漏挂的路由就没有校验
打法：把已知需要鉴权的路由前缀逐个试（/admin/、/api/admin/、/manage/）
```

ThinkPHP / Express / Gin 都常见。判据是**同一功能有两条路径**（一条挂了中间件，一条没挂）。

### 2.3 弱密钥的空间判断

```text
2 字符（a-z0-9）= 36² = 1296，秒级
3 字符 = 46656，分钟级
4 字符 = 1679616，小时级
6 位数字 = 10⁶，分钟级
常见弱密钥表（rockyou 前 10000）优先于暴力
```

判据是**密钥长度**。长度不明时先用字典，字典不通再按长度估。

**坑**：`HS256` 的密钥若由 `sha256(timestamp)` 生成，可以直接按时间窗口算，不用爆破。

### 2.4 JWT 的六个攻击面

| 攻击 | 判据 |
|---|---|
| `alg:none` | 服务端没校验 alg 白名单 |
| RS256→HS256 | 服务端用同一密钥验两种算法 |
| 弱密钥 | HS256 + 短密钥 |
| `kid` 注入 | `kid` 参与文件路径或 SQL |
| `jku`/`x5u` 指向攻击者 | 未做域名白名单 |
| 签名延展性 | ECDSA 的 `(r, n-s)` 也是合法签名 |

**关键**：RS256→HS256 的密钥是**整个 PEM 文件字节**（含 `-----BEGIN PUBLIC KEY-----` 和换行），不是裸模数。这是最高频的误判点。

## 3. 权限边界

### 3.1 IDOR 的三种 id 形态

```text
自增整数     → 直接 ±1 遍历
UUID v1      → 含时间戳，可推算相邻
UUID v4      → 不可推，但要找「列表接口」泄露
hash id      → 找生成规则（md5(id) 最常见）
```

判据是**id 是否可预测**。不可预测时找**能列出 id 的接口**（导出、搜索、分享链接）。

### 3.2 隐藏端点枚举

```bash
# 从 JS bundle 里提路由
grep -oE '"/api/[a-zA-Z0-9_/-]+"' app.js | sort -u
# 从 swagger 拿
curl http://target/v2/api-docs
curl http://target/swagger.json
curl http://target/openapi.json
```

判据是**前端有调用但页面没入口**。这类端点通常校验更松。

### 3.3 密码重置的四个判据

```text
1. token 可预测？     → 看长度与字符集，UUID v1 含时间
2. token 绑定用户？   → 换 host/换 email 后 token 是否还有效
3. token 一次性？     → 用两次看第二次是否成功
4. token 有过期？     → 隔一段时间再用
```

最常见的是 ②：token 只校验「存在」不校验「属于谁」，改 `email` 参数就能重置别人的密码。

## 4. 账号接管的组合链

单点通常不通，组合才成：

```text
信息泄露（邮箱/用户名） → 密码重置（token 不绑用户） → 接管
IDOR（读别人 profile）  → 拿到重置 token        → 接管
XSS（admin bot）        → 读 admin 的 token      → 接管
弱口令（爆破）          → 直接登录                → 接管
```

判据是**有没有一条链能把「已知信息」换成「凭据」**。

## 5. 纪律

- **先判载体再判攻击**。JWT 和 Flask session 的攻击面完全不同，看错载体等于白做。
- **先解 payload 再想伪造**。payload 里没有权限字段的 token，伪造了也没用。
- **弱密钥先字典后暴力**。rockyou 前 1 万条覆盖大多数 CTF 出题习惯。
- **RS256→HS256 用整个 PEM 文件**，不是裸模数。这一点错一次浪费半小时。
- **IDOR 不可预测时找列表接口**，不要死磕枚举。
- **密码重置先测「token 是否绑定用户」**，这是最高频的洞。
- **删除 token 仍能访问 = 路由漏挂中间件**，这比伪造 token 简单得多，先试这个。
