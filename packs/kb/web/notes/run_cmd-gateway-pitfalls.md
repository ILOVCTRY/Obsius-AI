# run_cmd 执行网关坑位与纪律（本工作区实测）

> 来源：2026-09-19「存量 visited host 终态收口合批」任务实测校准。适用于本工作区 run_cmd 工具（host/wsl runtime 均验证）。

## 已验证坑位与改道方案

### 坑 1：外层 shell 双重展开吃掉位置参数与变量
- 现象：`probe(){ name="$1"; ... }; probe depart ...` 中 `$1`、`$name` 被外层 `sh -c "..."` 提前展开为空，函数拿到全空参数（`---- ://: Host= ----`）。
- 原因：命令被包进外层 `sh -c "双引号上下文"`，`$var`/`$(...)`/`$1` 在进入内层脚本前已展开。
- 纪律：**run_cmd 命令全部字面量化**——不用函数、不用位置参数、不用脚本变量；多条请求直接顺序罗列。`curl -w '%{http_code}'` 的 `%{...}` 语法不受影响，可放心用。
- `$(date -u +%FT%TZ)` 会在外层展开（约等于命令启动时刻），做证据时间戳可接受，但要知道它不是"该条探测发出时刻"。

### 坑 2：静态网关拦截 `/dev/null` 与以 `/` 开头的模式
- 现象 1：`2>/dev/null` 直接被拒：「试图写入工作区外（/dev/null;）」。
- 现象 2：`grep -o '"/api/..."'`（模式以 `/` 起头）被误判为路径写入，同样被拒。
- 纪律：
  - 全程**不出现 /dev/null**；错误输出走相对路径临时文件（如 `2>err.tmp`）或省略。
  - grep/正则模式**不以 `/` 字符起头**（用 `'"[a-z0-9_/.-]+"'` 这类引号或字母起头的模式改写）。
  - 临时文件一律相对路径写当前 scratch 目录。

### 坑 3：WSL 内无界 DNS 查询会拖死整条命令
- 现象：探活脚本尾部 `nslookup`（默认解析器）挂起，140s 整体超时被杀，前面的探测结果一并丢失。
- 纪律：批量探活脚本**不要内联 nslookup/DNS 枚举**；解析信息用被动源（黑板既有记录/DoH 单发）单独获取。探测条目多时拆轮次（每轮 ≤4-8 条 curl），单条 `--connect-timeout 5 -m 8`。

### 坑 4：单条命令输出里的证据字段
- `curl -w 'RESULT code=%{http_code} remote=%{remote_ip} time=%{time_total}s size=%{size_download} err=%{errormsg}\n'` 一行拿全状态码/远端 IP/耗时/错误——超时（code=000 err=timed out）与拒连（curl(7) Failed to connect after Nms）可区分，这正是"不可达记账"要的证据形态（任务实测：libsys 前两次超时、后一次 6ms 拒连，两种都记录）。

## 单发终态纪律（recon 记账场景）
- 不可达类：单发超时/拒连即终态，不重试；证据=一条 RESULT 行 + UTC 时间戳（`date -u`）。
- verified 发现：同一请求 3/3 稳定复现（同尺寸/同状态码）才可标 verified；影响面延伸端点另单发，只读优先。
