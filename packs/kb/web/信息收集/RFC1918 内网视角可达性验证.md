# RFC1918 内网视角可达性验证

## 坑：RFC1918 闭环假设不可达导致误标 tested_clean

- 现象：资产 IP 为 RFC1918 私网段（如 10.205.1.x）时，直接按惯例视为不可达/不测试，导致资产被错误标记为 tested_clean。
- 本质：外网视角不可达 ≠ 内网视角不可达。若评估方拥有内网入口（docker 网桥、VPN、跳板机），RFC1918 地址完全可能直连存活。
- 证据锚点：find-6213f9426257（实测 10.205.1.113 / 10.205.1.82 / 10.205.1.83 从 docker 内网直连，分别返回 Tomcat 200、选课系统 200、services 502；状态已由 tested_clean 纠正为 open）。

## 已验证路径

1. 对标记为不可达/私网段的资产，先盘点当前环境是否具备内网视角（docker 容器、隧道、双网卡等）。
2. 从内网入口直接 curl/探测目标 RFC1918 地址，而非跳过或假设不可达。
3. 收到任何 HTTP 状态码（200/502 等）即视为服务存活：登记 finding 并纠正资产状态为 open。
4. 对确认无内网入口或仍不可达的主机，明确标 na/budget_stop，避免语义错位。

## 适用范围

- 资产可达性/全面性评估（tested_clean 审核）。
- 内网服务存活探测与状态校准。
