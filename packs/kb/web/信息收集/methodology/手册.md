# 信息收集与测试方法论

> **测绘节奏只认** `dig-scope` §1.0.1 / §2.1：只搜**当前这一个**种子；本种子剩余活面没挖完禁止新搜。认到短表形态只打当前站，禁止拿 Morph 去全网 FOFA。优质根域只回灌，本种子挖完才搜。
>
> **全量 nuclei 不当进度。** nuclei 只在需要已知 CVE / 暴露面（actuator、swagger、已知中间件）时辅助；禁止把「全量模板扫一遍」当本站矩阵。
>
> 调搜用 MCP `fofa`（工具 `mcp__fofa__get_alerts`），不要自己 curl。Key 在 `mcp-servers/fofa_MCP/.env`：主号 → backup → backup2，`fofa.py` 遇 429/820041 自动切。限流闸认 `dig-scope` §2.1.4。**禁止**把 email / key 写进本文件或对话。

## 0. 判据速查

| 阶段 | 核心问题 | 输出物 | 去哪节 |
|---|---|---|---|
| 目标选择 | 范围里有多少活资产 | 资产清单 | §1 |
| 子域枚举 | 有多少个入口 | 存活子域 + 解析 IP | §2 |
| 端口与服务 | 每个入口后面跑什么 | 端口矩阵 | §3 |
| 技术指纹 | 什么框架/中间件/版本 | 组件与版本表 | §4 |
| 端点发现 | 有哪些接口、哪些参数 | 端点 + 参数清单 | §5 |
| 源码与凭证 | 有没有泄露的密钥 | 凭证清单 | §6 |
| 漏洞测试 | 按面逐个打 | 漏洞项 | 各专项篇 |

**顺序不能跳。** 跳过指纹直接上字典，等于用几千个请求去猜一件事，而 `Server` 头已经告诉你了。

## 1. 测绘层级

```text
目标选择
└── 范围界定（in-scope 资产）
    └── 资产发现（子域 / IP / 域名）
        └── 技术指纹（跑的是什么）
            └── 端点发现（攻击面）
                └── 漏洞测试（按类型逐个打）
```

## 2. 子域枚举（最关键的第一步）

### 2.1 被动收集（不向目标发 DNS 查询）

```bash
subfinder -d target.com -o subdomains.txt
amass enum -passive -d target.com
curl -s "https://crt.sh/?q=%.target.com&output=json" | jq -r '.[].name_value' | sort -u
```

证书透明日志（crt.sh）是最容易被忽略的一路 —— 它记录的是**所有签发过的证书**，包括早已下线的内部服务。

### 2.2 主动爆破

```bash
# massdns 批量解析
massdns -r resolvers.txt -t A -o S -w output.txt <(sed 's/$/.target.com/' wordlist.txt)

# ffuf 子域爆破
ffuf -w subdomains-wordlist.txt -u https://FUZZ.target.com \
     -mc 200,301,302,403 -H "Host: FUZZ.target.com"

# dnsx 批量验证
cat subdomains.txt | dnsx -a -resp -o resolved.txt
```

字典用 `SecLists/Discovery/DNS/`。

### 2.3 虚拟主机发现

子域不存在但同一个 IP 上挂着别的站点时，只能靠 `Host` 头找：

```bash
ffuf -w wordlist.txt -u https://target.com -H "Host: FUZZ.target.com" -mc 200,301,403
gobuster vhost -u https://target.com -w wordlist.txt
```

判据：**响应体长度或状态码与基线不同**。只改 `Host` 但响应完全一致，说明是默认站点，不是 vhost。

## 3. 端口与服务

```bash
nmap -T4 -F target.com -oN ports.txt
cat resolved_ips.txt | nmap -iL - --open -p 80,443,8080,8443,8888,3000,5000 -oG scan.txt
cat subdomains.txt | httpx -title -tech-detect -status-code -o live_hosts.txt
masscan -p 80,443,8080,8443 10.0.0.0/8 --rate=1000
```

要点：

- **`-F` 只扫 top 100 端口**，正式打之前一定要全端口。`8443`、`9090`、`7001`、`10051` 这类管理端口经常不在 top 100 里。
- `httpx` 的 `-tech-detect` 直接给出技术栈，比后面手工指纹省事。
- 大段 IP 用 masscan 先出结果，再用 nmap 对开放端口做版本探测。

## 4. 技术指纹

```bash
whatweb https://target.com
httpx -u https://target.com -tech-detect
curl -sI https://target.com | grep -i "server\|x-powered-by\|x-generator\|cf-ray"
```

指纹来源，按可靠度排序：

| 来源 | 可靠性 | 例子 |
|---|---|---|
| 响应头 | 高 | `Server: nginx/1.18`、`X-Powered-By: PHP/7.4` |
| Cookie 名 | 高 | `PHPSESSID`→PHP、`JSESSIONID`→Java、`_rails_session`→Rails |
| 静态文件路径 | 中 | `/static/js/angular.min.js` |
| 报错页格式 | 中 | 堆栈格式、默认 404 页面 |
| HTML 注释 / meta | 低 | `<!-- Drupal 9 -->`、`<meta name="generator">` |

**Cookie 名比 `X-Powered-By` 可靠**：后者常被关掉或伪造，前者是框架自己写的，改起来要动代码。

## 5. 端点发现

### 5.1 目录爆破

```bash
ffuf -u https://target.com/FUZZ -w raft-medium-files.txt -mc 200,301,302,403 -t 50 -o dirs.txt
gobuster dir -u https://target.com -w wordlist.txt -x php,html,js,json
feroxbuster -u https://target.com -w wordlist.txt -x php,html,txt -r
```

### 5.2 隐藏参数

参数不存在时接口往往照常返回，所以要靠差分：

```bash
arjun -u https://target.com/api/endpoint
x8 -u https://target.com/api/endpoint -w params-wordlist.txt
```

### 5.3 JS 源码挖端点

前端 JS 里硬编码的接口路径，是目录爆破找不到的那部分：

```bash
gau target.com | grep '\.js$' | httpx -mc 200 | xargs -I{} curl -s {} | \
  grep -oE '"/[a-zA-Z0-9/_-]+"' | sort -u

python3 linkfinder.py -i https://target.com -d -o output.html

gau target.com | sort -u > all_urls.txt
waybackurls target.com | sort -u > wayback_urls.txt
```

### 5.4 API 与文档

```bash
# 常见 API 路径
ffuf -u https://target.com/FUZZ -w api-endpoints.txt

# Swagger / OpenAPI
# /swagger.json  /api-docs  /openapi.json  /v2/api-docs  /.well-known/  /docs/

# GraphQL
# /graphql  /gql  /v1/graphql  /api/graphql
```

Swagger 一旦可读，等于拿到完整接口清单加参数结构，比爆破高效一个数量级。

## 7. 测试方法论（zseano）

> **节奏不听本节。** 自由跳 / 一种子 / 力气先砸哪认 `dig-scope` + `src-value` §1.1。本节只当：参数怎么想、错误页/旧版本/移动端 API 别漏。

四条原则：

1. **深挖一个项目**，不要横跨很多个 —— 把应用摸透
2. **给公司建画像** —— 技术栈、开发习惯、发布流程
3. **去别人不看的地方** —— 报错页、管理路径、旧版本、移动端 API
4. **跟着过滤器走** —— 某处有过滤，说明那个功能真实存在，且可能被绕

单个功能的测试顺序：

```text
1. 无害 HTML 标签（<h2>、<img>）→ 是否被反射？
2. 不闭合标签 → 什么反应？（<iframe src=//evil.com ）
3. 编码测试 → %0d %0a %09 <%00
4. 看输出位置，不只看响应码 —— 你的输入出现在页面哪里？
5. 把同样的输入打到所有同结构页面（共享代码 = 共享漏洞）
6. 同一参数在移动端/API 端点再试一次（往往防护更弱）
```

参数语义推理 —— 每个参数都在暗示服务端做了什么：

```text
文件名参数   → 文件系统操作 → 路径穿越 / 命令注入
URL/位置参数 → HTTP 请求     → SSRF
模板/HTML    → 渲染函数     → SSTI
XML 字段     → 解析器       → XXE
SQL 过滤     → 查询构造     → SQLi
用户内容     → 持久化       → 存储型 XSS
```

## 8. 优先级：力气往哪砸

> **节奏不听本节。** 自由跳种子/换站认 `dig-scope`；力气先砸哪认 `src-value` §1.1。下面 Priority 不是第二套测绘，也不是 SRC 定级。

项目选择：

```text
✓ 范围大（*.target.com）
✓ 为 P2/P3 付费（不只收 RCE）
✓ 近期有技术变更（迁移 = 新 bug）
✓ 活跃开发（新功能 = 新攻击面）
× 冻结的老代码库（已知 CVE 早被领完）
× 范围极窄的严格项目
```

功能优先级（按出洞概率）：

```text
P1  认证、密码重置、2FA        → 账号接管
P2  文件上传、资料编辑、API    → 存储型 XSS、IDOR
P3  管理后台、用户管理         → BFLA、提权
P4  支付流程、订阅             → 业务逻辑
P5  导入导出、模板渲染         → XXE、SSTI
```

## 9. nuclei 的正确用法

全量模板扫一遍不当进度。只在已知 CVE / 暴露面需要时收窄：

```bash
nuclei -u https://target.com -t cves/ -severity critical,high
nuclei -u https://target.com -t exposures/
nuclei -u https://target.com -t misconfiguration/
cat subdomains.txt | nuclei -t exposures/ -t misconfiguration/ -o exposed.txt
```

## 12. Java 中间件指纹矩阵

| 中间件 | 探测路径 | 关键判据 |
|---|---|---|
| Tomcat | `/manager/html`、`/manager/status` | 默认口令 `tomcat:tomcat`、`admin:admin` |
| JBoss / WildFly | `/jmx-console/`、`/web-console/` | JMX MBean 访问、WAR 部署 |
| WebLogic | `/console/`、`/wls-wsat/` | 7001/7002 的 T3 协议、IIOP |
| Spring Boot Actuator | `/actuator/`、`/actuator/env`、`/actuator/heapdump` | JSON 端点列表；heapdump 含内存里的密钥 |
| Spring Boot 冷门路径 | `/actuator/jolokia`、`/actuator/gateway/routes` | Jolokia JMX 桥、Gateway 路由注入 |
| Jenkins | `/script`、`/manage` | Groovy 控制台、cookie 里的 API token |
| GlassFish | `/common/`、`/theme/` | 4848 管理端口、默认空口令 |
| Jetty | `/jolokia/` | JMX 访问 |
| Resin | `/resin-admin/` | 管理面板 |

### Actuator 利用优先级

```text
/actuator/env            环境变量（库凭证、API key）
/actuator/heapdump       下 JVM 堆 → 搜内存里的口令
/actuator/jolokia        JMX → MBean 操作可 RCE
/actuator/gateway/routes Spring Cloud Gateway → SpEL 注入（CVE-2022-22947）
/actuator/configprops    全部配置项
/actuator/mappings       全部 URL 映射（隐藏端点）
/actuator/beans          全部 Spring bean
/actuator/shutdown       POST 关停应用（DoS）
```

**`heapdump` 是被低估的**：它包含运行时的所有字符串，包括数据库连接串和第三方 token。下载下来直接 `strings | grep -i password`。

## 14. 纪律

- **顺序不能跳**。指纹拿不到就上字典，是用几千请求猜一件 `Server` 头已经写明的事。
- **证书透明日志是被忽略最多的一路**。crt.sh 里的历史子域，往往包括已下线但 DNS 还在的内部服务。
- **vhost 判据看响应差异，不看状态码**。只改 `Host` 但响应体一模一样，是默认站点。
- **`-F` 之后必须全端口**。管理端口几乎都不在 top 100。
- **JS 里的接口路径，目录爆破永远找不到**。先 `gau` 拿 JS 列表，再从中抽路径。
- **被删的密钥仍在 git 历史里**。`git log -p --all -S` 比看当前文件有效。
- **nuclei 全量扫不是进度**。它的价值在已知 CVE 和暴露面确认，不在发现新东西。
- **优先看 `heapdump` 和 `env`**，它们直接给出可用凭证，比继续挖洞性价比高。
