# 漏洞报告写作格式（永久 · 唯一）

> **2026-09-06 定稿：报告版式 =「资产分析报告」；PoC = 原始 HTTP 报文（可直接复制）。**  
报告版式与 PoC 写法只认本文件；判级口径、落不落、匿名闸、认钥闸、清理纪律见 §二。  
加、减、改都在这里；禁止写到 Agents、src-value、dig-scope 或其它文件。

***

### 写报告前置闸（先判「落不落」，再谈版式）

> 任何想写进 `报告/` 的动作，先过闸再动笔；写报告是闸后确认的结果，**不是收尾默认动作**。  
**判级硬序列（每份报告必经 · 逐字读本节打勾，禁止凭记忆 / 禁止先定级再找规则）：**

````
L1 反问"看着像洞吗"：先按 edu-rating-rules 与 src-value §1.2 判内容级别。
   ——拿到的是谁的内容？强 PII（身份证/手机/卡/证件照/密码）？主机系统文件/源码？
   只有自然人敏感信息 / 业务源码 / 认证凭据且过 L2 认钥闸，才谈 ≥中危。
   "看着重要"（平台级/批量/跨平台）不是判级依据，先定重要再找规则 = 直接违规。
L2 过认证凭据闸（§二认钥闸）+ 过匿名闸（§二）：抄到钥不算洞，生产认了才写。
   ——密钥能当别人用的会话 / 认钥枪带出身份或列表？不过不写。
L3 反向复验：把结论拿低级规则逼一遍。读的这内容能算低危吗？哪个字段够"对得上人"？
   ——§二"防误报高危"逐条对；弱凭证（姓名+学号）不是敏感数据；低敏/未过闸 → 低危/信息。
三级缺一不写；返回只有低敏字段或凭据未过闸 → 直接降级；**降到低危照落报告（2026-09-11 新口径），降到信息级才不落**。
````

1. 先判级，不先写：有没有真 ≥低危（非信息级）？（认 §二 判级表，过 L1~L3 + 匿名闸/认钥闸才算确认；**2026-09-11 用户改：落报告门槛从 ≥中危降为 ≥低危**）
2. 只有信息级/无洞 → 一行都不进 `报告/`：留痕只许写 `README.md`，帽一行「仅信息级/无洞，未落报告」；**不建** **`报告/`** **报告/ 夹**，任务根按 task-folder §3.1 待清或手改归档。
3. 有 ≥低危 → 才开 `报告/`：文件名=`资产分析报告：<目标>.md`，走 §一 版式（头部 `>` 引用块 + 分级节 + 必填「结论与评级」）。
4. 文件名=断言：写下 `资产分析报告：…` 即等于声明「本任务有 ≥低危的真洞」。落笔前默念——断言成不成立？不成立回第 2 步。

一句话：收尾默认 = 过闸 + 决定（报告 / 工作记录 / 待清），**不是默认写报告**。

## 一、正文模板（唯一版式 · 资产分析报告）

```markdown
# 资产分析报告：<目标>

> 演练项目：…
> 目标：…
> 关联 IP：…
> 测试日期：…
> 范围说明：…

## 漏洞发现

### 严重（Critical）
#### <漏洞名称 1>
- 漏洞描述
- 验证 PoC
- 利用后果
#### <漏洞名称 2>
- …（同结构）
### 高危（High）
#### <漏洞名称>
- 漏洞描述
- 验证 PoC
- 利用后果
### 中危（Medium）
#### <漏洞名称>
- 漏洞描述
- 验证 PoC
- 利用后果
### 低危（Low）
#### <漏洞名称>
- 漏洞描述
- 验证 PoC
- 利用后果
### 信息（Informational）
#### <观察项名称>
- 观察内容
- 证据
- 安全影响或限制
### 其它
## 结论与评级   ← 报告末尾必填
```

| 块                    | 规则                                                                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 标题                  | `# 资产分析报告：<目标>`。目标写单位/平台 + 域名。                                                                                                                                                   |
| 头部引用块            | 单行 `>`，含：演练项目 / 目标 / 关联 IP / 测试日期 / 范围说明。关联 IP 如实（源站不可直连就写 WAF/CDN 与解析到的节点，不编源站 IP）。范围说明写清授权面、测试号、是否只读/最小样本、验证后是否还原。 |
| 漏洞分级节            | 严重/高危/中危/低危/信息/其它。**某级无实际条目：直接不写该级小节（不写「无」占位、不留空标题），只写有内容的级别。** 不凑数、不堆低危。分档判级只认 §二。                                           |
| #### 漏洞名称         | 一行。谁的站、做成了啥。有会话动别人对象写「越权」；没登录态打通写「匿名未授权」；能批量的带「任意/批量」。                                                                                          |
| 漏洞描述              | 第一人称大白话讲清做成啥（有会话「我拿自己的会话…」，没会话「我没登录…」）；说清对象、影响面。不贴复现、不列伤害清单。认证通道/头怎么带（authorization/Cookie）一句话说明即可。                      |
| 验证 PoC              | **原始 HTTP 报文**，整体复制粘贴到 Burp Repeater 等同工具即可直接复现。细则见下「PoC 报文规范」。                                                                                                    |
| 利用后果              | 只写最终能造成的伤害，按拿到身份/钥/数据的真实权限面写全（能改能删照写，没真打的不要编「删了谁」）；每种伤害单独一行；能批量就写「可批量」；有例子的必须举例（一两个姓名/手机/地址/内部标题实值）。  |
| 信息（Informational） | 观察项三要素：观察内容 / 证据（可给报文）/ 安全影响或限制。够不上低危的配置、指纹、加固观察放这里。                                                                                                  |
| 结论与评级            | **必填**。给整体评级（严重/高危/中危…）＋理由一段＋分步修复建议。复现账号是否已还原/最小取证说明收在这里。                                                                                           |

### PoC 报文规范（硬）

- **PoC 的目的 = 快速复现 + 证实危害**：默认用原始 HTTP 报文（可整体复制粘贴到 Burp Repeater 等同工具直接复现）；报文带防重放机制无法直接重放时 → 转脚本复现，硬要求与版式认下方「PoC 与脚本复现」专节（该节压过本节默认）。
- 每个 PoC（报文或脚本）是 **可整体复制的原始形态**，不是 curl、不是截图、不是描述。
- 报文要素：请求行（完整 `/tduck-api/…` 带 query）→ `Host:` 紧接 → 完整请求头（`Connection`、`User-Agent`、`Accept`、`Accept-Language`、POST 加 `Content-Type` + **精确** **`Content-Length`** **Content-Length**、`authorization`/`Cookie` 会话）→ 空行 → body（POST 报文）。
- 多步复现用多个报文块，编号 ①②③…；每步只一个报文。
- 会话：报文里写**当时实测可用的会话实值**；整段开头用一两句说明「过期后登录任意账号抓包替换 authorization 值即可；userId=1364 换成你所用账号的 userId」。禁用占位符 `<token>` 当主报文（实值为主，替换说明为辅）。
- 认证通道要按实测写：后端只认 `authorization` 头就放 `authorization`，别照抄「Cookie 里也有同名字段」的无关样例。
- 对照（原站/无会话 401）写在该步判据一句里，不另开一步。
- 报文中/报文块内**不写回包、不写「预期」**；回包判据放块外中文。
- **敏感数据是实读的不是推测的**：断言手机号/邮箱/密码/姓名/身份证/内部标题等敏感信息 → PoC 必须用**实读到的原始报文**（含真实返回）证明，禁止用推测、参考别站结构、或统计数字代替；没跑出可复现报文就写「字段存在未取实值」，不写「含手机号/可撞库」这类未证断言，并删除按别站结构猜出的无证字段描述（对应 `hunt-iter.md`「取证」行）。

### PoC 与脚本复现（硬 · 2026-09-11 用户定）

- **PoC 的目的 = 快速复现**：审阅者把报文贴进 Burp Repeater 即可直接重放；单洞单步优先纯报文。
- **报文防重放场景必须补脚本（脚本为主 PoC）**：报文含一次性 token / nonce / 签名 / timestamp 时效校验 / 验证码绑定等，直接重放必失败时，把**完整可运行的 Python 脚本全文写进报告正文**（```` ```python ```` 块），**替代报文当主 PoC**；静态报文可保留一条作通道示意（注明「示意，防重放不可直接重放」）。脚本硬要求：①**自动现算**时效值（取新 token / 当前时间戳重算签名），复制即跑、不依赖会话环境；②零第三方依赖优先（标准库 urllib/hashlib/base64 等），硬编码凭据写完整实值；③**无害化纪律内建**：默认最小样本（`$top=1` 等），批量参数带 ≤50 条上限与提醒，docstring 写明只读/不篡改边界；④脚本源文件落 `temp/`（同源）并实测跑通，运行日志落 `temp/evidence/`；报告内贴全文（或明确相对路径引用），**禁只给思路伪代码**。跑完输出与报文 PoC 同样口径的成立判据（代码块外一行中文写「返回什么算成立」）。
- **证实危害 = 回显危害（硬）**：报文回显或脚本运行输出必须真实呈现所断言的数据——断言泄露身份证/密码/手机号等强敏感字段，PoC/脚本就必须**实读并回显这些字段实值**（脚本支持 `$select` 探测指定字段、全字段原文回显，字段存在即如实呈现）；断言 RCE 就回显命令输出；断言越权就读出别人对象实值。断言与回显对不上 = 危害未证实，按判级规则降级或信息级处理，禁止只给状态码/「成功」字样冒充证明。仍守无害化最小样本（≤50 条）；未实证的强敏感字段不得虚构断言，如实写「字段存在未取实值」。

### 描述与命名（简短口径）

- 面向安全评审，不科普、不写说明书腔（禁「该接口未做鉴权即可调用」这类）。
- 硬编码/凭证/密钥从 JS 出来的：描述必须写完整实值 + 完整 JS 地址（http(s) 全路径）；接口清单出处不能替代。
- 落盘：`./target\{任务根}\报告\资产分析报告：<目标>.md`，CRLF，UTF-8。文件名即标题名。`./target` 根禁止散落报告。
- **≥低危就写报告（2026-09-11 用户改，压过旧「只有 ≥中危才写」）**：低危/中危/高危/严重 → 都写一份总报告（信息观察项随有报告的站带在里面）；**只有信息级/无洞 → 不写报告**（无报告的任务根按 task-folder §3.1 整根删）。
- 旧格式单洞草稿若被新总报告替代，暂存 `{名}_dig/archive/`，报告目录只留总报告，避免同洞重复交付。（注意：此为 **dig 内旧草稿暂存**，与整棵任务根移入 `./target/归档/` 是两回事——后者仅**用户手动**操作，见 task-folder §1.3。）

## 二、收洞判级与纪律（唯一 · 沿用口径）

### 等级判定

| 级            | 命中（至少一条即该级）                                                                                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **严重**      | 命令跑起来；进了别人的号或改掉别人的密/绑（人账号打登录出了真会话走这里）；钱真转走了，或录用/理赔/放行这类状态真变了。                                                                                                                                                   |
| **高危**      | 没到严重但中了至少一条：对得上人（手机/身份证/卡/证件照）；云密钥/token/库连接串/能当别人用的会话（须过认钥闸）；注入出了他主体的数；他人未公开的业务正文（内部知识库、未上架/未发布详情、工单/答卷正文这类，是正文不是标题摘要）。个人空间过权限墙只出标题/摘要 → 中危。 |
| **中危**      | 有权限扩大或业务敏感，上面两条一条都没中。拿不准不写。                                                                                                                                                                                                                    |
| **低危/信息** | 按 §一「信息」/版式「低危」「其它」放；低危可有可无，禁止把信息级堆成漏洞充数。                                                                                                                                                                                           |

定级只对上面几条，禁止比上一份多一个字段就跳档。批量越权、提权到超管但未真做改密/进号 = 高危（危害按真实权限面写全，不因「没执行破坏动作」降级成中危，也不编成严重）。

### 防误报高危：未授权/越权能「查到他人数据」≠高危（用户 2026-09-08，防再犯）

判高危必须真中 §判级表强条件；只中「业务敏感 / 权限扩大」的一律中危，低敏一律低危。遇到下面任一情况都别升档到高危：

- **返回只有低敏字段，别硬套「对得上人」**：未鉴权/越权能查到他人数据，但返回**不含身份证 / 手机号 / 卡 / 证件照 / 密码等强敏感字段**（只有姓名、学号、订单/缴费金额、班级、流水号这类低敏业务数据）→ 判低危。弱凭证（姓名+学号）本身不是敏感数据，不算命中「对得上人」。
- **「可猜 / 可遍历」≠「可批量」**：批量成立必须有能实际产出「有效可查询输入组合」的数据源（公开名单、可穷举且真回数据的 ID 区间）。只有理论上可猜、无获取来源的，不按批量升档，不写入「可批量」危害。
- **低敏业务数据（学费 / 缴费 / 订单金额）未授权查询**：实际无恶劣后果 → 低危 / 信息，禁止为凑报告硬升档。

### 落不落

| 不写         | 半条链；弱口令没进号；无密钥壳（含没账密的 DSN、health、版本、只有 host 没密码）；凭证/密钥/私钥没过认钥闸；进了号没有身份/列表的只读例；占位/过期/真假同一句错；仅未授权 up/down；信息级/配置提醒/证书过期/缺安全头/CORS/未授权发短信邮件验证码/滑块/本职可读/公开数据/指纹/仅害自己 CSRF/接口 200 有 JSON/短信验证码轰炸。**验证码/短信轰炸不算洞，一律不报**（用户 2026-09-08）：能对任意手机号发送验证码短信、绕验证码后触发短信发送、以及依赖"短信轰炸"作为主要危害的点，全部 N/A 不落报告。 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **立刻写**   | 中危/高危/严重，确认立刻写进 `报告/`，禁止攒到最后。没过匿名闸/认钥闸不算确认。                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **匿名闸**   | 标题写「匿名」前先问：打通那包有没有登录态。有会话 → 不写匿名改「越权」，描述「我拿自己的会话」，报文带会话实值。                                                                                                                                                                                                                                                                                                                                                                                      |
| **认钥闸**   | 抄到钥不算洞，生产认了才写（假值对照生产认了 + 认钥枪带出身份或列表）。没过不写。                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **别重复交** | 本任务 `报告/` 已有一模一样（同类型同一 url）→ 不写；同类型不同 url 照写；同一洞挖大改原篇。                                                                                                                                                                                                                                                                                                                                                                                                           |
| **密钥放哪** | 密钥实值、完整 JS 只进正式报告，不进短表/知识库。                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **清理**     | 无报告 → 整根任务夹删；有报告 → 只留 `资产/` + `报告/`（archive 随 dig 删）。不动浏览器存的账号密码。 |

## 四、国际平台转换（仅投 HackerOne 等国际众测平台时使用 · 新增 2026-09-11）

国内 SRC 一律 §一「资产分析报告」版式，不走本节。**只有**目标平台是 H1/Bugcrowd/Intigriti
等国际平台时，把已过 §二 判级闸的 finding 转换为下列三段式输出（内容同一份证据，两种版式）：

1. **标题**：≤80 字，精确到 endpoint + 漏洞类型（例：`SQLi in /api/v2/search filter parameter`）。
2. **重现步骤**：每步可执行，带 HTTP 包 / curl / 截图；HTTP 报文规范同 §一 PoC 报文规范
   （可整体复制、精确 Content-Length、实值会话）。
3. **影响 + 修复建议**：业务影响段 + CVSS 4.0 vector + 分步修复建议。

转换纪律：
- 判级仍以 §二 表为准做映射（严重→Critical、高危→High、中危→Medium），**不因平台奖励表虚升级**。
- 英文输出时中文版报告为底稿，事实与报文逐字对齐，不添未验证断言。
- 平台合规红线（safe-harbor、disclosure window、测试头）先 Read `references/compliance.md` 核对再提交。
- 现场构造 payload 的「现场构造，库无出处」标注在转换稿中改为 `payload: hand-crafted on-site`。                                                                                                                                                                                                                                                                                                                                                                                                  |
