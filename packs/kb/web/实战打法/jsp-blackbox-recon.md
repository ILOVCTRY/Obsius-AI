# JSP 自研系统黑盒打点：匿名端点探测 + 响应聚类定位未授权接口

## 适用场景
- JSP/Java 自研系统（Tomcat + nginx/WAF 前置），已获取登录页
- 登录面被封（WAF 全拦注入特征、验证码无响应差分），需低成本找未授权接口/信息泄露

## 已验证路径
1. **批量匿名访问业务 JSP 端点，按响应体聚类找 anomaly**（证据：find-ddd0a22a2b5c）
   - 对 200+ 常见 JSP 路径（report/list/view/upload/export/delete 等）逐个匿名 GET
   - 正常业务端点统一内部渲染登录页（200 + 登录页特征）；未授权接口是响应异构的少数派
   - 本任务中仅 export.jsp 返回 Tomcat 7.0.77 NPE 500 错误页（export_jsp.java:92），一次请求即确认：接口真实执行业务代码但绕过登录检查，且泄露完整技术栈
   - 判别要点：500 错误页带 servlet 源码行号/版本号 = 未授权执行 + 情报泄露，无需再触发其它路径
2. **.git 被 WAF 拦截时降级探测 .gitignore**（证据：find-d9835e5e7ed）
   - /.git/ 请求返回 403 时，改试 /.gitignore —— 本任务中匿名可读，泄露 Java IntelliJ 项目结构
   - .gitignore 虽非敏感文件，但可确认源码管理痕迹与构建/IDE 类型，为后续定向文件探测提供词表

## 坑
- 同一系统其余 200+ 业务 JSP 匿名访问均渲染登录页（状态码可能同为 200），**只看状态码/长度会漏掉未授权接口**，必须对比响应体特征聚类；唯一异构响应即突破口
- Tomcat NPE 500 错误页会完整输出调用栈与 JSP 编译行号，响应体本身就是情报，无需二次探测
- WAF 对 SQL 特征（or/union/||/注释符变体）全 403 时，登录侧注入/爆破/用户枚举通道基本封死，及时转向未授权接口探测面
- 验证码不校验但登录响应无差分（len 全 4239）时，用户名枚举无法用响应长度区分，属死路
- 同类系统先枚举并匿名访问全部业务 JSP（与导出/报表类接口优先），再考虑登录侧攻击
