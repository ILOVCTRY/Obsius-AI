# 文件与流量判据库

> 来源：219 篇 Misc 赛题 WP 的提炼（973 条观测 / 576 条失败尝试）。原始 WP 已消化完毕并从库中移除，仅保留本节判据。
> 主库 `misc/编码解码/`、`forensics/隐写与信号/` 已有工具手册，
> 本文补**判据化的分流**：先看现象属于哪条介质线，再选工具。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| `file` 显示「data」但大小异常 | 有拼接/追加数据 | §1.1 |
| 文件尾部有 `PK\x03\x04` | 尾部藏 zip | §1.1 |
| 一张图里有多张图的 magic | 图片拼接（binwalk 可切） | §1.1 |
| 图片正常但看不出内容 | LSB / 通道分离 / 调色板 | §3.1 |
| 音频波形看不出、频谱有横线 | 频谱图藏字 | §3.2 |
| pcap 里全是加密流量 | 先找密钥（TLS keylog / 硬编码） | §2.1 |
| pcap 里有 HTTP 但都是乱码 | webshell 流量，先判马的类型 | §2.2 |
| zip 有密码但内容很少 | 已知明文攻击（bkcrack） | §4.1 |
| zip 无法解压但能看目录 | 伪加密（改标志位） | §4.2 |
| 有大量小文件且命名规律 | 文件名编码 / 排序拼接 | §4.3 |

## 1. 文件结构

**判据**：先用 `file` + `xxd | head` 看头部，再用 `binwalk` 看内嵌。

```bash
file target
xxd target | head -5
binwalk target
# 有内嵌就切出来
binwalk -e target
# 或手工按偏移切
dd if=target of=part1 bs=1 skip=0 count=<offset>
```

### 1.1 拼接与追加

```text
JPG 尾接 ZIP:  FFD9 之后出现 504B0304
PNG 尾接 ZIP:  49454E44AE426082 之后出现 504B0304
JPG 头 + PNG 体: FFD8FFE0 开头但中间有 89504E47
```

判据是**文件尾的 magic 与文件头不匹配**。用 `binwalk` 能直接列出所有内嵌段的偏移。

### 1.2 头部损坏

```text
PNG 缺 89504E47 前 8 字节 → 补回后能开
ZIP 缺 504B0304 → 补 4 字节
7z 缺 377ABCAF271C → 补 6 字节
```

判据是**文件大小合理但打不开**。用 `xxd` 看头 16 字节，对照标准 magic 表。

### 1.3 结构异常的判据

| 格式 | 异常点 | 含义 |
|---|---|---|
| PNG | IDAT 块数量 > 10000 | CRC 或长度藏数据 |
| PNG | IHDR 的宽高异常 | 尺寸藏信息（可爆破 CRC 反推） |
| ZIP | 中央目录与本地头不一致 | 伪加密或藏数据 |
| JPEG | 多个 `FFD8` | 多图拼接 |
| GIF | 多帧但只显示第一帧 | 后续帧藏数据 |

**关键判据**：PNG 的 `IDAT` 块超过 1 万个且 CRC 不正常，基本可以确定是 CRC 隐写。

## 2. 流量分析

**判据**：先判「有没有加密」，再判「加密的密钥在哪」。

### 2.1 加密流量的三条路

```text
1. 有 keylog 文件     → 直接喂给 Wireshark（Preferences → Protocols → TLS → (Pre)-Master-Secret log）
2. 密钥硬编码在附件里 → 从 exe/apk/js 里提取
3. RSA 私钥在附件里   → 配到 Wireshark 的 RSA keys list
```

判据是**题目附件里有没有非 pcap 的文件**。给了一个 exe 或 apk，密钥大概率在里面。

### 2.2 webshell 流量识别

| 马的类型 | 流量特征 |
|---|---|
| 中国菜刀 | 请求体 `@ini_set`、`base64_decode`，响应是明文 |
| 冰蝎 2.x | AES 加密，密钥 `e45e329feb5d925b`（MD5 前 16 位） |
| 冰蝎 3.x | 请求体 AES，响应体内层 base64，`behind.php` |
| 哥斯拉 | 请求体 base64 + XOR，密钥在 `pass` 参数 |
| 蚁剑 | 请求体 `@ini_set("display_errors","0")` |

判据是**请求体的加密形态**。冰蝎的默认密钥 `e45e329feb5d925b` 是硬编码的，直接 AES 解密即可。

### 2.3 隐蔽通道

```text
DNS 隧道   → 看 TXT/CNAME 记录，base64 拼接后 rev
ICMP 隧道  → 看 data 字段长度或内容
HTTP 头    → 看 X-Forwarded-For、Cookie、User-Agent 的异常值
时序通道   → 看包间隔（长短 = 0/1）
```

判据是**同一字段在大量包里持续变化且不符合协议规范**。用 `tshark -T fields -e <字段>` 导出来看规律。

```bash
# 导出 DNS 查询名
tshark -r a.pcap -Y dns -T fields -e dns.qry.name | sort -u
# 导出 HTTP 全部 URI
tshark -r a.pcap -Y http.request -T fields -e http.request.uri
```

## 3. 图像与音频

### 3.1 图像

按这个顺序试，不要跳：

```text
1. file / exiftool            看格式与元数据
2. binwalk                    看有没有内嵌
3. zsteg（PNG/BMP）           LSB 全通道扫
4. steghide（JPG）            需要密码，先试空密码
5. 通道分离                    R/G/B/A 分别看
6. 调色板                     GIF/PNG8 的调色板顺序
7. 图像尺寸                   宽高藏数（爆破 CRC 反推）
```

判据是**图片「看起来正常」但题面提示有东西**。这时候优先 LSB 和通道分离。

LSB 的细节：

```bash
# zsteg 全扫
zsteg -a image.png
# 指定通道
zsteg -E "b1,rgb,lsb,xy" image.png > out.bin
# 常见变体：b1（1 位）、b2、b4；rgb / bgr；lsb / msb
```

**坑**：LSB 提取出来的数据不一定是文件头，可能是先 XOR 再拼。看到乱码先试 `XOR 0xFF`、`XOR 0xAA`。

### 3.2 音频

```text
1. 看波形         → Audacity，找明显的振幅变化（摩斯）
2. 看频谱图       → Audacity 切「频谱图」，找横线组成的文字
3. 听              → 倒放、变速、左右声道分离
4. 看元数据       → exiftool
5. LSB            → wav 的采样值低位
```

判据是**频谱图里有规则横线**——这是频谱藏字，直接读。摩斯码看波形长短。

**坑**：`wav` 的 LSB 要用 `wav` 解析库读采样值，不能直接当字节流读（有头）。

## 4. 压缩包

### 4.1 已知明文攻击

判据是**压缩包里有一个文件的内容可推测**（比如 PNG 头、已知的 readme）。

```bash
# bkcrack 需要至少 12 字节已知明文
bkcrack -C target.zip -c inner.png -p plain.png
# 拿到密钥后解密全部
bkcrack -C target.zip -k <key> -U out.zip password
```

**坑**：bkcrack 要求压缩算法是 ZipCrypto（传统加密），AES 加密的 zip 不行。

### 4.2 伪加密

```text
ZIP 本地文件头：50 4B 03 04 ... 通用标志位（偏移 6，2 字节）
奇数 = 加密，偶数 = 不加密
伪加密 = 标志位是奇数但实际没加密 → 改成偶数即可
```

判据是**能看目录但解压要密码，且密码怎么试都不对**。用 `010 Editor` 改标志位，或用 `zip -FF` 修复。

### 4.3 文件名编码

```text
文件名是 1.png 2.png ... → 可能按内容排序而非名字
文件名是 base64       → 解码后拼
文件名是 hex          → 转 ASCII
文件名是日期          → 按时间排序
```

判据是**大量小文件且名字有规律**。先 `ls | sort` 再 `cat` 拼接，顺序错了就是乱码。

## 5. 编码识别

**判据**：看字符集和长度。

| 特征 | 编码 |
|---|---|
| `A-Za-z0-9+/` 且长度 4 的倍数 | Base64 |
| `A-Z2-7` 且长度 8 的倍数 | Base32 |
| `0-9A-V` 且长度 8 的倍数 | Base32hex |
| 只有 `0-9a-f` | Hex |
| 只有 `.` `-` 和换行 | 摩斯 |
| 只有 0/1 | 二进制 |
| 两个字符交替 | 培根密码 |
| 密文与明文等长且字母频率偏移 | 凯撒/ROT |
| `%xx%xx` | URL 编码 |
| `&#xxx;` | HTML 实体 |

判据是**字符集**。长度对不上时考虑多层编码（先 base64 再 hex 之类）。

## 6. 纪律

- **先 `file` + `binwalk`，再谈其他**。这两条命令能解决一半的 Misc 题。
- **拼接题看文件尾**。`FFD9`、`49454E44` 之后的字节都是可疑的。
- **流量题先判有没有加密**，加密的先找 keylog 或密钥文件。
- **图片题按顺序试**（元数据 → binwalk → LSB → 通道），不要跳步。
- **zip 打不开先判伪加密**，改标志位比爆破快得多。
- **多层编码从「最外层特征最明显的」开始剥**，剥一层看一层。
- **文件名本身可能是数据**。排序、解码、当索引都试一遍。
