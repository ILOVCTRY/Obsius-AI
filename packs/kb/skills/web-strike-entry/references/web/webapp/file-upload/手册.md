# 文件上传漏洞测试手册

## 一、判定链：先判这个接口是不是“真上传漏洞”

判定“任意文件上传”的真实影响，不是看能不能传，而是看它是否能落到可执行、可公开读取、可跨用户覆盖、可分发脚本、或可触发客户端执行。

1. 鉴权门：同类接口无 token 返回 401 作对照；上传接口空 multipart 直达业务层，说明存在明显鉴权缺失。
2. 最小无害上传：先上传一个最小文本文件，确认是否可 GET / 复取 / 公网可读。看响应头是否含对象存储特征，如 `X-Amz-Request-Id`、`nosniff`、CSP 等。
3. 先判落地：文件落在 CDN / OSS / S3 / 本机静态目录，还是落在业务服务本地目录。不同落地决定后续影响范围完全不同。
4. 扩展名过滤与内容过滤必须分开看：只变 filename、只变内容、只变 type，分别测试，避免把 403 误归因到扩展名。
5. 先看“有无可执行/可公开/可覆盖/可下载”，再决定是不是高危。不是“能传”就算漏洞；要看是否真的构成 RCE、托管、XSS、覆盖其他对象、跨租户访问等。
6. 对象存储/静态托管场景中，`.svg`、`.js`、`.sh`、`.htaccess`、`.wsf`、`.vbe`、`.xml`、`.json` 之类落盘，常见于任意内容托管。 
7. SVG 只在顶层开启/iframe/object/embed 之类环境中执行；`<img>` 一般不会执行脚本，因此要看是否被顶层打开，而非只看“能返回 SVG”。
8. Office 宏文档需区分“上传成功”与“服务端真的能解析/消费”。只上传到对象存储/静态站点本身，不等于服务端读取并执行；必须确认有消费端（预览、导入、转码、渲染）才有意义。

## 二、开场测试流程

找上传点（头像/附件/导入/富文本）→ 先传正常文件看路径、是否重命名、落 CDN/OSS 还是本机、能不能直接打开。别停在“能传能下”，要继续跟覆盖他人对象、带签读、可执行/路径/SSRF、跨用户对象访问。

场景中，后缀过滤、Content-Type、解析绕过、文件名/路径/签名/对象 Key 这些点，必须现场按栈自己变，不要只看一条固定 payload。

## 三、上传测试的核心手法

### 1. STS / 对象 key 通配覆盖

认：对象存储（BOS / OSS / S3 / TOS）上传先申请 STS / 预签名；对象 key 常是文件 md5；桶名按日期或批次递增。请求里的 `filename` / `Action` 常被拿去拼 Policy。`xluser` / `AES` / `1.jpg` 常作为观察点；没有这类字样也要尝试通配。

打：
1. 申请凭证的 `identifier` / `key` / `object` / `prefix` / `filename` 长度不校验时，试 `*`、`**`，再试空串和 `/`。
2. 一个 `*` 可能落到空桶；两个以上可能命中当前业务桶，导致凭证范围被扩到当前桶。
3. path / `actionName` / Policy 里拼接的路径参数，试 `../../../`、`../../../&/../../`，看是否扩到根目录。
4. 别人的对象 key 往往是 md5：在文档页、JS、接口里搜 `md5sum` / `md5`，不用下载、不用付费。
5. 用领到的 STS，把上传 path 设成对方的 md5，尝试覆盖对象。
6. 对于 assumerole/Policy 的覆盖场景，可以再打 `filename=*-*`、`Action=*`。有些实现中，后段 Policy 会覆盖前段，本来应该受限的 key 变成整桶范围。
7. `PUT` 时尝试头部 `x-cos-acl: public-read` 和 `x-cos-grant-full-control: id="你的UIN"`。只有对象真的变成公有读，或控制权落到自己的 UIN，才算接管。
8. 若没有“文件已存在”提示，仍可猜短原文件名（如 `1.jpg` / `2.png` / `5.jpg`），用匿名 GET 去命中 CDN。
9. 若落地页写死了 Supabase / nocode 的 `role=anon` JWT，不能止步于表 CRUD；带 `apikey` + `Authorization: Bearer` 再打 `POST /storage/v1/object/{桶}/{前缀/探测key}`，用 `x-upsert: true` 覆盖同前缀文件，用公开对象地址对照内容。

算成：
- 能再打开/下载对方那篇/那张图，内容变成你传的
- 能 list 出别人的 key 并能删/盖
- 能覆盖官方前缀对象且内容变成自己传的

假点：
- `*` 只是签发了废桶
- 通配了但覆盖 403
- 改的是自己的对象
- 只通自己前缀
- CDN 一直不刷新看起来没盖上

### 2. 签名没绑 Host

认：COS / OSS / S3 带签 URL；`q-header-list` / `SignedHeaders` / `X-Amz-SignedHeaders` 中没有 host。只有对象存储场景才打，没有时不要空换域名。

打：
1. 看签名参数里签了哪些头；没有 `host` 才继续。
2. 把 URL 的主机换成同账号另一个桶的域名，path 和签名 query 不动。
3. 再加 `?uploads`（或已有 query 后拼 `&uploads`）尝试 ListMultipartUploads；能 GET 对象也继续打。

算成：能列出或读到其它桶里的对象。

### 3. 签名覆盖 Content-Type

认：对象内容可控，且对象上的 Content-Type 被卡死；手里有临时钥或能再出预签名。

打：
1. 上传时改 CT（如 `text/html`、`text/html,image/png`）仍要打；这说明签名没把 Content-Type 一并绑定。
2. 事后用临时钥给已有对象生成带 `response-content-type=text/html` 的 GET。
3. 在浏览器中打开新签 URL，而不是只看 curl 返回头。

算成：浏览器把对象当 HTML 执行，形成存储型 XSS。

### 4. webpack 明文对象存储永久钥

认：管理台/运营后台的 webpack 把真实 `accessKeyId` + `secretAccessKey` 打进 JS，或者 Weblogic 的 `/console/login/LoginForm.jsp` 里有 `_reportCfg` 这类 `SRV_` 键。前端的 `getUploadSign` 可能只是 HMAC 算签，不是登录后的 STS 接口。

打：
1. 抄 online/prod 的 AK/SK（实值只写报告，不放进知识库）。
2. 自己算 POST Policy，expiration 拉长，`starts-with $key` 按原 JS 保持一致。
3. POST 到桶，观察 `SignatureDoesNotMatch` 或 `conditions has no signature` 等返回值。
4. 任意 key PUT 后 CDN GET；DELETE 自己刚传的证明钥能写。
5. List/PUT 403 时先做 `GetBucketLocation`，确认真实 AK 是否可用。

算成：永久云钥能直接签发写入，甚至能覆盖官方已有对象。

### 5. 桶策略对匿名全开

认：官网/控制台的图、使用指南、协议直接挂在 OSS / cloudrun 一类桶域名上；桶根或 `?policy` / `GetBucketPolicy` 等开了全 Allow。

打：
1. 看策略；再对桶做 LIST（无 AK）。
2. 对已经在官网引用的对象尝试 PUT / 覆盖。
3. 私有资源优先，覆盖完之后用官方 URL 验收。

算成：官方指南/协议/图内容被你改写。

### 6. 存储代理 sign key=/

认：业务网关把对象存储代理成 `/api/storage/sign`，query 只吃 `key`。`key=/` 或 `key=.` 可能返回 S3 的 `ListBucketResult` XML，而不是正常的 `NoSuchKey`。

打：
1. GET `?key=/`，再试 `.`。
2. 抄业务前缀（如 `images/`、`editor-`）再 GET 同一口。
3. 查看对象是否为未公开素材，不要停在官网 Banner。

算成：能列出并读到他人未公开对象原文。

### 7. 制品下载详情把 uin 有无当登录闸

认：软件/专有云/物料下载中心的详情 JSON 有 `DownloadURL`；前端从 Cookie 把 `uin` / `skey` 拼到 query。空身份时 URL 是空串，页面跳登录。

打：
1. 不登录时 GET 详情；填一个非空假值 `uin=1`，不要带 skey，对照空 uin。
2. 拿回的带签 URL 做 Range GET，前几十字节看是否是 ELF / PK 等真实文件。

算成：下载到专有云安装包或内部部署文档，说明鉴权没有真正绑定。

### 8. 入驻 JS 写死 fileKey

认：入驻/资质 SPA 里有 mock 或演示的 formData，写死了密文 `fileKey`，站点根会 301 到新域，旧 host 下载口仍可能活。

打：
1. 跟新域 chunk 抄 `fileKey`。
2. 直接请求旧 host 的下载接口 `?fileKey=`。
3. 乱填时应空/错；真 key 时会出图或文件。

算成：能下载私有桶中的证件/执照图。

### 9. 分享鉴权 false 仍可下载媒体

认：云录制分享中，鉴权接口存在 `download_enable` / `view_minutes_enable` 之类字段；或者 JSON 网关根本没有 `permission/auth` 的真正校验。

打：
1. 同时打 `download-multi-record-file` 和 `sign-multi-record-file`，带上 `auth_share_id` + `resource_type`。
2. 若接口返回“参数非法”，可尝试改成 GET query 里把 `record_id` / `auth_share_id` 直接放进 URL。
3. 直接打公开 record-detail 下载口。
4. COS 无 Referer 的 403 不代表结束，带分享页 Referer 再试一次。

算成：鉴权写 false 仍能拉到真实 MP4，或能拿到纪要全文。

### 10. 密码分享回包带明文提取码

认：分享详情 JSON 一边写 `need_pwd` / `auth_level`，一边 auth 对象里直接附带明文提取码 `pass_word`，或者落地 HTML / `syncData` 里内联同一明文。

打：
1. 空提取码先打查看口，对照返回是否要求输入密码。
2. 从同一回包里抄明文码填回查看口，再看是否出现 `file_id`。
3. 直接拿 `file_id` 与提取码去打下载口，确认能拿到真文件头。

算成：可以不输入正确密码却拿到真实文件。

## 四、模板：最小可复用的验证方式

```bash
curl -s -m 12 -X POST -F "file=@${PAY};filename=${NAME};type=text/plain" \
  https://<api>/<ctx>/api/<mod>/user/uploadImage
# 200+data URL=OK；403页=blocked；401=前面漏鉴权判定要复核
```

```python
# Windows 子进程默认 GBK 解码 WAF 页会炸 → 必须显式 utf-8
cp = subprocess.run([...], capture_output=True, text=True,
                    encoding="utf-8", errors="replace")
body = cp.stdout or ""
```

```bash
# 无头验证 SVG 执行
"$EDGE" --headless=new --no-sandbox --user-data-dir=/tmp/ep_$$ --dump-dom "$URL" \
  | grep -oE 'data-xss="ok[^\"]*"|parsererror'
# 标记脚本：<script>document.documentElement.setAttribute("data-xss","ok-<ts>")</script>
```

## 五、坑：避免误判

- `--headless` 要用 `--headless=new`；对 SVG 这类页面，空 DOM 很常见，不能只看最表面的返回值。
- SVG 不要过度依赖 shell `printf`；`</script>` 这类字符很容易被转义。最好用 Python 规范写入文本再拿去测试。
- 上传 URL 可能是日期目录 + 服务器时间戳前缀，真正的目标必须以响应里的 data URL 为准，而不是本地 filename。
- 批量落盘测试时，需保留 URL 清单交给目标方清理。
- `.docm` 等文档型文件有时会返回空响应，需单独复测再下结论，不要直接把空响应当作“无漏洞”。
- 只要返回 200 不代表“漏洞成立”；必须确认能被公开访问、跨用户覆盖、被浏览器执行，或能触发真正的消费端解析。

## 六、最终判断标准

真正的上传漏洞，不是“能传一个文件”，而是看它是否能造成以下任意一种：
- 可执行：网站/容器/脚本实际执行
- 可公开读取：对象或文件可被未授权访问
- 可跨用户覆盖：覆盖他人对象/文件
- 可托管内容：任意脚本/文件被公开挂载
- 可触发客户端执行：SVG、Office 宏、脚本型 payload 在浏览器或客户端执行

只证明上传接口本身允许放文件，不等于有高危。必须继续跟到真正的利用链，才算拿到有效结论。
