# 控制缺失型审计手册（端点-权限矩阵与认证旁路）

> control-driven = **从"端点清单"出发**，逐一验证"该有的安全控制是否存在"，缺失即漏洞。
> 与 sink-driven 互补：grep 危险代码抓不到"**本应鉴权却漏了**"这类**缺失型**漏洞——本手册专治这类。
> 黑盒在线探针见 `web/playbooks/methodology/04-control-gap-hunting.md`（黑盒把本手册的白盒结论拿到线上验证）。

---

## 一、端点-权限矩阵（一切的前置测绘）

对每个对外端点建一行，这是 control-driven 的输入（等价于 sink 之于 D1）：

| 端点路径 | 方法 | 认证要求 | 权限注解/中间件 | 资源归属校验 | 备注 |
|---|---|---|---|---|---|
| /api/order/{id} | GET | 是 | 无 | ? | 待验 |
| /api/admin/* | POST | 是 | @RequireAdmin | — | 待验 |

生成方法：Grep 路由声明（`@RequestMapping/@GetMapping/router.get/app.route/...`）提取路径 → 对每个 Controller/Handler 检查类/方法级鉴权注解 → 记录。
**隐藏入口别漏**：内部 API、调试端点、遗留接口、定时任务、MQ 消费者、反序列化监听器。

## 二、认证旁路枚举（白名单豁免）

正向搜"认证代码"抓不到"**本应鉴权却被白名单豁免**"的端点。反向做：

1. Grep 认证豁免配置：`whitelist | permitAll | excludePath | anonymous | isPublic | @AllowAnonymous | skipAuth`。
2. 枚举所有被豁免的路径/端点。
3. 对每个被豁免端点判定：**是否返回/接受敏感数据？是否执行特权操作？**
4. 命中 → 候选（信息泄露 / IDOR / 未授权访问）。

## 三、资源归属（IDOR / 水平越权）与 CRUD 权限一致性

- 核心模式：对比 `findById(id)` vs `findById(userId, id)`——**仅按 id 查询、无归属约束 = 不安全模式**。
- 对每个 CRUD 操作追到 Mapper/DAO 层，检查查询是否带 `AND user_id = ?`（或等价租户约束）。
- **CRUD 一致性**：同一资源类型的 get/list/update/delete **四个动作逐一**验权——常出现"读有鉴权、写/删漏了"。
- 至少覆盖 3 类资源，才算 D3 覆盖。

## 四、Mass Assignment / 属性级越权

- 现象：框架把请求体**直接绑定到 ORM 实体/模型**，用户可塞入未授权字段。
- 探法：请求体加额外字段（`is_admin=true`、`role=admin`、`tenant_id=其他`、`balance=...`），看是否被接受落库。
- 白盒看：Model 绑定是否有字段白名单（`@JsonIgnore`/DTO 隔离/`fillable` 白名单）。

## 五、状态机与竞态（业务逻辑，D9）

- **状态机完整性**：能否跳过前置步骤（未支付即发货、未验证即改密）？状态转换是否服务端校验？
- **竞态（TOCTOU）**：余额/库存/优惠券的操作是否原子（锁/版本号/DB 约束）？并发下能否超额。
- **金额篡改**：价格/数量是否服务端重算，还是信客户端传入值。

## 六、收敛与最小伤害

- 候选链深度 = 1：一轮枚举候选、下一轮只消化，不派生新候选。
- 验证一律**最小伤害**（详规见 `web/webapp/idor/手册.md`）：默认读/列表差分，写越权"先加自己的再删自己加的"，禁止批量改删、禁止真资损。
