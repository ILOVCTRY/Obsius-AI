# 判据库总索引

## 这层是什么

`赛事专题/Writeup合集/` 下有 1027 篇 WP，合计约 2800 万字符。它们是**按比赛和题目**组织的，
读一篇只能解决一道题。这层做的事情是：把里面**换一题仍然成立**的部分抽出来，重排成**按判据索引**。

| | Writeup 合集 | 判据库 |
|---|---|---|
| 组织维度 | 比赛 → 题目 | 现象 → 判据 → 打法 |
| 一节的粒度 | 一道题 | 一类判据 |
| 换题后是否可用 | 不能 | 能 |
| 适合什么时候读 | 复盘、找同类题 | 现场卡住时 |

**和主库的分工**：主库（`web/漏洞分类/`、`binary/漏洞利用/` 等）讲**完整手法与细节**，
判据库讲**选路**——「我现在这个现象，该用主库的哪一节」。两者不重复：判据库给判据和失效条件，
主库给命令和代码。

## 怎么用

1. 先在下表找你的现象（左边一列是**你能观察到的**，不是漏洞名）
2. 跳到对应判据库的 §0 速查表
3. 按速查表跳到具体节
4. 需要完整代码时再回主库

**不要从第一篇读起**。这层是索引，不是教程。

## 按「卡在哪」路由

这一栏是现场最常用的——不是「这是什么题」，而是「我卡住了」。

| 卡点 | 去哪 |
|---|---|
| 不知道这题属于哪类 | 各篇的 §0 判据速查，按现象对号 |
| 知道类别但手法全试过不通 | 各篇的「纪律」节，通常是漏了前置条件 |
| 有执行但看不到输出 | [[web/赛事专题/判据库/rce-判据.md|rce-判据]] §6（外带三通道） |
| 有注入但 payload 不生效 | [[web/赛事专题/判据库/客户端攻击-判据.md|客户端攻击-判据]] §1.2（净化器判据） |
| 链构造出来了但打不通 | [[web/赛事专题/判据库/反序列化-判据.md|反序列化-判据]] §5（排查顺序） |
| 分解不出来 | [[crypto/赛事专题/判据库/rsa与数论-判据.md|rsa与数论-判据]] §1.1（规模判据，超了就放弃） |

## 抽象时的取舍

**保留**：换一题仍成立的判据、失效条件、版本分水岭、数值门槛。

**丢弃**：

```text
- 具体 flag 与题目名（换题即失效）
- 单题的完整 exploit 代码（主库已有同类）
- 战队风格与赛事八卦（不可迁移）
- 「某题用了某工具」这类一次性事实
```

**降级**：题目名只作为「手法例证」的括注保留，不单独成节。

## 已知边界

- **这层不替代主库**。判据告诉你去哪，主库给具体代码。
- **判据来自 2022–2026 的 CTF**，出题风格会变。看到「某判据不成立」时，先确认版本与年份。
- **未覆盖的部分**：`赛事专题/题目知识/` 下的英文长文（外部导入包）不在本次抽象范围。
- **WP 本身的质量参差**。低质量 WP 的 `lesson` 字段常有错误结论，本文只采纳能与其他 WP 互相印证的判据。
