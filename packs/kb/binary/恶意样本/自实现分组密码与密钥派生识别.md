# 自实现分组密码与密钥派生识别

通用 C2 协议侧见 [[binary/恶意样本/C2 流量与协议分析.md|C2 流量与协议分析]]（§4 按常量认算法、§6 密钥轮转），分组密码本身的安全性见 [[crypto/对称加密/分组密码、MAC 与 AEAD 攻击.md|分组密码与 AEAD]]。

## 判据速查

| 现象 | 动作 | 去哪节 |
|---|---|---|
| 只读段有 256 字节表，前 4 字节 `d6 90 e9 fe` | 按国密 SM4 解，先核配套 FK/CK | §1 |
| 表像 SM4，但套国标实现解出来是乱码 | 试魔改的两个正交变量 | §2 |
| 连接首包极短，之后全是等长密文块，且每次连接首包都不同 | seed → `srand`/`rand` 派生会话密钥 | §3 |
| 输出要求约束了密钥的字符集与长度，而解出的密钥每次连接都变 | 先判硬编码还是派生，再定该取哪个值 | §4 |
| 32 轮、每轮 `rol`/`ror` + `xor` 的 ARX 结构，没有 S 盒 | 按轮数与移位量比对已知族 | §1 |
| 只读段有一段常量与标准族常量「位置、长度相同但值不同」 | 别当系统参数排除，当密钥试 | §4 |

## 适用条件

- 目标是样本二进制（ELF/PE 均可），且通信载荷是等长块、块长 8 或 16 字节、末尾有填充 —— 块密码形态。
- 已能抓到成对的「命令 / 回包」密文，可用于逐条校验。
- 手上有一条已知或可猜的短明文（`id`、`pwd`、版本号），用来判定解出的第一块是否可打印。

不满足第三条时先别动密码：先按 C2 手册 §1 把流量统计和会话结构理清，找到最短的那条载荷再回来。

## 1. 按常量表认分组密码族

**判据**：只读段出现 256 字节查表，或其附近有成组的 32 位立即数。

**动作**：按表首项定位族，再核对配套常量。

| 族 | 表的特征 | 配套常量 | 轮结构 |
|---|---|---|---|
| AES | 表首 `63 7c 77 7b`，`0x63` 反复出现 | 无（或 Rcon `01 02 04 08…`） | 10/12/14 轮，MixColumns 用 xtime |
| SM4 | 表首 `d6 90 e9 fe`，256 字节 | 4 个 32 位 FK：`a3b1bac6` `56aa3350` `677d9197` `b27022dc`；32 个 CK 从 `0x00070e15` 起 | 32 轮；密钥扩展 `t ^ rol13 ^ ror9`，加密 `t ^ rol2 ^ rol10 ^ ror14 ^ ror8` |
| TEA / XTEA | 无表 | `0x9E3779B9` 或其魔改值 | `<<4` 与 `>>5` 紧邻出现 |
| RC4 | 256 字节但按 `S[i]=i` 顺序初始化 | 无 | 逐字节，无 padding |

**不成立**：没有 256 字节表、也没有 `rol`/`ror` + `xor` 的 32 轮循环 → 不是分组密码，按流密码/哈希/编码链重新判（见 C2 手册 §4 的结构判据）。

## 2. 魔改 SM4：两处最常见的改法

**判据**：S 盒与 FK/CK 都在，但直接套国标 SM4 解出乱码，且密钥看起来是对的（同一密钥在别处能解出东西）。

**动作**：只试两个正交变量，用「解出的第一个块是否可打印」判定，不要一上来重写整个算法。

1. **T 变换里 S 盒取字节的顺序**。国标是高位在前：`out = S[b0]<<24 | S[b1]<<16 | S[b2]<<8 | S[b3]`。魔改常整体反转成 `out = S[b0] | S[b1]<<8 | S[b2]<<16 | S[b3]<<24`（等价于把 S 盒表本身按 4 字节一组倒序）。
2. **FK / CK 的读法**。国标按大端 32 位常量；抄代码时常被写成普通小端 32 位整数直接 `memcpy`，效果是把每个常量的 4 个字节倒过来。

两个变量组合共四种，逐个试。密钥扩展与加密轮函数的移位组合（`13/9` 与 `2/10/14/8`）一般不改，可以当作「确实是 SM4 系」的锚点。

**不成立**：四种组合都解不出可打印文本 → 密钥错了，不是算法魔改的问题，转 §3 / §4 重新确定密钥。

## 3. seed → `srand`/`rand` 派生会话密钥

**判据**：连接建立后服务端先下发很短的一段（个位数到十几字节），客户端随后才开始发等长密文块；重新建立连接时这一小段又变了。

**动作**：把首段按小端读成 32 位 seed，用**与样本同 ABI 的 libc** 的 `srand(seed)` 后连续取 `rand()`，每个结果按小端 4 字节拼接，直到凑满分组密钥长度（16 字节取 4 次，32 字节取 8 次）。

```python
import ctypes, struct
libc = ctypes.CDLL("libc.so.6")
libc.srand(ctypes.c_uint(seed))
key = b''.join(struct.pack('<I', libc.rand()) for _ in range(4))   # 16 字节
```

**必须用 glibc**：`rand()` 是 TYPE_3 加法反馈生成器，不同 libc（musl、BSD）输出完全不同，用错 libc 派生出来的密钥永远解不通。

**不成立**：解出乱码 → 依次改 seed 的字节序（大端读）、改取值形式（`rand() % 256` 逐字节、`rand() % 26` 取字母）、换随机源（`random()`、`drand48()`）。全部失败说明密钥不来自随机数，回到 §4 找静态常量。

## 4. 要求给「样本通信密钥」时，先判静态还是派生

**判据**：输出要求给了密钥的字符集约束（`hex` 小写、定长字符串）与长度量级，而解出来的密钥每条连接都不一样。

**动作**：

1. 把样本对同一 C2 端口的**全部连接**的首包取出来横向比较。
2. **每条都不同** → 密钥是会话派生，要的就不可能是派生结果，必然是二进制内的静态常量。此时回只读段找长度正好等于密钥长度的那段：字节表、成组立即数、或配置结构里的字符串。
3. **所有连接都一样** → 密钥确实是静态值，直接用。

**不成立**：静态常量段解出来仍不可打印，且派生路径也走不通 → 密钥可能来自外部输入（配置文件、服务端下发的完整密钥而非 seed），回流量侧找完整密钥的下发位置。

## 复现步骤（端到端）

1. `strings` / 只读段 dump 出 256 字节表与成组立即数 → §1 定位族。
2. 取**最短**的一条双向载荷（命令 4~8 字节那种）作校验对，避免拿大包试错。
3. 密钥候选按 §3（派生）→ §4（静态常量）顺序各试一遍，每试一次只看第一个块是否可打印。
4. 第一个块通了，用 PKCS#7 风格填充规则去尾（末字节值即填充长度），再验第二条。
5. **回环校验**：把解出的明文重新填充、用同一密钥加密，与抓包里的密文逐字节比对。相等才算密钥与算法都对 —— 这一步能挡住「解出半句可读文本其实是巧合」。

## 常见坑

- **把「像系统参数的常量」当系统参数排除掉**。只读段里与标准族 FK 位置相同、长度相同、但值不同的常量，往往是作者故意魔改后当密钥用的，判据只有「当密钥去解，第一块可打印」。
- **只解一个方向**。块密码 ECB 无状态，双向可分别解；但流密码状态在双向间共享，只取单向从第二段起全乱。
- **用错 libc 派生随机数**。同一 seed 在不同 libc 下 `rand()` 输出完全不同，必须与样本同 ABI（Linux ELF 基本就是 glibc）。
- **拿派生出来的会话密钥当「样本密钥」交差**。要求若约束了定长 hex，且样本每次连接首包都不同，答案必然是静态常量，不是某一次的派生值。
- **大包先试**。大包里常是目录列表、文件内容这类长明文，填充与分块边界更容易错位，先用短包把算法验通。
