# 高级利用手法判据

## 0. 判据速查

| 现象 | 原语 | 第一动作 |
|---|---|---|
| 校验用 `int32`，使用处转 `int16`/`char` | 截断绕过 | 找「过校验后变小/变负」的值（65534→−2） |
| 有符号比较配无符号长度 | 负数坐标 → 负索引 | 提交负坐标，看是否写进前一个对象 |
| 索引 = `y*width+x` 用 int32 | 乘法溢出成负数 | 令乘积回绕，`index < w*h` 恒成立 |
| `abs(hash) % size` | `abs(INT_MIN)` 仍为负 | 构造哈希 = `0x80000000`，索引 −2 |
| 循环计数器是 8 位 | 缓冲区 64 → 写 65 字节 | 溢出 1 字节改相邻 size 字段 |
| 两个变量共享栈槽 | 低位变量进位污染高位 | 反汇编找不同宽度访问同一 `[rsp+N]` |
| 校验后才赋值给全局索引 | 单函数内 TOCTOU | 越界索引留在全局，后续 edit 直接用 |
| 用户态 shadow stack 无边界检查 | 指针溢出 | 递归到 `shadow_stack_ptr` 越过数组进入可控缓冲 |
| 程序把栈帧当数值排序 | 排序即写原语 | 选 IEEE-754 位型等于目标（canary/ret）的浮点 |
| free 后不清 size/指针 | UAF + 陈旧大小 | `show`/`edit` 仍按旧大小访问 |
| tcache 首项 `fd = NULL ^ (addr>>12)` | `fd<<12` 得堆基址 | 免爆破 |
| `mmap(w*h)` 却 `munmap(compressed)` | over-unmap | 让新线程栈落进空洞，旧指针变写栈 |
| GC 跟随空引用到地址 0 | 假对象 + 紧凑搬移错位 | 连锁破坏相邻对象头 |
| 只有任意读 | 读也能当写 | `memcpy(dst, user_addr, user_len)` 溢出；或从 libc 读字节拼 ROP |
| 只有单比特翻转 | 累积改指令 | 优先改栈展开、分支、`mprotect` 参数 |
| 只有 4 字节 shellcode 但循环 4096 次 | callee-saved 寄存器跨轮保留 | 逐轮累积状态 + 计时侧信道 |
| seccomp 只允许 `openat/mmap/write` | ORW 变体 | 用 `xchg rdi, rax` 接 `open` 返回值，别硬编码 fd |
| BPF 反汇编出现 `???` | X 寄存器寻址（`0x1d`） | 手工读字节码，条件可能是 `rax == rdx` |
| 字节码先校验后执行 | 自修改绕过 | 用前面的指令把 `0f a0` 改成 `0f 05` |
| JIT 跳转偏移用 `uint16` | 超 64KB 后跳进指令中间 | `jmp $+3` 串 2 字节碎片做 JIT spray |
| 无 libc 泄漏 | 多 `fgets` 造 stdout | 每次写 7 字节，追加的 `\0` 落在本就为 0 的高位 |

## 1. 整数与类型

### 1.1 截断

**判据**：校验时用宽类型，使用处用窄类型。典型 `int32` 校验 `>= 0`，转 `int16_t` 后 `65534 → −2`、`65535 → −1`，于是 `array[-2]` 读到数组前 16 字节（常是 GOT/PIE 指针）。

**变体**：`signed char` 存 size、`unsigned char` 使用时，`-112 → 144`，配 127 字节缓冲 = 17 字节堆溢出。这是 C 里 `char` 隐式提升，不是位截断。

**除法先于乘法**：`x / 1000 * 1000` 的截断误差随输入量级放大，校验与使用各算一次就会出现「校验通过但实际值更大」。

### 1.2 符号混淆

- **负数数量**：`scanf("%d")` 收 `-1`，`quantity * price = -1e9`，`balance >= total_cost` 直接过。
- **负坐标**：`if (x < width)` 中 `x` 有符号、`width` 无符号 → `x = -1` 被提升成巨大无符号数，反而「小于」width，写进数组前方。
- **手工符号扩展**：`n >= 0x80000000 ? n - 0x100000000 : n` 是红旗。`[0x80000000, 0xFFFFFFFF]` 全变负数，后续当索引用不复查边界 → 逐字节泄漏。

### 1.3 乘法溢出

`index = y*width + x`（int32）在 `y` 很大时回绕成负数；`index < width*height` 用有符号比较，负数恒通过。于是「设置一个像素」变成「向堆前方向后写」。

**放大**：RGB 每像素 3 字节 → 天然的 24 位任意写原语，改掉另一个画布对象的 data 指针后，像素读写升级为任意读写。

## 2. 栈

### 2.1 单字节溢出

8 位循环计数器在缓冲区正好 64 字节时写 65 字节，多出的 1 字节改相邻 size。此后每轮按新 size 多读一点，形成**渐进泄漏**：一次 1 字节溢出可以滚成完整链。

**canary 保护**：溢出必须跨过 canary 时，先确认 canary 是否已知（fork 型服务 canary 固定、或先泄漏）。若 `valid` 标志在 buffer 与 canary 之间，只需覆到标志位即可。

**变量重叠**：`word` 在 `rsp+0x48`、`byte` 在 `rsp+0x49` 时，word 的高字节就是那个 byte。对它做加法进位即可改相邻变量，反汇编里表现为不同宽度访问重叠偏移。

### 2.2 用户态 shadow stack

实现方式是每次调用把返回地址同时压硬件栈和 `.bss` 的 `shadow_stack[]`，返回时比对。**漏洞点在 `shadow_stack_ptr` 只增不查界**：递归足够多次让它溢出数组，落进相邻的可控缓冲（如 username），把目标返回地址写进去，校验就通过了。

**判据**：有 `shadow_stack`/`canary` 之类自研保护，且指针/索引没有上界检查——保护本身成了写原语。

### 2.3 排序即写原语

程序读入 `double` 数组、`qsort` 后打印，而 canary 与返回地址就在同一帧里被重新解释成 double。**不需要写原语**：挑 IEEE-754 位型恰好等于目标（canary、ret、saved rbp）的浮点数，让排序把它们搬到对应槽位。

## 3. 堆与分配器

| 场景 | 要点 |
|---|---|
| free 后不清 size | `show`/`edit` 用陈旧大小访问已释放块 → UAF；先看 delete 是否只置空指针 |
| 菜单式 `strdup`/`free` | 退出路径 free 但「确定吗？」选否返回菜单，指针悬空；再次 `strdup` 复用同尺寸块，用无校验字段覆盖有校验字段 |
| tcache 首项 | `fd = NULL ^ (addr>>12)`，`fd << 12` 直接得堆区地址，无需爆破 |
| 伪造 chunk size 进 unsorted bin | size 改成 `>= 0x420`；`chunk_at_offset(p,size)->size` 必须带 `PREV_INUSE` 且合理，提前在该边界放好合法元数据 |
| safe-linking 多轮投毒 | 变换是 XOR → 建 GF(2) 线性方程组，逐 seed 施加，顺序无关 |
| `mmap`/`munmap` 尺寸不一致 | `mmap(w*h)` 却 `munmap(compressed_len)`，over-unmap 抹掉相邻映射；新线程栈填进空洞后旧指针就是写栈 |
| GC 跟随空引用 | `ref=0` 指向堆起始的零区，形成假对象；紧凑阶段 `memmove` 先搬假对象，错位破坏后续对象头，小 bug 放大成 OOB |
| Go 值拷贝 slice | 结构体按值拷贝只复制 `(ptr,len,cap)`，底层数组共享；构造 `cap > len` 后，被调方 `append` 原地写回调用方内存 |
| io_uring | UAF + 类型混淆控制 SQE 缓冲；内核信任用户态共享内存里的 SQE，可绕过 syscall 过滤 |
| 分配/释放顺序 | `strdup` 内部是 `malloc`，同尺寸复用；菜单顺序决定谁覆盖谁 |

**FSOP 链**：伪造 `FILE`（`_flags`、`_IO_write_base/_ptr`、`vtable`）+ `_IO_wide_data` + 宽 vtable，把 `_IO_list_all` 指过去；`_IO_WDOALLOCATE` 触发时 `rdx = _wide_data->_IO_buf_base`，配合 `mov rsp, rdx` 完成栈迁移。

## 4. 信息泄漏

**顺序**：GOT → libc → 栈（`environ`）→ canary。

| 无泄漏时的办法 | 做法 |
|---|---|
| 无格式化字符串、无 UAF、无 unsorted | 用 ROP 在 BSS 上用多次 `fgets` 拼出假 `stdout`，再 `fflush` 泄漏 GOT。`fgets` 追加的 `\0` 落在 libc 地址本就为 0 的高字节上，所以 7 字节一组正好 |
| 只有读原语 | 从 libc 各段读字节「导入」到栈上——libc 里有海量字节模式，读特定偏移即得想要的立即数 |
| 只有 CRC 计算 | 单字节 CRC 是双射，预计算 256 个值做反查表；指针溢出控制输入地址 → 任意读 |
| 只有 4 字节 shellcode | 循环 4096 次放大量级差异，`add r12,[rsp]` 累积栈值，靠计时读出 |
| 只有 1 字节溢出 | 每轮改 size 多读一点，渐进泄漏 |
| 逐字符校验 | 每对 1 个字符多耗 100–250ms，多次采样取均值 |

**`environ` 用法**：`libc.sym['environ']` 指向栈上的环境指针数组，从它到 `main` 返回地址的偏移固定（如 `−0x140`），拿到它就有栈地址。

## 5. 控制流劫持

| 目标 | 前提 | 要点 |
|---|---|---|
| GOT | 有任意读写 | 选「首参可控且覆写后还会被调用」的项：`strtoll`/`atoi`/`puts`/`printf` |
| `.fini_array` | 段可写（RWX） | 比 libc 路线更短，直接指向 shellcode |
| `atexit` | 任意读 + 任意写 | PTR_MANGLE = `xor secret` + `rol 0x11`；初始表第一项恒为 `_dl_fini`，用它反推 secret，再伪造任意项 |
| TLS dtor | glibc 2.34+（hook 已移除） | `__call_tls_dtors` 遍历链表调 `PTR_DEMANGLE(func)(obj)`；编码 `rol(target ^ guard, 0x11)`，guard 在 TLS 固定偏移 |
| SEH（Windows） | SafeSEH 关闭 | 用 `pushad` 一次性把 8 个寄存器压成 stdcall 调用帧，省掉稀缺的 `mov [esp+N],reg` |
| CFG（Windows） | 有间接调用点 | CFG 只校验「是不是合法函数入口」，`system()` 本身合法 → 覆写函数指针即可 |
| 派发表 | `mov rax,[base+rdx*8+C]` | 只要索引不受限，二进制里任何 8 字节对齐的 qword 都能当函数指针用 |
| 单比特翻转 | 每轮翻一位 | 优先改栈展开、分支指令、`mprotect` 参数；回到函数入口可无限翻 |

**mprotect/RWX 路线**：先 `mprotect(page, 0x1000, 7)`，再写入 shellcode，最后跳过去。适合 `.fini_array` 在 RWX 段、或 JIT 缓冲已经可执行的情况。

## 6. 沙箱与 seccomp

### 6.1 可用系统调用受限

```text
openat(AT_FDCWD=-100, "/flag", O_RDONLY=0)   # 257
mmap(NULL, 4096, PROT_READ=1, MAP_PRIVATE=2, fd, 0)  # 9
write(1, addr, 4096)                          # 1
```

**容器里 fd 不是 3**：Docker 中 `open` 常返回 5。用 `xchg rdi, rax; cld; ret` 把 `open` 的真实返回值传给 `read`，不要硬编码。`pop rdx; xor eax, eax; ret` 一箭双雕：既设长度又把 `rax` 清成 0（`SYS_read`）。

### 6.2 BPF 过滤器的盲区

`0x1d` = `BPF_JMP | BPF_JEQ | BPF_X`，比较 `A == X`（X 寄存器）。`seccomp-tools` 老版本不认这种寻址，反汇编显示 `???` 或直接跳过 → 看起来比实际严格。**必须手工按 `struct sock_filter {u16 code; u8 jt; u8 jf; u32 k;}` 读字节码**，或者实测。

若实际规则是 `rax == rdx` 才放行，那就把 `rdx` 也设成目标系统调用号（`execve = 59`），两个条件同时满足。

### 6.3 字节码/JIT 沙箱

- **静态校验 + 运行时自修改**：校验器只看初始字节，用前面的 `push` 把 `0f a0` 改成 `0f 05`，`push fs` 就变成 `syscall`。
- **JIT 偏移截断**：`if` 生成 `jz` 时偏移按 `(uint16_t)` 算，代码超 64KB 后跳到未来指令中间。用 `jmp $+3` 把 2 字节碎片串起来，形成 JIT spray。
- **单比特翻转**：见上表。

## 7. 特殊架构与载体

| 环境 | 关键差异 |
|---|---|
| m68k | 系统调用号在 `d0`，参数 `d1–d3`，`trap #0`；只有 14 字节 shellcode 时，第一段跳回程序自身的 `read()` 复用已 mmap 的 RWX 区 |
| DOS COM | 16 位实模式，代码段可写；`int 0x21` 的 `ah=0x3d/0x3f/0x09` 分别开/读/打印 |
| ARM/Thumb | `qemu-arm` + `gdb-multiarch`；静态链接时 gadget 全在自身 |
| ARM64 | `pop x0` 类 gadget 稀缺；找「返回值是指向常量字符串的指针」的函数：`getusershell()` 返回 `"/bin/sh"` 且落在 `x0`，两调用链 `getusershell → system` 即胜 |
| Chip-8 模拟器 | guest 内存 4KB 但 `I` 是 16 位且 `LD [I],Vx` 不查界 → 越界读写打到宿主栈，先泄 libc 再 one-gadget |
| 自制 VM | STORE 只查 `offset <= 0xfff`（有符号 `jle`）不查下界 → 负偏移任意写；NEWBUF/SLICE 共享 slab，GC 释放 slice 即释放活着的父 buffer |
| DNS 解析 | 压缩指针 `0xC0\|off` 不跟踪展开后总长 → 小包放大成大名字，溢出 1024 栈缓冲；多 question 把 ROP 链拆进各条，规避 label 长度限制 |
| ELF 签名 | 只哈希 section（`SHF_ALLOC`），不覆盖 program header；追加 shellcode 后改 PH 让它被映射，签名依旧有效 |
| 文件描述符 | `memfd_create`/`open` 少了 `MFD_CLOEXEC`/`O_CLOEXEC`，`system()` 起的子进程继承该 fd，`/proc/self/fd/N` 直接读；过滤用 `p'r'oc` 拆引号绕过 |
| 路径清洗 | 「删掉禁用字符并跳过下一个」的清洗器可用 `....//` 绕过 |
| UTF-8 大小写 | `g_utf8_strup()` 会让某些字符 2 字节变 4 字节（如 U+0587），按输入长度分配就溢出 |
| Game of Life | 用静物（still-life）围住 shellcode 行，15 轮迭代后仍可执行；更省事的做法是先拿执行权再 `read` 真 shellcode |
| 神经网络输出当索引 | 把偏置数组里的 double 位型写成 `print_flag` 地址，让网络输出 19 越过合法范围 |
| 唯一字节数限制 | `seen[256]` 计数器在栈上，第一轮用 push 喷洒污染它，第二轮跳过 `memset` 后计数器已回绕 |

## 8. 纪律

- **先定原语，再拼链**：整数截断 / 越界索引 / UAF / 单比特 / 只读 / 只写，每类的下一步完全不同。看错类型会浪费大量时间。
- 校验与使用之间只要类型或宽度变了，就有绕过空间；把「校验处的值」和「使用处的值」都算出来对比。
- 有符号/无符号混用是 CTF 里最高频的漏洞，尤其出现在坐标、长度、数量、索引四处。
- 「保护机制」本身常是新漏洞：用户态 shadow stack、自定义 canary、唯一字节计数器、字节码校验器都栽在没做边界检查。
- 没有写原语不等于不能写：排序、`memcpy` 溢出、从 libc 读字节、CRC 反查、单比特累积，都是写原语的替代品。
- 泄漏顺序固定为 GOT → libc → 栈 → canary；拿不到 libc 泄漏就考虑 BSS 上造 `stdout` 或从 `ld.so` 摸 `_dl_fini`。
- glibc 2.34+ 没有 `__free_hook`/`__malloc_hook`，优先 FSOP（House of Apple 2）、TLS dtor、`atexit` 三条出口。
- seccomp 题先手工读 BPF 字节码，别信反汇编器的 `???`；容器里 fd 号不固定，用 `xchg rdi, rax` 接返回值。
- 架构差异只影响最后一步：m68k/DOS/ARM64 的 syscall 约定与 gadget 生态不同，但整数、UAF、越界的分析流程完全一致。
