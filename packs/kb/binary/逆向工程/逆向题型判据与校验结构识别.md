# 逆向题型判据与校验结构识别

## 0. 判据速查

| 现象 | 校验结构 | 解法 |
|---|---|---|
| 改一个输入字节，只变一个输出字节 | 无扩散（逐字节独立） | 每字节 256 次试出，不需要密钥 |
| 输出 N 行哈希，改末字节只变末行 | 前缀哈希独立 | 逐位爆破，`N × |charset|` 次执行 |
| 大矩阵 + 系数 + 期望 64 位值 | 线性组合，解需落在可打印区间 | 格 CVP + LLL（不是普通代数） |
| `.rodata` 里有 N² 字节矩阵，出现 `0x1b` | GF(2^8) 线性系统 | GF 高斯消元（加法是 XOR） |
| 上百个 `f\d+` 函数互相调用 | 决策树混淆 | 脚本抽 CMP 常量 + 约束传播 |
| 单行 Python / 海量分号 / `:=` 链 | 布尔电路 | Z3 建模 |
| 固定窗口 popcount 数组 | 差分递推 | 只爆破首窗，其余确定 |
| `psadbw` on xmm | 绝对差之和 | 每 2 字节独立爆破（可打印约束） |
| 输出是逐层 sigmoid | 可逆网络 | 逐层反演 |
| 多个互素模数 + 大整数切片 | CRT | 取最小代表元，别爆破 |
| 一个只增不减的寄存器参与变换 | 路径相关 | 全模拟 + 逐字节爆破 |
| 二进制渲染后比像素 | 期望位图就在 `.rdata` | 直接提取 + OCR |
| 工具全部崩但能运行 | 节头损坏 | 只读 program header，手工解析 |
| GDB 下行为与正常运行不同 | suid + 被改的库 | `ldd` 查非常规路径，diff strings |
| 看不到 import，只有 `dlopen`/`dlsym` | 哈希解析符号 | `LD_PRELOAD` 钩加解密函数抓密钥 |
| `mmap` 带 PROT_EXEC 后跳过去 | 数据段里的 shellcode | 抽出来按 3 字节滚动 XOR 试解 |
| 只给 pass/fail 且数学味重 | 分类器而非校验器 | 逆向数学，自己算全部点画图 |

## 1. 先做减法：能不逆就不逆

### 1.1 数据段直接取

未 strip 时先看符号：`readelf -s binary | grep -E "EMBEDDED|ENCRYPTED|LICENSE"`。

- 嵌 ZIP：搜 `PK\x03\x04`，按符号表给的长度切出来 `unzip`。
- XOR 密文：明文（license 文件内容）已知，`flag = enc ^ license` 直接出。
- 追加在节后的数据：搜魔数（如 `\xDE\xAD\xBE\xEF\xCA\xFE\xBA\xBE`），后面按单字节 XOR 解。

**判据**：符号名自解释、有 `memcmp(user, embedded, n)`、有 `ENCRYPTED_*` → 全程不用执行程序，日期校验也一并跳过。

### 1.2 渲染比对 → 提取期望位图

二进制把输入渲染成图再比像素时，**期望像素就是 flag 的图**。

```python
blob = np.frombuffer(data[0xC3620:0xC3620 + 0x15F90], dtype=np.uint8)  # 450*50*4 BGRA
img = (blob ^ 0xAA).reshape(50, 450, 4)
Image.fromarray(img[:, :, 0], "L").save("target.png")
# tesseract target.png stdout -c tessedit_char_whitelist=abc...XYZ0123456789{}_
```

尺寸线索：`450*50*4 = 0x15F90`，从比对代码附近的 `.rdata` 大块反推。OCR 一定要给字符白名单，否则 `{}`/`_` 会丢。

### 1.3 数学分类器 ≠ 校验器

输入是一堆坐标、输出 pass/fail、点数能整除（`2600 = 130×20`）→ 这是把二维点分类后拼 ASCII art。

```python
def newton_converges_to_one(px, py, target=12):
    x, y, cnt = px, py, 0
    for _ in range(50):
        fr, fi = x**3 - 3*x*y*y - 1, 3*x*x*y - y**3
        jr, ji = 3*(x*x - y*y), 6*x*y
        det = jr*jr + ji*ji
        if det < 1e-9: break
        x -= (fr*jr + fi*ji)/det; y -= (fi*jr - fr*ji)/det
        cnt += 1
        if abs(x-1) < 1e-6 and abs(y) < 1e-6: break
    return cnt == target
```

要点：flag 在**分类结果的图案**里，不在程序输出里。自己重算所有点，按 `WIDTH` 折行画 `#`/`.`。

### 1.4 反分析绕行

| 手法 | 识别 | 处理 |
|---|---|---|
| 节头损坏 | `readelf -S` 崩，`readelf -l` 正常，程序能跑 | ELF 头偏移 40（`e_shoff`）置 0：`printf '\0'*8 \| dd of=b bs=1 seek=40 conv=notrunc` |
| fork+pipe 死分支 | `strace` 见 fork/pipe/read，`cmp [ebp-0xc],1` 恒假 | 补丁常量：`83 7d f4 01` → `83 7d f4 00` |
| 时间锁 | 比一个大整数常量，落在 1.35e9（2012）/1.5e9（2017） | `faketime "2012-12-21"` 或改系统时钟 |
| 单字节 XOR 打包 | `binwalk`/`file` 都认不出 | 扫 256 个 key 后跑 `file`，找 `ELF`/`PK`/`MZ`/ROM 名 |
| ptrace 反调 | 调试器起不来 | NOP 掉调用（5 字节 `0x90`），再 `strace -e ioctl` |
| 混淆库 | GDB 下密码对，正常运行错 | `ldd` 查非常规路径 → `strings \| diff` → 反汇编被改函数 |

**suid 关键点**：调试器会丢 suid，被改过的 libc 可用 `getuid`/`geteuid` 判断「是否在被调试」，从而换掉期望值。所以「GDB 里对、正常跑错」几乎必然是被改库。

### 1.5 LD_PRELOAD 抓密钥

不要逆哈希解析表。让程序自己解析，然后钩它最终调用的加解密函数。

```c
int EVP_CipherInit_ex(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *t, ENGINE *e,
                      const unsigned char *key, const unsigned char *iv) {
    if (key) { FILE *f = fopen("/tmp/aes_key.bin","wb"); fwrite(key,1,32,f); fclose(f); }
    return ((typeof(EVP_CipherInit_ex)*)dlsym(RTLD_NEXT,"EVP_CipherInit_ex"))(ctx,t,e,key,iv);
}
```

```bash
gcc -shared -fPIC -o hook.so hook.c -ldl
docker run --rm -v $(pwd):/work -w /work ubuntu:22.04 bash -c "LD_PRELOAD=./hook.so ./ransom; xxd /tmp/aes_key.bin"
```

**无 import 的识别**：`readelf -d` 只剩 `dlopen`/`dlsym`，`strings` 没有 API 名，反汇编是「算哈希 → 间接调用」循环。常见哈希：DJB2（`5381`）、FNV（`0xcbf29ce484222325`）、SipHash（两个 64 位种子）、Windows 系 ROR13（`h = (h>>13)|(h<<19); h += c`）。密钥确定，跑一次就能复用。

**安全**：勒索样本只在容器/VM 里跑，挂载副本。

## 2. 按校验结构选解法

### 2.1 逐字节独立（无扩散）

判据：改第 i 个输入字节，只有第 i 个输出字节变。每位置试 256 个值即可，不需要密钥。这类「分组密码」实际是查表，扩散为零。

### 2.2 前缀哈希独立

输出 N 行、每行是前 i 字节的哈希 → 第 i 个字符只由 `hashes[i]` 决定。

```python
for pos in range(1, len(target)):
    for ch in charset:
        if run(known + ch + pad)[pos] == target[pos]:
            known += ch; break
```

与「逐字节分组密码」同构：把不可分的哈希拆成 N 个独立子问题。

### 2.3 线性系统（三种域，别混）

**整数 + 范围约束 → 格 CVP/LLL**。判据：分组字符乘系数矩阵比对 64 位常量，解必须落在 32–126。

```python
mid, scale = 63, 1000                 # scale 把「接近 mid」变成短向量
# 格基：[系数矩阵 | I*scale]，目标向量先减去 mid 偏移
L = M.LLL(); closest = L * L.solve_left(target_vec)
sol = [closest[n + j] // scale + mid for j in range(n)]
```

**GF(2^8) → GF 高斯消元**。加法是 XOR，乘法走 `0x1b` 归约，除法用 `gf_inv` 暴力（256 个元素足够）。

```python
def gf_mul(a, b):
    p = 0
    for _ in range(8):
        if b & 1: p ^= a
        hi = a & 0x80; a = ((a << 1) & 0xff) ^ (0x1b if hi else 0); b >>= 1
    return p
# 消元：行缩放用 gf_mul(v, gf_inv(pivot))，行相减用 XOR
```

**模 2^32 线性 → 同余高斯消元**（`Matrix(coefficients) % 2**32`）。注意模数非素，主元可能不可逆，需要换主元或改用 CRT 分解到 2^k。

### 2.4 布尔电路 → Z3

单行 Python 的 `:=` 链只是变量赋值，按分号切开逐句翻译；混淆 XOR `(a | b) & ~(a & b)` 就是 `a ^ b`；输入被当成一个大整数时用 `BitVec('ari', 8*n)`，取位用 `LShR(ari, shift)`，最后断言终值 `== 0`。

**布尔门网络**（license / 电路图）：每个门一条约束，所有门输出 True，125 变量 250 门毫秒级。`model_completion=True` 必须加。

### 2.5 差分递推（滑窗 popcount）

```text
popcount(w[i+1]) - popcount(w[i]) = bit[i+16] - bit[i]
⇒ bit[i+16] = bit[i] + (d[i+1] - d[i])
```

只有首 16 位自由（受 `d[0]` 约束），其余全部确定。枚举 `0x10000` 个首窗、过滤 popcount、逐个递推，新位不在 `{0,1}` 就丢弃。总位数 = `len(d) + 15`。

### 2.6 绝对差之和（psadbw）

`psadbw xmm0, xmm1` 对 8 组字节求 `Σ|x[i]-k[i]|`，结果是和式方程，非线性但有界：可打印 ASCII 下每组 2 字节只有 `95² ≈ 9000` 种，直接爆破。多解时用 flag 前缀/词形/后续轮次消歧。

### 2.7 可逆网络（DNN）

`sigmoid_inv(x) = -log(1/x - 1)`，逐层「反激活 → 减 bias → 乘权重逆矩阵」。**别忘了输入的预处理**：若输入是 `1.0/char`，最后要再取倒数。权重矩阵必须是方阵才可逆，看到 N×N 就是给你反演的。

### 2.8 CRT + 查表

五个互素模数把 key 唯一确定在乘积（约 4.7e19）模下，**取最小代表元**，不要爆破（否则会撞出上万个同样合法但难看的 key）。

```text
key mod 27644437 == 213 ; key mod 10459 == 229 ; key mod 1489 == 25
key mod 1046527 == 83   ; key mod 16127 == 135
```

第二段看着复杂，其实是两个固定索引函数读同一张 10000 字节表：`idx = 100*(10*d0+d1) + 10*dm+dm+1`，第二轮把两项各自平方 `% 97`。表 dump 一次，两轮都退化成数组读。

### 2.9 混淆控制流

**决策树**：几百个 `f315732804` 式函数，每个算一个多项式再比常量。用 Ghidra headless 批量抽 CMP 立即数，再从已知输出（`http://HTB{`）反向传播固定位置，剩余自由变量由根方程锁定，最后靠英文词形消歧。

**析构函数**：`main` 看起来空 → 查 `__cxa_atexit` 注册和 `.fini_array`，验证常在全局对象析构里（含 4 字节块正则 + 累加和模校验）。

**ROP 链混淆**：找 `mov esp, eax; ret` 栈迁移，链存在 `magic_buf`（0x080b0000，0x40000 字节）。逐 4 字节读返回地址、`x/3i` 反汇编，剔除重复的展开循环与 `ret imm16` 跳块，还原成算法：长度检查 → 字符运算 → MD5 → 前缀比对 → 用 MD5 当 keystream XOR。中间量（如字符和）可爆破。

**线程竞态 + 符号扩展**：先选通过 `skill_id <= 4` 的技能，睡眠期间切到 `skill_id=5`（damage=`0xFFFFFFFF`），醒来读到的伤害经 `cdqe` 符号扩展成 `-1`，`boss_hp(0x7FFF...) -= (-1)` 溢出成负数 → 秒杀。

## 3. VM 与模拟器

### 3.1 不要重写解释器，先记录轨迹

自修改派发（LCG 打乱 opcode 表、rotor）专门用来惩罚「老实重写」。挂条件断点在派发处，dump `(opcode, stack)`，然后对比两个只差一位的输入：

```python
# trace("abcd") vs trace("dcba") → 相同的 mul/mod 序列暴露真实算法
def calc_hash(x, mod):
    for _ in range(8): x = x * x % mod
    return x * x_orig % mod
```

轨迹对给定输入是确定的，diff 把 VM 开销全部消掉。拿到每组模数与期望哈希后爆破 4 字符排列。

### 3.2 隐藏 opcode

CHIP-8 类模拟器要遍历**所有**派发分支，非标准 opcode（如 `FxFF`）可能直接触发 AES-256-CBC。密钥不必逆：钩 `EVP_DecryptInit_ex` 打印 32 字节。

### 3.3 多线程 channel VM

16 线程 + futex channel + 30 字符 flag。按「谁读谁写哪个 channel」定角色（输入 / 变换 / 校验 / 输出），在特定 opcode 上打断点取常量。两个坑：

- **逻辑可能反着写**：合法返回 0，被拦返回非 0；
- **futex 语义副作用**：对未持有的 mutex `unlock_pi` 返回 `EPERM=1`，这个返回值可能参与运算。

用 BFS 在状态机上搜索（已知 `dice{` 前后缀），从目标态回溯。

### 3.4 顺序 key-chain

每块输出 key 喂给下一块 → 必须按序解，但**块内可并行**。变换是 1000+ 轮 xorshift（`13/17/5`）+ `*0x2545f491`，故意不可逆，只能爆破 2^24。

```c
#pragma omp parallel for
for (int v = 0; v < 0x1000000; v++)
    if ((process(input_val ^ old_key) ^ (input_val ^ old_key)) == expected_key) { ... }
// gcc -O3 -march=native -fopenmp
```

287 块 × 16.7M 候选：并行几分钟，单线程几小时。bytecode 常被常量 XOR 成「看起来像 ASCII」的样子。

### 3.5 GLSL shader VM

256×256 RGBA 纹理：行 0 是寄存器（像素 0 = IP，1–32 通用），行 1–127 是程序（RGBA = opcode, arg1..3），行 128–255 是 VRAM。每帧 16 步。

**GPU 渲染必然失败**：同帧内多个 VRAM 写只保留最后一个（丢 75%+ 像素），STORE 自修改补丁也会互相覆盖。必须**顺序模拟**：先跑解密阶段把 STORE 补丁全部落地，再跑绘制阶段保留所有写。

判据：给了 `program.png`、题目说「什么都没渲染出来」、GLSL 里有自定义 opcode 表。

### 3.6 指令计数器当状态

手写汇编里有个只增的寄存器（如 `r12`）参与 `xor/rol/mul`，则第 N 字节的变换依赖前 N-1 字节执行了多少条指令 → 路径相关，代数反演不可行。用 Unicorn 全模拟，逐字节试 256 个值，保持正确前缀的状态。

判据：无标准库调用、寄存器用法异常、某寄存器只增、题目名暗示「计数」。

### 3.7 多层自解密

256 层、每层读 2 字节密钥、SHA-NI 派生 keystream 后 XOR 下一层。**oracle**：错误密钥解出垃圾；正确密钥解出的代码里恰好有 2 条 `call read@plt`。

性能分层决定成败：

| 方式 | 速度 | 256 层耗时 |
|---|---|---|
| Python 子进程 | ~2/s | 数天 |
| ptrace 注入 | ~119/s | 6 小时+ |
| JIT + fork/候选 | ~1000/s | 140 分钟 |
| JIT + 共享 BSS + 32 进程 | ~3500/s | **~17 分钟** |

JIT 做法：把二进制按原虚拟地址 `mmap(MAP_FIXED)` 进解题进程，解题器编到不冲突的 `-Wl,-Ttext-segment=0x10000000`，补丁 `read@plt` 注入候选字节、把层尾 `jmp/call` 改成 `ret`，每候选 fork 一次靠 COW 隔离。BSS（16MB+）放 `/dev/shm` 以 `MAP_SHARED` 映射，子进程改 `MAP_PRIVATE`，fork 开销从 16MB 页表降到 ~4KB。

坑：层间可能用 `call 0xe8` 而非 `jmp 0xe9`；BSS 可能超出 ELF MemSiz（内核 brk 扩展）；SHA-NI 即使 `/proc/cpuinfo` 没报也能用。

## 4. 批量化与工具化

**批量 crackme**（上百个同构二进制）：`objdump -M intel -d` 抽 `add/sub rdi,N` 与 `cmp rdi,target`，从 target 逆序撤销运算即可，不用执行。

```python
ops = re.findall(r'(add|sub)\s+rdi,(0x\w+)', asm)
target = int(re.search(r'cmp\s+rdi,(0x\w+)', asm).group(1), 16)
for op, val in reversed(ops):
    target = target - int(val,16) if op == 'add' else target + int(val,16)
```

**批量抽取常量**用 Ghidra headless（`analyzeHeadless ... -postScript extract_tree.py`），比手工点几百个函数快一个数量级。

**侧信道实现**（Spectre-RSB 之类）不要试图在特殊硬件上跑：S-box 表全在数据段，`0x340` 表示 bit=1、`0x100` 表示 bit=0，8 个 S-box × 8 输出位 × 256 项，加上 64 字节置换表和 8 个轮密钥，静态取完就能自己实现加解密。

**图像 XOR 掩码**（`key = (mask*x - y) & 0xFF`）：自然图像相邻像素平滑，枚举 256 个 mask，用「相邻像素差绝对值之和」打分取最优，每个区域独立，代价可忽略。

## 5. 纪律

- 先看符号与数据段，再决定要不要逆算法；`readelf -s` / `strings` 三十秒的收益常大于三小时反编译。
- 判断校验结构比读懂代码重要：**独立 / 线性 / 布尔 / 递推 / 不可逆**五类对应五种完全不同的工具。
- 只要看到「解必须落在可打印区间」+「大系数线性组合」，就是格问题，别硬解方程。
- GF(2^8) 不是整数运算：加法 XOR、乘法带 `0x1b` 归约，用整数高斯消元必错。
- 自修改派发、指令计数、多线程 channel 这类 VM，一律「记录轨迹/全模拟」而不是「重写解释器」。
- 工具崩了不等于文件坏：ELF 运行只依赖 program header，节头是给分析器看的元数据。
- 「GDB 里对、正常运行错」先查 `ldd` 与库 diff，不要怀疑自己的输入。
- 大规模爆破先算吞吐再写代码：Python 子进程与 JIT+fork 差三个数量级，方案选错等于没做。
- 训练/推理类（DNN）题目先看激活函数可逆性与权重矩阵是否方阵，能反演就不要搜索。
- 交叉参考：约束求解与格的基础见 [[crypto/高阶专题/高阶数学攻击.md|高阶数学攻击]]，编码层套路见 [[misc/编码解码/高级编码与专用格式判定.md|高级编码]]。
