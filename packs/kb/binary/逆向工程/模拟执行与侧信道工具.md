# 模拟执行与侧信道工具

核心动态工具（Frida、angr、lldb、x64dbg）见 [[binary/逆向工程/动态工具.md|动态工具]]；Triton 完整参考与高级符号执行见 [[binary/逆向工程/高级工具与去混淆.md|高级工具]]；Unicorn 手工模拟见 [[binary/逆向工程/Unicorn 模拟.md|Unicorn 模拟]]；反分析对抗见 [[binary/逆向工程/反分析的对抗手法.md|反分析对抗]]。

## 0. 判据速查

| 卡在哪 | 换什么工具 | 去哪节 |
|---|---|---|
| 反调试太狠，挂不上调试器 | Qiling（模拟器里没有调试器痕迹） | §1 |
| 目标是 ARM / MIPS / RISC-V | Qiling（x86 主机上跑异构） | §1 |
| 需要大量重复试输入 | Qiling 快照 / Pin 计数 | §1.4、§3 |
| 路径爆炸，angr 跑不动 | Triton（单路径 DSE） | §2 |
| 校验逻辑被 movfuscator 展开 | Pin `inscount` 数指令 | §3 |
| 每字符解锁新代码段，字符间有耦合 | Pin + 遗传算法 | §3.2 |
| 总指令数不随正确性变化 | 改 Pin，只数成功分支地址 | §3.3 |
| 只有 opcode 没有寄存器值 | 按地址排序还原控制流 | §4 |
| 时间/随机数导致结果不确定 | LD_PRELOAD 冻结 `time`/`rand` | §5 |
| 校验用 `memcmp`/`strcmp` | LD_PRELOAD 改成返回匹配字节数 | §6 |

**选择顺序**：能挂调试器就先挂（最快）→ 挂不上换 Qiling → 需要批量试换 Pin 计数 → 需要求解换 Triton。

## 1. Qiling

Qiling 建在 Unicorn 之上，补上了 **OS 层**（系统调用、文件系统、注册表）。Unicorn 只模拟 CPU，Qiling 模拟整个运行环境。

```bash
pip install qiling
git clone https://github.com/qilingframework/rootfs
```

```python
from qiling import Qiling
from qiling.const import QL_VERBOSE

# Linux ELF
ql = Qiling(["./binary", "arg1"], "rootfs/x8664_linux", verbose=QL_VERBOSE.DEFAULT)
ql.run()

# Windows PE（不需要 Windows）
ql = Qiling(["rootfs/x86_windows/bin/binary.exe"], "rootfs/x86_windows")
ql.run()

# ARM / MIPS（IoT 固件）
ql = Qiling(["rootfs/arm_linux/bin/binary"], "rootfs/arm_linux")
ql.run()
```

### 1.1 过反调试

```python
from qiling import Qiling

ql = Qiling(["./binary"], "rootfs/x8664_linux")

# hook ptrace 系统调用，直接返回成功
def hook_ptrace(ql, ptrace_request, pid, addr, data):
    ql.log.info("ptrace bypassed")
    return 0

ql.os.set_syscall("ptrace", hook_ptrace)

# hook 特定地址（例如反虚拟机检查）
def skip_check(ql):
    ql.arch.regs.rax = 0
    ql.log.info(f"Skipped check at {ql.arch.regs.rip:#x}")

ql.hook_address(skip_check, 0x401234)
ql.run()
```

**为什么模拟器天然过反调试**：`ptrace(PTRACE_TRACEME)` 在模拟环境里没有真实调试器竞争，默认就返回成功。这是「换环境」而不是「打补丁」，比改二进制干净。

### 1.2 批量试输入

```python
import string
from qiling import Qiling
from qiling.const import QL_VERBOSE

def test_input(candidate):
    ql = Qiling(["./binary"], "rootfs/x8664_linux",
                verbose=QL_VERBOSE.DISABLED, stdin=candidate.encode())
    ql.run()
    return ql.os.stdout.read()

for ch in string.printable:
    if b"Correct" in test_input("flag{" + ch):
        print(f"Found: {ch}")
```

### 1.3 相对 GDB/Frida 的优势

```text
无调试器痕迹      → 所有反调试默认失效
跨架构无需硬件    → x86 主机上跑 ARM/MIPS/RISC-V
Python 脚本化     → 迭代速度远快于 GDB 命令行
快照/恢复         → 适合大量重复试输入
```

**什么时候用**：异构架构、IoT 固件、反调试很重、需要自动化试大量输入。

## 2. Triton

单路径动态符号执行。**angr 的路径爆炸是它最大的短板，Triton 正好补这个洞**：喂一条具体执行轨迹，符号化特定输入，在比较点求解。

```python
from triton import *

ctx = TritonContext(ARCH.X86_64)

# 符号化输入缓冲区
for i in range(32):
    ctx.symbolizeMemory(MemoryAccess(0x600000 + i, CPUSIZE.BYTE), f"flag_{i}")

# 处理指令、收集约束，到比较点求解
model = ctx.getModel(ctx.getPathConstraintsAst())
flag = "".join(chr(v.getValue()) for _, v in sorted(model.items()))
```

**适用**：单路径符号执行、去混淆、污点分析。执行流已知且是线性的情况下，比 angr 快。

完整用法见 [[binary/逆向工程/高级工具与去混淆.md|高级工具]]。

## 3. Intel Pin 指令计数

原理：校验越往后走，执行的指令越多。**用指令总数当适应度**。

### 3.1 逐字符

```python
import string
from subprocess import Popen, PIPE

pin    = "./pin"
tool   = "./source/tools/ManualExamples/obj-intel64/inscount0.so"
binary = "./target"

key = ""
while True:
    best_count, best_char = 0, ""
    for c in string.printable:
        p = Popen([pin, "-injection", "child", "-t", tool, "--", binary],
                  stdout=PIPE, stdin=PIPE, stderr=PIPE)
        p.communicate((key + c + "\n").encode())
        with open("inscount.out") as f:
            count = int(f.read().split()[-1])
        if count > best_count:
            best_count, best_char = count, c
    key += best_char
    print(f"Found: {key}")
```

对 **movfuscator** 这类把每条指令展开成大量 `mov` 的混淆最有效 —— 静态分析完全无望，但指令数差仍然存在，正确字符通常多出 1000+ 条指令。

### 3.2 遗传算法（字符间有耦合时）

自修改代码「每通过一位才解密下一段」时，逐字符贪心会失效：字符之间有交互，且搜索空间太大。

```python
import random, string, subprocess

PIN_PATH  = "/tmp/pin-3.5/pin"
TOOL_PATH = "source/tools/ManualExamples/obj-intel64/inscount0.so"

def fitness(candidate):
    subprocess.Popen([PIN_PATH, "-t", TOOL_PATH, "--", "./binary"],
                     stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                     stderr=subprocess.PIPE).communicate(candidate.encode())
    try:
        with open("inscount.out") as f:
            return int(f.read().split()[-1])
    except Exception:
        return 0

def mutate(ind, rate=0.1):
    r = list(ind)
    for i in range(len(r)):
        if random.random() < rate:
            r[i] = random.choice(string.printable[:62])
    return r

FLAG_LEN, POP, SURVIVORS = 40, 100, 20
population = [random.choices(string.printable[:62], k=FLAG_LEN) for _ in range(POP)]

for gen in range(10000):
    scored = sorted(((fitness("".join(p)), p) for p in population), reverse=True)
    best_score, best = scored[0]
    print(f"Gen {gen}: {best_score} {''.join(best)}")
    survivors = [s[1] for s in scored[:SURVIVORS]]
    population = survivors + [mutate(random.choice(survivors)) for _ in range(POP - SURVIVORS)]
```

40 字符的 flag 大约 30 分钟收敛。**遗传算法能同时发现多位正确字符**，这是它比逐字符快的原因。

### 3.3 只数成功分支

**总指令数不随正确性变化时**（典型是表驱动比较），改 Pin 的 icount 工具，只统计成功分支地址的执行次数：

```cpp
static ADDRINT target_addr = 0x401234;      // 成功分支地址
static UINT64 target_count = 0;

VOID CountAtTarget(ADDRINT ip) {
    if (ip == target_addr) target_count++;
}

VOID Instruction(INS ins, VOID *v) {
    INS_InsertCall(ins, IPOINT_BEFORE, (AFUNPTR)CountAtTarget,
                   IARG_INST_PTR, IARG_END);
}
```

判据：先跑两个已知错误的输入，看总指令数是否可区分。**不可区分就换这个改法**，不要在总计数上继续调参。

## 4. 只有 opcode 的轨迹还原

给的轨迹只有 opcode，没有寄存器/内存值。仍然能还原程序：

```text
1. 按地址排序 + 去重 → 恢复代码布局
2. 识别基本块边界（跳转、调用、返回）
3. 从轨迹顺序推出每个分支的 taken / not-taken
4. 排序类算法：分区比较直接泄露元素的相对大小
```

**为什么排序算法最怕这个**：快排的分区比较结果是「谁比谁大」，而分支方向就是比较结果。把每一轮的分区方向收集起来，输入的完整排序关系就出来了 —— 不需要任何数据值。

## 5. LD_PRELOAD 冻结时间

时间/随机数导致结果不确定时，把不确定性干掉：

```c
// gcc -shared -fPIC -o freeze.so freeze_time.c
#include <time.h>

time_t time(time_t *t) {
    if (t) *t = 1234567890;
    return 1234567890;
}
```

```bash
gcc -shared -fPIC -o freeze.so freeze_time.c
LD_PRELOAD=./freeze.so ./binary

for byte in $(seq 0 255); do
    echo -n "$(printf '\x%02x' $byte)" | LD_PRELOAD=./freeze.so ./binary
done
```

`srand()`/`rand()` 也参与时一并覆盖：

```c
int rand(void) { return 42; }
```

**冻结之后，再复杂的 VM 也退化成逐字节预言机** —— 每次输入一个字节，看输出对不对。

## 6. LD_PRELOAD 改 `memcmp`

把 `memcmp` 换成「返回匹配字节数」，任何比较式校验立刻变成逐字节预言机：

```c
// gcc -shared -fPIC -o hook.so memcmp_hook.c
int memcmp(const char *s1, const char *s2, int n) {
    int cnt = 0;
    for (int i = 0; i < n; ++i) {
        if (s1[i] == s2[i]) cnt++;
        else break;
    }
    return cnt;
}
```

```bash
LD_PRELOAD=./hook.so gdb ./binary
# 在 memcmp 返回后下断，读返回值 = 已匹配字节数
# 逐位试，找让计数增加的那个字符
```

**检测前提**：`ltrace` 或导入表里能看到 `memcmp`/`strcmp`，且它被用户输入和期望值调用。如果校验是自己写的逐字节循环，这一招不生效 —— 改用 Pin 计数。

## 7. 纪律

- **能挂调试器就先挂**。工具越复杂，出问题的地方越多。
- **反调试重就换模拟器，不要逐个打补丁**。Qiling 里 `ptrace` 天然返回成功，比改二进制干净。
- **异构架构直接上 Qiling**，不要装 QEMU 再折腾 rootfs。
- **angr 路径爆炸就换 Triton**。Triton 吃的是具体轨迹，不走分支探索。
- **Pin 计数先用两个错误输入验证可区分性**。不可区分就改数成功分支地址，别在总数上死磕。
- **字符间有耦合时用遗传算法**。逐字符贪心只在「每位的正确性独立可测」时成立。
- **不确定性先冻结再分析**。`time`/`rand` 冻结后，复杂 VM 也变成逐字节预言机。
- **`memcmp` 劫持只对库函数调用生效**，自己写的循环校验要换思路。
