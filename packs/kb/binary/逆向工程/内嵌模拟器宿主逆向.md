# 内嵌模拟器宿主逆向

## 判据速查

| 现象 | 第一动作 | 去哪节 |
|---|---|---|
| 静态链接二进制体积异常大，`.rodata` 有模拟器内部串 | 认宿主，先脱外层壳再看 | §1、§7 |
| 找到 `uc_open` 调用点 | 读实参定 guest 架构，别猜 | §2 |
| 找到 `uc_mem_write` + `uc_emu_start` 相邻出现 | 在 API 边界 dump guest 代码与数据 | §3 |
| 已 dump 出 guest，要还原算法 | 离线重放，先对齐宿主行为 | §4 |
| 有可重放 oracle，要解输入 | 两个已知输入做差分，先定变换性质 | §5 |
| 宿主 `.text` 巨大 + 大量间接跳转 | **跳过**反平坦化，直接用 API 边界 | §6 |
| 外层还有壳 | 先脱壳，顺序不能反 | §7 |

「我主动用模拟器跑目标」见 [[binary/逆向工程/Unicorn 模拟.md|Unicorn 模拟]]；保护壳与去混淆框架见 [[binary/逆向工程/高级工具与去混淆.md|高级工具与去混淆]]。本篇是**反向场景**：目标程序自己就是模拟器宿主，磁盘上没有那段被校验的代码。

## 适用条件

**成立**（本篇手法可用）：

- 目标为静态链接可执行体，体积远超功能量级，`.rodata` 含模拟器自身源码路径串或内部告警串
- 运行时读入定长输入后立即判定，宿主侧无可观察的中间运算
- 能在代码里定位到模拟器 API 一族调用点（`uc_open` / `uc_mem_write` / `uc_emu_start` / `uc_reg_read`）

**不成立**（换路径）：

- 无任何模拟器标识串且找不到 API 调用点 → 真编译器混淆或自研字节码解释器，转 [[binary/逆向工程/高级工具与去混淆.md|去混淆]]
- 有 API 调用点但输入→输出全在宿主侧完成、guest 只做无关计算 → 同样转去混淆框架
- 目标依赖真实 syscall 语义（文件/网络/`ptrace`）→ 宿主可能是 Qiling 类带 OS 层的模拟器，dump 后需连同 rootfs 行为一起建模

## 1. 认出「目标是模拟器宿主」

**判据**：满足任两条即可怀疑——

- 静态链接、体积远超功能量级（几十 MB 级而功能只有读输入+比对）
- `.rodata` 里出现**模拟器自身的源码路径串**与内部告警串（这类串只在编译模拟器时被拼进来，业务代码不会带）
- 符号表/调试串里出现 `uc_open`/`uc_mem_write`/`uc_emu_start`/`cpu_exec`/`tcg_*` 一族
- 字符串里出现目标架构的 **CPU 型号名**（模拟器会为每类 target 注册型号串）
- 运行时行为与静态代码量严重不匹配：读入定长输入后立刻出结果，中间没有可观察的运算

**动作**：

```bash
strings -a binary | grep -iE 'unicorn|qiling|qemu|tcg|uc_(open|mem_write|emu_start)'
strings -a binary | grep -iE '/(target|hw)/.*\.c$'    # 模拟器源码路径
strings -a binary | grep -iE '\-cpu$'                  # 注册的 CPU 型号
```

命中后**不要**去读宿主逻辑，直接进 §2。

**不成立**：完全没有模拟器标识串，且找不到 `uc_*` 调用点 → 是真编译器混淆或自研字节码解释器，转 [[binary/逆向工程/高级工具与去混淆.md|去混淆]] 的 §4/§10。

## 2. 从 `uc_open` 实参定 guest 架构

**判据**：定位到 `uc_open` 调用点（三实参：arch、mode、输出句柄指针）。

**动作**：断在调用点，读前两个实参的**具体数值**。arch/mode 是**枚举值**，不是可随意 or 的位掩码——同一个数值在不同模拟器版本含义可能不同，务必对照该版本头文件核对，不要凭印象认。

交叉验证：用 §1 捞到的 CPU 型号串确认 target 家族。

**不成立**：实参推出的架构与型号串矛盾 → **以实参为准**。型号串可能只是链接进来的死代码（模拟器注册表里有全部 target，未使用的也在）。

## 3. 在模拟器 API 边界 dump guest 代码与数据

**判据**：`uc_mem_write` 出现在 `uc_emu_start` 之前。典型模式是三步：写代码 → 写数据/常量 → 启动。

**动作**：

1. 在每个 `uc_mem_write` 调用点断下，记录三元组 **(dst_addr, src_ptr, size)** 与当时的字节内容，**按 dst_addr 分桶落盘**。
2. 在 `uc_emu_start` 调用点读 **(begin, until, timeout, count)** 四实参。
3. 写往低地址（接近 `0x0`）的那块通常是 **guest 代码**；写往高位固定地址的是 **数据/常量**。但**按目标地址区分，不要按调用顺序猜**——顺序在不同程序里会变。

GDB 侧用 Python 断点最省事（`stop()` 返回 `False` 只记录不停，一次跑完拿全）：

```python
import gdb

class DumpMemWrite(gdb.Breakpoint):
    def __init__(self, addr):
        super().__init__(f"*{addr}", gdb.BP_BREAKPOINT)
    def stop(self):
        f = gdb.selected_frame()
        dst = int(f.read_register("rsi"))     # 按实际调用约定核对
        src = int(f.read_register("rdx"))
        size = int(f.read_register("rcx"))
        data = gdb.selected_inferior().read_memory(src, size).tobytes()
        open(f"memwrite_{dst:#x}.bin", "wb").write(data)
        print(f"mem_write dst={dst:#x} size={size}")
        return False
```

**不成立**：只有一个 `uc_mem_write` 且 dst 是数据区 → guest 代码是**静态躺在文件里**的，直接按 §3 第 2 步拿到的 `until` 长度从 `.rodata` 对应偏移取，不需要断点。

## 4. 离线重放 guest，先对齐宿主

**判据**：已拿到 guest 代码段、常量段、输入写入地址与长度、`emu_start` 四实参。

**动作**：按 §2 的 arch/mode 建 `Uc`，映射与宿主**一致**的地址区间，按宿主相同顺序 `mem_write`，`emu_start` 四实参照抄，读返回值寄存器。

```python
mu = Uc(ARCH, MODE)
mu.mem_map(CODE_ADDR & ~0xfff, ALIGN_UP(len(code) + 0x1000))
mu.mem_write(CODE_ADDR, code)
mu.mem_map(DATA_ADDR, 0x10000)          # 常量与输入同一页时合并映射
mu.mem_write(CONST_ADDR, const)
mu.mem_write(INPUT_ADDR, probe_input)
mu.mem_map(STACK_ADDR, STACK_SIZE)      # 栈务必离开 0x0
mu.reg_write(SP_REG, STACK_ADDR + STACK_SIZE - 0x100)
mu.reg_write(A0_REG, INPUT_ADDR)        # 按 guest ABI 填参数
mu.reg_write(A1_REG, CONST_ADDR)
mu.emu_start(BEGIN, UNTIL, timeout=TIMEOUT, count=COUNT)
ret = mu.reg_read(A0_REG)
```

**第一步永远是拿一个已知输入跑，返回值/输出与宿主一致再往下走**。不一致时按此顺序查：栈指针初值 → 未 dump 到的额外 `uc_mem_write`（补 hook 记录全部）→ `timeout`/`count` 是否与宿主一致 → 字节序/模式位。

**不成立**：宿主返回值本身就不稳定（多次运行结果不同）→ guest 里有未建模的外部输入（时间、地址随机化），先 hook 出那个读取点。

## 5. 差分测试先定变换性质，再解方程

**判据**：已有可重放 guest 或任何黑盒 oracle，需要从「期望输出」反推输入。

**动作**：取两个已知输入跑同一路径，比较输出差分——

| 差分结果 | 结论 | 求解 |
|---|---|---|
| `out(A) ^ out(B) == A ^ B` 逐字节成立 | 纯异或 | `in = target ^ K`，K 用零输入一次测出 |
| `out(A) - out(B) == A - B` 逐字节成立 | 纯加法 | `in = target - C`，C 用零输入测出 |
| 差分与输入无关（恒定） | 输出是常量 | 直接取该常量，输入无关 |
| 不满足任何线性关系 | 非线性 | 转符号执行 / 逐字节爆破 |

**先定性质再解方程**——纯异或的题用符号执行解是几十倍成本换同一个答案。

**不成立**：差分稳定但 `out` 是输入的置换（每个字节出现在别处）→ 是换位不是代换，先求出置换表再套上表公式。

## 6. 已验证路径：模拟器 API 边界优先于反平坦化

**判据**：宿主 `.text` 体积远大于实际功能量（MB 级）、数千个函数入口标记、上百处 `jmp *(%reg,%idx,8)` 形式的间接跳转 → 控制流平坦化。

**动作**：**不要反平坦化**。直接按 §3 在模拟器 API 调用点下断——那是**最干净的语义边界**：边界一侧是混淆过的调度层，另一侧是 guest 代码，输入输出关系完全由边界两侧的契约决定。混淆只包住了「怎么调到那里」，没包住「到那里做什么」。

**不成立**：遍历全部 `uc_*` 相关调用点后仍找不到任何输入→输出边界（即所有运算都在宿主侧完成）→ 这时才需要 D-810 / GOOMBA 或符号执行，见 [[binary/逆向工程/高级工具与去混淆.md|去混淆]]。

## 7. 先脱外层壳，顺序不能反

**判据**：文件体积与段结构异常——程序头极少、多个 LOAD 段文件偏移重叠、入口落在非代码段、存在壳的签名串。

**动作**：先脱壳，再执行 §1 的识别。壳内 `.rodata` 是压缩过的，`strings` 拿不到模拟器标识串——**在壳里找模拟器会白费一轮**。

**不成立**：脱壳后仍无任何模拟器标识串 → 不是模拟器宿主题，回 §1 的不成立分支。

## 纪律

- **先判「目标是不是模拟器宿主」，再决定逆谁**。认错载体，后面全白做。
- **arch/mode 读实参，不读字符串**。型号串可能来自未使用的注册表项。
- **`uc_mem_write` 按目标地址分桶**，不按调用顺序猜哪块是代码。
- **重放先对齐再求解**。已知输入跑不通就说明状态没恢复全，此时任何求解结果都不可信。
- **差分优先于符号执行**。两个输入就能定出变换性质，比建符号模型快一个数量级。
- **有 API 边界就别碰混淆区**。反平坦化是最后手段，不是第一动作。
- **报的是「边界在哪」还是「算法是什么」**：边界找不到才需要去混淆，算法看不懂才需要符号执行。
