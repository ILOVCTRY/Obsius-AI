# 二进制利用判据库

> 来源：`binary/赛事专题/Writeup合集` 中 183 篇 Pwn WP（796 条观测 / 388 条失败尝试）。
> 主库 `binary/漏洞利用/` 已有堆、ROP、格式化字符串的完整手法，
> 本文补**版本差异判据**与**非 x86 载体**两类主库薄弱的部分。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| 菜单题有 malloc/free/edit/show | 堆题，先判 glibc 版本 | §1 |
| `free` 后还能 `show` | UAF | §1.2 |
| 只能写 1 字节且在下个 chunk 头 | off-by-one / off-by-null | §1.3 |
| `printf(buf)` 直接输出 | 格式化字符串 | §2 |
| 有 `read` 但 buffer 很小 | 栈迁移 | §3.1 |
| 无 `system` 但有 `syscall` | ORW | §3.2 |
| 有 seccomp | 先 dump 规则 | §3.3 |
| 目标是 `.ko` 或 `/dev/xxx` | 内核题 | §4 |
| 目标架构是 ARM/MIPS/RISC-V | 特殊架构 | §5 |
| 目标是 QEMU 设备 | MMIO/PMIO | §6 |

## 1. 堆

### 1.1 先判 glibc 版本

```bash
# 从二进制里找
strings binary | grep -i 'glibc'
# 从题目附件里找 libc
./libc.so.6   # 直接跑会打印版本
strings libc.so.6 | grep 'GNU C Library'
```

| 版本 | 关键特性 |
|---|---|
| 2.23 | 无 tcache；fastbin + unsorted bin；`__malloc_hook` 可用 |
| 2.27 | 引入 tcache；`__free_hook`/`__malloc_hook` 可用 |
| 2.29 | tcache 加 `key` 字段（double free 检测） |
| 2.31 | tcache 检查加强 |
| 2.32 | 引入 safe-linking（`fd` 指针异或） |
| 2.34 | 移除 `__malloc_hook`/`__free_hook` |
| 2.35+ | 改用 `_IO_wfile_jumps` + `setcontext` 链 |

判据是**版本决定所有手法**。`2.34+` 之后 hook 类手法全废，必须走 IO 链或 `setcontext`。

### 1.2 UAF 的利用路径

```text
有 show        → 直接读 fd 泄露堆/libc 地址
有 edit        → 改 fd 做 tcache poisoning
只有 free      → 靠 unsorted bin 的 fd/bk 泄露
```

判据是**free 之后还能不能访问**。有 show 就有泄露，有 edit 就有写。

### 1.3 off-by-one / off-by-null

```text
off-by-one  → 改下一块的 size 的低字节（扩大或缩小）
off-by-null → 把下一块 size 的最低字节置 0（只能缩小）

利用：
1. 改 size 让 chunk 覆盖到相邻块
2. 制造 overlap
3. 泄露 / 改写
```

判据是**写入长度比分配长度多 1**。看 `read(fd, buf, size+1)` 或 `buf[size] = 0`。

**关键**：高版本 glibc 的 off-by-null 需要绕 `bck->fd == P` 检查（unlink 前的一致性校验），比 2.23 难得多。

### 1.4 tcache 的版本差异

| 版本 | tcache 检查 |
|---|---|
| 2.27 | 只检查 `tcache->counts`，double free 不检测 |
| 2.29 | 加 `key` 字段，free 时写 `tcache` 地址，double free 会报错 |
| 2.32 | 加 safe-linking，`fd` 存的是 `ptr ^ (pos >> 12)` |

判据是**能不能 double free**。2.29+ 需要先改 `key` 字段。

### 1.5 高版本的替代路径

`2.34+` 没有 hook 之后：

```text
1. _IO_2_1_stdout_ 的 vtable 劫持（FSOP）
2. setcontext + 61（glibc 2.35+ 的偏移变了）
3. exit_handler / atexit 链
4. TLS dtor（__call_tls_dtors）
5. __run_exit_handlers
```

判据是**能写哪个全局结构**。有任意写就找这些目标。

## 2. 格式化字符串

```text
%p / %x      → 泄露栈
%s           → 解引用（需要栈上有指针）
%n           → 写（4 字节）
%hn          → 写（2 字节）
%hhn         → 写（1 字节）
%N$p         → 直接读第 N 个参数
```

判据是**能控制格式化字符串本身**（`printf(buf)` 而不是 `printf("%s", buf)`）。

**关键技巧**：

```text
1. 先 %p 扫一遍找自己的输入在栈上的位置
2. 用 %N$p 精确定位
3. 写的时候用 %hn 分两次（避免一次写太多导致输出爆炸）
4. 目标地址放在 payload 末尾，用 %N$hn 指向它
```

**坑**：`%n` 写 4 字节时如果值很大（比如 `0x7f...`），`printf` 会输出几 GB 字符，直接超时。必须用 `%hn` 拆分。

## 3. ROP 与栈

### 3.1 栈迁移

```text
条件：溢出长度 < 返回地址偏移，或 buffer 太小放不下 ROP 链
手法：leave; ret  → rsp = rbp, pop rbp; ret
      需要先控制 rbp 指向可写区域（bss / 堆）
```

判据是**溢出长度不够**。先算 `offset = 返回地址 - buf`，再看能写多少。

### 3.2 ORW

```text
没有 system 时：
open('/flag') → read(fd, buf, n) → write(1, buf, n)

需要：
1. pop rdi; ret  （filename）
2. pop rsi; ret  （flags = 0）
3. pop rdx; ret  （mode = 0）
4. syscall
```

判据是**二进制里没有 `system` 但有 `syscall`**。或者 seccomp 只允许 `open/read/write`。

**省字节技巧**：把 `/flag` 字符串写到 bss，用 `read` 读入后再 `open`。

### 3.3 seccomp

```bash
# dump 规则
seccomp-tools dump ./binary
```

判据是**允许的 syscall 集合**。只允许 `open/read/write` 就走 ORW；允许 `execve` 就直接拿 shell。

**坑**：`execve` 被禁但 `execveat` 没禁时，可以用 `execveat` 绕过。

## 4. 内核

**判据**：目标是 `.ko` 模块，或题目给 `/dev/xxx` 设备。

### 4.1 常见漏洞模式

| 模式 | 判据 |
|---|---|
| 栈溢出 | `copy_from_user` 到栈上固定 buffer |
| 堆溢出 | `kmalloc` 后 `copy_from_user` 超长 |
| UAF | `kfree` 后没置 NULL，还能通过 ioctl 访问 |
| 越界读写 | 数组索引没检查 |
| 类型混淆 | `container_of` 用错类型 |

判据是**`copy_from_user`/`copy_to_user` 的长度参数是否可控**。

### 4.2 提权路径

```text
1. modprobe_path 覆盖（最常用）
2. core_pattern 覆盖
3. commit_creds(prepare_kernel_cred(0))
4. 修改当前进程的 cred 结构
```

判据是**能不能任意写内核内存**。能写就改 `modprobe_path`（最简单）。

```c
// modprobe_path 触发
// 1. 把 modprobe_path 改成 /tmp/x
// 2. 执行一个未知格式的文件
// 3. 内核会以 root 执行 /tmp/x
```

### 4.3 KASLR 绕过

```text
1. 泄露内核地址（UAF 读 / 信息泄露）
2. EntryBleed（侧信道，需特定 CPU 配置）
3. prefetch 侧信道
```

判据是**有没有泄露点**。没有泄露点又要 KASLR，成本极高。

## 5. 特殊架构

### 5.1 ARM64

```text
调用约定：x0-x7 传参，x0 返回值
gadget：没有 pop rdi，用 ldp x0, x1, [sp], #0x10
ret2csu 等价物：找 __libc_csu_init 的等价段
```

判据是**架构**。ARM64 的 gadget 形态与 x86 完全不同，x86 的 ROP 链不能直接搬。

### 5.2 MIPS

```text
延迟槽：跳转指令后的那条指令总会执行
调用约定：a0-a3 传参，v0 返回值
栈：没有 push/pop，用 sw/lw 手动操作
```

判据是**延迟槽**。写 ROP 链时要考虑延迟槽里的指令会执行。

### 5.3 架构识别

```bash
file binary          # ELF 32/64-bit, ARM/MIPS/x86
readelf -h binary    # Machine 字段
checksec --file=binary
```

## 6. QEMU 与设备

**判据**：题目给了 QEMU 启动脚本，或目标是 `qemu-system-*`。

```text
MMIO：设备寄存器映射到内存地址，读写触发回调
PMIO：端口 I/O，in/out 指令
```

判据是**设备的 `mmio_ops` / `pio_ops` 里的 read/write 回调有没有边界检查**。

常见漏洞：`case` 分支里对 `addr` 没做范围校验，导致越界读写 QEMU 进程内存 → 逃逸到宿主机。

## 7. 纪律

- **先 `checksec` + 判 glibc 版本**，这两个决定所有手法。
- **2.34+ 别想 hook**，直接走 IO 链。
- **格式化字符串写大值用 `%hn`**，`%n` 会输出几 GB 字符超时。
- **溢出长度不够就栈迁移**，不要硬塞。
- **seccomp 先 dump 规则**，别猜。
- **内核题先找 `modprobe_path`**，比 `commit_creds` 简单。
- **特殊架构先看调用约定**，x86 的链搬过去一定错。
- **本地复现用对应版本的 libc**，版本不对所有偏移都错。
