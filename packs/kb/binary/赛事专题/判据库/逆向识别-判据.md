# 逆向识别判据库

> 来源：`binary/赛事专题/Writeup合集` 中 152 篇 Reverse WP（690 条观测 / 433 条失败尝试）。
> 主库 `binary/逆向工程/patterns-ctf.md` 已覆盖校验结构分类，
> 本文补**算法常数指纹表**与**魔改点定位法**两类主库没有的内容。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| 出现 `0x9E3779B9` | TEA 家族 | §1.1 |
| 出现 `0x61C88647` | TEA（负数形式） | §1.1 |
| 有 256 字节的表且被反复索引 | AES S-box 或 RC4 | §1.2 |
| 有 64 项常量数组 | SHA-256 / SHA-512 | §1.3 |
| 有 `0x67452301` | MD5 / SHA-1 初值 | §1.3 |
| 大量 `shl`/`shr`/`xor` 循环 | 可能是 MD5/自定义 | §1.4 |
| `switch` + 密集跳转表 | VM 解释器 | §2 |
| 大量 `jne` 跳到同一目标 | 复合条件 `a&&b&&c` | §1.5 |
| 运行时才解密代码 | SMC（自修改代码） | §3.1 |
| 有 `ptrace`/`IsDebuggerPresent` | 反调试 | §3.2 |
| 有除零 / 非法指令 | 异常流控 | §3.3 |

## 1. 算法指纹

### 1.1 TEA 家族

```text
TEA:    delta = 0x9E3779B9
XTEA:   delta = 0x9E3779B9，但轮函数拆成两半
XXTEA:  不用 delta，用 sum 累加
魔改:   delta 改成 0x61C88647（= -0x9E3779B9 的补码）
        delta 改成 0x114514 / 0x87654321（出题人玩梗）
```

判据是**这个常数**。看到就基本确定，剩下只需确认轮数。

```c
// 标准 TEA 加密
sum += delta;
v0 += ((v1<<4) + k0) ^ (v1 + sum) ^ ((v1>>5) + k1);
v1 += ((v0<<4) + k2) ^ (v0 + sum) ^ ((v0>>5) + k3);
```

**魔改点**：`delta`、移位位数（4/5）、轮数（32）、`+=` 改 `-=`、`k` 的顺序。

### 1.2 AES 与 RC4

```text
AES S-box 首字节：0x63, 0x7c, 0x77, 0x7b, 0xf2, 0x6b, 0x6f, 0xc5
逆 S-box 首字节：0x52, 0x09, 0x6a, 0xd5, 0x30, 0x36, 0xa5, 0x38
Rcon:           0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80, 0x1b, 0x36
MixColumns 系数：0x02, 0x03, 0x01, 0x01
逆 MixColumns：  0x0E, 0x0B, 0x0D, 0x09
```

判据是**S-box 首字节 `0x63`**。有 256 字节表且以 `0x63` 开头就是 AES。

**AES 的魔改点**：

```text
1. S-box 被换（自定义表）
2. ShiftRows 方向反了（左移改右移）
3. MixColumns 系数改了
4. keyExpansion 改了
5. 轮数改了（不是 10/12/14）
6. 最后一轮没有 MixColumns（标准行为，别误判为魔改）
```

**判据**：如果加密结果与标准 AES 不符，按上面六点逐个对照。**不要直接套标准实现**。

```text
RC4 特征：先初始化 0..255 的表，再 KSA 打乱，再 PRGA 异或
RC4 魔改：KSA 加反向轮 / PRGA 用三个 S-box / 索引加 k%256
```

### 1.3 哈希函数初值与常量

| 算法 | 初值 / 特征常量 |
|---|---|
| MD5 | `0x67452301, 0xefcdab89, 0x98badcfe, 0x10325476` |
| SHA-1 | `0x67452301, 0xEFCDAB89, 0x98BADCFE, 0x10325476, 0xC3D2E1F0` |
| SHA-256 | `0x6a09e667, 0xbb67ae85, 0x3c6ef372, 0xa54ff53a` |
| SHA-512 | `0x6a09e667f3bcc908, ...`（64 位） |
| SM3 | `0x7380166f, 0x4914b2b9, 0x172442d7, 0xda8a0600` |

判据是**这些初值**。看到 `0x67452301` 就是 MD5 或 SHA-1（看有没有第五个初值）。

**SHA-256 的 K 表**：64 个 32 位常量，第一个是 `0x428a2f98`。有这张表就是 SHA-256。

### 1.4 自定义混淆的识别

```text
模式：for i in range(n): x = ((x << a) | (x >> b)) ^ k[i]
判据：移位 + 异或 + 循环 → 可能是自定义流密码
打法：不一定要逆，可以「正向跑一遍」——如果能拿到加密函数，直接暴力输入
```

判据是**能不能直接调用加密函数**。能调就不逆，暴力或 z3 更快。

### 1.5 复合条件识别

```text
5 个 jne 串联跳到同一个失败标签
= if (a && b && c && d && e) 的编译结果
```

判据是**多个条件跳转指向同一目标**。这时候逐个条件逆，不要试图整体理解。

## 2. VM 逆向

**判据**：有一个大的 `switch`（或跳转表），每个 `case` 做简单操作，整体在一个循环里。

### 2.1 识别步骤

```text
1. 找 dispatch 循环（通常是 while(1) + switch(opcode)）
2. 提取 opcode 表（每个 case 的编号）
3. 提取每个 opcode 的语义（加/减/异或/跳转/读写内存）
4. 写一个模拟器（Python 最快）
5. 用模拟器跑字节码
```

判据是**字节码在哪里**。通常在 `.rodata` 段，或运行时解密出来。

### 2.2 常见 opcode 语义

```text
0x01 push 立即数
0x02 pop
0x03 add
0x04 sub
0x05 xor
0x06 jmp
0x07 jz
0x08 load
0x09 store
0x0A syscall / print
```

判据是**操作数与栈/寄存器的交互方式**。写模拟器时先实现 3-4 个 opcode，跑一小段验证，再补全。

### 2.3 加速技巧

```text
1. 不要用 IDA 的 F5 硬读，直接写模拟器
2. 字节码是数组的话，用 Python 的 list 直接索引
3. 遇到不认识的 opcode，打印出来看上下文
4. 有 tzcnt/bsf 之类指令的 dispatch，说明是「位编码」的 opcode
```

## 3. 反分析与绕过

### 3.1 SMC（自修改代码）

```text
现象：静态看某段代码是乱码，运行时才正常
判据：代码段有写权限（W+X），或有 mprotect 调用
打法：在解密之后 dump 内存（gdb 的 dump memory）
```

```bash
# gdb 里 dump
dump memory out.bin 0x400000 0x401000
```

判据是**代码段可写**。`checksec` 看到 `RWX` 就是。

### 3.2 反调试

| 手法 | 绕过 |
|---|---|
| `ptrace(PTRACE_TRACEME)` | patch 掉调用，或 `LD_PRELOAD` 覆盖 |
| `IsDebuggerPresent` | patch 返回值 |
| `NtQueryInformationProcess` | 同上 |
| 时间检测（`rdtsc`） | patch 或改返回值 |
| 异常处理藏逻辑 | 见 §3.3 |
| 天堂之门（`CS=0x33; retf`） | 用支持 64 位的调试器，或 patch |

判据是**程序在调试器下行为不同**。先在非调试环境跑一遍看正常行为，再对比。

### 3.3 异常流控

```text
现象：程序有除零、非法指令、访问违例，但正常运行不崩
判据：装了 SEH / signal handler，异常被捕获后跳转到真实逻辑
打法：patch 掉异常指令（改成 nop），或直接在 handler 里下断点
```

判据是**有 `signal`/`SetUnhandledExceptionFilter` 调用**。

### 3.4 混淆代码的清理

```text
1. 找「计算出来但没用」的代码块（死代码）
2. 找恒定跳转（jz 到下一个指令，条件永远真）
3. 找等价指令序列（push/pop 成对、xor eax,eax 后立即 mov）
4. 用 IDA 的 NOP 功能批量清理
```

判据是**代码块对输出无影响**。先跑一遍记录输出，再逐块 nop 看输出是否变化。

## 4. 特殊载体

| 载体 | 判据 | 工具 |
|---|---|---|
| Python 打包（PyInstaller） | 有 `PYZ` 魔数 | `pyinstxtractor` + `pycdc` |
| .NET | 有 `BSJB` 或 `mscoree` | dnSpy / ILSpy |
| Go | 有 `go.buildid` 段 | IDA + golang 插件 |
| Rust | 有 `rustc` 字符串 | IDA + 手工 |
| Android APK | zip + `classes.dex` | jadx / Frida |
| WASM | 有 `\0asm` 魔数 | wasm2wat / wasm-decompile |
| VHDL/GHDL | 二进制里没有常见 magic | ghdl + 波形分析 |
| Unity IL2CPP | 有 `global-metadata.dat` | Il2CppDumper |

判据是**魔数或特征字符串**。先 `file` + `strings | head -50`。

## 5. 纪律

- **先找常数，再读逻辑**。`0x9E3779B9` 一个常数省掉半小时读汇编。
- **魔改 AES 不要套标准实现**，逐点对照六个魔改位。
- **能调用加密函数就别逆**，正向暴力或 z3 更快。
- **VM 题直接写模拟器**，不要用 F5 硬读 dispatch。
- **反调试先跑非调试环境**，记录正常行为再对比。
- **异常流控 patch 掉异常指令**，不要试图理解 handler。
- **AI 辅助逆向会编造轮数和密钥派生**，必须用实际运行输出对齐。
