# 流密码攻击

分组密码与 AEAD 见 [[crypto/对称加密/modern-ciphers.md|现代分组密码]]；通用 XOR 判定见 [[crypto/古典密码/classic-ciphers.md|古典密码与结构化 XOR]]。

## 0. 判据速查

| 观察 | 结论 | 动作 |
|---|---|---|
| 密文与明文等长、保留长度 | 流密码/异或 | 用已知头恢复 keystream |
| keystream 呈线性递推（GF(2)） | LFSR | Berlekamp-Massey 或按步求解 |
| 256 字节状态反复置换 | RC4 家族 | 偏差测试 + 差分测试 |
| 递推含输出反馈、密钥周期 | 自定义流密码 | Z3/约束求解，打印性约束 |
| 每字节密钥不变 | 重复 XOR | 频率/列分析 |
| 多段密文同源 | keystream 复用或密钥复用 | 逐段异或比对 |

## 1. 第一步：把 keystream 抠出来

文件头是最可靠的已知明文来源：

| 格式 | 头部字节 | 可得 keystream |
|---|---|---|
| PNG | `89 50 4e 47 0d 0a 1a 0a 00 00 00 0d 49 48 44 52` | 128 bit |
| PDF | `25 50 44 46 2d` | 40 bit |
| ZIP | `50 4b 03 04` | 32 bit |
| ELF | `7f 45 4c 46` | 32 bit |
| JFIF | `ff d8 ff e0` | 32 bit |

异或后先看 keystream 是否有明显结构（周期、线性、字节频率），再决定攻击路线。长度不守恒（有 padding）说明可能不是纯流密码，先排除分组模式。

## 2. LFSR 类

### 2.1 结构判定

- Fibonacci 型：反馈由多个 tap 异或后进入末端；多数 CTF 工具默认此型。
- Galois 型：反馈分散到寄存器中；Galois 多项式是 Fibonacci 多项式的互反。
- 右移 Galois：`out = state & 1; state >>= 1; if out: state ^= tap_mask`。

Berlekamp-Massey 在 keystream 上直接求最短线性递推，但默认按 Fibonacci 语义解释；对 Galois 实现会给出错误 tap。先用少量样本手工验证递推方向。

### 2.2 Galois tap 直接恢复

对右移 Galois LFSR，任取两个连续状态，当移出位为 1 时：

```text
tap_mask = (state >> 1) ^ next_state
```

若无现成连续状态，把 keystream 按候选位宽分窗，对每个宽度检验：LSB=0 时 `next == state>>1`，LSB=1 时收集 `(state>>1)^next` 的众数；正确宽度下 mask 得票一致且零冲突，错误宽度出现矛盾 mask。这比 Berlekamp-Massey 更快且不需要代数库。恢复 `seed`（第一个 keystream 块）、`tap_mask` 和位宽后逐块解密并验证文件 magic。

### 2.3 已知 2L 位求解

给定至少 `2L` 个连续 keystream 位，可直接解 L 位状态与反馈系数：

```text
k[i+L] = c[0]*k[i] ^ c[1]*k[i+1] ^ ... ^ c[L-1]*k[i+L-1]
```

把方程排成 GF(2) 线性系统，高斯消元求 `c` 与初态。样本不足时系统欠定，不要硬解。

### 2.4 相关性攻击与滤波函数

若输出是 LFSR 状态的某个非线性滤波函数但与某条内部序列强相关，可用相关性攻击逐位假设并统计吻合度。滤波函数在 GF(2) 上线性化（把 `g(f(state_t))` 表示为 `state_0` 各位的线性组合，矩阵 `A`），解 `A*state_0 = 0` 的核得到候选种子，再用明文可打印性筛选。湮灭器方法只适用于低代数次数滤波函数。

### 2.5 常见长度

| 位宽 | 常用本原多项式 | 周期 |
|---|---|---|
| 16 | `x^16+x^14+x^13+x^11+1` | 65535 |
| 32 | `x^32+x^22+x^2+x+1` | `2^32-1` |
| 64 | `x^64+x^4+x^3+x+1` | `2^64-1` |

本原多项式保证最长周期 `2^L-1`；观察到周期远小于此，可能是抽头或初始化错误。

## 3. RC4 家族

### 3.1 先识别变体

CTF 标注 RC4 但实际可能是 RC4A（双状态交替）、VMPC（重置换）、Spritz（海绵式）。不要拿标准 RC4 攻击静默失败。识别手段：

- 差分测试：两密钥只差一字节，比较 keystream 前若干字节的差异模式。
- 偏差测试：RC4 第二个输出字节为 `0x00` 的概率约 `1/128`（随机为 `1/256`）；大量采样可区分 RC4/RC4A 与无偏差变体。
- 代码特征：状态数组数量、是否出现 `a,i,j,k,w,z` 六个量。

### 3.2 各变体攻击面

- RC4：FMS/Klein、第二字节偏差；密钥长度与 IV 复用是主要破裂点。
- RC4A：两条独立 RC4 交替输出，偶数位来自 `S1`、奇数位来自 `S2`，可分别恢复后交叉验证 `t` 值。
- VMPC：KSA 多轮置换，可用 Z3 以排列约束（AllDifferent）+ 已知 keystream 反推。
- Spritz：状态含吸收与 whip/crush，把完整状态建模为 BitVec 数组并展开 PRGA。

### 3.3 相邻字节相关

若同一明文用不同密钥加密两段密文，观察相邻密文异或：

```text
plain2[i] ^ plain1[i] == (ct2[i]^ct2[i+1]) ^ (ct1[i]^ct1[i+1])
```

利用相邻异或消去密钥中不变部分，可在已知一段明文时还原另一段。适用条件是密钥轮换周期大于相邻间隔。

## 4. 自定义流密码：约束求解

自定义递推（如 `enc[i] = (flag[i] + key[i%13] + enc[i-1]) % 128`）优先用 Z3/BitVec 建模，而不是逐位分析。要点：

- 以已知明文前缀作为锚点，缩小搜索。
- 所有未知量加打印性/取值范围约束。
- 递推引用前面的密文时，按顺序展开求解。
- 若服务是“位移种子预言机”（每次偏移改变种子），把种子位移量作为未知量一并建模。

约束满足即得候选密钥与明文；仍需回代原始递推验证每一位。

## 5. 现代流密码（eSTREAM 家族）

Trivium/Grain/Mickey 等以非线性状态更新为特征，直接线性化不可行。可行路线是对**削减轮数**建模：

- 把状态、密钥、IV 设为 BitVec，展开有限步更新。
- 用已知 keystream 位约束输出等式。
- 保持系统低次数（Trivium 的 3 个 AND 门为二次），Sage 布尔多项式或 Z3 均可。

参数检查清单：Grain-v1（80 bit key、64 bit IV、160 状态）、Grain-128a（128/96/256/320，反馈含认证）；Trivium 288 bit 状态。题目若为完整轮数，通常存在实现错误或参数缩减，先审代码。

## 6. 其他技巧

- **keystream 撞编码**：输出经过游程或简单编码时，先逆向编码再找 keystream 规律。
- **密钥来自环境**：主机名、DNS 查询名等可能直接作为 XOR key；有抓包时可从流量中提取候选 key 再验证。
- **多段复用**：同源多段密文按位置异或，结合可打印性约束恢复每段。

## 7. 纪律

先恢复 keystream 再谈攻击；识别生成器结构时至少用两种独立证据（递推检验 + 偏差/差分测试）。候选参数必须通过对原始密文的完整解密与 magic/可打印性验证，不能只匹配前若干字节。记录 keystream、位宽、tap、密钥长度和验证结果，避免同一生成器反复误判。
