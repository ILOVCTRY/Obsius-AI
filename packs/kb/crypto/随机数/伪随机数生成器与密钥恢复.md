# 伪随机数生成器与密钥恢复

部分位泄漏、输出遮蔽与状态污染见 [[crypto/随机数/PRNG 攻击（CTF 手法）.md|PRNG 进阶攻击]]；格工具见 [[crypto/格与后量子/格与 LWE 攻击.md|格与 LWE]]。

## 0. 判据速查

| 现象 | 方向 | 手段 |
|---|---|---|
| 给 MT19937 连续 624 个 32 位输出 | 状态完全恢复 | untemper → 预测 |
| 只给 `random.random()` 浮点 | 等价 53 位输出 | GF(2) 矩阵反推 |
| 输出有线性递推 | LCG/线性 | 差分求参数 |
| 种子来自时间/PID/文件名 | 种子可预测 | 时间窗暴力 |
| 目标进程用 C `rand()` | 同步复放 | ctypes 载同一 libc |
| 密钥由 flag/口令派生 | 非随机源 | 逐字节 oracle/爬山 |
| 混沌映射（logistic/Henon） | 量化初值 | 小域暴力 |
| BBS 且 `n` 为偶数 | 奇偶直接泄漏 | 线性恢复 |

## 1. 状态恢复通用流程

1. **反 temper**：若输出经过 xor-shift/mask 输出函数，先求逆变换得到内部状态位。
2. **恢复参数或状态**：线性生成器解线性系统；截断输出归约到格/HNP。
3. **预测与验证**：用已观测之外的数据验证；不匹配时检查对齐、字节序、跳过了预热输出。
4. **导出密钥/令牌**：按目标实现的方式（字节拼接、取模、哈希）复现，而不是照抄“下一次输出”。

## 2. 各生成器

### MT19937

- 624 个连续 32 位输出可直接 untemper 得完整状态；不足 624 时结合 GF(2) 线性关系部分恢复。
- `random.random()` 浮点等价 53 位输出，可用预计算 GF(2) 矩阵反推状态（约需 3360 个浮点）；同时用于伪造依赖该流的令牌。
- V8 `Math.random()` 是 XorShift128+ + double 转换，且输出按 LIFO 缓存顺序返回：先逆缓存顺序再解状态。

### LCG

已知若干连续输出可解 `a, b (mod m)`：用相邻差消去 `b`，再解乘法参数；`m` 已知时差分即可，未知时需额外样本或格。恢复后前后预测生成流；若密钥就是 LCG 输出序列，直接同步。

### PCG / xoroshiro / xoshiro

- PCG：先解底层 LCG 状态递推，再处理输出置换（XSH-RR/XSL-RR）；旋转量未知时可枚举 64 种并用后续输出验证。
- xoroshiro/xoshiro：状态更新在 GF(2) 上线性，置混淆器为约束，用 Z3/Sage 联立求解；先确认是 `+`、`**` 还是 `starstar` 混淆器。

### 其他

- **middle-square**：状态空间小时直接暴力；seed 来源若是 `time*1000 % 10^6` 则仅 10⁶ 候选。
- **logistic / Henon / Arnold cat**：量化到有限精度时对小域初值暴力；Henon-XOR 层可结合 PNG 头等已知明文给候选打分。
- **BBS**：`p,q ≡ 3 (mod 4)`（Blum 素数）时 LSB 不可预测；但 `n` 为偶数时奇偶性直接泄漏，可按线性方式恢复后续位。

## 3. 种子可预测

- **时间种子**：用文件 mtime、日志时间或题面给出的事件时间圈定窗口，按秒（或毫秒）枚举并验证输出/加密结果。时区、时钟偏移和容器时间粒度都会移动真实种子，窗口要放宽。
- **C 库同步**：目标若用同一 libc 的 `srand(time(NULL)); rand()`，用 `ctypes` 加载相同 `libc`，在同一秒播种即可复现序列（需核对 `RAND_MAX` 与调用次数差异）。
- **派生密钥**：对称密钥若由时间戳/PID 派生，同样按候选空间枚举并用已知明文验证；ChaCha20 等若 key 来自可预测源，不需要攻击算法本身。

## 4. 非随机源做 PRNG

- 若流由 flag/口令字节驱动，可用逐字节 oracle（每次只改一位看输出变化）或爬山（按匹配得分逐位修正）恢复源。
- 目标把多段数据按同一密钥复用（RSA key reuse/replay）时，先判断是否真的同源，再走对应数学攻击，而不是当作 PRNG 问题。

## 5. 口令恢复策略

`hashcat`/`john` 的组织方式：先按哈希类型确定 mode，再从规则、掩码、字典到混合逐级扩大搜索空间；命中后立即停止并验证。记录使用的模式、规则集与耗时，避免在失败模式上重复消耗预算。

## 6. 纪律

先判断输出是完整、截断还是仅有统计泄漏；反 temper 与线性恢复只能处理线性部分，非线性输出函数必须作为约束求解。所有候选状态/参数必须用未参与恢复的观测验证，再按目标实现复现密钥或令牌。仅对授权目标执行口令与密钥恢复。
