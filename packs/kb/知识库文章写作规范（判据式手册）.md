# 知识库文章写作规范（判据式手册）

> 本文件是**写手册时的对照表**，不是知识本身。新增/改写任何 `packs/kb/` 手册前先读一遍。
> 机械可校验的部分已落进 `core/skills/doctor.py` 与 `core/skills/proposals.py`。

## 0. 一句话口径

**手册回答「我卡住了，下一步查哪」，不回答「我这一题怎么解的」。**

判据三段式（全库统一）：

| 段 | 回答什么 | 反例 |
|---|---|---|
| **看到什么现象** | 用工具能直接观测到的（字段值、报错、结构异常） | 「这题是 CAN 总线题」——题面信息不是现象 |
| **该做什么** | 具体命令/操作，可复制执行 | 「分析一下流量」——不可执行 |
| **什么情况算不成立** | 失效条件，防止模型在错误方向上死磕 | 无——没有失效条件等于没有判据 |

## 1. 两种标准模板

### 模板 A：穷举型（适合「介质/入口明确，方向多」）

适用：图片隐写、杂项、编码、协议异常——**入口唯一，但可能性有十几条**。

```markdown
# 图片隐写

## 测试面

| # | 方向 | 判据 | 动作 |
|---|---|---|---|
| 1 | 元数据检查 | `exiftool` 有非常规字段 | 读 EXIF/XMP/ICC/comment 全字段 |
| 2 | 附加数据 | `binwalk` 检出尾部嵌入 | `binwalk -e` 分离 |
| ... | | | |

> 成本分层：1-3 结构层（不破像素）→ 4-6 数据层 → 7-8 序列层 → 9-11 感知层 → 12 兜底。

## 1. 元数据检查

**判据**：`exiftool` 输出里出现 `Comment`/`Author`/`XPComment` 等非常规字段，
或 `strings` 出现可读长串但像素统计正常。

**动作**：
```bash
exiftool -a -u -g1 file.jpg        # -u 显示未知字段，关键
```

**不成立**：字段全为相机默认值（`Make`/`Model`/`DateTime`）且无自由文本 → 跳过。

## 2. 附加数据
...
```

### 模板 B：选路型（适合「现象明确，但手法多且互斥」）

适用：PWN、Crypto、Web 反序列化——**现象已定，要选哪条利用路径**。

```markdown
# 堆利用

## 判据速查

| 手上的原语 / 现状 | 首选手法 | 去哪节 |
|---|---|---|
| 有 UAF + 能改 freed 块的 `fd` | tcache poisoning（注意 safe-linking） | §1 |
| glibc ≥ 2.34，hooks 已移除 | House of Apple 2 | §2 |
| 能改 top chunk 的 `size`（< 2.29） | House of Force | §7 |

## 1. tcache poisoning 与 safe-linking

**判据**：能对已 free 的块写 `fd`。

```python
mangled_fd = target_addr ^ (current_chunk_addr >> 12)
```

**不成立**：目标块在 tcache 且 `key` 校验通过但 `counts` 已满 → 走 fastbin。
```

## 2. 硬性规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **首节必须是表**，标题用 `## 测试面` 或 `## 0. 判据速查` | 卡住时先看表，不读全文 |
| 2 | 表头三列固定语义：`方向/手法` + `判据` + `动作/去哪节` | 检索与人工扫读都靠这三列 |
| 3 | **每个方向一个 H2**，节内按「判据 → 动作 → 不成立」写 | 可被 skill 用 `§标题` 精确引用 |
| 4 | 禁止 `本题`/`实测`/`该题`/`这道题` 叙述 | 那是解题日志，不是知识 |
| 5 | 禁止把答案、帧号、偏移、哈希、flag 写进表格 | 换题即失效，且会误导模型 |
| 6 | 数字只保留**阈值与量级**（`< 30%`、`高一个数量级`），不留观测值 | 观测值属于单题 |
| 7 | 失效条件必写；没有失效条件的方向不成立 | 无失效判据 = 会让模型死磕 |
| 8 | 命令块只放可复制执行的，不放伪代码占位 | 「这里填 payload」等于没写 |
| 9 | 长手册（> 400 行）必须配 `.idx.md` 分段索引 | `kb_open` 返回全文，会撑爆上下文 |

## 3. 反面样例（真实的坏写法）

下面这段是**典型错误**，看到自己写成这样就停下重写：

```markdown
| 口径 | 取值方法（本题实测值） |
|---|---|
| 全局帧号 | 12149 |
| pcapng 块偏移 | 0x8E6B4 |
```

三处违规：①「本题实测值」进了表头；②答案 `12149` 成了表格内容；
③`0x8E6B4` 对任何其他题都无意义。

**正确写法**：

```markdown
| 口径 | 取值方法 | 常见误用 |
|---|---|---|
| 全局帧号 | `-e frame.number`（1-based，Wireshark 状态栏同值） | 与流内序号混报 |
| 块偏移 | `-e frame.offset` | 当成文件偏移 |
```

## 4. 单题素材怎么处理

做完一道题，**先判断它是不是新方向**，再决定写不写：

| 情况 | 动作 |
|---|---|
| 已有方向的**新变体** | 并入该方向节，加一句「变体：…」，不新开篇 |
| **全新方向**（表里没有） | 表格加一行 + 新开一个 H2 节 |
| 只是**这一题的参数/答案** | 不写进库，留在会话或 WP 里 |
| 已消化的整题 WP | 抽成判据后原文删除（见 `赛事专题/判据库/`） |

## 5. 与 skill 的关系

手册不是孤立的：新增一篇或新增一个方向，**必须同步三个面**：

| 面 | 文件 | 改什么 |
|---|---|---|
| 知识本体 | `packs/kb/<域>/<模块>/<手册>.md` | 测试面表 + 方向节 |
| 技能入口 | `packs/kb/skills/<阶段>/<技能>/SKILL.md` | 穷举表加一行 + `→ 详解` 路径 |
| 任务导航 | `packs/kb/route_index.yaml` | `point` / `match` / `kb` 条目 |

漏了第 2 面，模型永远不知道该方向存在；漏了第 3 面，`route_lookup` 命中不到。
两者都不是靠"记得"保证的——见 `doctor.py` 的 `kb-route-missing` 与 `kb-skill-orphan` 检查。

## 6. 渐进式入口（长手册必须做）

**问题**：`kb_open` 返回**全文且不支持锚点**。一篇 1000+ 行的手册一次打开约 40KB，
把上下文挤满，模型反而看不到后面的方向。

**做法**：三面协同，让模型只读需要的那一节。

| 面 | 写什么 | 例 |
|---|---|---|
| 手册本体 | 每个方向一个 H2，节号与「测试面」表**一一对应** | `## 4. LSB` |
| 分段索引 `<手册>.idx.md` | 导航表：`\| § \| 方向 \| 行范围 \| 什么时候读 \|` | `\| 4 \| LSB \| L443-L514 \| zsteg 有输出 \|` |
| `SKILL.md` 表 | 加一列「详解」，写 `§N · L<行号>` | `\| 4 \| LSB \| zsteg 有输出 \| zsteg -a \| §4 · L443 \|` |

`SKILL.md` 里同时要写清读取顺序：

```markdown
**渐进式读取**（重要）：`图片隐写.md` 有 720 行，`kb_open` 会返回全文挤占上下文。
已知方向时**先读分段索引** `forensics/隐写与信号/图片隐写.idx.md` 拿行号，
再用 `read_file` 带 offset/limit 只读那一节。只有完全没头绪时才整篇打开。
```

**行号会漂移**：任何增删节的操作都会让后面的行号全部失效。改完必须用脚本重算
（遍历 H2/H3 取真实起止行），不能手改。`doctor.py::kb-long-manual-no-index`
会报出所有 > 400 行但没配 `.idx.md` 的手册，`pack_doctor.py --list-long` 出全清单。
