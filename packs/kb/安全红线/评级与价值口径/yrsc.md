# yrsc 评级与价值口径（判级条款 / 资产价值分级…）

## 严重漏洞：

1.能获取任意用户的摄像头实时视频及回放。(通过API越权等业务逻辑类漏洞可直接获取任意用户的摄像头实时视频或历史视频回放数据。能够影响的用户需要达到一定体量且大于等于一千用户，如不满足按照实际情况酌情评分)

2.直接获取核心系统权限的漏洞。包括但不仅限于：命令注入、远程命令执行、上传获取 WebShell、SQL 注入获取系统权限、缓冲区溢出（包括可利用的 ActiveX 缓冲区溢出）、远程内核代码执行漏洞以及其它因逻辑问题导致的远程代码执行漏洞(以确认获取到的权限为判断依据)。

3.严重的信息泄漏。包括但不限于核心DB的SQL注入漏洞、需泄漏三个及以上的敏感信息字段，且影响数量达到一定量级（大于等于10万条）；如不满足，按照实际情况酌情评分（敏感信息字段是指个人真实姓名、身份证号、住址、联系方式、银行卡号、完整交易信息等）。

4.直接影响现金交易的(非等价现金的虚拟商品或增值服务，需满足可直接提现且无利用限制，并且影响金额超过十万)。

5.严重的逻辑设计缺陷。包括但不仅限于对核心域名产品的任意账号登陆、任意账号密码修改(能够影响的用户需要达到一定体量且大于等于一千用户，如不满足按照实际情况酌情评分，分布式爆破场景不适用于严重漏洞)。

## 高危漏洞：

1.直接获取一般系统权限的漏洞。包括但不仅限于：命令注入、远程命令执行、上传获取 WebShell、SQL 注入获取系统权限、缓冲区溢出（包括可利用的 ActiveX 缓冲区溢出）、远程内核代码执行漏洞以及其它因逻辑问题导致的远程代码执行漏洞(以确认获取到的权限为判断依据)。

2.敏感的信息泄漏。包括但不限于非核心DB的SQL注入漏洞、需泄漏三个及以上的敏感信息字段，且影响数量达到一定量级（大于等于1万条）；如不满足，按照实际情况酌情评分（敏感信息字段是指个人真实姓名、身份证号、住址、联系方式、银行卡号、完整交易信息等）。

3.能直接访问萤石内网且可完全回显的 SSRF 漏洞。

4.重要系统的越权。包括但不仅限于越权修改重要信息、绕过认证直接访问管理后台、重要业务配置修改等较为重要的越权操作(根据实际业务场景判定)

5.未授权访问核心管理平台并具备管理员权限。包括但不限于敏感管理后台登录;相关平台的活跃度、用户基数(用户量不少于千人)、功能重要性、用户信息敏感度等将作为高危漏洞的评级标准。

## 中危漏洞：

1.能直接盗取用户身份信息的漏洞。包括重点页面的存储型XSS漏洞、普通站SQL注入漏洞。

2.越权访问。包括但不仅限于普通接口越权绕过限制修改用户资料、执行用户操作、后台弱口令等 (根据实际业务场景判定)

3.普通信息泄露。包括但不限于云平台密钥泄露，能证明可利用且可产生一定危害或泄露一定量的个人敏感信息(按照实际情况酌情评分)。

4.绕过限制获取增值产品服务的优惠(例如：无限获取试用套餐次数、多次领取优惠券等，边缘/冷门产品会继续降级)

5.未授权获取普通管理平台的管理员权限。

6.对于需用户主动点击链接、输入信息、授权操作等交互行为，或依赖社工/钓鱼手段才能获取设备权限、用户信息、账户权限的漏洞，不直接判定为高危及以上级别。需结合业务场景、攻击链路的实际利用门槛与稳定性进行评估，根据实际影响范围、用户交互必要性、利用成功率进行降级处理，一般最高不超过中危等级。

## 低危漏洞：

1.需交互才能获取用户身份信息的漏洞。包括但不限于反射型 XSS（包括反射型 DOM-XSS）、JSON Hijacking、重要敏感操作的CSRF、普通业务的存储型 XSS。

2.轻微逻辑设计缺陷。包括但不仅限于短信验证码绕过、邮件验证绕过、短信验证码暴力破解、短信轰炸等。

3.轻微信息泄漏漏洞。包括但不限于 GitHub 泄露的内部系统源码、phpinfo、logcat 敏感信息泄漏、正确的内网账号密码。

4.边缘系统的越权访问。包括但不限于非重要核心功能接口越权操作。

## 无影响：

1.无关安全的bug。包括但不限于网页乱码、产品功能缺陷、样式混乱。

2.无法利用的“漏洞”。包括但不限于没有实际意义的扫描器漏洞报告（如 Web Server的 低版本）、Self-XSS、无敏感信息的 JSON Hijacking、无敏感操作的 CSRF、无意义的源码泄漏、内网 IP 地址/域名泄漏、无敏感信息的 logcat 信息泄漏。

3.部分风险过低或难以利用的漏洞。包括但不限于 PDF XSS、URL跳转、邮箱轰炸、无法请求内网的SSRF、无回显的SSRF、用户名枚举、并发请求操作某些产品中不重要的数据（如浏览量、报名人数、不重要的点赞评分功能）、无意义的API Key泄露、只提供 dnslog 的命令执行漏洞。

4.不能直接体现漏洞的其他问题。包括但不仅限于纯属用户猜测的问题。

5.不能重现的漏洞。包括但不限于经YSRC专员确认无法重现的漏洞。

6.通过其他渠道已经获知的漏洞做忽略处理，并会通过漏洞提交途径告知漏洞提交者。

7.非萤石业务漏洞、不涉及萤石产品自身 BUG 且非萤石产品直接造成的安全问题。

8.不收取测试环境、预发布环境、私有云演示环境漏洞(例如域名中开头带有t、test、pb等)，除非可证明该漏洞同时能对线上环境造成危害。

9.移动客户端本地拒绝服务漏洞。包括但不限于组件权限导致的本地拒绝服务漏洞。

10.对于仅通过短信、社交媒体、二维码等方式诱导用户访问非萤石官方域名（含IP地址）的钓鱼类攻击场景，本身不直接属于业务安全漏洞，不予收录。
