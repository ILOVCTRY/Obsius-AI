# 取证与应急响应判据库

> 来源：37 篇取证赛题 WP + 部分二进制赛题中涉及取证的 WP
> （162 条观测 / 83 条失败尝试）。主库 `forensics/` 已有各工具手册，
> 本文补**按证据层分流**与**工控协议判据**两类。

## 0. 判据速查

| 现象 | 判据 | 去哪节 |
|---|---|---|
| 给了 `.raw`/`.mem`/`.vmem` | 内存镜像，先 profile | §2 |
| 给了 `.E01`/`.dd`/`.vmdk` | 磁盘镜像，先挂载只读 | §3 |
| 给了 `pcap`/`pcapng` | 网络流量 | §4 |
| 给了 Modbus/S7comm/OPC UA | 工控协议 | §5 |
| 给了 APK/备份/`msgstore.db` | 移动取证 | §6 |
| 问「什么时候中的招」 | 时间线，先建统一时区 | §1.2 |
| 问「后门账号是谁加的」 | `/etc/passwd` 的 uid=0 | §1.1 |
| 问「回连到哪」 | 网络连接 + 进程 | §1.3 |

## 1. 主机应急响应

**判据**：题目给的是一个 Linux/Windows 系统的目录快照或登录权限。

### 1.1 五个必查点（Linux）

```bash
# 1. 特权账号（uid=0 但名字不是 root）
grep ':0:' /etc/passwd
# 2. 可登录账号
grep -E '(/bin/bash|/bin/sh)$' /etc/passwd
# 3. sudo 权限
cat /etc/sudoers; ls /etc/sudoers.d/
# 4. SUID 文件
find / -perm -4000 -type f 2>/dev/null
# 5. 定时任务
crontab -l; ls -la /etc/cron.*; cat /etc/crontab
```

判据是**上面五项里出现「不该有的」**。`uid=0` 的非 root 账号是最高优先级。

### 1.2 时间线

```bash
# 统一时区再排序，否则时间线是错的
find / -newermt '2024-01-01' -type f -printf '%T+ %p\n' 2>/dev/null | sort
# 关键文件的时间
stat /etc/passwd /etc/crontab /root/.bash_history
```

判据是**文件修改时间（mtime）与访问时间（atime）的差异**。攻击者通常 `touch` 改 mtime 但不改 ctime。

**关键**：`ctime` 无法被用户改（只能被系统改），所以 `ctime > mtime` 说明 mtime 被伪造过。

### 1.3 回连与进程

```bash
# 网络连接与对应进程
ss -antp; lsof -i -P -n
# 进程树（看异常父子关系）
ps auxf
# 进程打开的文件
lsof -p <pid>
# 进程的可执行文件路径
ls -l /proc/<pid>/exe
# 进程的环境变量（常含 flag 或密钥）
cat /proc/<pid>/environ | tr '\0' '\n'
```

判据是**进程的可执行文件已被删除（`/proc/<pid>/exe` 指向 `(deleted)`）**——这是典型的木马自删除。

### 1.4 日志

```text
/var/log/secure         RHEL 系 SSH 登录
/var/log/auth.log       Debian 系
/var/log/wtmp           last 命令读
/var/log/btmp           失败登录（lastb）
/var/log/lastlog        lastlog
~/.bash_history         命令历史
/root/.viminfo          vim 编辑记录
```

```bash
# 找爆破 IP（失败次数排序）
awk '{print $(NF-3)}' /var/log/secure | sort | uniq -c | sort -rn | head
# 找成功登录
grep 'Accepted' /var/log/secure
```

判据是**同一 IP 大量失败后出现一次成功**——这是爆破成功的标志。

## 2. 内存取证

**判据**：给了 `.raw`/`.mem`/`.vmem`/`.dmp`。

### 2.1 第一步永远是 profile

```bash
# Volatility 2
volatility -f mem.raw imageinfo
# Volatility 3（自动识别，不用 profile）
vol -f mem.raw windows.info
```

判据是**镜像的操作系统与版本**。Volatility 2 必须指定 profile，3 自动识别。

### 2.2 标准流程（Windows）

```bash
vol -f mem.raw windows.pslist        # 进程列表
vol -f mem.raw windows.pstree        # 进程树（看异常父子）
vol -f mem.raw windows.cmdline       # 命令行
vol -f mem.raw windows.netscan       # 网络连接
vol -f mem.raw windows.malfind       # 可疑内存段（注入）
vol -f mem.raw windows.hashdump      # 密码哈希
vol -f mem.raw windows.lsadump       # LSA 密钥
vol -f mem.raw windows.filescan      # 文件句柄
vol -f mem.raw windows.dumpfiles --physaddr <addr>   # dump 文件
```

判据是**`malfind` 的输出**。有 `PAGE_EXECUTE_READWRITE` 且有 `MZ` 头的内存段就是注入的 PE。

### 2.3 Linux 内存

```bash
vol -f mem.raw linux.pslist
vol -f mem.raw linux.bash        # 命令历史（从内存里捞）
vol -f mem.raw linux.envars
```

判据是**`linux.bash` 能捞到 `.bash_history` 里被删的命令**。

## 3. 磁盘取证

**判据**：给了镜像文件。

### 3.1 挂载（只读！）

```bash
# 先看分区表
fdisk -l disk.img
# 算偏移（起始扇区 * 512）
mount -o ro,loop,offset=$((2048*512)) disk.img /mnt
# E01 格式先用 ewfmount
ewfmount image.E01 /mnt/ewf
```

判据是**分区偏移**。挂载失败多半是偏移算错。

### 3.2 已删除文件恢复

```bash
# ext4
extundelete disk.img --restore-all
# NTFS
ntfsundelete disk.img -u -i <inode>
# 通用 carving
photorec disk.img
binwalk -e disk.img
```

判据是**文件系统类型**。`file disk.img` 或 `fdisk -l` 能看出来。

### 3.3 关键痕迹位置

| Windows | 内容 |
|---|---|
| `C:\Windows\System32\config\SAM` | 本地账号哈希 |
| `C:\Windows\System32\config\SYSTEM` | 系统配置（含 USB 记录） |
| `C:\Windows\System32\winevt\Logs\*.evtx` | 事件日志 |
| `C:\Windows\Prefetch\*.pf` | 程序执行记录 |
| `C:\Users\*\NTUSER.DAT` | 用户注册表（含最近文件） |
| `C:\Users\*\AppData\Local\Microsoft\Windows\UsrClass.dat` | ShellBag（文件夹访问） |
| `$Recycle.Bin` | 回收站 |
| `$MFT` | 主文件表（含全部文件记录） |

| Linux | 内容 |
|---|---|
| `/var/log/` | 系统日志 |
| `/root/.bash_history` | root 命令历史 |
| `/etc/passwd`, `/etc/shadow` | 账号 |
| `/var/spool/cron/` | 定时任务 |

判据是**问题问的是什么**。问「谁插过 U 盘」查 `SYSTEM` 的 `USBSTOR`；问「运行过什么程序」查 Prefetch。

### 3.4 USB 插入证据

```text
注册表路径：SYSTEM\CurrentControlSet\Enum\USBSTOR
每个键含设备型号与序列号
配合 setupapi.dev.log 能拿到首次插入时间
IndexerVolumeGuid 是卷的 GUID 记录
```

判据是**`USBSTOR` 下的子键**。有序列号就能定位到具体设备。

## 4. 网络取证

**判据**：给了 pcap。见 `misc/赛事专题/判据库/文件与流量-判据.md` §2，这里只补工控与协议细节。

### 4.1 快速定位

```bash
# 协议分布
tshark -r a.pcap -q -z io,phs
# 会话列表
tshark -r a.pcap -q -z conv,tcp
# 导出 HTTP 对象
tshark -r a.pcap --export-objects http,out/
# 全局搜关键字
tshark -r a.pcap -Y 'frame contains "flag"'
```

判据是**协议分布里有没有异常协议**（比如 HTTP 里混了 DNS 隧道）。

### 4.2 常见隐蔽通道

| 通道 | 提取命令 |
|---|---|
| DNS 查询名 | `tshark -r a.pcap -Y dns -T fields -e dns.qry.name` |
| ICMP data | `tshark -r a.pcap -Y icmp -T fields -e data.data` |
| HTTP Cookie | `tshark -r a.pcap -Y http.cookie -T fields -e http.cookie` |
| TCP 载荷 | `tshark -r a.pcap -T fields -e tcp.payload` |

判据是**同一字段持续变化且不符合协议规范**。

**坑**：ICMP 的序列号在 Wireshark 里默认按小端显示，按协议应是大端。解析时要注意。

## 5. 工控协议

**判据**：流量里有 Modbus / S7comm / OPC UA / IEC104 / DNP3。

| 协议 | 端口 | Wireshark 过滤器 | 关键字段 |
|---|---|---|---|
| Modbus TCP | 502 | `modbus` | `func_code`、`regval_uint16` |
| S7comm | 102 | `s7comm` | `header.errcod`、`param.func` |
| OPC UA | 4840 | `opcua` | `NodeId` |
| IEC 104 | 2404 | `iec60870_104` | `ioa`（信息体地址） |
| DNP3 | 20000 | `dnp3` | `al_objtype` |
| FINS | 9600 | `fins` | 魔数 `46494e53` |
| MQTT | 1883 | `mqtt` | `topic`、`msg` |

### 5.1 判据

```text
Modbus func_code = 5   → 写单个线圈（开/关阀门）
Modbus func_code = 6   → 写单个寄存器
Modbus func_code = 8   → 诊断（常被忽视的隐蔽通道）
Modbus func_code = 16  → 写多个寄存器
S7comm errcod != 0x00  → 异常响应（可能是攻击探测）
```

判据是**功能码的语义**。写操作（5/6/16）出现在「不该写」的时间点就是攻击。

### 5.2 数据提取

```bash
# Modbus 寄存器值
tshark -r a.pcap -Y modbus -T fields -e modbus.regval_uint16
# 数值转字节再拼
```

判据是**寄存器值拼起来是不是文件头**。比如 `35152 = 0x8950`，是 PNG 的前两字节。

## 6. 移动取证

**判据**：给了 APK、手机备份、或 `msgstore.db`。

| 目标 | 位置 |
|---|---|
| 应用数据 | `/data/data/<package>/` |
| 数据库 | `/data/data/<package>/databases/*.db` |
| 偏好 | `/data/data/<package>/shared_prefs/*.xml` |
| 缓存 | `/data/data/<package>/cache/` |
| 外部存储 | `/sdcard/Android/data/<package>/` |

```bash
# 备份文件解开
abe.jar unpack backup.ab backup.tar
# 或
python abe.py unpack backup.ab backup.tar
```

判据是**`backup.ab` 的加密状态**。未加密可直接解 tar，加密需要密码。

## 7. 纪律

- **先判证据层，再选工具**。内存镜像用 Volatility，磁盘镜像用挂载，流量用 tshark，不要混。
- **挂载一定加 `ro`**，写操作会破坏证据。
- **时间线先统一时区**，否则排序全错。
- **`ctime` 比 `mtime` 可信**，`ctime > mtime` 说明 mtime 被改过。
- **内存取证先 `imageinfo`/`info`**，profile 错了后面全错。
- **工控题先看功能码语义**，写操作在异常时间点就是攻击。
- **答案格式要精确**（手机号、身份证、MD5 大小写），格式错等于没做对。
