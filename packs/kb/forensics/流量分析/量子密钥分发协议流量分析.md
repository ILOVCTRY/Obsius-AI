# 量子密钥分发（QKD/BB84）流量分析

QKD 协议流量题的通病：题目伪装成「量子物理」，实际考点仍是经典密码学错误——明文控制面、
密钥流复用、PRNG 可预测。物理原理不构成任何安全性，**协议实现细节才是攻击面**。

核心排序（按性价比）：**已知明文恢复 keystream > 基串 sifting 派生密钥 > PRNG 预测**。

## 测试面

| # | 方向 | 判据（怎么发现） | 动作 |
|---|---|---|---|
| 1 | 控制面明文提取 | 载荷里出现 `SEED:` / `XOR_KEY:` / `KEY:` 前缀，或 `+`/`x`（`×`）组成的长串 | 逐包抽 payload，按前缀与字符集分类为「控制包 / 密文包」 |
| 2 | 密钥流复用检测 | 密文长度相近、条数多、无响应包 | 比对固定位置的 `ct ⊕ 推测 pt`，看是否得到同一循环串 |
| 3 | 诱饵字段排除 | 明文给的 seed/key 解不开任何一条密文 | 按 PRNG 实现穷举抽取顺序；脱靶即判定为诱饵，转 §2 |
| 4 | 基串 sifting 派生密钥 | 基选择串被明文广播，且诱饵 key 无效 | 按 `+`/`x` 分组取 bit，作候选密钥去试解 |

## 1. 控制面明文提取

**前置**：只要能读出每条报文的 payload 即可（tshark 可用，或纯 Python 解析 pcap/pcapng；
注意链路类型不一定是以太网，Raw IP 抓包需按 IP 头起解，无 TCP 头时直接取 IP 之后全部字节）。

**判据**：报文数量与长度分布呈「少量短报文 + 大量等长短报文」两簇；短报文是 ASCII 可打印、
带 `名字:值` 结构；长报文整体不可打印。

**动作**：把每条 payload 打印成 `序号 / 源-目的端口 / 长度 / repr 前缀`，人工一眼分类。
同一源端口连续发往递增目的端口的单向流，通常就是一个会话的全部报文，无握手、无应答。

**不成立**：payload 全不可打印且没有任何带冒号前缀的短包 → 控制面被加密，转 §2 仍按
「等长短报文模板」思路走；若流量是标准协议（TLS/HTTP2）而不是自定义协议，说明方向错了，
回到通用流量分析：`tshark -q -z io,phs` 看协议分层。

**降级**：无 tshark 时用纯 Python 读 pcapng（分块：SHB/IDB/EPB），或先判链路类型；
pcapng 的 EPB 里有 Interface ID，多接口时按 IDB 的 LinkType 分别解。

## 2. 已知明文恢复密钥流（首选）

**前置**：至少 2 条以上密文共用同一密钥流（XOR 或同长度 OTP 复用），且其中一条的明文结构
可推测（固定前后缀、数字段、模板句）。不需要知道任何 key。

**判据**：把两条密文互异或后，结果里出现成片的零字节或可读 ASCII——这是模板重叠的直接证据。
单条密文里固定列位置（如开头 `flag{`、结尾 `}`）的 `ct ⊕ pt` 在**多条密文上取同一值**，
则该值就是该位置的密钥流字节。

**动作**：对所有密文按字节下标分组，对每个下标收集「`ct[i] ⊕ 推测pt[i]`」的票数，
取票数最高的候选；若最高票与次高票差距悬殊，说明模板推断正确，逐字节恢复出完整循环密钥流
（密钥流通常远短于密文，按密文长度取模复用）。恢复后用其解密所有密文，挑出**唯一突破模板的那条**
（长度/内层格式与其余不同的那条），即目标明文。

**不成立**：逐列投票出现票数分散、无唯一赢家 → 说明各条密文的明文模板不同或密钥流逐条变化，
此时改用 §4 的 sifting 派生密钥路径，或回到「密钥流每条独立」的假设去找 PRNG。

**降级**：没有固定前后缀模板时，用「明文为可打印 ASCII」这一约束做单字节穷举——对每个位置试
256 个候选，保留使整条密文全部落在可打印区间的 `ct ⊕ pt` 值，多条文交叉取交集。

## 3. 诱饵字段排除（防死磕）

**前置**：控制面明文给了 seed 或 key，需要用同语言（通常是 CPython `random`）的 PRNG 复现。

**判据**：按 seed 复现，尝试 `randint` / `choice` / `getrandbits` / `randrange` / `randbytes`
× 不同抽取顺序与字节序，全部复现不出后续任何一条密文的密钥流或控制串的完整内容。

**动作**：一旦出现「部分匹配」——只对上了某个串的前若干字符之后开始脱靶——就要怀疑
seed 是单独为这半段编的诱饵，不是真实密钥流来源。此时不要在 PRNG 上继续加组合，
直接转 §2：用密文本身恢复密钥流，成本低一个数量级。

**不成立**：若某个抽取顺序能稳定复现控制串全部内容且能解开机密报文，则这个 PRNG 才是真路径，
按 seed 前向推导即可（此时也顺便检查是否存在跨会话同 seed）。

**降级**：无对应版本运行时时，手写该 PRNG 的核心（如 MT19937 的 state 初始化与 tempering），
只实现用到的输出函数，避免为跑一条推测装整套环境。

## 4. 基串 sifting 派生密钥

**前置**：抓包里存在被明文广播的基选择串（`+` 与 `x`/`×` 两种字符），长度明显长于密文所需
密钥字节数；同时控制面给的 key 已被 §3 证明是诱饵。

**判据**：基串长度 / 8 ≥ 密文密钥长度，说明它足够当密钥来源；且题目强调 BB84，sifting
（按基过滤）本就是协议关键步骤，是出题人预设的第二条路径。

**动作**：按两种基把基串分成两组，各自按 `+`=1/`x`=0（及反向）打包成 bit 流，
再试 MSB/LSB 两种位序、目标明文前缀对齐偏移遍历，逐候选去解那条异常密文；
同时检查是否残留纠错码/隐私放大步骤的输出（额外短包可能就是隐私放大后的密钥）。

**不成立**：所有基串派生候选都解不出可打印明文，且 §2 已拿到唯一合理明文 →
说明基串只是协议演示的装饰，停止该方向。

**降级**：给不出明文模板时，用「解出结果必须全可打印且含花括号」作为 oracle 自动筛候选，
不必人工逐个看。

## 5. 已验证路径与常见坑（复现要点）

**适用条件**：自定义二进制协议的单向抓包，控制面短包明文、载荷包等长且数量上百。

**已验证路径**（按此顺序，最省时）：① 抽全部 payload 并按长度/前缀分成控制包与密文包；
② 用密文固定列 `ct ⊕ 推测pt` 逐列投票恢复循环密钥流，检查每列最高票是否远高于次高票；
③ 用它解密全部密文，找与模板不一致的那一条即目标。

**常见坑**：
- **在 PRNG 上死磕**：seed 常是诱饵，穷举输出函数与抽取顺序容易耗掉大部分时间且全脱靶；
  出现"部分匹配后脱靶"就应立即止损转已知明文路径。
- **误把明文 key 当真密钥**：控制面的 `XOR_KEY:` 一类字段可能故意给错，先拿它对一条密文试解，
  解不出可打印就判诱饵，不要反复怀疑自己的解析。
- **忽略链路类型**：Raw IP / LINKTYPE 129 之类的抓包没有以太网帧头，直接按以太网偏移解析会整体错位。
- **只看诱饵不看异常包**：绝大多数密文长得一样，突破口往往是长度/内层格式唯一不同的那一条。
