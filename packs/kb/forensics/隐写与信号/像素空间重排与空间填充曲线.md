# 像素空间重排与空间填充曲线

> 与 [[forensics/隐写与信号/图片隐写.md|图片隐写全方向]] 互补：那边按“载体层”穷举（元数据→附加→结构→LSB→调色板→…），
> 这边处理**像素集合不变、只有顺序被换掉**的一类。两类题的外观差异极大，不要混着试。

## 测试面

| # | 方向 | 判据（怎么发现） | 动作 |
|---|---|---|---|
| 1 | 尺寸数论特征 | 图像边长恰为 2 的整数次幂或 3 的整数次幂；像素总数是完全幂/完全平方 | 记下边长 N，阶数 k 由 N = 基数^k 反解，据此确定曲线族基数 |
| 2 | 提示层分离 | 主图结束标记之后仍有完整图像或文本；尾随图高度是基数（2/3）的倍数 | 剥离尾随数据，按 y 相位均分成多帧分别看 |
| 3 | 颜色基数 | 画面只有极少数颜色（二值/三值），且呈规则横竖条纹或纯色块 | 直方图取前若干色的占比，确定载荷是二值还是多值 |
| 4 | 曲线族判据 | 提示里出现方向字母集（wasd / hjkl）、分形/维度/填充/降维一类词 | 按提示选曲线族：Hilbert、Peano、Morton(Z-order)、Gosper、Sierpiński |
| 5 | 产生式校验 | 生成点集大小 == 像素数；去重后仍 == 像素数；相邻点曼哈顿距离恒为 1 | 三条硬校验全过才写回，比“看起来像”可靠 |
| 6 | 逆映射写回 | 重排后出现二维码三个 finder pattern、成行文字或规则模块格 | 按曲线点序逆置回二维并翻转 y |
| 7 | 解码前处理 | 逆映射后结构明显，但扫码器返回 0 个符号 | 反色 / 二值化 / 最近邻放大后再扫；注意前景背景对比度 |

**成本分层**：1-2 秒级（看尺寸、看尾部）；3-4 决定曲线族；5-7 是求解主体。先做 1-2，不要一上来爆参数。

## 适用条件（何时该走这条线）

**判据**：三条同时成立才值得投入——① 边长是 2^k 或 3^k；② 全图用色极少且呈规则条纹/纯色块；
③ 常规通道全部干净（`zsteg -a` 无输出、chunk 无文本、尾部无追加或追加物本身就是提示）。
满足三条说明“像素没被改值，只是被改了位置”。

**动作**：先按 §1 反解阶数，再按 §2 取提示层，只有提示层或配色明确指向“曲线/分形/维度”时才进 §5。

**不成立**：若用色分布连续（自然照片）或 `zsteg` 有输出 → 属于改值型隐写，
回 [[forensics/隐写与信号/图片隐写.md|图片隐写全方向]]，不要在本页继续。

## 1. 尺寸数论特征

**前置**：只需能读文件头里的宽高（`file`/`identify`/Pillow 任一），无需任何解码库。
**判据**：边长落在 2^k 或 3^k 上（如 2 的十次上下、3 的五到七次方），
或宽高不等但**乘积**是整齐的幂。空间填充曲线的第 k 阶恰好铺满 基数^k × 基数^k，
尺寸对不上说明要么阶数取错、要么图被裁掉了一部分。

**动作**：
```bash
identify -format "%w %h %[colors]\n" pic.png   # 宽 高 实际用色数
python3 - <<'PY'
n = 729
for base in (2, 3, 4):
    k = 0
    while base ** k < n: k += 1
    print(base, k, base ** k == n)
PY
```

**不成立**：边长既不是 2 的幂也不是 3 的幂，且所有候选基数下都不整除 → 不是曲线族题，
转图片隐写全方向的 §8 空间轴（切块拼图）。

**降级**：没有 ImageMagick 时用 Pillow 读 `im.size` 与 `len(im.getcolors(maxcolors=1<<20))`；
连 Pillow 也没有时手工读 PNG 的 IHDR（第 16-24 字节是两个大端 32 位宽高），结论等价。

## 2. 提示层分离

**前置**：只需文件读权限与 Python 标准库（`open`/`rfind`）；`binwalk` 仅用于加速定位，非必需。
**判据**：文件尾不在标准结束标记处；`binwalk`/`foremost` 在结束标记之后列出第二个完整图像。
尾随图常常不是载荷本身，而是**提示牌**——里面写着曲线族、维度、方向序列。

**动作**：
```bash
binwalk pic.png
python3 - <<'PY'
d = open('pic.png','rb').read()
i = d.rfind(b'IEND') + 8
open('tail.bin','wb').write(d[i:])
print('tail bytes', len(d) - i)
PY
file tail.bin
```
尾随图高度是 2 或 3 的倍数时，按 y 均分成 2/3 帧分别渲染，提示文字常被压成多条窄带叠在一起。

**不成立**：结束标记就在文件末尾 → 无提示层，曲线族只能靠颜色基数和外观猜，转 §3。

**降级**：`binwalk` 缺失时用 `rfind`/`find` 枚举所有已知魔数出现位置，逐个按偏移切出再 `file` 判类型；
`file` 也没有时按首字节判断（`89 50 4e 47`=PNG、`50 4b 03 04`=ZIP、`FF D8`=JPEG）。

## 3. 颜色基数与符号化

**前置**：需要能遍历像素的库（Pillow）或能解 PNG 的 IDAT（`zlib.decompress` + 按 filter 逐行 unfilter）；
纯命令行也可用 `convert pic.png -format %c histogram:info:-` 代替。
**判据**：直方图里前 2-3 种颜色占比接近 100%，其余为零星过渡色（压缩/抗锯齿引入）。

**动作**：
```python
from PIL import Image
im = Image.open('pic.png').convert('RGB')
cols = im.getcolors(maxcolors=1 << 22)
cols.sort(reverse=True)
print(cols[:5], 'total colors', len(cols))
```
取占比最高的两种颜色做阈值分割，得到 0/1 位图；三种颜色则可能是三进制符号（0/1/2），
但**三进制符号不等于三进制曲线**——先按 §4 判断到底是“顺序被打乱”还是“值被当成符号”。

**不成立**：颜色数上百且分布连续（自然照片）→ 不是索引式打散，回图片隐写的 LSB/频域方向。

**降级**：无 Pillow 时先手工解 IDAT（`zlib.decompress` 后按行首 filter 字节做 Sub/Up/Average/Paeth 还原）
再统计直方图；连 zlib 都没有时用 `convert pic.png -colors 8 -format %c histogram:info:-` 看前 8 色占比，
占比结论足以支撑判据，不需要全像素遍历。

## 4. 曲线族判据（选路）

| 手上的线索 | 首选手法 | 去哪节 |
|---|---|---|
| 提示出现方向字母集（wasd 等）+ 分形/维度词 | L-system 生成空间填充曲线 | §5 |
| 边长为 2^k，提示里出现 “Hilbert/分形/递归四象限” | Hilbert 曲线（基元 4 种朝向） | §5 |
| 边长为 3^k，提示里出现 “Peano/九宫格/3×3” | Peano 曲线（基元 9 种朝向） | §5 |
| 无提示，边长 2^k，打散像是按坐标位交错 | Morton / Z-order（2-adic 位交错） | §5 的位交错分支 |
| 打散后局部仍有连续块，只是块之间错位 | 块级置换（网格切分重排） | 图片隐写 §8 空间轴 |

**判据**：把曲线族与基元朝向当作有限假设集，**每个假设都必须过 §5 的三条硬校验**，过了才写回。
盲目枚举朝向而不校验，会得到一堆“看起来有点结构”的噪声图。

**不成立**：所有曲线族的点集都无法与像素数对上（双射不成立）→ 顺序没被换，回图片隐写主表。

**降级**：容器里没有分形库时不要装依赖，L-system 只需字符串替换 + 海龟走位，纯 Python 几十行即可。

## 5. 产生式校验（关键步骤）

**前置**：能用 Python 读像素（Pillow，或手工解 PNG 的 IDAT + unfilter）；曲线阶数 k 已由 §1 反解。
**判据**：三条硬校验全部通过才算找到正确产生式——
① `#F`（前进指令数）== 像素数 − 1；
② 生成点集去重后大小 == 像素数（双射，每个像素恰好访问一次）；
③ 相邻采样点曼哈顿距离恒为 1（曲线连续，没有跳步）。

**动作**（L-system 生成 + 校验，参数化后逐个假设跑）：
```python
RULES = {
    # 三元(Peano)与二元(Hilbert)各一组，公理 X，delta=90°
    'peano':   {'X': 'XF+YFY+FX-F-XFXFX-FYFY+', 'Y': '-XFXF+YFYFY+F+YF-XFX-FY'},
    'hilbert': {'X': '+YF-XFX-FY+',            'Y': '-XF+YFY+FX-'},
}

def expand(ax, rules, k):
    s = ax
    for _ in range(k):
        s = ''.join(rules.get(c, c) for c in s)
    return s

def walk(s):
    dirs = [(1, 0), (0, 1), (-1, 0), (0, -1)]   # E N W S，'+' 逆时针
    x = y = d = 0
    pts = [(0, 0)]
    for c in s:
        if c == 'F':
            dx, dy = dirs[d]; x += dx; y += dy; pts.append((x, y))
        elif c == '+': d = (d + 1) % 4
        elif c == '-': d = (d - 1) % 4
    return pts

def check(pts, npix):
    uniq = len(set(pts))
    maxstep = max(abs(a[0]-b[0]) + abs(a[1]-b[1]) for a, b in zip(pts, pts[1:]))
    return {'count_ok': len(pts) == npix,
            'bijection': uniq == npix == len(pts),
            'continuous': maxstep == 1}
```
转向符号（`+`/`-`）与起始朝向是四个等价变体，**不要凭外观挑**：四种组合都跑一遍校验，
只有通过校验的那些才继续；都不通过说明产生式串本身抄错了一个字符。

**不成立**：某个变体三项全过但写回后仍是噪声 → 曲线对、但**映射方向反了**（把“被打散后的位置读成原始位置”），
改用逆映射（pts 当作逆置换）再试一次；两次都不成才放弃该曲线族。

**降级**：内存吃紧时别展开整条指令串——按字符流式走位、只保留 `F` 处的坐标，
或把展开改成按需递归求第 i 个点的坐标；`#F` 与点集大小仍可实测得到。

## 6. 逆映射写回

**前置**：§5 的三条校验已通过并得到长度 == 像素数的点序 `pts`；有 Pillow 或能直接写 PPM 的文件写权限。
**判据**：写回图的角落出现标准二维码 finder pattern（三个回字形角标 + 一个定位格），
或出现成行文字/规则模块格——这是“顺序确实是这条曲线”的第二次独立确认。

**动作**：
```python
from PIL import Image
src = Image.open('pic.png').convert('RGB')
W, H = src.size
px = list(src.getdata())

xs = [p[0] for p in pts]; ys = [p[1] for p in pts]
minx, miny = min(xs), min(ys)
canvas = [None] * (W * H)
for i, (x, y) in enumerate(pts):
    canvas[(H - 1 - (y - miny)) * W + (x - minx)] = px[i]   # 海龟 y 向上，Pillow y 向下
out = Image.new('RGB', (W, H))
out.putdata(canvas)
out.save('unshuffled.png')
```
顺序写回（`out[pts[i]] = px[i]`）与逆序写回（`out[i] = px[pts[i]]`）是互逆的两种假设，
**两种都要存图并都送解码器**，不解码器之前不要靠肉眼判“哪张对”。

**不成立**：两种写回都只是噪声 → 回到 §5 换曲线族/变体，不要继续调颜色。

**降级**：无 Pillow 时直接写 PPM（`P6` 头 + RGB 字节，写文件只需标准库 `open`），
再用 `convert`/`zbarimg` 消费；坐标系方面，海龟 y 轴与位图 y 轴方向不一致是“结构对了但图是镜像/倒置”的
最常见原因，可把四种 transpose 翻转各存一张一起送解码器。

## 7. 解码前处理

**前置**：有一个能解 QR/条码的解码器（`zbarimg`；或 Python 的 `pyzbar`/`zxing` 之一）；
若全都没有，改用 §7 降级的模块格手工判定路径。
**判据**：写回图结构明显（能看出码/字）但 `zbarimg` 返回 `scanned 0 barcode symbols`。

**动作**：
```bash
zbarimg -q unshuffled.png
convert unshuffled.png -negate inv.png && zbarimg -q inv.png     # 前景背景对比度不足
convert unshuffled.png -colorspace Gray -threshold 50% -resize 300% big.png && zbarimg -q big.png
zbarimg -Sqr.enable -q --raw inv.png
```
二维码的编码区域只要定位图案完整、模块格清晰就能读出；颜色反了、缩放不是整数倍才扫不出。
**单符号输出但内容极短且无结构（如单个标点）按误检处理**，不要当载荷。

**不成立**：反色 + 二值化 + 整数倍放大后仍 0 符号 → 内容可能不是图形码，
按位图重新当文本流解码（行优先/列优先、MSB/LSB）或回 §5 换曲线族。

**降级**：没有解码器时，先用肉眼确认三个 finder pattern 存在（存在即说明曲线解得对，
剩下的只是解码问题）；再按标准 QR 的版本表定位模块格尺寸，逐格取中心颜色得到位矩阵，
套用格式信息里的掩码与纠错等级自行解出。此法不需要任何外部库，只慢。

## 复现步骤（最短可执行路径）

**判据**：想快速验证一条曲线假设是否成立时按此顺序，前一步不成立立刻回头而不是继续往下。

**动作**：① 取尺寸与用色数 → 反解基数与阶数；② 结束标记之后 dump 尾随数据并渲染，
读出提示（曲线族、方向字母集、维度）；③ 用 §5 脚本对候选产生式跑三项硬校验，
只保留全过的变体；④ 顺序/逆序两种写回各存一张；⑤ 反色 + 二值化 + 整数倍放大后送解码器。

**不成立**：③ 阶段没有任何变体通过双射校验 → 顺序未被重排，直接放弃本类假设。

## 常见的坑

- **只做一次写回方向就判定失败**：顺序写回与逆序写回互逆，两种都要出图送解码器；只试一种会把正确答案丢掉。
- **海龟坐标系与图像坐标系反向**：曲线点集的 y 轴向上、位图 y 轴向下，漏了翻转会得到镜像/倒置图，
  看起来“结构对了”但解码器必然失败；先试四种 transpose 翻转再怀疑曲线。
- **把“三进制符号”当成“三进制曲线”**：颜色 0/1/2 量化出的符号流与 3-adic 曲线遍历是两件事，
  前者不成立不代表后者不成立，反之亦然；分开验。
- **低置信扫码结果当作载荷**：解码器报单个标点且质量值极低时按误检处理，不要据此宣布“条码解出来了”。
- **在改值型隐写里死磕曲线**：`zsteg -a` 有输出、chunk 里有文本时优先走图片隐写主表，曲线族一定不成立。
- **依赖没装就放弃**：曲线生成只需字符串替换 + 走位，扫码也可退化为模块格手工取位，
  不需要科学计算或 CV 库；缺库时按各节“降级”走，不要反复尝试安装。
