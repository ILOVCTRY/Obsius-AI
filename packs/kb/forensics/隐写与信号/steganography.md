# 通用隐写结构与容器分析

图像格式专属手法见 [[forensics/隐写与信号/stego-image.md|图像格式隐写与载体修复]]；FFT、SSTV、音频、视频、JPEG XL 等进阶手法见 [[forensics/隐写与信号/stego-advanced.md|图像隐写进阶]]；编码判定见 [[misc/编码解码/encodings.md|编码与解码基础]]；DNS/网络隐蔽信道见 [[forensics/网络取证/network-advanced.md|高级网络取证与隐蔽信道]]。

## 0. 判据速查

| 现象 | 优先检查 | 常见误区 |
|---|---|---|
| 文件能打开但尺寸异常 | 尾部追加、魔数被覆盖、多流容器 | 只按声明尺寸读取 |
| 图像正常但内容“少一块” | IHDR 宽高/CRC、chunk 顺序、帧数 | 只检查 magic 与 CRC |
| 文档有“看不见”的文字/图形 | 注释、链接、矢量矩形、压缩流、元数据 | 只跑 `strings` |
| 同源两份文件互相覆盖 | 交错、叠加、异或嵌套 | 先跑通用 LSB 工具 |
| 终端/矢量输出很大 | 转义序列、keyframe、微坐标 | 直接渲染后截图 |
| 图看起来全重复/可“对眼” | 自相关求重复宽度，做差 | 纯肉眼观察 |

## 1. 容器边界与格式修复

### 1.1 尾部追加与魔数覆盖

格式逻辑结束标记（如 PNG `IEND`）之后仍可附加数据；追加段的魔数也可能被改写成宿主格式签名以便伪装。定位结束标记后检查尾部，按候选 magic（ZIP `PK`、7z `37 7a bc af`、gzip `1f 8b`）识别并切分到工作副本。不要在原文件上直接改写。

### 1.2 PNG 尺寸与 chunk

- IHDR 宽高与可见内容不符：用 CRC 反推正确高度（CRC 匹配即为原始值）；若 CRC 也被改，先试提高高度再重算 CRC 并验证 IDAT 可完整解码。
- chunk 顺序非法：官方要求 IHDR 在前、IDAT 连续、IEND 结束；按类型重排时保留原 CRC，仅调整顺序。
- chunk 名大小写决定 critical/ancillary/private/safe；小写的关键 chunk 会被忽略。
- 多帧 PNG：检查 `acTL/fcTL/fdAT`，普通查看器只显示第一帧；用 APNG 工具导出全部帧后再逐帧分析。
- 自定义 chunk：非标准四字母类型通常被解析器忽略，却是理想的载荷容器；逐 chunk dump 并按长度切分。

### 1.3 多流容器

MP4/MKV 等可含多个视频/音频/字幕轨，播放器默认只显示第一条。先枚举全部流，再按 index 提取：

```bash
ffprobe -hide_banner file.mp4
ffmpeg -i file.mp4 -map 0:1 -c copy second.mp4
```

注意 `handler_name`、语言标签等元数据可能只是线索。隐藏轨可能使用少见编码，提取失败时先校验轨道参数与解码器可用性。

## 2. 结构元数据载体

### 2.1 PDF

把 PDF 当结构文件而不是文本：对象、流、注释、页面树和元数据都是可能载体。检查顺序建议：

1. `strings`/对象级扫描，找注释与隐藏文本片段。
2. 解压 FlateDecode 流后再搜索；压缩流里常藏 `strings` 看不到的内容。
3. 解包后检查注释、链接 `/Annots` 与 `/URI`（注意 `\{`、`\}` 等转义）、表单域和 OpenAction。
4. 用 pdfimages 抽取所有嵌入图像，另行做隐写分析；模糊/涂黑区域可用反卷积或移除覆盖物还原。
5. 内容流里的矢量图形可能是伪装的二维码：解析 `re` 等绘制算子，取几何中心重建成栅格再解码。
6. 元数据（Producer/Author/Keywords）与 `%%EOF` 之后的尾部都要看。
7. 图像 LSB 可能不在 bit0；逐通道逐位面检查后再判定。

### 2.2 SVG

动画 keyframe 的颜色交替可编码二进制（如两种填充色对应 0/1），间隔时长可再叠一层 Morse；先解析 `<animate>` 的 `keyTimes/values`，再按色值与时间双重解码。

SVG 的坐标精度可能承载微尺度图形：某些 `<g>` 的坐标聚集在极小范围，正常视口下不可见。检查小数位数异常的坐标，通过 viewBox/transform 放大到该区域后再渲染。

### 2.3 终端协议与转义序列

Kitty 图形协议把图像分块编码进 `ESC_G...;base64` 序列，头部带格式、压缩（如 zlib）、尺寸和后续块标志；按块拼接后再 base64/zlib 解码，按 `f=24` 等字段还原像素。ANSI 终端艺术可能在转义码之间插入不可见文本；剥离转义序列与特定字符集后可取回，注意区分“真隐藏字符”与正常排版字符。

### 2.4 表格与结构化数据

单元格数值的频次排序可能构成字节映射。先统计唯一值数量（接近 256 提示按字节处理），按频率排序得到值→序号映射，再替换并验证输出是否为可识别文件。频率相近或映射不唯一时不要硬解，需结合出现位置或 padding 规则。

## 3. 交错与多层数据

### 3.1 字节/行交错

两份文件按奇偶字节交错时，按步长切分即可还原；但识别标志常是切分后仍“有条纹”。此时再做一次扫描线级 deinterleave（奇偶行/列）。双层扩展名、目标文件重复 magic 都可作为线索。

### 3.2 嵌套与渐进层

嵌套 PNG 常通过自定义 chunk 逐层 XOR，key 可能是递增词或由上一层内容揭示；每层解密后重新走 chunk 解析。用已知频数字节（如 `FF`）跑异或分析，得到候选 key 后逐层验证。短重复 key XOR 会保留大尺度像素结构，即使未完全解密也可能出现可读图案——这只能作为存在性证据，仍需完整解密确认。

Angecryption 说明 AES-CBC 也可以构造出“加密后仍是合法文件”的特例：给定 key/IV 时可能从一个合法文件得到另一个合法文件。遇到两份结构相似的文件与密钥材料，可构造验证；不要把它当作通用“无损加密”假设。

## 4. 视觉与信号恢复

### 4.1 立体图与自动立体图

重复宽度是核心参数。对单行做自相关，取中心后第一个峰值作为移位量；再用图像与移位副本做差，重复背景相消后显现深度/文字。移位量不对时输出接近噪声，应扫描候选范围并比较可读性。

### 4.2 帧间差分

GIF/视频中的隐藏信息可能只在相邻帧差异中出现：逐帧导出后比较对应像素，把“是否变化”“变化量”“变化位置”三种假设分别尝试。压缩编码、帧尺寸不一致和调色板差异会造成伪差异，先统一帧格式再定义规则；结果按 Morse、ASCII 或文件 magic 复核。

### 4.3 反射/残缺二维码

球面反射、遮挡、低分辨率二维码可借助结构先验：先找 finder pattern 与尺寸推定版本，再反变换（镜像/去畸变/缩放）；模块不确定时用已知明文修正早期数据位，让 ECC 纠正剩余错误。手工转录只在工作副本进行，保留原始帧与每一步矩阵。

### 4.4 调色板帧编码

帧数异常多且为完全平方数时，可能是“每帧一像素”的调色板编码：每帧像素相同但 palette 不同，用调色板首项决定黑白后即可按 √n 拼出隐藏图。先验证帧数与尺寸关系，再检查调色板索引规则。

## 5. 边界像素与视觉编码

一像素边框的黑白可承载位流：沿固定方向（顺时针/逆时针）遍历边框，按亮度阈值取 bit。方向、起点和阈值都要先用已知样本或同步位确认。边框宽可能不是 1 像素；也可能是内嵌第二层图案而非纯黑白位。

## 6. 纪律

容器题优先看“文件比内容大多少”和“结构比渲染多什么”。任何提取都必须跨层验证：magic、长度、CRC、zlib 可解、图像可解码、文本可读。遇到多层嵌套时记录当前层使用的 key/chunk/偏移，避免重复或跳层。题面名称只提出假设，最终结论必须由字节级证据支撑。
