# EDUC 评教育行业资产评级规则（高危 / 中危标准，edu.cn / 教育部资产一律走此套）

> **类别：评级与价值口径（F11，2026-09-17）**——注入时带判级硬指令：severity 必须按本文件判级，rating_basis 填「rating:edu-rating 条款+一句话依据」；授权/无害化边界仍跟 owners 侧规则。
> 触发条件：**目标属教育行业资产**——各级各类学校/高校的 `.edu.cn` 一级/二级域名与相关资产、各省教育厅/人社局、中科院体系单位等 EDUSRC 收录范围。
> 生效：凡判定为上述教育资产，**漏洞评级与是否申报**一律按本规则的高危/中危标准核定，不再用其他口径；授权/无害化边界仍跟 `edusrc-rules.md`。
> 来源：本工作区多校 HRMS 上报实战校准（2026-09-08），与用户明确给定判级标准合并沉淀。

## 高危（High）——满足任一条即高危

1. **直接获取普通系统权限**：远程命令执行 / 代码执行 / 上传 webshell / 缓冲区溢出等。
2. **严重逻辑设计缺陷与流程缺陷**：任意账号密码修改 / 重要业务配置修改 / 泄露。
3. **可直接批量盗取用户身份权限**：普通系统 SQL 注入 / 用户订单遍历等。
4. **严重权限绕过**：绕过认证直登管理后台 / cookie 欺骗。
5. **运维相关未授权访问**：后台管理员弱口令 / 服务未授权访问（如 MinIO、Redis、ES、Kibana 等未授权/弱口令）。

申报前提：**须有交互性实证**。仅「端口公网开放 + FOFA 佐证」不够——例如 MinIO 控制台只到「:9001 对公网开放、疑似弱口令」而无实际登进去拿凭证，**不得按高危（第 5 条）申报**；必须在放行对应端口的出口实测拿到控制台/未授权才升高危。

## 中危（Medium）——满足任一条即中危

1. **一定条件下获取服务器/网站/核心数据库数据**：交互性代码执行 / 一定条件的注入 / 特定系统版本下的 getshell 等。
2. **任意文件操作**：任意文件写 / 删除 / 下载 / 敏感文件读取等。
3. **水平权限绕过**：绕过限制修改用户资料 / 执行用户操作。

### 关键技术裁定：什么才算「任意文件写」（实测沉淀，判定核心）

- **任意文件写 = 覆盖式**：能写任意路径/内容、**能覆盖已存在文件**、能写关键配置、能配 getshell（LFI 写、模板注入写、写 /tmp 等）。核心是「覆盖 OVERWRITE + 路径可控」。
- **新增上传 ≠ 任意文件写**：仅能对对象存储/某目录做「新增 PUT」而非覆盖——如 `POST /oss/upload` 把对象新增进 S3/MinIO 桶、且 final key 由服务端加时间戳/前缀生成、上传参数无目录与 key 控制点 → **不构成「任意文件写」**。归类为「未授权新增对象上传 + 公网可读托管」，**定中危临界/偏下**，不得锚定「中危·任意文件操作」。
- 要把它升为「任意文件写」/中危核，**需补验下列之一并实测通过**：
  - Content-Type 可控 → 存储型 XSS（投放 `.html`/`.svg` 被用户浏览器按 HTML 解析）；
  - 覆盖已存在对象（key 碰撞 / 破坏他人数据，落「任意文件写」）；
  - 桶越权读 / 列表（落「任意文件下载 / 敏感读」）。
- 以上三条拿不到交互实证时，**如实按临界/偏下交付，不虚报中危**。

## 低危（Low）——满足任一条即低危

1. **能够获取一些数据，但不属于核心数据的操作**：非核心业务数据、低敏数据的未授权/越权读取、受影响面有限的交互，未涉及身份证/手机/证件照等强敏感字段或核心业务流程。
2. **在条件严苛的环境下能够获取核心数据或者控制核心业务的操作**：利用链可行但前置条件苛刻（如需先获得强敏感输入组合/特定身份/极窄可利用窗口），实际难以稳定批量触发。
3. **需要用户交互才可以触发的漏洞**：主要指存储型/反射型 XSS 等须诱导用户点击、输入或经过有状态会话才能被触发的场景；主动交互面（管理员后台操作）中仅能靠用户点击实现的影响。

> 低危档与中危档边界：能稳定、低门槛、无用户交互就拿到强敏感数据或直接影响核心业务 → 中危；拿到的是非核心数据 / 条件严苛才拿得到核心数据 / 必须靠用户交互触发 → 低危。拿不准向下不虚报。

## 判级操作要求

- **只认实证**：判级以实测交互结果为准，推演/契约/FOFA 扫描仅作佐证并在报告如实标注「未获实测」。高危尤其如此。
- **锁面/上线流程不变**：挖什么跟 `src-value-hunting`、范围/持续跟 `dig-scope-workflow`、报告格式只跟 `vuln-report-format`；本规则只负责**评级口径**。
- **命名准确、不夸大**：洞的类型命名贴合本质（如「未授权新增对象上传+公网可读」而非「任意文件写」），避免为冲等级拔高定性。
- 与 萤石(YSRC)/OPPO(OSRC) 规则冲突时：**更严者生效**；但教育资产生效前提是注册白帽 + 无害化三原则（认 `edusrc-rules.md`）。

## 与其他规则层级

- 本规则压过通用默认评级惯例；教育资产生效时与 `edusrc-rules.md` 同时读——前者给「授权 + 无害边界」，后者给「评级口径」。
- 不改变「CORS 不深挖」「短信轰炸不报」等既有禁令。
