## 约定与坑

- 平台/格式/漏洞类**不建包**，只走 frontmatter 标签（platforms/formats/vuln_classes）+ file_features 路由加权。
- `rules/*.md` 不递归是有意设计：owners/、rating/、role-rules/ 借此天然分层，不自动注入。
- `packs/kb/route_index.yaml`（v0.65）维护路径：人工直改或 index 提案（M0 只能 edit 增补，Agent 不直写，doctor 体检三类 warning 兜底）；条目挂 tags 才参与角色裁剪，无 tags 全角色可见。
- rating/ 是「评级与价值口径」（F11，判级依据+资产/目标价值分级），owners/ 是「接触程度红线」（授权边界/操作红线）；同一 tag 可两处各有文件，语义不同，doctor 只要求 rating 有 owners 配套（反向不要求）。
- 专家 yaml 字段全是软边界：skills/task_types 为 null = 不过滤（不是拒绝一切）；skills=null（全量专家）在 caps_effective 语境=全能力包。
- 改路由权重/标签词表先改 DESIGN.md；测试护栏在 tests/test_skills.py（真实包断言 + 夹具评分断言）。
- 跑测试：`E:\Miniconda3\python.exe -m pytest tests/test_skills.py -q`（先设 PYTHONIOENCODING=utf-8）。
