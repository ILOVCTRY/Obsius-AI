# core/api/

> core API：HTTP + WebSocket 把黑板/任务/会话/编排暴露给 WebUI 与 CLI（DESIGN.md：所有写经 core API 单一入口）。**全项目唯一 import fastapi 的地方**，核心引擎保持零依赖。

## 文件

- `app.py` — `create_app(workspace_root, packs_root, tools_root, *, executor_llm=None, planner_llm=None, providers_config=config/providers.json, static_dir=None)`。`app.state.llm_store`=ProviderStore（多供应商）；`app.state.campaign`=CampaignMemory（全局库 `data/campaign.db`，构造内含老位置惰性迁移）。LLM 缺省=路由覆写目标或全局默认；测试可注入 executor_llm 或 tmp providers_config 避免种子污染。无可用 key → Agent/编排端点 **503**（不崩）。
- `JobRegistry` — 长耗时动作（跑 Agent / orchestrator tick/auto-tick/auto-wait/replan）后台线程执行，`POST` 返 job_id，`GET /api/jobs/{id}` 轮询；`submit(..., on_done=)` 状态翻 done/error 后回调（异常只 log），是 L2 链防搁浅的关键。**worker loop 每轮调 `agent.run_session()`**（会话中心化 v24）：有委托干活（`take_session_next` 读窗内队首，串行接件）、无委托 `run_chat()` 回应收件箱、都没有 None 空退回待命；异常 try/except 只 log+break，收尾由 `AgentSession._fail_task_on_error` 负责（异常静默杀线程曾致任务悬 claimed 孤儿心跳续租、看板永久「执行中」）。

## 端点速查（前缀 /api）

**分析包基础层**（无表，独立节）：`POST /projects/{pid}/sample-packages` 导入单文件/ZIP/7z/TAR 或目录（统一路径穿越/特殊条目/配额校验，返回包版本+候选目标+依赖边）；`.../sample-packages/uploads` 可恢复分片上传、`GET .../sample-packages[/{package_id}]`、`POST .../versions/{version_id}/targets`、`GET/POST .../targets/{target_id}` + `POST .../analyze`（复用 IDA/Ghidra headless 异步出报告——PE/ELF/Mach-O 正式分析，APK/AAB 只读解析 Manifest/DEX，其他格式返 `analyzer-unavailable` 不伪造成功）。旧 `/samples` 与 `/binaries/{sha}` 保持兼容。

## 关键约定

- **零业务逻辑**：只做 HTTP↔core 翻译，规则全在 blackboard/gateway/agent/orchestrator。
- **会话控制（§3）**：work/pause/resume/abort 先经 `_ensure_agent(pid,sid)`——内存命中直取，缺失（重启/历史孤儿窗）按黑板 sessions 行 rehydrate（meta 带 `resume_snapshot` 指针的行载回快照回 paused 可续跑），未知/closed 才 404；API 线程只置 Event，worker 在步边界消费。**重启清扫**：`_project` 惰性首开钩子 `_sweep_restarted_project`——孤儿 claimed 统一 fail(awaiting_human)；resume_snapshot 指针+快照文件双在场的会话其 claimed 保留；**重启即急停**对全部会话一律 `worker_armed→False`（防 kick 链把陈旧会话重新拉起）；**会话继续钮**对有快照文件的会话一律归位 paused。**优雅停机**：shutdown 钩子对在跑会话逐个 `pause_snapshot_now()` 落断点快照。阻塞路由用 `def`（FastAPI 自动线程池），WS 用 `run_in_threadpool` 调 SQLite。
- **rev 服务闭包 `_rev_service(proj)`**：每项目独立 cache/db 目录，缓存于 `app.state.rev_services[pid]`，构造时装 MCP 实时桥（配置缺失回 {} 绝不 500）；测试经 `app.state.rev_service_factory` 注入假后端。**Agent 会话工厂刻意不装 MCP**（无人值守不赌 GUI 当前库）；factory 第三参 `existing_session` 走 rehydrate；内层读 config.advisor 覆写本会话 planner_llm（**必须在 factory 内层**，外层会污染 Orchestrator 自身 plan_llm）。**例外**：Agent 的 decompile 经 `build_headless_service(mcp_provider=)` 回调 `ida_mcp_manager.ensure` 按需拉起无窗口 idat 实例（不违反不赌 GUI 库的红线）；manager 单例 + shutdown 钩子兜关。
- **审批 op 处理器（红线）**：`_APPROVAL_OP_HANDLERS` 是 dict 白名单分派，**绝不 eval**；`spawn_session` 生产方两处（编排器 L1 纯开窗单 + publish 绑窗成功后的执行审批单）——**Agent 工具集没有任何建单入口**（防伪造红线）；处理器在 `decide_approval` 翻状态**之后**跑，异常只落 `approval.exec_failed`（审批保持 approved，HTTP 200）。
- **L2 全自动链（纯事件驱动，无调度器/无轮询）**：唯一续 tick 闸门 `_maybe_auto_tick(pid,reason)`，七闸顺序=档位重读→paused→重启急停→预算双硬闸→无在跑 worker→无在跑 tick 系（硬去重=自动 job 内抢租约）→`chain_ticks>=max`→10s 节流。五触发点：A worker 空退、B tick 收尾、C 开窗落地、D 人手插话、E 审批批准；全部经 `_kick_workers` 与 **`_submit_worker`（agent-work 唯一提交口）**。停止原因八值；急停后链不自动恢复。
- **任务即窗口调度器（v0.72）**：唯一入口 `_schedule(pid, reason)`，两段式，整体持 `_schedule_lock`（RLock，防启动段读旧计数超卖）。绑定段（L1/L2 与 paused 建窗；**L0 跳过**）扫 open 且无绑定任务逐个 `_bind_task_window`；启动段（仅 L1/L2 且项目未 paused）先重读任务表，`claimed_count < max_concurrent_tasks` 时取最高优先级任务起跑（L2 才武装+提交 worker，L1 待命等审批）。触发点：publish、reopen、worker-idle、`_post_tick`、`_do_close_session`、**60s 后台 sweep**。⚠ `app.state.schedule_sweep = _schedule` 赋值必须在 `def _schedule` **定义之后**，放前面会变局部变量→UnboundLocalError 全套崩。
- **A5 优先级重排**：唯一自动入口 `_maybe_replan(pid,reason)`，四闸=L2 & !paused & 无 tick 系在跑 & 距上次 ≥30s；触发点 D（POST /tasks）与 A（worker 空退）；**无 open 空转不调 LLM、不刷计时**（否则紧随的正常触发必排长命 wait，曾堵死自动链）。
- **C2 作战模式接线**：会话创建时按 **project.track** 分支注入（redteam 轨注入红队语义+ROE 摘要，其余轨注入影响证明级上限）；mode 键退役剥离。**派生可观测**：mission 兜底轮询 daemon 线程（0=不启动，测试全局置 0 直调 `app.state.mission_poll_sweep()`）；`_emit_llm_error(pid,source,err,session_id=None)` 落 `llm.error`（60s 节流、429/quota 加 kind_hint，worker 循环死亡传真实异常文案+会话归属）。**L0 提案模式**：唯一接线点 `_build_orchestrator` 注入 `propose_only`；**没有独立采纳端点**——人点「采纳」即走既有 POST /tasks 与 POST /agents。
- **地址纪律**：headless 内部 int，出 API 一律 hex 字符串（JS Number 无 64 位精度），路径参数不带 0x；样本绝不执行，headless 定性 trusted 解析。
- packs 写操作三件套：建前查目录（重名 409/宿主不存在 404/非法 slug 422）、写前 `_pack_history_backup`（同秒避让 `.n`）、删除走 `_trash_move`；**所有 packs 写端点整体包进 `core.skills.writing.pack_write_lock()` 临界区**（进程内 RLock），仅保单进程部署。
- **删除项目前置链**：`_project_busy` → 置 `projects_closing` 闸门 → pop 缓存 → `browser_pool.close_project(pid)`（先停 Chromium 释放 profile 锁）→ `store.delete_project` 内 `bb.close_all()`+`proj.close()` → rename（退避重试，耗尽才 422）。双层关闭标志使旧引用访问即抛 `BlackboardClosedError`（全局 handler 转 409），**杜绝惰性重连在 Windows 上重新锁死 db**（曾是删除必 422 的根因）。启动：`scripts/serve.py [port]`（默认 127.0.0.1:8420）。
- **F6 浏览器装配**：`app.state.browser_pool = BrowserPool(...)`；shutdown 钩子 `close_all()`；**轨门控在 `_registered_session_factory`：`proj.track in ("pentest","redteam","ctf")` 才注入 dispatcher.browser**（轨外工具自动 no-tool，schema 仍全量下发）。

## 坑与注意

- Agent 开窗依赖真实 Ark key（.env），无 key 时 Agent 端点 503、黑板/任务端点照常可用；测试里 WS 收消息条数必须与事件数精确匹配，多收会挂（TestClient 无超时）。多进程部署（uvicorn workers>1）会让 app.state 会话表/任务 job 失效——当前按单进程设计。intel 端点注入口/惰性建库见 [`core/intel/CLAUDE.md`](../intel/CLAUDE.md)。
