# core/api/

> core API：HTTP + WebSocket 把黑板/会话/团队/编排暴露给 WebUI 与 CLI（DESIGN.md：所有写经 core API 单一入口）。**全项目唯一 import fastapi 的地方**，核心引擎保持零依赖。

## 文件

- `app.py` — `create_app(workspace_root, packs_root, tools_root, *, executor_llm=None, planner_llm=None, providers_config=config/providers.json, static_dir=None)`。`app.state.llm_store`=ProviderStore（多供应商）；`app.state.campaign`=CampaignMemory（全局库 `data/campaign.db`，构造内含老位置惰性迁移）。LLM 缺省=路由覆写目标或全局默认；测试可注入 executor_llm 或 tmp providers_config 避免种子污染。无可用 key → Agent/编排端点 **503**（不崩）。
- `JobRegistry` — 长耗时动作（跑 Agent / orchestrator tick·auto-tick·auto-wait / team-fanout / session-review）后台线程执行，`POST` 返 job_id，`GET /api/jobs/{id}` 轮询；`submit(..., on_done=)` 状态翻 done/error 后回调。**`_submit_worker` 是 agent-work job 唯一提交口**（Team 分支走 `_team_worker_loop`）；worker 循环 `agent.run_session()`：有窗内委托干活、无委托对话，都没有空退待命，**不扫描公共任务池**。**任务机制退役（2026-10-06）**：不再有任务认领/直派/绑定（`/work` 的 task_id 参数保留兼容但忽略），worker 异常由 `AgentSession._fail_task_on_error` 收口。

## Team direct API

`/projects/{pid}/teams` 是独立于旧 coordination DAG 的 Team/Member/Run API（**旧 `/coordination*` 端点群已随任务机制退役，2026-10-06**）。创建只登记 roster（draft，不建任务/会话）；`preflight` 生成 revision（revision 乐观锁 + 四项确认）；start 事务创建 Run 快照后由后台 `_fanout_team` 逐成员创建专属 session，并经 `_submit_worker` 的 Team 分支（`_team_worker_loop`）执行。新路径不调用 TaskQueue claim/take_session_next/start_direct；cancel 只 request_abort Team session，不调用旧 cancel_task。**`GET .../teams/{id}/runs`** 列团队历史 Run（新→旧，前端运行报告取最新）；团队生命周期事件（`team.created/updated/run.started/member.updated/run.finished`）由 `core/team/store.py` 在事务外发出（前端「指挥」页签团队卡消费）。指挥建队工具 `build_team` 即调本 API 的 `create_team`（只登记 draft）；`execute`（指挥亲自执行）不经本 API，由编排器直接建 `_generalist` 会话跑 `run_team_execution`。

## 端点速查（前缀 /api）

**分析包基础层**（无表，独立节）：`POST /projects/{pid}/sample-packages` 导入单文件/ZIP/7z/TAR 或目录（统一路径穿越/特殊条目/配额校验，返回**完整**分析包对象——含 `entries`/`origin`/`created_at`/`tree_ref`/`targets`/`dependencies`，与 `GET .../sample-packages/current` 同形，另附 `raw_sha256`/`undo_available`；2026-10-12 起不再回摘要——此前丢 `entries` 致前端上传后文件树为空、须手动刷新页面）；`.../sample-packages/uploads` 可恢复分片上传、`GET .../sample-packages[/{package_id}]`、`POST .../versions/{version_id}/targets`、`GET/POST .../targets/{target_id}` + `POST .../analyze`（复用 IDA/Ghidra headless 异步出报告——PE/ELF/Mach-O 正式分析，APK/AAB 只读解析 Manifest/DEX，其他格式返 `analyzer-unavailable` 不伪造成功）。**空文件（0 字节）允许进文件夹/追加上传（2026-10-12）**：`_write_upload_temp(allow_empty=)`——`files` 多选/`.../files` 追加走 `allow_empty=True`（空文件是合法目录成员，压缩包导入本就允许；此前文件夹里任一空文件会让**整批** 422「空文件」失败），单文件分支仍拒绝空文件。旧 `/samples` 与 `/binaries/{sha}` 保持兼容（走 `_spool_upload`，不受影响）。**上传物落项目工作区内（2026-10-13）**：内容树 `<project>/trees/<manifest_sha256>/`、原始上传物 `<project>/raw/`，不再写全局 `data/sample-store/`（旧全局树保留只读兼容，旧 `tree_ref` 仍可解析）。

**登记为资产（不复制文件，2026-10-12）**：`POST .../targets/{target_id}/register` 把包内 **PE/ELF/Mach-O** 目标登记为 `binary` 黑板资产（其余格式 422，仍走 `.../analyze`）——**不复制文件**，资产 `meta` 记包坐标 + **包内相对路径**（`{filename,size,path,source:"sample-package",package_id,version_id,target_id}`）。文件定位交 `_sample_path(proj,sha)`：`meta.source=="sample-package"` 时经 `_package_store().resolve_target` 还原为**项目内容树绝对路径**（`<project>/trees/`，同项目内跨包复用、不可变），否则原 `_inside(proj,meta.path)`。据此 `retry_triage`/`_run_binary_triage` 改吃**已解析绝对路径**（去内部 `_inside`）。**删除护栏**：`_purge_sample_files` 仅当 blob 落在 `proj.path` 内**且不在 `<proj>/trees`、`<proj>/raw` 下**才删——内容树/原始物绝不被删资产或删分析包动作波及。幂等：重复登记只 `update_asset_meta`。包内目标分析的缓存修复分支与 `_run_sample_target_analysis` 同走 `_register_package_binary_asset`。

## 关键约定

- **零业务逻辑**：只做 HTTP↔core 翻译，规则全在 blackboard/gateway/agent/orchestrator。
- **chat 僵尸轮运行期自愈（2026-10-11 事故）**：轮次后台线程可能静默死亡（没走正常收尾也没落 error），进程不重启则重启清扫够不着 → 线程永久 `running`（实测卡「思考中/执行中」2h+，停止钮也无效）。`_chat_running_reconcile(proj)` 扫 running 线程，其**原生线程号**（`app.state.chat_thread_idents`，`_run` 启动登记 / `finally` 弹出）经模块级 `_native_thread_alive` 判死则 `recover_running_threads` 归位 idle。**存活判据必须用原生退出码**：Windows 下线程被 `TerminateThread` 硬杀时 `Thread.is_alive()` 仍报 True（实测 exit_code 259→7 而 is_alive 恒 True），故 `_native_thread_alive` 走 `GetExitCodeThread`（259=活；非 259 或 OpenThread 失败=死；非 Windows/异常保守 True）。对账接线：`GET .../chat/threads`、`GET /api/chat/threads/{tid}`、mission-poll sweep。`chat_stop` 对「不在 running 集合但 DB running」的孤儿从空操作改为对账归位。
- **会话控制（§3）**：work/pause/resume/abort 先经 `_ensure_agent(pid,sid)`——内存命中直取，缺失（重启/历史孤儿窗）按黑板 sessions 行 rehydrate（meta 带 `resume_snapshot` 指针的行载回快照回 paused 可续跑），未知/closed 才 404；API 线程只置 Event，worker 在步边界消费。**重启清扫**：`_project` 惰性首开钩子 `_sweep_restarted_project`——孤儿 claimed 统一 fail(awaiting_human)；resume_snapshot 指针+快照文件双在场的会话其 claimed 保留；**重启即急停**对全部会话一律 `worker_armed→False`（防 kick 链把陈旧会话重新拉起）；**会话继续钮**对有快照文件的会话一律归位 paused。**优雅停机**：shutdown 钩子对在跑会话逐个 `pause_snapshot_now()` 落断点快照。阻塞路由用 `def`（FastAPI 自动线程池），WS 用 `run_in_threadpool` 调 SQLite。
- **rev 服务闭包 `_rev_service(proj)`**：每项目独立 cache/db 目录，缓存于 `app.state.rev_services[pid]`，构造时装 MCP 实时桥（配置缺失回 {} 绝不 500）；测试经 `app.state.rev_service_factory` 注入假后端。**Agent 会话工厂刻意不装 MCP**（无人值守不赌 GUI 当前库）；factory 第三参 `existing_session` 走 rehydrate；内层读 config.advisor 覆写本会话 planner_llm（**必须在 factory 内层**，外层会污染 Orchestrator 自身 plan_llm）。**例外**：Agent 的 decompile 经 `build_headless_service(mcp_provider=)` 回调 `ida_mcp_manager.ensure` 按需拉起无窗口 idat 实例（不违反不赌 GUI 库的红线）；manager 单例 + shutdown 钩子兜关。
- **审批 op 处理器（红线）**：`_APPROVAL_OP_HANDLERS` 是 dict 白名单分派，**绝不 eval**；白名单= `spawn_session`（纯开窗单）/`phase_transition`/`authorization`——**2026-10-06 任务退役删 `delegate_window`/`cancel_task`/`requeue_task`**；**Agent 工具集没有任何建单入口**（防伪造红线）；处理器在 `decide_approval` 翻状态**之后**跑，异常只落 `approval.exec_failed`（审批保持 approved，HTTP 200）。
- **L2 全自动链（纯事件驱动，无调度器/无轮询）**：唯一续 tick 闸门 `_maybe_auto_tick(pid,reason)`，七闸顺序=档位重读→paused→重启急停→预算双硬闸→无在跑 worker→无在跑 tick 系（硬去重=自动 job 内抢租约）→`chain_ticks>=max`→10s 节流。五触发点：A worker 空退、B tick 收尾、C 开窗落地、D 人手插话、E 审批批准；全部经 `_kick_workers` 与 **`_submit_worker`（agent-work 唯一提交口）**。停止原因八值；急停后链不自动恢复。
- **C2 作战模式接线**：会话创建时按 **project.track** 分支注入（redteam 轨注入红队语义+ROE 摘要，其余轨注入影响证明级上限）；mode 键退役剥离。**派生可观测**：mission 兜底轮询 daemon 线程（0=不启动，测试全局置 0 直调 `app.state.mission_poll_sweep()`；`require_idle` 改判 `autonomy.count_active_sessions`）；`_emit_llm_error(pid,source,err,session_id=None)` 落 `llm.error`（60s 节流、429/quota 加 kind_hint，worker 循环死亡传真实异常文案+会话归属）。**L0 提案模式**：唯一接线点 `_build_orchestrator` 注入 `propose_only`；**没有独立采纳端点**——人点「采纳」按提案 op 走对应人类入口落地（建队→`POST /teams`，开窗→`POST /agents`）。
- **地址纪律**：headless 内部 int，出 API 一律 hex 字符串（JS Number 无 64 位精度），路径参数不带 0x；样本绝不执行，headless 定性 trusted 解析。
- packs 写操作三件套：建前查目录（重名 409/宿主不存在 404/非法 slug 422）、写前 `_pack_history_backup`（同秒避让 `.n`）、删除走 `_trash_move`；**所有 packs 写端点整体包进 `core.skills.writing.pack_write_lock()` 临界区**（进程内 RLock），仅保单进程部署。
- **删除项目前置链**：`_project_busy` → 置 `projects_closing` 闸门 → pop 缓存 → `browser_pool.close_project(pid)`（先停 Chromium 释放 profile 锁）→ `session_containers.remove_project(pid)`（先停删会话级常驻容器，释放卷挂载句柄；P3，2026-10-07）→ `store.delete_project`（**代理池已全局化，2026-10-11 从此链移除**——池/日志落 `data/proxy/`、与项目工作区无句柄关系） 内 `bb.close_all()`+`proj.close()` → rename（退避重试，耗尽才 422）。双层关闭标志使旧引用访问即抛 `BlackboardClosedError`（全局 handler 转 409），**杜绝惰性重连在 Windows 上重新锁死 db**（曾是删除必 422 的根因）。启动：`scripts/serve.py [port]`（默认 127.0.0.1:8420）。
- **F6 浏览器装配**：`app.state.browser_pool = BrowserPool(...)`；shutdown 钩子 `close_all()`；**轨门控在 `_registered_session_factory`：`proj.track in ("pentest","redteam","ctf")` 才注入 dispatcher.browser**（轨外工具自动 no-tool，schema 仍全量下发）。
- **会话级常驻容器装配（P3，2026-10-07）**：`app.state.session_containers = SessionContainerManager(DockerBackend(), enabled=session_containers)` + `start()`（懒 reaper 首轮对账）；shutdown 钩子 `shutdown_all()`（与 browser/ida 同款 `add_event_handler("shutdown", ...)`）。**只注入 `_registered_session_factory` 的网关**（`ExecutionGateway(bb=proj.bb, containers=...)`，唯一产 `sess-` 的网关）；`_do_close_session` 关窗时 `remove(pid, sid)`。`create_app(session_containers=False)` 供测试禁用（同 `mission_poll_interval` 惯例；conftest 默认 False，否则 reaper 对账会真跑 `docker ps`）。

## 坑与注意

- **题目补建只在真有遗留数据时发生（2026-10-20）**：`_backfill_challenges` 是**存量迁移**（给老项目的无主 findings / 游离根资产找归属），触发条件必须包含「**存在待归拢数据**」。只判「CTF 轨 + 无 challenge 行 + 未标记」会让**新建的空项目**也建出一道以**项目名**命名的空壳题（`author=system`，用户实测项目名混进题目列表）。无数据时直接返回并落 `challenge_backfill_done` 标记（语义是「迁移已判定完毕」，不是「补建成功」）。清理已污染库：删 `author='system'` 且 `value==项目名` 且**子资产/发现/flag 三者全零**的行——非空壳的可能已收编真实数据，删它等于丢数据。
- Agent 开窗依赖真实 Ark key（.env），无 key 时 Agent 端点 503、黑板/团队端点照常可用；测试里 WS 收消息条数必须与事件数精确匹配，多收会挂（TestClient 无超时）。多进程部署（uvicorn workers>1）会让 app.state 会话表/job 失效——当前按单进程设计。intel 端点注入口/惰性建库见 [`core/intel/CLAUDE.md`](../intel/CLAUDE.md)。
