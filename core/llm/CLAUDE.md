# core/llm/

> LLM 接入层（DESIGN.md §8）：内部统一 Anthropic `/v1/messages` 标准，火山引擎 Ark 优先，多供应商可配。

供应商条目可设置 `proxy: "http://host:port"`，该代理会同时用于普通请求、SSE 流式请求、模型发现和测活；未设置时沿用系统 `HTTP_PROXY/HTTPS_PROXY` 环境变量。当前代理协议为 HTTP/HTTPS。

## 文件

| 文件 | 职责 |

| `provider.py` | 抽象基类 + 数据类 `LLMResponse/ToolCall/Usage`、`LLMError`；`assistant_message`/`tool_results_message` 将 typed 响应重建为内部 Anthropic 消息，调用方勿从 provider-specific `raw` 猜工具块；`chat(messages, system, tools, max_tokens, temperature)` 为唯一调用面 |
| `sdk_engine.py` | **官方 SDK 主引擎（2026-10-03 LLM SDK 迁移）**：`build_anthropic_transports` / `build_openai_transports` 返回与旧 urllib 版**同签名**的 `(transport, stream_transport)`——SDK 负责连接/代理/UA/HTTP 状态分类/超时/SSE 事件解析，本模块把 SDK 事件经 `_ev_to_sse` **还原成 SSE 行**交给既有 `_consume_stream`（Ark 特化零重写）。`TeeTransport`（httpx.BaseTransport，thread-local 缓冲）旁路录制原始字节；`_SdkStream` 在两种情形抛 `RawFallback`（带原始字节）让上层改走自研行式解析：①SDK 抛 `JSONDecodeError`（Ark 尾部冗余）②**SDK 一个事件都没产出**（SDK 的 SSE 解码器按 `event:` 行分发，缺 `event:` 行的网关会被静默丢空；或网关无视 `stream:true` 回整份 JSON）——这条兜底防「静默空响应」。`_as_conn_error` 把 `APIConnectionError/APITimeoutError` **以及裸 `httpx.TransportError`/`httpx.TimeoutException`** 转回 `ConnectionError/TimeoutError`（既有连接重试分支口径不变；裸 httpx 一档见下「流式 body 中断」）；`_error_dict` 把 `APIStatusError` 转成 `{"error":{...}}`。**鉴权坑（必须遵守）**：SDK 会把自持凭据与 `default_headers` **拼接**（`x-api-key: a, b`）且 `api_key/auth_token=None` 时回退读 `ANTHROPIC_API_KEY/ANTHROPIC_AUTH_TOKEN/ANTHROPIC_BASE_URL` 环境变量（本机 .env 有真实 `ANTHROPIC_AUTH_TOKEN`，会串进无关供应商请求）——故用 `anthropic.Omit` 关掉另一条鉴权通道并阻断 env 回退，构造后把未用通道显式置 `None`（否则 `Omit` 会以 `Bearer <anthropic.Omit object at 0x...>` 落进 Authorization 头）。openai 侧显式传 `api_key` 阻断 `OPENAI_API_KEY/OPENAI_BASE_URL` 回退 |
| `parsing.py` | 响应解析纯函数：`parse_anthropic_response(data)` / `parse_openai_response(data, format=)`——从 compat 类提出，compat 的 `_parse` 与 SDK 引擎共用同一口径；只依赖 `core.llm.provider`（防环） |
| `retry.py` | 传输层共享重试策略：`HTTP_5XX_STATUS`(500/502/503/504) / `HTTP_5XX_RETRIES=10`（共 11 次尝试）/ `HTTP_5XX_BACKOFF` 封顶 30s；`retry_note(done, budget)` 生成错误文案里的 `（已重试 N/M 次）` 后缀（两条 compat 路径共用，budget≤0 返空串） |
| `anthropic_compat.py` | `AnthropicCompatProvider`：OpenAI/Anthropic 兼容协议适配（tools、tool_use、thinking 解析）；测试用 ScriptedLLM 继承它回放剧本；标准 5xx（500/502/503/504）共 11 次尝试（首次 + 10 次重试，退避封顶 30s），429 仍共 2 早回头+帧间隔超时天然抗长思考。**thinking 开关（2026-09-19）**：`enable_thinking=True` 时 body 注入 `{"thinking":{type:enabled,budget_tokens:8192}}`；HTTP 400 文案含 "thinking" → 去参重建 payload 立即重试并记实例标志不再注入（模型不支持优雅降级）；`_parse` 对 content 无 thinking block 时兜底接 OpenAI 式顶层 `reasoning_content`。**思考流式（2026-09-19）**：`chat(..., on_thinking=, should_cancel=)`（类属性 `stream_capable=True` 供 Agent 层探测）走 SSE `stream:true`——`_consume_stream` 解析 `content_block_delta` 帧，`thinking_delta` 逐帧回调 on_thinking，帧拼回与非流式同形 dict 复用 `_parse`（tool_calls/usage 兼容）；建连在原重试循环内（首帧前 429/5xx/超时仍重试，**首帧后不重试**——流不可重放，网络错误包成 LLMError）；逐行轮询 should_cancel 命中即关流抛 LLMError（即点即停）；网关无视 stream 返整份 JSON → 兜底按普通响应解析；400 文案含 "stream" → `_stream_disabled` 本实例回退非流式。**Prompt caching（retrieval-upgrade M1，2026-09-23）**：`chat(..., system=)` 接受 str 或块数组（`build_system_blocks` 产的 stable/dynamic 两 text 块）——`_system_payload` 对 str 单块包装（`enable_cache=True` 缺省打标）并在 stable 块末尾落 `cache_control:{"type":"ephemeral"}`（Ark 兼容层实测直接接受，同前缀第二跑 cache_read>0）；dict 元素浅拷贝透传；HTTP 400 文案含 "cache_control" → `_cache_disabled` 实例置位、剥除全部标记重试一次（不支持的供应商优雅降级）；每次调用新建块对象不污染调用方。**截断防御（2026-09-20 事故修复）**：流结束后拼 tool_use 增量 JSON 失败（输出预算耗尽/网关断流致参数残缺，GLM 两次死在 `{"cmd":` 处）不再裸抛 JSONDecodeError 炸任务——包成 `LLMError(truncated=True)`（含 stop_reason），agent 层据此整轮重试；**尾部冗余容错（2026-10-01 事故修复）**：`json.loads` 失败时先 `json.JSONDecoder().raw_decode` 取「开头完整的 JSON 值」——仅接受 dict，成功即采用并 `log.warning` 留痕（网关 SSE 尾部多发字符：stop_reason=tool_use 正常收尾却报 "Extra data"）；仍失败才抛 `LLMError(truncated=True)` 交上层整轮重试。**按类别重试预算（2026-10-07）**：标准 5xx（500/502/503/504）共 11 次尝试（首次 + 10 次重试，退避 `HTTP_5XX_BACKOFF` 封顶 30s），429 维持总 2 次尝试与 `RETRY_BACKOFF=30s`；OpenAI 的 520/524 并入同一预算（2026-10-07 拉齐，原各自 5 次专用预算已删）；**连接类**（`ConnectionError`/超时，含 WSAECONNRESET 10054）独立预算（2026-10-08 与 5xx `max_tokens` 4096→16384**（原值与思考 budget 8192 倒挂）。**传输层 = 官方 SDK（2026-10-03）**：`transport`/`stream_transport` 未注入时按需构建 `sdk_engine` 的 SDK 传输（`_sdk_transports()` 惰性 + 缓存），两侧都注入则完全不碰 SDK（60+ 处测试与 ScriptedLLM 走注入路径，零改动）。`_consume_stream` 捕 `RawFallback` → 用 `fb.lines` 重喂同一解析器（已吐增量则不重放，抛 LLMError 如实上报） |

## 约定与坑

- **OpenAI 兼容层 520/524 重试（2026-10-03 起，2026-10-07 与标准 5xx 拉齐）**：上游中转/CDN 返回 520（边缘拿到源站无效响应）或 524（源站超时）时，`openai_compat.py` 与标准 5xx 走**同一分支与同一预算**——共 11 次尝试（首次 + 10 次重试），退避 2/4/8/16/30s 封顶；每次通过 `on_retry` 落 `chat.retry` 事件（`total=10`）。鉴权、参数和其它非暂态 HTTP 错误不重试。
- **上游 5xx + 流内错误帧重试（2026-10-07 事故修复）**：两条独立缺口，症状都是整轮炸成「执行异常 unknown」。
  ① **OpenAI 路径此前只重试 520/524**，`if status != 524: return` 让 500/502/503/504 直接上抛——现按共享标准策略对 500/502/503/504/520/524 共 11 次尝试（首次 + 10 次重试），退避为 2/4/8/16/30s 封顶（`on_retry` 照报）。**429 刻意不重试**（配额耗尽白等；Anthropic 路径的 `RETRYABLE_STATUS` 另含 429，口径不同）。**重试计数入文案（2026-10-07）**：`retry.py::retry_note(done, budget)` 把耗尽次数写成 `（已重试 10/10 次）` 插在冒号前（`LLM 调用失败 HTTP 502（已重试 10/10 次）: …`），两条路径共用——排查时一眼分清「一次就抛」还是「11 次全试过」，不必再数 `chat.retry` 事件；不可重试类（400/401 等）budget=0 不带后缀。
  ② **流内错误帧**（HTTP 200 已建连、SSE 里发 `{"error":{"type":"upstream_error",...}}`）：SDK 在迭代中抛 `APIError`（openai）/`APIStatusError`（anthropic），既非传输异常也带不上 `.status`，此前裸穿 → 不重试 + unknown。`_as_conn_error` 现按 `TRANSIENT_STREAM_HINTS`（upstream / temporarily unavailable / service unavailable / bad gateway / gateway timeout / overloaded）判定，瞬时类转 `TransientStreamError(ConnectionError)`——**继承 ConnectionError 是为了让既有「流已建连、未吐增量则安全重试」分支零改动接住**；内容策略等硬错误原样上抛快速失败。回归：`tests/test_llm_sdk.py`（5xx 重试两例 + 流内帧重试两例 + 只转瞬时类一例）。
- **传输层故障分类移交 SDK（2026-10-03）**：原自研 urllib 层按 errno 白名单（WSAECONNRESET 10054 等）与 `ssl.SSLEOFError` 判定可重试，现已删除——httpx 把连接重置/TLS EOF/超时统一抛 `httpx.TransportError`，SDK 包成 `APIConnectionError/APITimeoutError`，`sdk_engine._as_conn_error` 转回 `ConnectionError/TimeoutError`，**既有 `CONN_RETRIES=4` 预算与退避口径不变**。DNS 解析失败等非瞬时错误仍快速失败（httpx 也归入 `TransportError`，故也走连接重试——与旧行为相比略宽松，可接受）。
- **流式 body 中断须由 `_as_conn_error` 兜裸 httpx（2026-10-06 事故修复）**：`httpx` 的 `send(stream=True)` 只读响应头，**body 延迟到 `iter_bytes`**，而 SDK 的 `Stream.__stream__` 只 `finally` 关流、**不包异常**——对端半途关连接会直接抛 `httpx.RemoteProtocolError("peer closed connection without sending complete message body (incomplete chunked read)")`，绕开 `_stream_transport` 的 `APIConnectionError` 分支。故 `_as_conn_error` 必须同时映射裸 `httpx.TransportError`→`ConnectionError`（`httpx.TimeoutException`→`TimeoutError`，先判超时），否则该异常裸穿到上层：**既不走连接重试，又被 `core/chat/runtime._classify_error` 判成 `unknown`「执行异常」**（用户实测症状）。修后由 `_SdkStream.__iter__` 的兜底 `except` 转类 → 既有「无增量则安全重试」闸放行重试（已吐增量则按流中断如实上报，不重放）。回归：`tests/test_llm_sdk.py` 流式 body drop 重试两例。
- **已吐增量后的流中断打 `partial` 标记（2026-10-08）**：`LLMError` 增 `partial` 字段——「无增量」分支照旧转 `ConnectionError` 走连接重试；**「已吐增量」分支**（半截内容已上屏、流不可重放，不重发）由 `LLMError(partial=True)` 上报，交上层决定续写策略。两条 compat 路径同一口径。**注意 `partial` 只表示「吐过任何增量（含仅 thinking / 工具参数）」，不等于「有可续的半截文本」**——消费链各自按文本累加判空：chat 工作台有半截文本 → 「接着续写」，只有 thinking 无文本 → **原样重发本 step（2026-10-09 事故修复，`_CHAT_RESEND_MAX=3`）**；Agent 会话 `partial` 一律整轮重发（不看文本）。
- **依赖（2026-10-03）**：`anthropic>=0.40` / `openai>=1.40` / `httpx>=0.27` 落 `pyproject` **核心依赖**（`core/llm` 导入期即需要，放 extra 会留坏导入路径）；`scripts/build_exe.py` 的 `BUILD_DEPS` 同步（漏了则打包件一导入 `core.llm` 即崩）。`tiktoken>=0.7` 落**可选 extra `tokens`**（`tokenizer.py` 惰性 import，未装降级估算器，不影响功能）。
- **测试**：`tests/test_llm.py` 走注入式 fake transport（不触网、不碰 SDK）；`tests/test_llm_sdk.py` 用 `httpx.MockTransport` 换掉底层传输，让 SDK 走完整解析链路，覆盖正常流 / Ark 特化全量保住 / 两种降级 / 鉴权头回归。

- **工具调用序列协议（2026-10-04）**：`LLMResponse.raw` 永远是供应商原始协议，不保证顶层 `content`；Agent/Orchestrator 历史必须用 `assistant_message(response)` + `tool_results_message(...)` 重建。OpenAI Chat Completions 流式按声明的 `(choice.index, tool_call.index)` 聚合（后续 delta 可无 id），Responses 用 `item_id↔call_id` 别名合并；流式与非流式共用出口校验，拒绝空/重复 call id、空工具名或非对象参数，避免 `tool_call_sequence_broken`。
- 无可用 key 不崩：API Agent/编排端点返回 503；LLM 缺省 = 路由覆写目标或第一个启用供应商的第一个模型。
- Agent 会话内可经 `POST /agents/{sid}/llm` 运行时动态切换 provider 引用，下一次 chat 生效（落 llm.switched 事件）。
- 测试可注入 executor_llm/planner_llm 或用 tmp providers_config，避免种子污染真实 config/providers.json；禁止把任何 key 写进技能文件或提交物。
