# core/agent/

> Agent 会话主循环与工具分发（DESIGN.md §3）。所有写操作走黑板 API / 执行网关，本目录不直写存储、不裸执行命令。任务机制（run_task/任务快照/租约心跳/计划闸 A2）2026-10-06 已退役。

Agent 创建或补充 finding 时可填摘要、受影响资产、测试环境、操作步骤、验证结果、风险评估及多条 `pocs`（HTTP/Python）；正式漏洞报告须满足存储层报告门禁，历史 evidence POC 保持兼容。

## 执行模型（Team / 会话轮）

- `execution.py` 的 `ExecutionContext`（execution_id + 可选 team/run/member/session/objective/role/runtime/threat_class）+ `AgentSession.run_team_execution(context)`：**Team 成员执行唯一入口**——不设 `current_task_id`，工具面屏蔽任务生命周期工具（task_plan/task_step/task_reconcile/publish_task/complete_task/fail_task/finish），资产/发现/产物/命令仍走原黑板单一写入口、gateway、runtime、ROE 与 approval。
- `run_session()`（会话轮）：**只做对话**——收件箱有可回应消息 → `run_chat()`；无消息 → None 空退、窗回待命（真空闲退出置 DB status=idle）。不再认领任务/扫队列。暂停/中断请求只清标志 + 落审计（无任务现场可续）。
- 人工引导（human_note）降级为**纯对话**：不再判定「任务」意图自动 publish 任务（`_classify_human_intent` 已删）；需要受管执行由指挥组建团队（编排器工具 `build_team`）或亲自执行（`execute`）。

## 文件

- `session_state.py` — **会话状态单一容器**：`SessionState` dataclass + `reset_for_task()` 单入口复位（每轮 `_loop_body` 入口调）+ `state_proxy(attr)` 工厂。状态原先散在 `AgentSession`/`ToolDispatcher` 两处、复位点分散，历史多次踩「上一轮残留字段带进下一轮」stale bug。两处各以 `xxx = state_proxy("xxx")` 保留**原属性名**（property 双向代理到共享实例），既有读写点与测试断言零改动，**控制流与闸门评估顺序一字未动**。`reset_for_task` 只列原先真被复位的字段；`current_task_id`/`last_progress_step`/`resume_state`/`live_state`/`salvage_ctx`/`stale_alerted` 由各自生命周期路径管理，**不得顺手加进去**。
- `tool_registry.py` — **工具唯一真相源**：`ToolSpec`(name/description/input_schema/group/flags/handler) + `tool()` 装饰器 + `REGISTRY`。此前六项散在 4-6 处，漏改一处即静默改变闸门放行面。**flags 是闸门口径的声明式表达**：`control`/`plan`/`plan_pre`/`intent_flow`/`intent_pre`/`spill_skip`/`collab`/`knowledge`/`file`；派生常量（`AGENT_TOOLS`/各白名单集合/`agent_tool_group`）由注册表推导、**名字逐字保留**，外部消费方零改动。**改工具只动本文件一处 + `tools.py` 补 `_tool_<name>`**：group 非法/重名当场抛错，handler 缺失由 tools.py 末尾导入期自检抛错，flags 漂移由 `tests/test_tool_registry.py` 对照迁移前快照拦下。`_ADDR_DESC` 也在此定义（tools.py 反向 import 防两份漂移）。
- `loop.py` — `AgentSession(*, project_id, bb, gateway, llm, planner_llm?, packs_root, track, capabilities=None, role="_generalist", session_name?, capability_prompt?, config?, decompiler?, artifacts_dir?, enable_sediment=False, allowed_roles=None)`。
  - **系统提示** = `build_rules_preamble`（轨+能力包红线、owner 规则、**rating 评级与价值口径段**、role-rules〔按专家 id〕）+ 能力清单 + 专家人设 + **技能全量描述注入**（**K8：废弃 top-1 路由命中**——白名单优先/generalist 全量，每技能注入 name+description 一行，正文仍靠 skill_open 按需打开；候选集 = caps ∪ track 再经专家白名单裁剪）+ 目标 + 软边界行 + 工具纪律。**Prompt caching 拆块**：`build_system_parts` 产 (stable, dynamic)——stable=规则链+角色+能力清单（会话内字节稳定，末尾打 cache_control ephemeral）、dynamic=技能指引+当前目标+纪律尾；`build_system_prompt` 拼接版保留作兼容与测试基准（拼接全等断言钉死）；调用点（run_team_execution/run_chat）走 blocks。
  - **卡死升级（stuck-convergence M1 + D7 + D9）**：`_stuck_waves`/`_stuck_extensions` 每轮复位、有黑板进展清零。**D9 预检（仅 waves=0、ext<stuck_max_extensions）**：`_active_exploration` 命中新文件/命令演进→静默延长（`agent.stuck_extend`，零 LLM 不打断）；否则**波次 1=顾问建议**（`advisor.suggest`，注入重复命令排行）；**波次 2=顾问裁决 `advisor.verdict`**（只收 JSON `{decision,reason,instruction}`，`_parse_verdict` 对非 JSON/非法 decision/continue 缺 instruction 一律回落 terminate——宁严勿松绝不回落 continue；terminate→`_stuck_escalate`；human→awaiting_human；continue→半强制注入最高优先 user 指令并重开观察窗）；**波次 3=机械硬闸兜底**（累计 ≤36 步、≤2 次 planner，宁停不烧）。**事件窗一律 `tail=` 取最新**——`recent_events(limit=N)` 取的是最早 N 条，长会话会看到会话开头。
  - **`last_claim_idle`**：真空闲退出（无收件箱可回应）才为 True，会话轮入口置 False。API 层只在 True 时触发 L2 续 tick。
  - **`run_chat()`（空闲对话轮）**：收件箱有未读时跑对话循环——`_drain_inbox("chat")` → 工具面 `CHAT_TOOLS`（=AGENT_TOOLS 去 finish，**勿把 finish 加回**）循环 → 纯文本落 `agent.chat` 事件。**历史统一存会话级** `chat-<sid>.json`（`_load_session_chat` 读末 60 条、原子写、轮末回写问答对，`sanitize_snapshot_tail` 清悬空 tool_use 半对防 API 拒）。abort 语义：暂停/中断/暂停态置位时不消费引导（留收件箱）；对话中被中断→清标志、静默 None（半截回复由 `_flush_interrupted_reply` 落 `agent.chat{interrupted:true}`）。**对话化**：`chat_max_steps=24`；system 文案「有价值阶段性结论随手 bb_add_finding」；回复流式 `stream_text=True`。
  - **会话控制**：`request_pause()`（步边界软暂停，快照可恢复）/ `request_abort()`（硬中断）。**■ 即点即停**：中断不再等步边界——`_chat_interruptible` 让 LLM 调用在旁路线程跑、主线程 0.3s 轮询 `_abort_req`，置位即抛 `_StepInterrupted`；命令侧经 dispatcher.abort_event → gateway 杀进程树。暂停仍是步边界语义（要干净现场）。**思考流式**：llm 声明 `stream_capable` 时给 chat 传 `on_thinking`/`should_cancel`，主线程节流落 `llm.thinking.delta`（≥120 新字符或 ≥1s），终稿经 `_emit_final_thinking` 落 `llm.thinking` 并 `prune_thinking_deltas` 清剪 delta。**截断整轮重试**：`LLMError.truncated` 在 `_chat_interruptible` 内整轮重发 ≤`_CHAT_TRUNC_RETRIES`(2) 次；**最后一轮降级非流式**；非截断 LLMError 原样穿出走 `_fail_task_on_error`。**回复流式**：`stream_text=True` 另挂 `on_text` 攒 text_acc，节流（≥80 新字符或 ≥1s）发 `agent.chat.delta`；终稿带 `stream_id` 并清剪同流过渡行。**中断落盘**：`on_text` 恒传；abort 两抛出点抛前调 `_flush_interrupted_reply`。假 LLM 测试签名必须显式 `on_text=None`。
  - **C1 awaiting_human 挂起**：拒绝熔断/卡死裁决挂人时置 dispatcher.awaiting_human，`_loop` 步边界检测后**先落盘断点快照再退出**（现场保留）；`_resume_state` 用后必须清（内存态泄漏会被下轮快照消费分支误清盘）。每轮 `_loop_body` 入口 `SessionState.reset_for_task` 复位。
  - **E2 拒绝熔断**：拒绝分两类、计数单位=**模型步**（并行批多票只计 1）。硬拒绝（`HARD_REJECT_PREFIXES`=[越界拒绝]/[网关拒绝]/[拒绝]；[错误]/[冲突] 不算）连续 ≥`_REJECT_BREAK_LIMIT`(3) 个模型步 → awaiting_human + `agent.reject_breaker`；任何不含硬拒绝的步（含纯文本步）清零。**计划闸已随任务机制退役**（`_classify_step_rejections` 恒清 plan-only）。**新增拒绝路径必须复用既有前缀回填**。

## 角色软边界（§6.6，违例回填 `[越界拒绝]`，循环不中断）

- **tools 白名单**：不在 `allowed_tools` 的工具分发前拒绝；`_CONTROL_TOOLS`/`_PLAN_TOOLS` 永远放行。
- **执行取件**：会话执行由 `run_team_execution` / 对话轮驱动，不做类型/噪声过滤；角色经换装生效；完成后会话空退待命。

## kb_open（M0 全局形态）

- **M0 kb 全局单根**：数据源 = `load_kb_sources` 按启用域合成 `[packs/kb/<cap>]`（恒递归，目录不存在=空源；kb_sources.json 退役）。module 主口径=**全局形态** `<域>/<快照>/<路径>`（如 `web/webapp/authn/auth-jwt.md`）——首段==启用域时锁定该域解析（跨域同名快照天然消歧），否则按启用域顺序逐域尝试域内相对形态（兼容旧引用）；resolve 后强制落在 root 内（穿越返回 `[拒绝]`，且不落 kb.open 事件）；不存在时回可用清单（前 50 个，防幻觉）。legacy `kb_search` 返回 path **已补域前缀**，即 kb_open 的 module 口径——默认方法入口是自包含 Skill 的 `skill_open`，legacy 工具只服务尚未迁移的历史资料。
