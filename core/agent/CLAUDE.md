  - 系统提示 = `build_rules_preamble`（轨+能力包红线、owner 规则、**rating 评级与价值口径段（F11，owner 段后 role 段前，带头注评级硬指令：判级须按口径、bb_add_finding 的 rating_basis 填规则名+条款）**、role-rules〔M2 起按专家 id〕；owner/rating 段经 `AgentConfig.rule_profiles` 三态启用）+ 能力清单 + 专家人设（M2 起 role=experts/ 池内专家 id，`load_expert` 经轨变体加载）+ 技能路由正文（候选集 = caps ∪ track，再经专家白名单）+ 任务目标 + 软边界行 + 工具纪律。

  - **`last_claim_idle`（批 5，§6.8）**：最后一次 `claim_next` 返回 None（队列空退出）才为 True；每次认领前置 False，暂停/中断退出不残留。API 层只在 True 时触发 L2 续 tick（触发点 A）。
  - **`run_chat(task_id=None)`（空闲对话轮，2026-09-19，§6.7）**：队列空转（worker 在 `run_next_task()` None 且 `last_claim_idle` 时调）且收件箱有未读时，跑对话循环——drain → `CHAT_TOOLS`（=AGENT_TOOLS 去 finish，模块级常量；**勿把 finish 加回**——对话轮无任务可收尾，纯文本回复即终止）循环 → 纯文本落 `agent.chat` 事件并返回文本。**v0.71 延续模式（2026-09-20）**：task_id 非空（绑定窗终态续聊）时先从 C10 任务现场文件载入末 60 条既往对话作上下文（`sanitize_snapshot_tail` 清悬空 tool_use 半对，防 API 拒；损坏/缺失空降级），回复后问答对**回写现场文件**（`_append_chat_to_transcript` 原子写，只追加问答两条）——续聊跨轮、跨重启不丢上下文。与任务轮互斥点：**不认领任务、不落快照、不起心跳、不动 current_task_id/finished/awaiting_human，会话状态不翻转**。abort 语义：暂停/中断/暂停态置位时不消费引导（留收件箱）；对话中（含 LLM 调用期间）被中断→清标志、静默 None（drain 已消费；半截回复已由 `_flush_interrupted_reply` 落 `agent.chat{interrupted:true}`，2026-09-21）。API 层 note 端点在空闲时自动踢 worker 触发本方法。**会话窗对话化一期（2026-09-20，DESIGN §6.9）**：①收件箱消费走订阅声明表（见私信分流渲染条），chat 场景 4 kind（human_note/escalation_result/**agent_message/task_receipt**；basis_stale/finding_update 须任务上下文不消费，留收件箱等认领期）；②纪律放开——`AgentConfig.chat_max_steps=24`（与 dispatcher.max_steps 取 min），system 文案删「不登记发现」改「有价值的阶段性结论随手 bb_add_finding（evidence+relates_to 上图，未验证标 unverified）」——对话轮产 finding 无任务上下文无 basis 边（DESIGN 定稿可接受）；③历史分流：绑定窗=任务现场文件，非绑定窗=**会话级 `chat-<sid>.json`**（`session_chat_path`/`_load_session_chat`/`_append_chat_to_session`，120 条滚动、读末 60 条、原子写，失败只 log 不影响回复）；④回复流式 `stream_text=True`（见下条）。
  - 会话控制：`request_pause()`（步边界软暂停，快照可恢复）/ `request_abort()`（硬中断）。**■ 即点即停（2026-09-19）**：中断不再等步边界——`_chat_interruptible` 让 LLM 调用在旁路线程跑、主线程 0.3s 轮询 `_abort_req`，置位即抛 `_StepInterrupted`（_loop 当场 `_abort_current_task`；run_chat 清标志静默 None，响应丢弃，usage/thinking 不落）；命令侧经 dispatcher.abort_event（构造时传入）→ gateway 杀进程树。暂停仍是步边界语义（要干净现场）。**思考流式（2026-09-19）**：llm 声明 `stream_capable` 时 `_chat_interruptible` 给 chat 传 `on_thinking`（旁路线程只攒缓冲）/`should_cancel`（接 `_abort_req`，中断即刻掐流），主线程轮询间隙节流落 `llm.thinking.delta` 事件（payload=累计全文+seq+stream_id，≥120 新字符或 ≥1s 有变才发）；终稿经 `_emit_final_thinking` 落 `llm.thinking`（带 stream_id）并 `bb.prune_thinking_deltas` 清剪该流 delta 行——审计只留终稿；中断/异常路径不清剪（残留 delta=被中断思考现场）。**截断整轮重试（2026-09-20 事故修复）**：`LLMError.truncated`（工具参数流截断，L 层打标）在 `_chat_interruptible` 内整轮重发 ≤`_CHAT_TRUNC_RETRIES`(2) 次——传输层流不可重放只能轮级重试；重试轮 thinking 缓冲清零重流（stream_id/seq 延续，终稿统一清剪）；**最后一轮重试降级非流式**（不带 on_thinking/should_cancel，走 L 层内建非流式路径——网关 SSE 连续断流时整包响应不受影响，实测连续 3 轮流式截断的场景靠它救回）；非截断 LLMError 原样穿出走 `_fail_task_on_error` 兜底。**回复流式（2026-09-20 对话化）**：`_chat_interruptible` 加 `stream_text=False` 参数（任务轮叙述不流式控爆炸半径）——置位时旁路线程另挂 `on_text` 回调攒 text_acc，镜像 thinking 节流（**≥80 新字符或 ≥1s**，比思考短——回复短、要近打字机观感）发 `agent.chat.delta` {stream_id, text 累计, seq}；run_chat 终稿 `agent.chat` payload 带 `stream_id`（取 `resp.raw["_stream_id"]`）并 `bb.prune_chat_deltas` 清剪同流过渡行；截断重试轮 text 缓冲清零。**中断落盘（2026-09-21）**：`on_text` 在流式分支内**恒传**（任务轮也攒，`_flush_text` 由 stream_text 守卫零 delta 事件——爆炸半径不变）；abort 两抛出点（轮询环/err+abort）抛前调 `_flush_interrupted_reply`——text_acc 有存货落 `agent.chat`{`interrupted:true`}，对话轮带 stream_id 并清剪 delta（turn 有收口回复），任务轮带 step、截 2000 同终稿口径；thinking 残留 delta 维持现状（中断现场审计不落终稿）。`_chat_interruptible` 加 `step` 参数（_loop_body 传步号、run_chat 不传——无 step 前端收口为回复气泡）。假 LLM 测试签名必须显式 `on_text=None`（stream_capable 继承自 AnthropicCompatProvider）。

## 角色软边界（§6.6，违例回填 `[越界拒绝]`，循环不中断）

- **tools 白名单**：不在 `allowed_tools` 的工具分发前拒绝；complete_task/fail_task/finish 永远放行。
- **max_runtime 是运行时等级软上限，不是秒**：`RUNTIME_RANK host<wsl<docker<sandbox`，超等级拒绝（`timeout` 只是普通透传参数）。只能比网关 threat_class 允许集更严。
- **认领零过滤（2026-09-18 v0.63，用户定稿「任务才是本体」）**：窗口不做任何 role 过滤——`run_next_task` 认领不传类型/噪声条件（旧 task_types 白名单与 default_noise 噪声过滤已删）；角色 task_types/default_noise 是**换装后生效的执行边界**（前者已无运行时消费点、后者仅系统提示自陈）；任务绑定 role 经认领即换装生效（见上）。**v0.71 修订**：绑定窗（meta.bound_task_id）worker 每轮 `run_next_task(only_task=bound)`，跑完自己任务即退（不进公共池）。**v0.72 修订**：`run_next_task(only_task=None, assigned_only=False)` 恢复透传——无绑定手动窗一律 `assigned_only=True`（公共池认领全局退役，DESIGN §6.1 v0.72 修订块），认领恒空、有引导走 run_chat 后退出。

## kb_open（M0 全局形态）

- **M0（2026-09-21）kb 全局单根**：数据源 = `load_kb_sources` 按启用域合成 `[packs/kb/<cap>]`（恒递归，目录不存在=空源；kb_sources.json 退役）。module 主口径=**全局形态** `<域>/<快照>/<路径>`（如 `web/webapp/authn/auth-jwt.md`）——首段==启用域时锁定该域解析（跨域同名快照天然消歧），否则按启用域顺序逐域尝试域内相对形态（兼容旧引用 `ctf-web/auth-jwt.md`）；resolve 后强制落在 root 内（穿越返回 `[拒绝]`，且不落 kb.open 事件）；不存在时回可用清单（前 50 个，防幻觉）。
