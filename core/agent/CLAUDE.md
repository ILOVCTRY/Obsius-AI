# core/agent/

> Agent 会话主循环与工具分发（DESIGN.md §3）。所有写操作走黑板 API / 执行网关，本目录不直写存储、不裸执行命令。

Agent 创建或补充 finding 时可填摘要、受影响资产、测试环境、操作步骤、验证结果、风险评估及多条 `pocs`（HTTP/Python）；正式漏洞报告须满足存储层报告门禁，历史 evidence POC 保持兼容。

## 文件

- `session_state.py` — **会话状态单一容器**：`SessionState` dataclass + `reset_for_task()` 单入口复位 + `state_proxy(attr)` 工厂。状态原先散在 `AgentSession`/`ToolDispatcher` 两处、复位点分散，历史多次踩「上一任务残留字段带进新任务」stale bug。两处各以 `xxx = state_proxy("xxx")` 保留**原属性名**（property 双向代理到共享实例），既有读写点与测试断言零改动，**控制流与闸门评估顺序一字未动**。`reset_for_task` 只列原先真被复位的字段；`current_task_id`/`last_progress_step`/`resume_state`/`live_state`/`salvage_ctx`/`stale_alerted` 由各自生命周期路径管理，**不得顺手加进去**。
- `tool_registry.py` — **工具唯一真相源**：`ToolSpec`(name/description/input_schema/group/flags/handler) + `tool()` 装饰器 + `REGISTRY`。此前六项散在 4-6 处，漏改一处即静默改变闸门放行面。**flags 是闸门口径的声明式表达**：`control`/`plan`/`plan_pre`/`intent_flow`/`intent_pre`/`spill_skip`/`collab`/`knowledge`/`file`；派生常量（`AGENT_TOOLS`/各白名单集合/`agent_tool_group`）由注册表推导、**名字逐字保留**，外部消费方零改动。**改工具只动本文件一处 + `tools.py` 补 `_tool_<name>`**：group 非法/重名当场抛错，handler 缺失由 tools.py 末尾导入期自检抛错，flags 漂移由 `tests/test_tool_registry.py` 对照迁移前快照拦下。`_ADDR_DESC` 也在此定义（tools.py 反向 import 防两份漂移）。
- `loop.py` — `AgentSession(*, project_id, bb, gateway, llm, planner_llm?, packs_root, track, capabilities=None, role="_generalist", session_name?, capability_prompt?, config?, decompiler?, artifacts_dir?, enable_sediment=False, allowed_roles=None)`。
  - **系统提示** = `build_rules_preamble`（轨+能力包红线、owner 规则、**rating 评级与价值口径段**、role-rules〔按专家 id〕）+ 能力清单 + 专家人设 + **技能全量描述注入**（**K8：废弃 top-1 路由命中**——白名单优先/generalist 全量，每技能注入 name+description 一行，正文仍靠 skill_open 按需打开；候选集 = caps ∪ track 再经专家白名单裁剪）+ 任务目标 + 软边界行 + 工具纪律。**Prompt caching 拆块**：`build_system_parts` 产 (stable, dynamic)——stable=规则链+角色+能力清单（会话内字节稳定，末尾打 cache_control ephemeral）、dynamic=技能指引+当前任务+纪律尾；`build_system_prompt` 拼接版保留作兼容与测试基准（拼接全等断言钉死）；三调用点（run_task/run_chat/恢复路径）走 blocks。
  - **`run_session()`（Worker 唯一入口，会话中心化 v24）**：仅执行 `dispatcher.current_task_id` 指向且由本会话 `start_direct` 绑定的任务；无直派任务→`run_chat()` 回应收件箱；都没有→None 空退、窗回待命（**暂停闸空退留审计**：`paused` 置位时先落 `session.work_state{paused:true}` 再 return）。不再扫描窗内 open 队列或公共任务池。
  - **卡死升级与收尾收敛（stuck-convergence M1 + D7 + D9）**：`_stuck_waves`/`_stuck_extensions` 每任务复位、有黑板进展清零。**D9 预检（仅 waves=0、ext<stuck_max_extensions）**：`_active_exploration` 命中新文件/命令演进→静默延长（`agent.stuck_extend`，零 LLM 不打断）；否则**波次 1=顾问建议**（`advisor.suggest`，注入重复命令排行）；**波次 2=顾问裁决 `advisor.verdict`**（只收 JSON `{decision,reason,instruction}`，`_parse_verdict` 对非 JSON/非法 decision/continue 缺 instruction 一律回落 terminate——宁严勿松绝不回落 continue；terminate→`_stuck_escalate`；human→awaiting_human；continue→半强制注入最高优先 user 指令并重开观察窗）；**波次 3=机械硬闸兜底**（累计 ≤36 步、≤2 次 planner，宁停不烧）。**事件窗一律 `tail=` 取最新**——`recent_events(limit=N)` 取的是最早 N 条，长会话会看到会话开头。**D6 收尾确认**：`_closing_gate` 在 reconcile 闸后拦截首次 complete——注入 findings/assets/artifacts+plan 完成度清单；一轮零新增黑板写入后再 complete 才真 done，封顶 `closing_max_rounds`（0=首次即放行）、`dry_tail_steps=stuck_after−2` 零新增直接放行；每任务 `reset_closing`。`_finalize` 未收尾任务自动 fail（**E8 起步数耗尽不走此路**）；收尾末尾把 DB status 置 **idle**（此前只落事件，status 残留 running 致 session_list 与事件流打架；closed 窗不覆盖）。
  - **`last_claim_idle`**：最后一次 `claim_next` 返回 None（队列空退出）才为 True；每次认领前置 False。API 层只在 True 时触发 L2 续 tick（触发点 A）。
  - **`run_chat(task_id=None)`（空闲对话轮）**：队列空转且收件箱有未读时跑对话循环——drain → `CHAT_TOOLS`（=AGENT_TOOLS 去 finish，**勿把 finish 加回**）循环 → 纯文本落 `agent.chat` 事件。**延续模式**：task_id 非空时先从 C10 任务现场文件载入末 60 条既往对话作上下文（`sanitize_snapshot_tail` 清悬空 tool_use 半对防 API 拒），回复后问答对**回写现场文件**。与任务轮互斥点：**不认领任务、不落快照、不起心跳、不动 current_task_id/finished/awaiting_human，会话状态不翻转**。abort 语义：暂停/中断/暂停态置位时不消费引导（留收件箱）；对话中被中断→清标志、静默 None（半截回复由 `_flush_interrupted_reply` 落 `agent.chat{interrupted:true}`）。**会话窗对话化**：①收件箱消费走订阅声明表（chat 场景 3 kind：human_note/agent_message/task_receipt；basis_stale/finding_update 须任务上下文不消费）；②纪律放开——`chat_max_steps=24`，system 文案删「不登记发现」改「有价值阶段性结论随手 bb_add_finding」；③历史分流：绑定窗=任务现场文件，非绑定窗=会话级 `chat-<sid>.json`（120 条滚动、读末 60 条、原子写，失败只 log）；④回复流式 `stream_text=True`。
  - **会话控制**：`request_pause()`（步边界软暂停，快照可恢复）/ `request_abort()`（硬中断）。**■ 即点即停**：中断不再等步边界——`_chat_interruptible` 让 LLM 调用在旁路线程跑、主线程 0.3s 轮询 `_abort_req`，置位即抛 `_StepInterrupted`；命令侧经 dispatcher.abort_event → gateway 杀进程树。暂停仍是步边界语义（要干净现场）。**思考流式**：llm 声明 `stream_capable` 时给 chat 传 `on_thinking`/`should_cancel`，主线程节流落 `llm.thinking.delta`（≥120 新字符或 ≥1s），终稿经 `_emit_final_thinking` 落 `llm.thinking` 并 `prune_thinking_deltas` 清剪 delta（中断/异常路径不清剪=现场）。**截断整轮重试**：`LLMError.truncated`（工具参数流截断）在 `_chat_interruptible` 内整轮重发 ≤`_CHAT_TRUNC_RETRIES`(2) 次；**最后一轮降级非流式**（网关 SSE 连续断流时整包响应不受影响）；非截断 LLMError 原样穿出走 `_fail_task_on_error`。**回复流式**：`stream_text=True` 时另挂 `on_text` 攒 text_acc，节流（**≥80 新字符或 ≥1s**）发 `agent.chat.delta`；run_chat 终稿 `agent.chat` 带 `stream_id` 并清剪同流过渡行。**中断落盘**：`on_text` 恒传（任务轮也攒，`_flush_text` 由 stream_text 守卫零 delta 事件）；abort 两抛出点抛前调 `_flush_interrupted_reply`。假 LLM 测试签名必须显式 `on_text=None`。
  - **C1 awaiting_human 挂起**：`fail_task(blocked_reason=awaiting_human)` 不直接 fail——置 dispatcher.awaiting_human，_loop 步边界检测后**先落盘快照再 fail**（resumable=true），会话不结束 worker 继续认领；`_resume_state` 用后必须清（内存态泄漏会被下轮快照消费分支误清盘）。**每任务在 _loop 入口复位**（收敛为 `SessionState.reset_for_task`）。认领注入：`_old_plan_notice`。
  - **E2 拒绝熔断**：拒绝分两类、计数单位=**模型步**（并行批多票只计 1）。硬拒绝（`HARD_REJECT_PREFIXES`=[越界拒绝]/[网关拒绝]/[拒绝]；[错误]/[冲突] 不算）连续 ≥`_REJECT_BREAK_LIMIT`(3) 个模型步 → awaiting_human + `agent.reject_breaker`；任何不含硬拒绝的步（含纯文本步）清零。计划闸是教练类不进硬熔断：累计 `_PLAN_GATE_STEPS`(2) 个模型步撞闸 → `plan_only_mode=True` + 注入 `_PLAN_ONLY_NUDGE` + `agent.plan_nudge`；模式后下一模型步末计划仍空 → `agent.plan_gate_block` + 挂人。**新增拒绝路径必须复用既有前缀回填**。
  - **E12 中断保留现场**：`_abort_current_task` 人工中断**不再清落盘快照**（仅任务已删除触发的中断仍清）；`revive_snapshot(task_id)` 刷新会话行取最新指针、载回 `_resume_state`（限原会话）。API `POST /tasks/{tid}/resume`=校验 failed+claimed_by → revive → reopen+claim → **清 `_stop_after_task`** → submit worker。
  - **C6 失败任务跨会话完整续跑**：`_persist_snapshot` **双写任务键快照** `snapshots/task-<tid>.resume.json`（**不含 system** 跨角色安全）；`run_task` 认领时 `_load_task_resume` 命中（objective 未改）→**认领即复活**（messages 整体还原+`start_step=next_step` 断点还原+消费即删+跳过注入链+追「⚡ 已从中断现场续跑」）；objective 被改→删快照降级 C10 transcript 接手。`_abort_current_task` resumable 判定改「会话键**或**任务键快照任一存在」。
  - **rehydrate**：构造传 `existing_session=<sessions 行>` 则附着旧会话不新建行（服务重启/孤儿窗恢复；角色 yaml 按当盘重载）；暂停快照持久化到 workspace 文件，`_load_persisted_snapshot()` 载回即回 paused 可续跑。
  - **E8 步数预算与人工引导**：①`_loop` 是**薄包装**（在册/注销 `_live_state`）+ `_loop_body` **while** 循环、每轮重读 `dispatcher.max_steps`（range 预计算会截断自救）；剩余 <20 步注入预算提醒。②步数耗尽→`_budget_pause`：快照（reason="budget"）+ claimed/心跳保留 + `session.budget_paused`，**不 fail**。③暂停快照四方法：路径 `<workspace>/<pid>/snapshots/<sid>.json`，`sessions.meta` 存 `resume_snapshot` 指针。④私信第三类分流 `_human_note_notice`——**轮末语义：只在认领期/恢复期/对话轮消费，步边界不消费**（**勿把 human_note 加回 step 场景**，前端靠 task.claimed 事件清「排队引导条」）。
  - **v0.64 暂停请求即时落盘**：`_loop` 退出（含暂停/中断/异常）必清 `_live_state`；`pause_snapshot_now()` 从在册现场构建断点快照（next_step=`dispatcher.step+1`，尾部经 `sanitize_snapshot_tail` 截掉半步悬空对）双写会话键+任务键文件——**不动行状态/不置 paused/不碰 `_resume_state`**（worker 到步边界后以干净快照覆盖；进程死了这份兜底）。pause 端点与优雅停机钩子两处调用。
  - **租约心跳**：认领后起守护线程 `_LeaseHeartbeat`，每 `lease_renew_seconds`（默认 600s）调 `renew_lease`，防长任务超 TTL 被回收双跑；complete/fail/abort/_finalize 必停，pause 期间保留；续租 ClaimError（任务易主/被删）心跳自退；`stop()` 置位后有界 `join(2s)` 等线程退出。
  - **任务现场工具历史清洗（2026-10-04）**：`sanitize_snapshot_tail` 对暂停快照/任务现场的最近 tool-use 组严格校验 ID 非空唯一、tool-result 集合与之完全相等；重复/错配/半步整组丢弃，防旧现场再次触发 `tool_call_sequence_broken`。
  - **C10 任务现场落盘与跨会话接手**：`task_transcript_path(artifacts_dir, task_id)` → `<workspace>/<pid>/snapshots/task-<tid>.json`（文件名确定性推导，无需 DB 指针）。`_checkpoint_task_transcript` **每步落盘**（temp+`os.replace` 原子；失败降级）——fail/崩溃/重启清扫任何路径不丢现场。新会话认领时 `_load_task_transcript` 载入为初始历史（**末尾 60 条**，截断不拆 tool_use/tool_result 对）+`_handover_notice`；认领期 `inbox_drain` 改**无条件**。现场文件归 agent 层，DB context 列只走 `TaskQueue._finish`。
  - **步边界任务存活检查**：`_control_point` 在 abort/pause 检查后调 `_task_gone()`——current_task_id 非空且 `tq.get_task()` 为 None → `_abort_current_task()`；当前步所有工具返回后才生效，单步工具调用不可打断。
  - **私信分流渲染**：消费口径唯一真相源=loop.py 模块级 **`_INBOX_SUBSCRIPTIONS` 订阅声明表**（kind→场景元组：claim/resume/step/chat），四处消费点统一走 `_drain_inbox(scenario)` 单一入口（渲染顺序=表内声明序；basis_stale 签名特例接 stale_refs 现场补水，其余为 `_<kind>_notice` 命名约定）。**新增 kind 必须先登记订阅表**——未登记 kind 滞留收件箱红点可见，绝不被静默吞。notice 函数族：`_basis_stale_notice`（⚠ 三选一强制；任务挂标+收件箱双来源合并）、`_finding_update_notice`（ℹ）、`_human_note_notice`（💬 含 📎 附件行）、`_authorization_result_notice`（✅）、`_approval_rejected_notice`（❌ 统一渲染「不要继续等待，按当前边界换路」）、`_agent_message_notice`（📨 subkind 中文标注+from 显示名）、`_task_receipt_notice`（✅/❌ 子任务回执）。**认领期 basis_stale 纯私信形态**不再被 stale_refs 非空门控吞。
  - **附件随发注入**：`_attachment_lines(attachments)` 模块级渲染；两个消费点——①`run_task` 非续跑分支 objective 注入前（守卫是 `if task_id`，**勿改 `if task`**：无 task_id 调用时 `task` 未绑定会 UnboundLocalError），从 `task.context.attachments` 拼「📎 任务附件（可用 run_cmd 读取，只读勿改写，工作区相对路径）」；②`_human_note_notice` 每条引导下追加附件行。附件本体在 `<proj>/artifacts/attachments/`，agent cwd=scratch 读项目内路径无 pathguard 拦截。

## 角色软边界（§6.6，违例回填 `[越界拒绝]`，循环不中断）

- **tools 白名单**：不在 `allowed_tools` 的工具分发前拒绝；complete_task/fail_task/finish 永远放行。

## kb_open（M0 全局形态）

- **M0 kb 全局单根**：数据源 = `load_kb_sources` 按启用域合成 `[packs/kb/<cap>]`（恒递归，目录不存在=空源；kb_sources.json 退役）。module 主口径=**全局形态** `<域>/<快照>/<路径>`（如 `web/webapp/authn/auth-jwt.md`）——首段==启用域时锁定该域解析（跨域同名快照天然消歧），否则按启用域顺序逐域尝试域内相对形态（兼容旧引用）；resolve 后强制落在 root 内（穿越返回 `[拒绝]`，且不落 kb.open 事件）；不存在时回可用清单（前 50 个，防幻觉）。legacy `kb_search` 返回 path **已补域前缀**，即 kb_open 的 module 口径，防前缀幻觉——默认方法入口是自包含 Skill 的 `skill_open`，legacy 工具只服务尚未迁移的历史资料。
